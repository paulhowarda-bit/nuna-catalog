# 2026-11-22, the audit feed closes each reader it replaces (item 149)

- `AuditFeed.reader()` now closes the `EventsReader` it replaces when the audit table's pointer moves; `EventsReader`
  is `AutoCloseable` and closes its `S3FileIO`. So Iceberg no longer logs "Unclosed S3FileIO instance" with a stack
  trace for each one as the collector reaches it (seen in the nuna-demo's catalog log).
- `EventsReader.open` lends `S3FileIO` the server's S3 client through `Borrowed`, an SDK `DelegatingS3Client` whose
  `close` does nothing, so closing a reader leaves the shared client open.
  - Read from iceberg-aws 1.12.0's bytecode: `S3FileIO.finalize` calls `close()` before it warns, and that closes
    the client it holds. So before this fix, each collected reader also closed the shared client, and the readers
    after it read through a closed client.
- Test: `AuditFeedReaderTest` (catalog-server, fast build). The real feed runs over a store double, and an S3 double
  serves a real audit table (`AuditTableOverS3`, moved out of `EventsReaderOnTheServerTest`).
  - It checks that the replaced reader is closed, the shared client stays open, and the next reader reads.
  - It fails with both halves of the fix taken out, and passes with them.
- Bites, each BITES with the tree restored (`bites/run.sh`, one at a time):
  - new: `bites/D23/feed-leaves-replaced-reader-open.patch` and `bites/D23/feed-reader-closes-the-servers-client.patch`;
  - item 148's `bites/D23/feed-reader-builds-aws-factory.patch`, recorded again with the same break against the moved
    line.
- A view's Governance tab no longer says "Commits are allowed." when there is no DR freeze. On a view it now says
  "Its definition may be replaced." (`panels.js`).
- `./gradlew build` after merging main is green: 1,374 test results, none failing. Nothing heavy was run.
- The running demo was not changed.
