# 2026-11-15, compaction on need, in a nightly cleanup window (backlog 46, D30 amended 2026-11-15)

What changed:
- `CleanupWindow` (catalog-maintenance): `keel.maintenance.cleanup-window`, start and end as local times and a named
  zone, required. An end before the start crosses midnight; an end equal to the start is the whole day. A start the
  clocks skip opens as late as the skip; a time the clocks repeat is its first, so a night never opens or closes twice.
- `Worker`: compaction and orphan scans start only while the window is open. Expiry, manifest rewrite, purges and
  due deletions run at every scan, as before. A worker started in the day starts neither. The orphan interval counts
  whole nights; an orphan scan the window's end cuts short (`OrphanScan.CutShort`) is not recorded, so its table is
  scanned the next night.
- `CompactionNeed`: reads the current snapshot's data and delete manifests. A table needs compaction for small files
  (a partition with at least `compaction.min-input-files` data files under 75% of `compaction.target-file-size-bytes`),
  for deletes (delete files of every kind more than `compaction.delete-file-ratio` of the data files), or for any
  equality-delete file. Defaults are rewrite_data_files' own: 5, 0.3, 512 MiB. The catalog's `MaintenancePolicy`
  knows and checks the two new keys.
- `NightlyCompaction`: each enabled table assessed once a night. The needy queue equality deletes first, then by
  score (how far past its thresholds). At most `compaction.max-jobs` (new, default 2) run at once, and none starts once
  the window has closed. When it closes, Jobs still running are counted as cut off and queued tables as left over.
- `KubernetesJobs`: one Job per table and night, `keel-compact-<table id>-<yyyyMMdd>`, so a restart finds tonight's
  Job and starts no second. Each Job has `activeDeadlineSeconds` to the window's end and runs rewrite_data_files with
  `partial-progress.enabled`, the thresholds it was judged by and, for deletes, `delete-file-threshold=1` and
  `remove-dangling-deletes`. A Job's state is read from its conditions (`DeadlineExceeded` is cut off). The TTL is a
  fixed day, for the log, and schedules nothing.
- Removed: `compaction-interval` and `compaction.deadline` (settings, README, chart).
- Meters (`WorkerMetrics`): `tables.assessed`, `tables.needing.compaction` by `reason`, `compactions.started`,
  `compactions.cut.off`, `tables.left.over`, and the gauge `table.compaction.need` per needy table, labelled
  catalog, namespace and table, uncapped. A table that no longer needs compaction, or was not assessed that night,
  loses its gauge. docs/observability/worker-metrics.md lists them and adds a "compaction falling behind" alert.
- Chart: `config.keel.maintenance.cleanup-window` is required and its times are quoted in application.yaml (YAML 1.1
  reads an unquoted 22:30 as 1350); `compaction.max-jobs` replaces `deadline`. values.yaml and the README say how.
- `MatrixCompaction` and `EngineMatrixTest` (catalog-tests-engines) and `KubernetesCompactionTest` moved to the new
  `launch` and the chart's window.

Choices, not settled by the item:
- The window has no default: the chart and the worker refuse to start without one.
- Small files are counted per partition, as rewrite_data_files groups them.
- A delete-driven Job rewrites every data file with a delete and removes dangling deletes.
- `compaction.max-jobs` is new (default 2); `compaction.deadline` went, the window's end replacing it.
- A failed (not cut short) orphan scan counts as that night's scan.
- Night state is in memory. A restart in the window assesses again and rescans orphans, and its cut-off and left-over
  counts are lost.
