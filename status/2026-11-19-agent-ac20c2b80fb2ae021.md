Item 79 (D21, amended 2026-11-20: "Yes, non-root"). Built, not yet run live; the item stays open.
- `deploy/local/run.sh up` makes the catalog's own Silo user, `nuna-catalog`, before the chart. Its policy lets it
  read, write and list beneath `s3://warehouse/tables`, and delete there too, on purpose: the delete policy with
  `except` must be what refuses the catalog a delete, as wherever another grant gives it. `values.yaml` signs the
  catalog in as that user, no longer as Silo's root user, whom no policy binds.
- Once the catalog is up, `up` reads `GET /management/v1/maintenance/delete-policies` as `oscar` and applies the
  MinIO pair: `except` as policy `nuna-no-delete` on `nuna-catalog`, `to` on the worker's user `nuna-maintenance`,
  which `up` now makes (it moved there from `run.sh worker`, which keeps working on it).
- `run.sh smoke` loads the table as `lake` with vended credentials, puts `data/smoke-probe` beneath it with them,
  then expects: the vended credentials' DELETE 403, `nuna-catalog`'s DELETE 403, the vended GET 200 (the file is
  still there), `nuna-maintenance`'s DELETE 204. Each request is signed by curl (`--aws-sigv4`) through a
  port-forward to Silo, so no new tool is needed. `mc rm` was not used: it stats the object first, which the
  worker's delete-only policy refuses, and it exits 0 when a delete is refused.
- `deploy/README.md` ("Delete rights", "Trying it locally") says so.
