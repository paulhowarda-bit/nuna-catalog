# 2026-11-19, the overnight load tests allow one full load per credential-epoch window boundary (backlog 76)

Since item 15 a table load's ETag carries the issuance window it falls in (7.5 minutes by default), so it changes at
every window's end. `SloTest` and `TenThousandSnapshotsTest` (catalog-tests-load, `overnight`) asserted that every
conditional load over some 25 seconds was a 304, which a boundary inside that stretch broke, about one night in 6.

What changed, all in catalog-tests-load's tests:
- `ConditionalLoads` (new) judges one client's conditional loads of one table. A 304 always passes. A 200 passes
  only with a new ETag and a window boundary between the sending of the load that gave the held ETag and this
  load's answer (so a load in flight across a boundary counts as crossing it); the client then holds the new ETag,
  and that boundary is used up, so no test can see more full loads than boundaries crossed. The window is
  `nuna.storage.credential-lifetime` / 4, bound through the server's `StorageSettings` with the settings the load
  stack gives its servers (none: the 30-minute default), numbered `floor(now / window)` as `StsCredentialVending`
  numbers it, on the test's clock (the servers run on the same machine).
- `SloTest`: each of the 16 readers holds its own ETags and keeps the new one after a boundary load. Only 304s are
  timed; boundary loads are counted and reported in `slo.txt` with the boundaries passed. The cross-server check
  now runs right after the ETags are taken, so its line reads 32 of 32 unless a boundary falls in those few seconds, and
  counts any boundary load; it is still reported, not asserted.
- `TenThousandSnapshotsTest`: its 200 conditional loads, per format version, are judged the same way and reported.

Checked:
- `ConditionalLoadsTest` (new, Java only, runs in the fast build): 10 of 10 passed. Among them a client loading for
  two hours with 5 s loads 0 to 20 s apart against a server whose ETag is its window's at an instant inside each
  load: 556 loads, 16 full loads for 16 boundaries, 3 loads in flight at a boundary, answered on either side.
- Bites: two in `bites/D14/`, `boundary-load-anywhere` (no window check) and `straddle-counted-twice` (a straddling
  load does not use its boundary up), each checked with `git apply --check` and run once here through the shared
  build script with `:catalog-tests-load:test --tests nuna.catalog.load.ConditionalLoadsTest --continue -x
  bitesApply`: 4 of 10 tests failed on assertions, then 1 of 10 (the one named); the file was restored and its hash
  checked against the commit. `bites/run.sh` did not run.
- After merging `main` (5d10db7), the shared fast build script (`./gradlew build`): "All 328 bites apply.",
  BUILD SUCCESSFUL in 26s; the test results in every module's build folder hold 1002 tests in 90 classes, none
  failed or skipped.

Not covered:
- `SloTest` and `TenThousandSnapshotsTest` did not run: they are `overnight` and start containers; the overnight run
  shows them. Nothing was run against servers.
- Tests that expect one 304 milliseconds after taking an ETag (`RestRoutesTest`, `CatalogMetricsRoutesTest`,
  `VendingRouteTest`, `GovernanceRoutesTest`, the conformance `ClientOperationsTest`) were left as they are.
