# 2026-11-20, item 103: commits on a branch and the merge transaction in the store (D33)

What changed:
- `catalog-store-api`: `RefLock` (`Hold` for a commit on a branch, `End` for a merge); `CommitBatch` gains
  `Optional<RefLock> ref` and `refKey()` and checks a batch's keys fit its ref (the older constructors are a batch on
  no ref); `CommitResult.Inactive` gains a `Subject` (`OBJECT`, `REF`); `WriteResult.Reason.REFERENCED`.
- Stores (PostgreSQL and CockroachDB, Oracle, MongoDB): a batch's ref is locked before any pointer and checked first
  (gone, a tag or expired: `Inactive(REF)`; a swap outside the branch's cut: `Inactive(OBJECT)`; a merge that does
  not hold an own pointer of the branch: `Conflict` on it); a merge ends the branch after its swaps with the code
  `deleteRef` now shares. `claimPurge` answers `Refused(REFERENCED)` while a ref's cut names the object, and
  `listPurgeEligible` leaves such objects out. `docs/storage-design.md` sections 3, 8, 9 (f) 3 and 8, (g).
- Tests: `BranchCommitSuite` (11 tests, heavy) nested as `BranchCommits` in the four store suites; `MutationSuite`
  drives "commit on a branch" and "merge"; `RefLockTest` (5 tests, Java only). `RefSuite#aDeletionLeavesNothing`
  made its first own pointer at version 2, which `PointerSwap` refuses; it is version 1 now.
- Item 103 stays open (its progress section lists the choices made).
