# 2026-11-20, a CA bundle per storage profile, in the server and the worker (backlog 21)

A storage profile can name a CA bundle, a PEM file of the CA that signed an on-prem store's certificate; every S3
and STS client built for that profile trusts it beside the JVM's CAs. Without the setting nothing changes, and the
JVM's trust store is left alone.

- `catalog-objectstore`: `CaBundle` reads the PEM (one certificate or several, labels between them allowed) and
  refuses a file it cannot read, one with no certificate, or one with a certificate that does not parse, the last
  certificate cut short included, which the JDK's parser drops without a word. `applyTo` gives an SDK builder the
  Apache 5 client with a trust store of the JVM's CAs plus the bundle's. `MetadataFiles` and `CredentialVendor`
  take an `Optional<CaBundle>`.
- Server: `nuna.storage.profiles.<name>.ca-bundle` (`StorageSettings.Profile.caBundle`). `CatalogStorage` reads
  each profile's bundle at startup and stops with `nuna.storage.profiles.<name>.ca-bundle: ` and the file's path
  when it cannot.
- Worker: `nuna.maintenance.storage.<name>.ca-bundle`, which needs the profile's `endpoint`. `TrustedS3Clients`,
  an Iceberg `S3FileIOAwsClientFactory`, repeats Iceberg's default S3 client chain but trusts the bundle registered
  for the client's `s3.endpoint` (scheme, host and port). The worker's own `S3FileIO`s use it, and so do those
  reading tables with vended credentials, through the client properties `Catalogs` gives its REST clients. Two profiles naming different files
  for one endpoint, or an unreadable file, stop startup naming the setting. `catalog-maintenance` now depends on
  `catalog-objectstore` for `CaBundle`.
- Vended credentials are unchanged: engines trust the store through their own setup, compaction Jobs (Spark)
  included.
- Helm: both charts take `storageCaConfigMap.name` and mount it at `/etc/nuna/storage-ca`, as they mount the OTLP
  CA. Docs: `docs/install-at-work.md` sections 5 and 6, `catalog-maintenance/README.md`'s settings table, the
  charts' values comments. `build-plan.md`'s M6 Open line corrected.
- Test support: `PrivateCa` in `catalog-tests-s3` makes a private CA and a server certificate for localhost and
  127.0.0.1 with the JDK's keytool, and serves canned answers from an in-process JDK `HttpsServer`.
- Bites, in `bites/M6/`: `ca-bundle-not-trusted`, `ca-bundle-cut-short-accepted`, `ca-bundle-ignored`,
  `ca-bundle-unreadable-ignored`, `worker-ca-bundle-ignored`, `worker-ca-bundle-any-endpoint`,
  `worker-ca-bundles-collide`. `M6/startup-overlap-unchecked` and `OBS-41/objectstore-not-observed` recorded again
