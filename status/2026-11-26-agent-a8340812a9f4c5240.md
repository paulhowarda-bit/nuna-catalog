# 2026-11-26, backlog 265 at home: every 5xx answer ends its server span ERROR

**What was wrong, verified.** Spring's server observation filter marks the request's span ERROR only for a failure that
escapes to the container. A 5xx built by an `@ExceptionHandler` (`ErrorResponses`, `AuditUnavailableResponses`), or
written by a route or a filter without a throw (a commit's `Unavailable` reply, authentication's 503), left the span's
status UNSET, so a tail sampler keeping traces with status ERROR would miss them. An escaped failure was recorded with
its message, which can name a table or a principal. Both shown by the new test with the fix taken out (the two bites).

**What changed.** `RequestMetrics` marks the server span ERROR for every 5xx on an Iceberg REST route, with an
`AnswerFailed` naming the status and the exception's class or the body's error type, never a message; an escaped
failure is logged in full and rethrown as an `AnswerFailed`. A 4xx stays unset. `MetricsWiring` passes it the
`ObservationRegistry`. Boot's `http.server.requests` now tags a 5xx `exception=AnswerFailed`. Docs: spans.md, "The
server span's status"; README.md, "Sampling", says which traces head and tail sampling keep.

**Checked.**

- `./gradlew :catalog-server:test --tests ...ServerSpanStatusTest --tests ...CatalogMetricsTest --tests ...ObservedTest`:
  8, 4 and 5 tests, all pass. `ServerSpanStatusTest` is untagged (Java only, MockMvc and the OpenTelemetry bridge).
- Bites, run by hand once each: `bites/OBS-265/five-hundred-not-error.patch` fails 5 of the 8 (expected ERROR, was
  UNSET); `bites/OBS-265/escaped-failure-message-on-span.patch` fails the escaped case (the message on the span). Both
  `git apply --check` clean, source restored.
- The three `bites/OBS-39/requests-*` patches recorded again with the same breaks against the new `RequestMetrics`;
  all apply, as does `bites/M8/store-outage-escapes-routes.patch`. Their test (`CatalogMetricsRoutesTest`) is heavy
  and was not run.
