# 2026-11-24, rule expressions parsed when set, and If-Match on rules (backlog 244)

**Changed:**

- **Parsing:** setting a row filter or column mask parses it with Trino's own parser, `io.trino:trino-parser` 484
  (Apache-2.0), and refuses one that does not parse with 400, saying where. Subqueries and other tables are accepted
  (D20, amended 2026-11-24). `RuleColumns` reads a filter's columns from the parse tree instead of its words.
- **Versions:** each rule has a version, given in the list. Set and remove take `If-Match: "<version>"`; a stale one
  answers 412 and writes nothing. If-Match is optional on the server; the console's edit and removal send it and
  say in words when another grant admin changed the rule, then redraw the list.
- **Stores:** a `rule_version` column on PostgreSQL (`V16`), CockroachDB (`V15`) and Oracle (`V17`), a `version`
  field on MongoDB. A removal now locks the table's row, as a put does.
- **Dependencies:** trino-parser brings trino-grammar, Guava 33.6.0-jre and antlr4-runtime 4.13.2 (about 5.2 MB);
  `docs/install-at-work.md` lists them for the mirror.
