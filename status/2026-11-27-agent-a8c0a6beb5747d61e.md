# 2026-11-27, backlog 303: the DR drill's archive tail

- Cause: `LogWriter.offer` (catalog-audit-tables) refused past `2 * maxRows`, an int; the M8 stack's archive leg
  passes `Integer.MAX_VALUE`, so the bound overflowed to -2 and every OTLP request was answered 503 after its records
  were archived. The servers' exporter retries 503 with backoff and sends one batch at a time, so the last batches were
  still queued when the drill killed the primary servers, and the archive never held each table's last swap. Came in
  with backlog 262 (b38c610c), which moved archiving from Kafka to the log.
- Fix: the bound is taken in long. `LogWriterTest#aMaxRowsPastHalfTheIntRangeStillTakesRecords` added; bite
  `bites/OBS-303/max-rows-doubled-in-int.patch`, checked with `git apply --check`.
