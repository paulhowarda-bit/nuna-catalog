# 2026-11-22, merge a branch into main (backlog 107)

What changed:
- `POST /management/v1/catalogs/{catalog}/refs/{ref}/merge`, with `?dry-run=true`. It moves every table and view the
  branch changed onto main in one `CommitBatch` (main's swaps, the branch's own pointers held, `RefLock.End`), or
  answers 409 `RefMergeConflictException` naming every conflict and moves nothing.
- The merge rebases over main's compaction and expiry. A table changed on both sides beyond that, or dropped on main,
  is a conflict.
- Main's rules, holds and the DR freeze judge the whole change from main's metadata to the branch's. The caller needs
  `write` for data alone and `modify` for a definition change, on each table, in one batched check, plus `create` on
  the catalog.
- The cap is `nuna.refs.max-merge-tables`, and the branch ends with the merge.
- Choice made (Paul may overrule): main takes its own unmarked copy of the branch's metadata at main's next version,
  whose predecessor is main's file, so a DR reconcile never follows a branch's chain. `backlog/107.md` has this, the
  rebase and the other choices.
- New code: `MergeMetadata` (catalog-iceberg), `Merge` (catalog-core, from `CommitEngine.merging()`), and the route in
  `RefRoutes`.
- The dry run counts, and does not name, the tables the caller cannot describe (security finding 2).
