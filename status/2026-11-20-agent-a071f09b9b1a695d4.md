# 2026-11-20, the DR reconcile's archive read streams each chain instead of holding it whole (backlog 86)

`ArchivedCommits.read`, which `dr-reconcile`'s `accept-archived` calls, no longer joins every segment of a chain into
one byte array and decodes every record into one list. Each chain is checked in one pass, segment by segment: a
segment is fetched (a streamed `GetObject` of its version) only once the one before it has been read to its end, and
the read holds one buffer of the chain (`ObjectLockArchive.READ_BUFFER`, 64 KiB) besides the record being checked.
Of each chain only its commit records are kept, and only its main-pointer swaps and a count are held; they count only
once the chain verifies. `ReconcileRoutes` needed no change (item 28 held it): its call is the same.

- The check is the one the read made before, through the same code: `ArchiveVerifier.verify` over the segments
  joined in order, from genesis to the last segment's recorded end (or the anchor), every record's sequence and hash
  across segment boundaries, the same line numbers and defects. The read makes no signature or Object Lock check, now
  or before. `ArchiveVerifier` gained a package-private overload that takes the caller's buffer and hands over each
  record's body once its hash checks; `ObjectLockArchive.verify` and `events` use the same pass.
- A chain that fails part way yields nothing: the read throws `IllegalStateException` as before (500 at the route) and
  returns no `Read`.
- The order of failure is kept. After a break the read still fetches the chain's later segments, as the read that
  fetched every segment before checking any did, so a segment the store cannot serve still fails the read as
  unreadable (503) before the break fails it as broken (500). An event that cannot be decoded fails the read only once
  the chain is known to verify, as before. The cost: a broken chain is still read to its end, streamed.
- Tests, all Java only, over `MemoryS3` (which now answers a streamed `GetObject` and counts the bytes it hands out):
  `ArchivedCommitsTest` 9 (4 new). A chain of 40 segments, 1,000 records, about 1 MB, read with a 256-byte buffer:
  when each record is handed over no more than 256 bytes past its end have been fetched, every byte is fetched once,
  one GET open at a time, and `ArchivedCommits.read` returns the 500 swaps and 750 commit records. A record changed in
  segment 21 and segment 21 emptied each fail the read, with the default and the small buffer, with exactly the
  message of the whole chain's check (`HASH_MISMATCH` at line 504, `SEQUENCE_BREAK` at line 501). A break in segment
  21 with segment 31 unservable fails as unreadable.
- Bites in `bites/M8/`: `archive-read-yields-broken-chain`, `archive-read-stops-at-break`,
  `archive-read-holds-whole-segments`; `reconcile-archive-reads-other-branches` recorded again against the moved
  filter. Each was applied in turn and `./gradlew build -p catalog-audit --continue` run through the agents' build
  script: the first failed 4 tests ("Expecting code to raise a throwable"), the second 1 (`IllegalStateException`
  where `S3Exception` was expected), the third 1 (26,104 bytes fetched when record 1 was handed over, at most 1,402
  allowed), the fourth 2 (another branch's swaps counted); every other test passed; the file was restored after each.
