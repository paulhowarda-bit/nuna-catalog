# 2026-11-20, the console's "Sign out" ends the IdP's session (backlog 17)

Paul, 2026-11-19 (D16, amended): "End the IdP session".

- `auth.js` `signOut`: the console forgets its token, reads `end_session_endpoint` from the IdP's discovery document
  (the same read as signing in) and sends the browser there with `client_id` and `post_logout_redirect_uri`, its own
  page, the sign-in's redirect URI. Back on the page it shows "Signed out.". It keeps no ID token, so it sends no
  `id_token_hint`; Keycloak and PingFederate then ask the person to confirm. No `end_session_endpoint`, or discovery
  unreadable: the token goes, the browser stays, and the message says the IdP's session was not ended.
- The console's Keycloak clients allow the page as a post-logout redirect URI (`post.logout.redirect.uris`): the
  demo's realm (`demo/k8s/keycloak-realm.json`, edited, not applied to the running demo) and the test's
  (`keycloak/console-realm.json`). `deploy/local/keycloak.yaml` has no console client (its console signs in with the
  token box), so it is unchanged.

  post-logout settings, and `nuna.ui.oidc` in the values. `demo/README.md` and `demo.sh`'s closing text no longer
  say the console's sign-out leaves Keycloak's session; `build-plan.md`'s UI open item follows.
