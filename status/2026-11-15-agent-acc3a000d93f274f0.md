# 2026-11-15, table health and the worker's scans kept by the catalog (backlog 47, D38)

What changed:
- Store API: `TableAssessment`, `CompactionRun`, `MaintenanceScan`, `TableHealth` and six `MaintenanceStore` calls
  (record an assessment, record a compaction, read one table's health, list the neediest, record a scan and prune to
  the newest 50 plus the last success, list the scans). The newest assessment wins; a later compaction start wins, and
  one reported running once it has ended changes nothing; an ended scan keeps its end. Writes are bookkeeping, not
  audited. Scores are kept to four decimals, at most 1e9.
- Schema steps, each adding only: PostgreSQL `V8__table_health.sql`, CockroachDB `V7__table_health.sql`, Oracle
  `V9__table_health.sql` (`table_health`, `maintenance_scan`), MongoDB step 7 (indexes on the two new collections; the
  neediest index covers needy tables only). Older servers never read or write them, so the rolling upgrade stays safe.
  A purge deletes the table's health row on every store. SchemaAtStartupTest and RollingUpgradeTest now expect 8.
- Server (`HealthRoutes`): three PUT report routes for the worker (maintenance principals acting as themselves, 403 for
  anyone else; 404 for a table gone, 409 for a name now another table's) and three reads: the neediest tables the
  caller may `select` (batch-authorized, paged by the store's rank token, at most 2,000 examined a page), one table's
  health (`select`), and the scans with the last success (platform operators). MutatingRoutesAuditTest keeps the
  report routes out of its audit-record test, since reports write none, and checks their refusals are audited.
- Worker: `HealthReports` sends the reports; `Worker` reports each scan's start and end (succeeded as its meters judge
  it; the first work-list failure or exception as the error); `NightlyCompaction` reports each assessment and each
  Job's start (or the Job found after a restart) and end, cut-off at the window's close. `CompactionNeed` counts
  deletion vectors (Puffin delete files) apart from position deletes, keeping its 7-argument constructor for
  catalog-tests-engines. `ScanReport` gained the scan's id and a `report` failure kind.
- Docs: new docs/observability/table-health.md (routes, who may call, the JSON the console page will read, the rules,
  the storage); worker-metrics.md (the `report` kind); docs/observability/README.md; catalog-maintenance/README.md.
