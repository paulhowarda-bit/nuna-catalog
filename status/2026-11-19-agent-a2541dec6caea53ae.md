# 2026-11-19, audit-trail reads are limited per caller (backlog 19)

`GET .../audit` opens a Kafka consumer for each read. One caller (the principal its token names, or the end user a
trusted engine acts for) may now read at most `nuna.governance.audit-reads-per-minute` times in any minute on a
server, default 60. It is built as the purge limit is: counted in each server's own memory, so per replica, over a
sliding minute. Beyond it the route answers 429 `TooManyRequestsException` with `Retry-After: 60` in the purge
limit's error body, opens no consumer, and audits nothing, as the purge limit's 429 is not audited. A refused (403)
or badly asked (400) read takes no slot. 60 because the console reads only when a person opens an object's Audit
tab, changes its count or presses Refresh; nothing polls it.

Changed: `AuditReadRoutes`, `GovernanceSettings` (the setting, at least 1), the new `AuditReadLimitTest`, the
constructors in `ManagementHiddenNamesTest` and `MaintenancePolicyTest`, `GovernanceServer` (the limit at 1000, so
`AuditReadRouteTest`'s 200 ms polling never meets it), the bite `bites/UI/audit-read-unlimited.patch`,
`deploy/README.md` (Before production, "Audit-trail reads": per replica) and `build-plan.md`'s UI v1 Open line.
