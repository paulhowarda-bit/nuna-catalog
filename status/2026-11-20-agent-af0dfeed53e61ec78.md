# 2026-11-20, the server on Oracle and on MongoDB through a database outage (backlog 70)

Item 7 made the Oracle and MongoDB stores raise `StoreUnavailableException` for a database they cannot reach; this
branch checks the server's answer to it at the routes.

- `OracleBackendTest` and `MongodbBackendTest` (heavy) put their database behind Toxiproxy on a Docker network, as
  the store tests' `OracleFree` and `MongoReplicaSet` do, and point the server at the proxy (`LinkForTests`). Each
  gains `anOutageAnswers503WithRetryAfterUntilTheLinkIsBack`, which runs `BackendFlow.outage`: with the link cut, a
  load and a commit each answer 503 `ServiceUnavailableException` with `Retry-After: 2` in the Iceberg error shape;
  with it back, the load (repeated on Retry-After, at most two minutes) shows the 503 commit applied nothing, then the
  commit and a reload succeed. The store fixtures are package-private in item 28's store modules and shared by no
  test jar, so the proxy is made the same way in `catalog-server`'s tests; the build's `testcontainers-toxiproxy`
  dependency and pinned `toxiproxy.image` are reused (`catalog-server/build.gradle.kts`).
- `StoreOutageRoutesTest` (Java only; `catalog-server` had no test of this mapping): the real table routes, commit
  engine and `ErrorResponses` through MockMvc, over a store double raising `StoreUnavailableException`, with the
  database away and lost mid-request (a load at its pointer read, a commit inside the engine).
  `ErrorResponsesForTests` hands the package-private advice to it, as `DenialsForTests` does for `Denials`.
- Bites: `bites/M8/store-outage-escapes-routes.patch` (the `ErrorResponses` handler removed) and
  `bites/M8/commit-unavailable-answers-500.patch` (`ObjectRoutes.reply` answers `Unavailable` with 500), each checked
  with `git apply --check`.
