# 2026-11-17, HTTPS for the demo at one front door, with a certificate work's can replace (backlog 58)

Changed: every port the demo publishes, 8180 to 8186, is HTTPS through one nginx pod, `front`
(`demo/k8s/ports.yaml`), which ends TLS with the certificate in `~/.nuna-demo/tls/` (`tls.crt` with its
intermediates, `tls.key`, `ca.crt`) and passes each request on over plain HTTP to the Services the stack already
uses. `NUNA_DEMO_HOST` (default `localhost`) names the host every browser address uses. At home `up` makes a demo
CA, constrained to localhost and 127.0.0.0/8, and a server certificate from it, and renews the server certificate
30 days before it expires; at work Paul replaces the three files and sets `NUNA_DEMO_HOST`. `up` checks the
files before publishing them as Secret `demo-tls`: all three there, the certificate names the host, has not
expired, matches the key and chains to `ca.crt`. Keycloak (`--hostname`, `--proxy-headers=xforwarded`), kafbat
(forwarded headers), oauth2-proxy (Secure cookie), the realm's redirect addresses and the catalog's issuer all
use `https://<host>:<port>`. `demo.sh`'s own calls trust `ca.crt` only. The README has a section on the
certificate; `docs/install-at-work.md` section 10 says how to plug in work's files, a `.pfx` included.

Found: Studio cannot sit behind a TLS proxy over plain HTTP: it builds the address Keycloak posts its SAML
response to from the request it gets, so it asked for `http://` and Keycloak refused it. Studio now serves HTTPS
itself with the same certificate (`singlestore.Dockerfile`), and nginx forwards to it over HTTPS. SingleStore's
`saml_message_recipient` follows `NUNA_DEMO_HOST` through a build argument.

time the front door's pod was replaced: Docker Desktop's LoadBalancer still sends a new connection to the pod
