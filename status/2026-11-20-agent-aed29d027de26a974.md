# 2026-11-20, a table's first DR watermark is never its empty creation version; item 99's doc lines (backlog 99)

- **"Never the empty version"** (D37, amended again 2026-11-20). `DrVerify.whole` gives no version when the newest
  whole one it finds is below the pointer and no snapshot of it reaches a data or delete file (no snapshot, or one
  whose manifests list no live file). So a table that lost an old file, whose only whole version is its creation
  version, gets no first watermark and stays with its owner, as before item 99. The test covers every snapshot the
  version holds, so an empty create-as-select's creation version counts as empty and a version after a delete of
  every row does not. At the pointer the creation version is still given, as before item 99: a new table is that
  empty, and the drill waits for that watermark before its writers start. Only a version found below the pointer
  costs a read of its metadata file again and of its manifest lists until one lists a live file. Views keep the rule
  as built.
