# 2026-11-20, the audit catalog's groups as a server setting, D23's fourth bite and the engine matrix's audit leg (backlog 85)

Item 27's rest, as D23 (amended 2026-11-20) settles it.

- **The setting.** `nuna.audit.tables.catalog`, `.readers` and `.writers` (`AuditCatalogSettings`, read by a new
  component, `AuditCatalogGrants`, in `catalog-server`'s `security` package). At startup, after the declared catalogs
  are created, the server grants the readers' group `select` on the audit catalog and the writer's group `create` and
  `write`, each through the store's conditional grant write with the separation of duties checked inside it, as the
  grants API does. A grant that already exists is left as it is; unset makes no grants; grant admins may grant other
  groups there through the API, and nothing refuses or revokes them. The server refuses to start when the catalog is
  not declared, a group is named without a catalog, or a grant breaks the separation of duties.
- **Audited.** Chosen to match the server's other startup writes (the catalogs and profiles `CatalogStorage` declares):
  each grant it makes writes a `nuna.catalog.grant` record through the outbox in the same write, by principal
  `nuna-configuration` (engine `catalog-server`, request `startup`), and is recorded as granted by
  `nuna-configuration`. A grant left as it was records nothing, so a restart records nothing.
- **The fourth bite**, `bites/D23/readable-without-the-grant.patch`: the server grants the readers nothing. Recorded
  against the Java-only test `AuditCatalogGrantsTest#grantsTheReadersSelectAndTheWritersCreateAndWriteOnTheAuditCatalog`
  instead of the heavy `AuditTablesTest#onlyTheAuditorsFindTheAuditTable`, as the brief allowed. That test's fixture
  now takes both groups from the setting instead of writing `grant_record` rows, so it would fail on the same break.
- **The engine matrix's leg**, `EngineMatrixTest#auditTables` (order 5; SingleStore moves to 6): the catalog declares
  `nuna_audit` with the groups set (`k8s/catalog.properties`); the harness builds the writer's image from its runnable
  jar, runs it from its chart against a token endpoint of its own (`k8s/token-endpoint.yaml`,
  `images/python/token_endpoint.py`), waits for a commit reaching the topic's end offsets, then Spark and PyIceberg
  read `nuna_audit.audit.events` as the readers' group (`audit_tables_matrix.py` in both images). The module's
  README says what it checks.
- `catalog-audit-tables/README.md`, "Deploying it", names the setting instead of grants made by hand.
