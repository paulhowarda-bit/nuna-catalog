# 2026-11-19, the credential epoch is a shared issuance window, so ETags survive a change of server (backlog 15)

Paul chose "Shared epoch" over sticky routing (D14, amended 2026-11-19). The ETag's credential epoch was a hash of
the server's own cached access key, so a conditional load answered by another server was a 200 (M8: 0 of 32).

What changed, all in `StsCredentialVending` (catalog-server, `storage/`):
- The epoch is a hash of the issuance window, `floor(now / window)` on the server's clock counted from the Unix
  epoch, with the profile, location, access, principal, subject and engine the credentials are for. The window is a
  quarter of `nuna.storage.credential-lifetime` (7.5 minutes by default), so servers with the same lifetime share
  windows; no new setting. Another caller or another access level is still another ETag, as before.
- Cached credentials are renewed when they have less than a window, the refresh margin and a minute left (13.5 of 30
  minutes by default; it was the larger of a quarter of the lifetime and the margin plus a minute, 7.5). Every set
  handed out in a window so lasts through the window's end and the margin, with a minute to spare. The cost: a set
  is reused for 16.5 minutes instead of 22.5, about a third more AssumeRole calls per caller, table and server.
- Credentials that would not last through their window's end and the margin (a margin near the lifetime, as
  `VendingNearExpiryTest`'s 20 minutes over 15; or STS's clock far behind the server's) keep an epoch of their own,
  the access key's hash as before, so only the server holding them can answer 304 for them, and the route's existing
  margin check stops that.
- `TableRoutes` and `ETags` are unchanged; `CredentialVending.Vended`'s javadoc says what the epoch now is.

Why a client never gets a 304 for credentials too near expiry: it holds a window's ETag only with credentials that
last past the window's end and the margin, and a server answers that ETag only while its own clock is in the window.
So the credentials have at least the margin (5 minutes) less that server's clock lag left. A server whose clock is
on the other side of a boundary gives the other window's ETag: the client loses a 304, nothing worse.
