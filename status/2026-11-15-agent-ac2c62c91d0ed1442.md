# 2026-11-15, spans and timers for the store, object store, STS and Kafka audit calls (backlog 41)

What changed:
- Each call a request makes to the catalog store, to the object store for metadata files, to STS for AssumeRole, and
  each synchronous audit publish to Kafka up to its acknowledgement, is a Micrometer Observation: a child span of the
  request's server span and a timer of the same name (`keel.store`, `keel.objectstore`, `keel.sts`,
  `keel.audit.publish`), tagged with bounded values and the call's outcome (`committed`, `conflict`, `found`,
  `written`, `issued`, `acknowledged`, `error`, ...) and `exception`.
- New package `keel.catalog.server.tracing`: `Observed` makes the observation; `ObservedStore` (a dynamic proxy, so
  every store method is covered, a new one included), `ObservedTableFiles` and `ObservedPublisher` decorate the
  collaborators where they are wired (StoreWiring, CatalogStorage, GovernanceWiring); `StsCredentialVending` observes
  AssumeRole. The stores, catalog-audit and catalog-objectstore are unchanged.
- A failed call's span is an error that names the exception's class only (`CallFailed`): those messages carry table
  locations, STS session names (which name the principal) and values a database refused.
- A call made outside any observation is not observed: the outbox relay claims every 250 ms, and each claim would
  start a trace of its own. So the relay, the archive and startup make no spans or timers.
- New docs/observability/spans.md; README.md's "Traces" points to it.
- Knock-on changes to tests: the store bean is now the observed proxy, so MongodbBackendTest and OracleBackendTest no
  longer assert the bean's class (their self-check codes, which only that store reports, still show the backend);
  VendingRouteTest passes `ObservationRegistry.NOOP` to CatalogStorage; TelemetryTest waits for the request's server
  span instead of the first span of its trace, which can now be a child. catalog-server's tests take
  `micrometer-tracing-bridge-otel`, already on its runtime classpath through the starter. Item 41's Touches line gained
  these files and README.md.

Checked:
- `ObservedTest` (5), on Micrometer's OpenTelemetry bridge with an SDK tracer and a SimpleMeterRegistry: a call inside
  an observation is one child span and one timer with its tags; outside any, neither; a failure is an ERROR span
  whose name, status, attributes and events hold nothing of the message; store outcomes.
- `SpanTreeTest` (3), the server with PostgreSQL, Silo's S3 and STS and a Kafka broker (the `GovernanceServer`
  harness), through an in-memory `SpanExporter` bean: a commit's tree (server span; object store write ending before
  the store's `commit` starts; STS; the credential issue's publish) and a load's (store reads; the read audit's
  publish), and no attribute naming a principal, the table, the namespace, a location, the bucket or the vended
  credentials, each span carrying only its own keys.
- Bites, `bites/run.sh bites/OBS-41`: all 8 BITES, each on its intended assertion (store, object store, STS and Kafka
  not observed; a location in the attributes; the exception's message on the span; calls observed with no parent; store
  outcomes all `ok`). The 8 OBS-38 bites aimed at the TelemetryTest methods whose waits changed: all BITES again.
  `bites/M6/renewed-inside-margin.patch` still applies (the new field's assignment sits outside its hunk).
- The fast build, `./gradlew build`: the first run failed 2 of TelemetryTest's tests, both on the first span of a
  trace now being a store span (fixed above); RESULT_PLACEHOLDER

Not covered:
- Oracle and MongoDB run through the same proxy, but only PostgreSQL ran here; MongodbBackendTest and
  OracleBackendTest (heavy) were changed and HEAVY_PLACEHOLDER
- Nothing has been pointed at a real collector; the timers' names in Prometheus are Micrometer's naming, not checked
  against a running Prometheus.
