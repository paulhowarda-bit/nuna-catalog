# 2026-11-15, spans and timers for the store, object store, STS and Kafka audit calls (backlog 41)

What changed:
- Each call a request makes to the catalog store, to the object store for metadata files, to STS for AssumeRole, and
  each synchronous audit publish to Kafka up to its acknowledgement, is a Micrometer Observation: a child span of the
  request's server span and a timer of the same name (`nuna.store`, `nuna.objectstore`, `nuna.sts`,
  `nuna.audit.publish`), tagged with bounded values and the call's outcome (`committed`, `conflict`, `found`,
  `written`, `issued`, `acknowledged`, `error`, ...) and `exception`.
- New package `nuna.catalog.server.tracing`: `Observed` makes the observation; `ObservedStore` (a dynamic proxy, so
  every store method is covered, a new one included), `ObservedTableFiles` and `ObservedPublisher` decorate the
  collaborators where they are wired (StoreWiring, CatalogStorage, GovernanceWiring); `StsCredentialVending` observes
  AssumeRole. The stores, catalog-audit and catalog-objectstore are unchanged.
- A failed call's span is an error that names the exception's class only (`CallFailed`): those messages carry table
  locations, STS session names (which name the principal) and values a database refused.
- A call made outside any observation is not observed: the outbox relay claims every 250 ms, and each claim would
  start a trace of its own. So the relay, the archive and startup make no spans or timers.
- New docs/observability/spans.md; README.md's "Traces" points to it.
- Knock-on changes to tests: the store bean is now the observed proxy, so MongodbBackendTest and OracleBackendTest no
  longer assert the bean's class (their self-check codes, which only that store reports, still show the backend);
  VendingRouteTest passes `ObservationRegistry.NOOP` to CatalogStorage; TelemetryTest waits for the request's server
  span instead of the first span of its trace, which can now be a child. catalog-server's tests take
  `micrometer-tracing-bridge-otel`, already on its runtime classpath through the starter. Item 41's Touches line gained
  these files and README.md.
- Merging item 39 (main 7f4250f): its `CatalogMetricsRoutesTest#labelsNameNoTableNamespacePersonOrFilterValue` held
  every `nuna.` meter to the catalog meters' eight label names, and this item's timers carry their own (`backend`,
  `profile`, `access`, `topic`, `event`, `exception`, and Micrometer's `error`; spans.md), so it failed. Its
  label-name checks now cover the `nuna.catalog.` meters, which all of item 39's are (catalog-metrics.md: "A catalog
  meter carries only these labels"). Its check that no label value names a namespace, table, person or filter value
  still covers every `nuna.` meter, these timers included. Item 41's Touches line gained the test.
