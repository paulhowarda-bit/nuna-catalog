# 2026-11-15, the catalog's own meters: Iceberg calls, commits, loads, vends, alerts and client reports (backlog 39)

What changed:
- `nuna.catalog.requests`: `RequestMetrics`, a filter right after `RequestIds` and before authentication, times every
  route of the Iceberg REST spec, named by its operationId (`rest/Operations`, a table of the routes). Its labels are
  `catalog` (set by `Lookup` and `ConfigRoute` only once a catalog resolves, `none` otherwise), `outcome` (the status
  class) and `error.type`. `ErrorCapture` reads the error type from the error body, so the routes', `ErrorResponses`'
  and `Authentication`'s errors are all named. The histogram buckets are at 10, 50 and 300 ms (`RequestMetrics.SLO`).
- `nuna.catalog.commits`: each commit engine reply on the eight committing routes, by outcome (committed, unchanged,
  replayed, requirement-failed, refused, unknown, failed). The requirement's type comes from where it fails:
  `Metadata` checks the requirements one by one and names the one that does not hold
  (`Outcome.RequirementFailed.requirement`), and `CommitEngine` carries it in `CommitReply.Failure.requirement`.
- `nuna.catalog.credential.vends` times each vend: issued, none or failed, with the error type.
  `nuna.catalog.metadata.cache.lookups` counts the hits and misses that `MetadataCache` now keeps.
- `ServerAlerts` has a counter per alert kind beside its log line.
- Client reports: `RestRequest.MetricsSummary` gains the operation, the engine name and the results. A timer is
  converted by its stated `time-unit`. A counter is kept only in the spec's unit. Only names iceberg-core's own reports
  hold are kept (`RestRequest.reportResults`). `CatalogMetrics.report` records them as `nuna.catalog.report.<result>`
  timers and distribution summaries, labelled by catalog, report type, operation (`other` beyond the spec's four) and
  engine name (the first 20 per server that look like one, then `other`).
- New: docs/observability/catalog-metrics.md and backlog 53.
- Bites recorded again with the same breaks: `bites/D13/metrics-filter-unsanitized` and
  `metrics-unknown-body-forwarded` (RestRequest moved), and `bites/D15/guard-not-held` and `transaction-partial`
  (CommitEngine moved). All four were run with `bites/run.sh`, and all four BITES.
- Tests that pinned a requirement failure now expect its type: two in `MetadataTest`. Two replay tests,
  `CommitEngineTest$Idempotency#failureReplayed` and `TransactionTest$Idempotency#outcomesReplayed`, compare the
  replayed answer without it, because a key's stored answer (`Replies`) keeps the type and message only.

Choices:
- A refusal replayed by its `Idempotency-Key` counts as `refused`, even when a requirement refused it first. The stored
  answer's format stays as it was.
- A report's timer result is recorded as one timing of its total.
- The claim was released and claimed again at once, to add the three tests and four bite files above. Item 39's
  Touches line lists them.
