# 2026-11-20, the DR reconcile takes the tips the audit archive records as committed (backlog 10)

`POST /management/v1/catalogs/{catalog}/dr-reconcile` takes `"accept-archived": true`. The route then reads every
chain of the audit archive whole before walking any table, each checked from genesis to its last segment's recorded
end before any of its records counts (`ArchivedCommits.read`, through `ObjectLockArchive.events`). Where no later file
proves which file follows the one the walk has reached, a swap of the main pointer that the archive records from that
file decides (`Reconcile.plan`): its file is taken if storage holds it at the recorded version and SHA-256, with proof
`archived`, which the journal and the answer show. The walk stops there instead when the archive records two swaps
from one file, or one whose file storage does not hold as recorded, or when `accept` names another file; that entry
is listed in the answer's new `contradicted-accepts`. Where the archive records nothing, `accept` decides as before,
so the hand-made list still works. A tip nothing proves stays in `tips`. The answer also says `accept-archived` and,
with it, `archive: {chains, commit-records}`.

The option fails the whole request, with nothing applied: 409 `ArchiveNotConfiguredException` when the server has no
archive (`nuna.audit.archive.bucket` unset), 503 when the archive's store cannot be read, 500
`ArchiveIntegrityException` when a chain does not verify. `AuditRuntime` hands the route the archive it already holds.

What the archive proves: a swap's commit record goes to the outbox in the swap's own transaction (D23), so a record
shows the swap committed on the primary, not that its client got the answer. That is the standard the walk's
successor proof already uses, and the archive has no record of answers, so nothing stricter can be read from it.

The DR drill (`DrDrillTest`, overnight) now runs its stack with an Object Lock archive (segments written a second
after their first record), waits up to 3 minutes for a dry run in which the archive proves each table's acknowledged
tip (the DR server's archive consumer takes the dead primaries' partitions after Kafka's session timeout), then
applies with `accept-archived` and no hand-made list. It is skipped on `-Ps3=aws`: the servers lock the archive in
COMPLIANCE mode, so an AWS bucket could not be deleted for five years.
