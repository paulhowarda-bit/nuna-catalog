# 2026-11-22, a nightly or heavy run by hand holds the build lock (item 136)

- `nightly.sh` and `heavy.sh` hold `.overnight/running`, the lock `overnight.sh` holds and `CLAUDE.md` tells every
  session to build nothing beside. Each finds the main checkout from `git rev-parse --git-common-dir` (the lock is
  `$NUNA_OVERNIGHT_HOME/running` when that is set, as in `overnight.sh`), writes its pid there in `overnight.sh`'s
  format (`pid:`, `started:`, then `by: <script> in <folder>`) when no live pid holds it, and removes it from an `EXIT`
  trap only if the pid in it is still its own (`INT` and `TERM` exit 130 so the trap runs, as in `overnight.sh`). A lock
  a live pid holds it leaves alone and runs anyway, saying so. The block is the same in both scripts.
- Under the overnight run, `nightly.sh` runs in `.overnight/clone`, a clone of its own, not a worktree: there
  `--git-common-dir` names the clone, not the main checkout. So a checkout named `clone` with `runs/` beside it is taken
  for the overnight run's clone, and the lock is the one beside it, `<home>/running`. `overnight.sh` is unchanged.
- `CLAUDE.md` (Builds) says a run by hand holds the lock too, and that an overnight run starting while one does stops
  at once ("another overnight run is going") and tests nothing that night.
- Checked, with a watcher polling the main checkout's `.overnight/running` every 0.2 s and logging each change:
  - `./nightly.sh --test-dry-run` in this worktree: the lock appeared at 20:01:06 with its pid (135647, `by: nightly.sh
    in <this worktree>`), both steps passed, exit 0, and it was gone at 20:01:59 as the run ended.
  - Two dry runs: A (an init script passed through `-I` slept 40 s in each step) took the lock at 20:02:00 with its
    pid, 136633; B, started while A held it, printed "pid 136633 holds ... leaving it to that run" and ended at 20:03:33
    with exit 0, the lock still A's, byte for byte; A ended at 20:04:32, exit 0, and the lock was gone. The watcher saw
    only A's content in between.
  - With stub builds in scratch layouts (no Gradle, no Docker): `overnight.sh`'s layout (`home/runs`, `home/clone` a
    repository of its own, `home/running`), a live pid's lock left unchanged and nothing written under the clone, a
    dead pid's lock taken over and removed, no lock written to `home/running` and removed; `heavy.sh` in a git worktree
    of a scratch repository, the lock in that repository's main checkout, removed after a pass (exit 0), a failed build
    (exit 1, Ceph leg and bites not run) and a `TERM` mid-build (exit 130), a live pid's lock left unchanged, a dead
    pid's taken over and removed; `overnight.sh --dry` (its home in scratch, failing `docker` and `kubectl` stubs on the
    path), given the lock of a running `heavy.sh`, said "another overnight run is going (pid ...); stopping", exit 1,
    and left that lock as it was.
  - Fast build: `./gradlew build` passed on bfbcab6 plus this change, BUILD SUCCESSFUL in 1m 4s, with `:bitesApply`;
    every test task came from the build cache, as nothing it compiles changed.
- Not covered: two runs by hand starting within the same instant can both find the lock free (check, then write, as
  in `overnight.sh`). A run by hand does not refuse to start while the overnight run holds the lock; `CLAUDE.md`
  already says to start no build then.
