# 2026-11-20, item 23: one KMS key per AWS S3 storage profile (D26)

What changed:
- `catalog-objectstore`: `StorageProfile` has an optional `kmsKey`, checked by `requireKmsKey`: a key ARN
  (`arn:<partition>:kms:<region>:<account>:key/<uuid or mrk- id>`) in the profile's region and partition, on an
  AWS S3 profile only. `SessionPolicy.forTable` takes it: with a key, PutObject (which covers
  CreateMultipartUpload) moves to a statement of its own whose condition requires `s3:x-amz-server-side-encryption`
  = `aws:kms` and `s3:x-amz-server-side-encryption-aws-kms-key-id` = the key ARN, and a statement allows the key's
  use (`kms:GenerateDataKey` and `kms:Decrypt` for writers, `kms:Decrypt` for readers). Without a key the policy
  text is unchanged. `CredentialVendor` passes the profile's key; `MetadataFiles.put` writes with SSE-KMS under it.
- `catalog-server`: `nuna.storage.profiles.<name>.kms-key`; startup refuses a bad one as
  `nuna.storage.profiles.<name>.kms-key: ...` before anything reaches the store. The vended config carries
  `s3.sse.type: kms` and `s3.sse.key: <ARN>` (Iceberg's `S3FileIOProperties`, read from iceberg-aws 1.12.0), not the
  storage credential. `NoKmsBoundaryTest` now lets `MetadataFiles` and `SessionPolicy` alone name the encryption
  headers; the server still has no KMS client.
- Tests: `SessionPolicyTest` (exact text with a key, reader and writer), `StorageProfileTest` (accepted and refused
  keys), `KmsKeyProfileTest` (new, Java-only: the metadata PUT's headers against an in-JVM HTTP store, the vended
  config, the startup check), `KmsKeyAwsTest` (new, heavy, AWS only). Five server tests take the new setting.
- Bites (M6): `kms-condition-dropped`, `kms-key-unchecked`, `metadata-write-without-kms-key`,
  `kms-key-not-in-config` (new); `session-policy-stem`, `list-condition-stem`, `policy-size-unchecked` and
  `vendor-skips-approve` recorded again, the same breaks against the moved code.
- `docs/install-at-work.md`, the chart's values comment and two `build-plan.md` lines (M6) say what the key does.
  Items 97 (MinIO and Ceph keys) and 98 (the key not recorded with the profile) added.
