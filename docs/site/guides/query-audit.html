Query the audit trail

Find who did what, to which object, and when, from the console's Audit page, the audit feed API, or SQL on the audit table.

For auditors and data stewards Needs select on the audit catalog Audited

Every commit, grant, read, refusal, credential issued and governance change is an audit record. The records land in an Iceberg table, by default nuna_audit.audit.events, which the console's Audit page and the audit feed API read, and which any engine can query. This guide answers one question three ways: who changed equities.fills yesterday?

Before you begin

  • The audit tables are configured on the server (nuna.audit.tables.catalog; Audit settings).
  • Your groups hold select on the audit catalog. Groups listed in nuna.audit.tables.readers are given it at startup.
  • Every read of the feed is itself audited, as a nuna.catalog.audit-read record.

Filter the records

  1. Select Audit in the rail.

    The page opens on Every record, newest first, for the catalog in the header.

  2. Enter equities.fills under Table or namespace.

    The field also takes a namespace, or @ and a branch's name for the records made through that branch.

  3. Under Filter by kind, choose Commits.

    The other kinds are Grants, Row and column rules, Governance, Branches and tags, Other changes, Reads, Credentials and Refusals. Audit reads are hidden until you tick Show audit reads.

  4. Narrow by Who and Up to if you need to.

    Up to ends the list at Up to now, Before an hour ago, Before six hours ago, Before a day ago or Before a week ago.

  5. Select Show record on a line to read it whole.

    The record shows its request id, where it was read from, its place in the hash chain and its reason.

curl -sS -G "$NUNA/management/v1/catalogs/trading/audit/feed" \
  -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "type=nuna.catalog.commit" \
  --data-urlencode "path=equities$(printf '\037')fills" \
  --data-urlencode "from=2026-11-25T00:00:00Z" \
  --data-urlencode "to=2026-11-26T00:00:00Z" \
  --data-urlencode "limit=50"

path is the namespace levels and the table's name, joined by the character 0x1F. from is included, to is not. Other filters: principal, branch (a branch's or tag's name without its @, or main), subject (a UUID) and type as a comma-separated list.

Pass next-page-token back as pageToken for the next page. table names the audit table snapshot the answer was read from. A caller may read the feed at most nuna.governance.audit-reads-per-minute times a minute (default 60).

The record above was not read from a running server: the local demo's audit table held no records when this page was checked. Its field names come from the route's code; the values are illustrative, and which of the record's fields are empty for a commit was not confirmed.

The audit table is an Iceberg table in its own catalog. Point an engine catalog at the warehouse nuna_audit and query it with SQL.

SELECT time, principal, engine, operation, request_id
FROM audit.audit.events
WHERE type = 'nuna.catalog.commit'
  AND catalog = 'trading'
  AND object_path = array('equities', 'fills')
  AND time >= TIMESTAMP '2026-11-25 00:00:00 UTC'
  AND time <  TIMESTAMP '2026-11-26 00:00:00 UTC'
ORDER BY time;

The table is partitioned by day of time, so a range on time reads only those days.

The audit table's columns

Columns of the audit table
ColumnWhat it holds
event_idThe record's id.
timeWhen it happened (timestamp with time zone).
typeThe record type, such as nuna.catalog.commit.
sourceThe deployment that recorded it.
principal, end_user, engineWho asked, for whom, and through which engine. An authentication failure has only a request id.
request_idThe request's id, shared by every record one request made.
catalog, object_kind, object_id, object_pathThe object acted on; object_path is a list of the namespace levels and the name.
operation, privilege, reasonThe operation, the privilege it needed, and the reason given or the refusal's reason.
dataThe whole event as a JSON string.
topic_partition, topic_offsetWhere the record sat in the audit topic. A row written from the catalog's log has topic_partition -1 and the writer's own number in topic_offset.
log_run, log_seqThe record's run and number in the hash chain.
branchFor a commit or a read, the ref it went through: main or the ref's name. For a ref record, the ref's name; for a grant, the branch it names. Empty for every other type.
subject_idsFor a ref record, the ref's id, then the ids of the tables and views it concerns (those a merge moved onto main, for instance). Empty for every other type.

Record types are nuna.catalog. followed by one of: commit, grant, drop, break-glass, read, denial, auth-failure, credential-issue, namespace, rename, engine, storage-setup, governance, hold, undrop, purge, audit-read, unregister, label, purge-claim, file-deletion, maintenance-exemption, ref, row-column-rule, run-end. Audit record reference describes each.

You have your answer

Each line names the principal, the engine and the time. To see everything one request did (a merge and its commits, for instance), filter by its request_id in SQL, or open the record in the console.

If it fails

What you see, why, and what to do
What you seeWhyWhat to do
503 The audit tables are not configured on this server (nuna.audit.tables.catalog)The server writes no audit table.Ask an operator to configure it (Audit settings).
503 The audit table cannot be read now; retry laterThe audit table or its storage did not answer.Retry.
429 More than 60 audit reads in a minute by …; retry laterYou passed the per-minute limit. The answer carries Retry-After: 60.Wait a minute, or query the table with SQL for large reads.
403 ForbiddenException naming selectYour groups lack select on the audit catalog.Ask a grant admin, or have the group added to nuna.audit.tables.readers.
400 path must be namespace levels, and a table or view name, separated by 0x1F, none of them emptyThe path was sent with dots or slashes.Join the levels with the character 0x1F.
400 from must be an instant such as 2026-11-22T00:00:00Z, not …A time is not in ISO-8601 UTC form.Send an instant with its Z.
400 from must be before toThe range is empty.Swap or widen the times.
400 type must be audit record types such as nuna.catalog.read, separated by commas, not …A type is not a nuna.catalog.* record type.Use the full type name.
400 pageToken is not one this feed gave: …The token came from another query.Repeat the first query, then page with its token.
