Commit to several tables at once

Send changes to several tables in one request that lands whole or not at all, through the Iceberg REST transactions endpoint.

For engine developers and data engineers Needs write or modify on each table Audited

POST /v1/{prefix}/transactions/commit takes one commit per table, each with its requirements and updates as a single-table commit has them. nuna checks every table, then applies all the commits in one store transaction, or none. Use it when two tables must change together, such as fills and the positions computed from them.

Before you begin

  • Every table exists. A transaction commits to existing tables only; it creates, drops and renames nothing.
  • Your groups may commit to each table as a single commit would need: write for a change of data, modify for a change of schema, partitioning or properties.
  • The transaction changes at most nuna.rest.max-transaction-tables tables (default 100), each named once.
  • For the curl example, NUNA and TOKEN are set as Use the APIs with curl describes.

Send the transaction

curl -sS -X POST "$NUNA/v1/trading/transactions/commit" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: eod-2026-11-25-restate" \
  -d '{"table-changes": [
        {"identifier": {"namespace": ["equities"], "name": "fills"},
         "requirements": [{"type": "assert-ref-snapshot-id", "ref": "main", "snapshot-id": 7210934412873551003}],
         "updates": [{"action": "add-snapshot", "snapshot": {…}},
                     {"action": "set-snapshot-ref", "ref-name": "main", "type": "branch", "snapshot-id": 7210934412873552117}]},
        {"identifier": {"namespace": ["equities", "daily"], "name": "positions"},
         "requirements": [{"type": "assert-ref-snapshot-id", "ref": "main", "snapshot-id": 4418820035512200871}],
         "updates": [{"action": "add-snapshot", "snapshot": {…}},
                     {"action": "set-snapshot-ref", "ref-name": "main", "type": "branch", "snapshot-id": 4418820035512209934}]}
      ]}'

The server answers 204 with no body when every commit has landed. With an Idempotency-Key, a retry after a lost answer gets the first answer again instead of a second commit.

Engines that support multi-table transactions over the Iceberg REST protocol send the same request.

Through a catalog branch (/v1/trading@dev/transactions/commit), the transaction commits to the branch's own copies of the tables.

What all-or-nothing means here

  • Either every table moves to its new metadata, or none does. A requirement that fails on one table fails the whole transaction.
  • The tables are locked in a fixed order, so two transactions over the same tables cannot deadlock.
  • It does not give readers a view of the tables at one instant: a reader that loads one table before the transaction and another after sees one old and one new.
  • If commits keep landing on the tables while it retries, it gives up and answers 409.

Every table moved

Each table's History tab shows a new commit, and the audit trail holds one nuna.catalog.commit record per table, all with the transaction's request id.

If it fails

What you see, why, and what to do
What you seeWhyWhat to do
409 CommitFailedException beginning with a table's name, such as equities.fills: …That table's requirement failed: another commit moved it. Nothing landed.Reload the tables, rebuild the changes and send again.
409 CommitFailedException Transaction lost to concurrent commits … times; its tables changed too often to apply itCommits kept landing on the tables while it retried.Send it again when the tables are quieter.
400 A transaction may change at most 100 tables; this one names …Too many tables in one request.Split the change, or ask an operator to raise nuna.rest.max-transaction-tables.
400 Table equities.fills is named more than once in the transactionTwo entries name one table.Merge them into one entry.
404 NoSuchTableException Table does not exist: …A table does not exist, or your groups cannot see it.Create it first, or check your grants.
400 beginning with a table's nameOne table's commit broke a rule, such as a path property outside the table's location.Fix that table's updates.
403 ForbiddenExceptionYour groups may not commit to one of the tables, or a legal hold or DR freeze refuses it.Ask a grant admin, or wait for the freeze to lift.
400 commitTransaction is refused on tag … of catalog trading: a tag is read-onlyThe request went through a tag.Send it to main or a branch.
