Register an existing table

Bring an Iceberg table whose metadata file already exists under nuna, leaving its data files where they are, or bring back a dropped or unregistered table from its own file.

For data engineers Needs create on the namespace Audited

Registering names a table in a namespace and points it at a metadata file that already exists. nuna reads the file, takes the table's UUID from it as the table's id, and from then on every commit goes through nuna. Nothing is copied: the data files and the metadata file stay where they are. The same call with a view's metadata file registers a view, at register-view.

Before you begin

  • Your groups hold create on the namespace, or on the catalog.
  • The metadata file lies beneath one of the catalog's storage profile's allowed-prefixes (Storage settings), and nuna's storage identity can read it.
  • No other table or view in nuna holds the table's UUID, and no table or view in the namespace has the name you give it.
  • You register on main. A branch or tag refuses registrations.
  • For the curl example, NUNA and TOKEN are set as Use the APIs with curl describes.

Register the table

Registering is the Iceberg REST catalog's register endpoint. The console has no register control.

curl -sS -X POST "$NUNA/v1/trading/namespaces/reference/register" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "X-Iceberg-Access-Delegation: vended-credentials" \
  -d '{"name": "instruments", "metadata-location": "s3://lake-trading/legacy/instruments/metadata/00012-….metadata.json"}'

The server answers 200 with the loaded table, as a table load does: its metadata location, its metadata and, with the delegation header, storage credentials. A nested namespace is written with its levels joined by the character 0x1F, URL-encoded as %1F.

Bring back a dropped or unregistered table

A dropped or unregistered table keeps its id and its location. Registering the metadata file it left at, under a free name in the namespace it left, brings it back as itself, with its grants and history. Only that one file brings it back, so it returns exactly as it left.

  • For a dropped table, this is an undrop: it needs what an undrop needs and must happen within the undrop window (Drop, restore and purge a table).
  • It comes back only in its own namespace. Move it afterwards with a rename (Rename or move a table or view).

Stop writing to the table elsewhere

After registering, commit only through nuna. A commit another catalog makes to the same files writes a metadata file nuna does not know, and nuna keeps reading the one it registered.

Once registered, the table is nuna's like any other.

The table is in the catalog

The table shows in its namespace in the console, and its History tab lists the commit that registered it. An engine reads it at trading.reference.instruments.
