Rename or move a table or view

Give a table or view a new name, in its namespace or another, keeping its id, its own grants and its history.

For data engineers Needs modify on the object and create on the destination Audited

A rename changes only the name and the namespace. The object keeps its id, so its own grants, its labels, its commit journal and its history go with it. Its files do not move: a table's location is set from its id when it is made, never from its namespace.

Before you begin

  • Your groups hold modify on the table or view, and create on the destination namespace (or the catalog).
  • The destination namespace exists. A rename never creates one.
  • You rename on main. A branch or tag refuses renames.
  • For the curl example, NUNA and TOKEN are set as Use the APIs with curl describes.

Rename it

The console has no rename control; rename from an engine or the Iceberg REST API.

curl -sS -X POST "$NUNA/v1/trading/tables/rename" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"source": {"namespace": ["equities"], "name": "orders"},
       "destination": {"namespace": ["equities", "daily"], "name": "orders"}}'

The server answers 204. A view uses POST /v1/trading/views/rename with the same body. An Idempotency-Key header makes a retry safe.

ALTER TABLE trading.equities.orders RENAME TO trading.equities.orders_v1;
ALTER TABLE trading."equities".orders RENAME TO trading."equities.daily".orders;

The Spark and Trino statements are those engines' standard rename forms; no engine test in the repository runs a rename, so they are not confirmed against nuna.

What changes and what does not

A rename's effect
ThingAfter the rename
Id, commit journal, snapshots, filesUnchanged.
Grants on the object itselfGo with it.
Grants inherited from a namespaceThose of the new namespace and its parents apply; the old namespace's no longer do.
Governance inherited from a namespace (a legal hold, a regulated mark)That of the new namespace applies.
Catalog branches and tags made beforeStill read the object under its old name.
Engines and jobs that use the old nameGet 404 until they use the new one.

Moving changes who can read

Before moving a table into another namespace, compare the two namespaces' grants on their Access tabs. Groups that read the table through the old namespace lose it; groups with grants on the new one gain it.

Tell the owners of jobs that use the old name before you rename: nothing redirects them.

The object answers to its new name

The console shows it in its new namespace, and its Audit tab shows a record renamed from the old path. The audit trail holds a nuna.catalog.rename record.

If it fails

What you see, why, and what to do
What you seeWhyWhat to do

404 NoSuchTableException Table does not exist: equities.ordersThe source does not exist, or your groups cannot see it.Check the name and your grants.
