Keep a point in time with a tag

Make a read-only tag of the whole catalog, read every table through it as it was, and remove it when it is no longer needed.

For engine users and data stewards Needs create on the catalog Audited

A catalog tag names one point: every table's and view's metadata file, and its name, as they were when the tag was made. Reading through the tag, trading@eod-2026-11-25, gives each table as it was at that point, under the name it had then, however main has moved since. A tag never expires and never takes a write. Keep one for each end of day, a month-end close or the data a report was run on.

Before you begin

  • Making and deleting a tag needs create on the catalog. Reading through it needs what reading main needs: a table's grants hold on every ref.
  • A catalog holds at most nuna.refs.max-tags tags (default 1000).
  • For the curl examples, NUNA and TOKEN are set as Use the APIs with curl describes.

Make the tag

  1. Select Branches and tags in the rail, then Make a branch or tag.

  2. Choose Tag and enter its name.

    Leave From at main, as it is now, or choose a branch to keep that branch's state. Say why the tag exists under Purpose (optional).

  3. Select Make it.

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/refs" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "eod-2026-11-25", "kind": "tag", "description": "End of day, 25 November"}'

The server answers 201 with the tag. A tag has no expires-at.

{
  "id": "c41d07b2-8e5a-4f63-a1d9-7b2e60f4a8c5",
  "name": "eod-2026-11-25",
  "kind": "tag",
  "from": "main",
  "created-at": "2026-11-25T22:00:03.512Z",
  "created-by": "trading-etl",
  "description": "End of day, 25 November",
  "cut-at": "2026-11-25T22:00:03.512Z"
}

Read through the tag

Point an engine catalog at the warehouse trading@eod-2026-11-25. Each table reads as it was at the point; a table created on main since is not there, and a table dropped or renamed since is there under its old name.

Choose the tag in the header's Reading control. Every catalog, namespace, table and view page then reads through it and says so; a property shown there is Read-only through a tag. The tag's own page, opened from Branches and tags, lists under What it keeps each table and view and the version it keeps.

spark.sql.catalog.eod=org.apache.iceberg.spark.SparkCatalog
spark.sql.catalog.eod.type=rest
spark.sql.catalog.eod.uri=https://nuna.example/
spark.sql.catalog.eod.warehouse=trading@eod-2026-11-25
spark.sql.catalog.eod.token=…
spark.sql.catalog.eod.header.X-Iceberg-Access-Delegation=vended-credentials
SELECT * FROM eod.equities.daily.positions;
from pyiceberg.catalog import load_catalog

eod = load_catalog("eod", type="rest", uri="https://nuna.example", warehouse="trading@eod-2026-11-25",
                   token=token, **{"header.X-Iceberg-Access-Delegation": "vended-credentials"})
positions = eod.load_table("equities.daily.positions").scan().to_arrow()

A tag is read-only three times over. The catalog refuses any write through it with 400; Iceberg Java and PyIceberg clients refuse a commit before sending it, since the tag advertises only read endpoints; and the storage credentials it vends only read, so the object store refuses a data file.

Remove the tag

A tag lasts until someone deletes it. Every file it names is kept until then: snapshot expiry and the orphan scan read every ref.

On the tag's page, select Delete, then Delete @eod-2026-11-25 in the dialog Delete the tag @eod-2026-11-25. The cross on the tag's line in Branches and tags opens the same dialog.

curl -sS -X DELETE "$NUNA/management/v1/catalogs/trading/refs/eod-2026-11-25" \
  -H "Authorization: Bearer $TOKEN"

The server answers 204.

To let one table's data go while keeping the rest of the tag, take that table out of refs instead: POST /management/v1/catalogs/trading/objects/<table id>/refs/remove with {"refs": ["eod-2026-11-25"]}, or {"all-refs": true} for every ref that names it. That needs manage-tags on the table, and a legal hold or DR freeze refuses it.

The tag keeps the catalog as it was

Commit to a table on main, then read it through the tag: the tag still returns the earlier rows. GET /management/v1/catalogs/trading/refs/eod-2026-11-25 shows the tag with its cut-at.
