Compact a table or scan for orphans now

Ask the maintenance worker to compact one table, or scan it for orphan files, at its next scan instead of waiting for the cleanup window.

For data engineers Needs modify on the table Audited

The maintenance worker compacts tables and scans for orphan files on its own, inside the cleanup window. A request puts one table at the front: the worker takes it at its next scan, in or out of the window. A request is one job, compaction or orphan-scan, for one table on main.

Before you begin

  • Your groups hold modify on the table, or on its namespace or catalog.
  • The maintenance worker runs for the catalog (Install the maintenance worker).
  • For the curl example, NUNA and TOKEN are set as Use the APIs with curl describes.

Ask for the job

  1. Open the table and select its Maintenance tab.

    Read main in the header's Reading control: the buttons are not offered while you read through a branch or tag.

  2. Under Assessment, select Compact now or Scan for orphans now.

    The panel says: Runs at the worker's next scan, even outside the cleanup window.

  3. Confirm with the same button in the dialog.

    The dialog, Compact fills now for a table named fills, shows the answer: Compaction of fills requested, with when and by whom it was asked.

From the catalog's Maintenance page, Compact a table now asks for the same job: choose the table under Choose a table, from Queued for tonight, Other tables you may compact, or Another table, by its path…, then select Next.

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/namespaces/equities/tables/fills/maintenance/requests" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"job": "compaction"}'

The server answers 202. For a scan, send {"job": "orphan-scan"}.

{
  "job": "compaction",
  "requested-by": "trading-etl",
  "requested-at": "2026-11-26T10:04:12.381Z",
  "state": "waiting"
}

Asking again while a request waits answers with the waiting request; it does not queue a second. Once the worker has taken it, state is started and started-at says when.

What the worker does

  • For compaction, the worker starts a Kubernetes Job named nuna-compact- followed by the table's id and the request's time. It takes one of the worker's compaction slots (compaction.max-jobs) and must finish within request-deadline, by default two hours.
  • For an orphan scan, the worker scans the table's location and removes files no snapshot of any ref names, older than its minimum age. A scan that reaches the deadline stops and records nothing.
  • The table's policy still applies: a table whose policy turns compaction off, or a table under legal hold for an orphan scan, refuses the request.

The request shows on the table

The table's Maintenance tab shows Compaction requested at the time, by you, with the state waiting and then started. With curl, GET …/tables/fills/health lists it under requests, and after the run last-compaction moves on. The audit feed holds a nuna.catalog.governance record for the request.

If it fails

What you see, why, and what to do
What you seeWhyWhat to do
409 MaintenanceNotAllowedException The maintenance policy of table equities.fills does not run compaction: compaction.enabled is false, set by …The table's policy, or one it inherits, turns the job off. The message names where it was set.Change the policy where it was set (Set a catalog's maintenance policy), or leave the table as it is.
409 MaintenanceNotAllowedException Table equities.fills is under legal hold: nothing may be removed, so no orphan-scan runsA legal hold on the table, its namespace or the catalog forbids removing files.Compaction is still allowed. The scan waits until a data steward releases the hold.
403 Table equities.fills is frozen for DR reconcile: …The table is frozen while a disaster-recovery reconcile runs.Ask again after the freeze is lifted (Freeze and unfreeze for disaster recovery).
403 ForbiddenException naming modifyYour groups see the table but lack modify on it.Ask a grant admin for modify (Grant and revoke access).
404Your groups hold nothing on the table, or the path is wrong.Check the path and your grants.
400 Field job is compaction or orphan-scanThe body names another job.Send one of the two.

How long a request that the worker never takes (the worker is down) stays waiting, and whether it expires, was not confirmed in the code.
