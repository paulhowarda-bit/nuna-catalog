Glossary

Every term these pages use for nuna and for Apache Iceberg, in alphabetical order, each with the meaning the code gives it.

Iceberg's own terms are defined as the Iceberg table spec defines them; this page says how nuna uses them.

Terms

Allowed prefix
A bucket path a storage profile lets tables live under. No two profiles' allowed prefixes overlap.
Archive
The seven-year record of the audit trail: hash-chained segments in a bucket with Object Lock in compliance mode, one chain per server run.
Audit record
One entry of the audit trail: a CloudEvent in JSON, of type nuna.catalog.name, naming who did what to which object, and why it was refused if it was.
Audit tables writer
The program that takes audit records from Kafka or over OTLP and writes them to the Iceberg table nuna_audit.audit.events, and, over OTLP, to the archive.
Audit trail
Every audit record the server makes: the lines of its log nuna.audit, their copies in Kafka, the archive and the audit table.
Catalog
The object that holds namespaces, tables and views, bound to one storage profile, KMS key set and legal entity. An engine names it as its warehouse. Catalogs are declared in the server's settings.
Catalog branch
A ref of a whole catalog that can take commits and be merged into main. It expires when idle.
Cleanup window
The hours, set in the worker's settings, in which compaction and orphan scans may run.
Column mask
A rule that replaces a column's values for a group's members, enforced by a trusted engine.
Commit
A change to a table or view: requirements the current metadata must meet, and updates to apply. A commit that succeeds writes a new metadata file and moves the table's pointer.
Compaction
Rewriting a table's small data files, and the files their delete files apply to, into fewer, larger ones. The worker runs it as a Kubernetes Job.
Console
nuna's web pages for people, served by the server at /ui/.
Data file
A file of a table's rows, in Parquet, ORC or Avro, listed by a manifest.
Delete file
A file that marks rows of data files as deleted: by position, by equal values (an equality delete), or as a deletion vector in format version 3.
DR freeze
A stop on commits, creates, drops, renames, restores and purges, and on maintenance, for a catalog, namespace or table during disaster recovery. A platform operator places and lifts it. After first mention, the freeze.
DR watermark
For each table and view, the newest version whose every file the DR object store holds, kept in the database by the worker's verifier.
Drop
Removing a table or view's name. Every drop is soft: the files stay, and the object can be restored until its purge time.
End user
The person a trusted engine acts for, named in the request's headers. Authorization then decides for the end user.
Engine
A program that reads and writes tables through the catalog: Spark, Trino, PyIceberg, Kafka Connect, SingleStore and the rest.
Flagged table
A table with a row or column policy. Only trusted engines and the maintenance principal get storage access to it.
Format version
The version of the Iceberg table format a table uses. New tables are version 3; versions 1 to 3 are accepted.
Grant
A privilege given to a group on a catalog, namespace, table or view; it applies to everything beneath. Also the act of giving it. To revoke is to take it back.
Grant admin
A member of a group the server's settings name as grant admins, who manages grants and holds no data privilege by it.
Group
A group from the identity provider's token. Grants are made to groups only.
Hash chain
The archive's form: each line holds the SHA-256 of the line before and its own record, so a changed or missing line breaks the chain.
Health score
The figure a maintenance scan gives a table: 1 when a figure reaches its threshold, 2 at twice the threshold.
Idempotency key
The Idempotency-Key header of a change. The same key with the same request within 24 hours gets the first answer again, and the change is not applied twice.
Journal
The database's record of every pointer move: who, the requirements and updates, the old and new metadata file, and when.
Legal hold
A stop on deleting an object's data: its snapshots cannot be removed, and it cannot be dropped, purged or unregistered. A principal with manage-tags places and lifts it. After first mention, the hold.
Location
The object store path under which a table's files live: the storage profile's table root followed by the table's id.
Main
The catalog itself, as a ref: what an engine reads and writes when its warehouse names no branch or tag.
Maintenance principal
A principal named in nuna.security.maintenance-principals, which the worker signs in as. Only it may claim and complete purges and record pending deletions.
Maintenance worker
The program that scans tables and runs expiry, manifest rewrites, compaction, orphan scans, deletions and purges. After first mention, the worker.
Manifest
An Iceberg file that lists data or delete files with their statistics. A manifest list names a snapshot's manifests.
Metadata file
A table or view's state as JSON: schemas, partition specs, properties, snapshots and refs. Each commit writes a new one.
Metadata log
The list, inside each metadata file, of the metadata files before it. The console's History tab and the metadata log route read the journal beside it.
Namespace
A level of a catalog's tree, holding tables, views and other namespaces, to any depth.
nuna
The product: an Iceberg REST catalog with its maintenance worker, audit tables writer and console. Always written in lower case.
Object store
The S3-compatible store that holds tables' files: AWS S3, Ceph, or a MinIO-compatible store such as Silo.
Orphan file
A file under a table's location that no snapshot reaches. An orphan scan finds those older than the policy's age.
Outbox
The database table where a change's audit records are written in the change's own transaction, until the relay writes them to the log.
Pending deletion
A file the worker has recorded to delete once the point-in-time recovery window has passed.
Point-in-time recovery window
How far back the database can be restored, declared in nuna.governance.pitr-window (7 days by default). No file is deleted sooner.
Platform operator
A member of a group the server's settings name as platform operators, who runs the deployment (DR freezes, reconcile, delete policies) and holds no data privilege by it.
Pointer
A table or view's record in the database of its current metadata file: the file's location, a version number and the file's SHA-256. A commit moves it.
Principal
Who a request acts as, mapped from the token's claims.
Privilege
One of describe, select, write, modify, create, manage-grants and manage-tags.
Purge
Deleting a dropped object's files once its restore window has closed. Only the maintenance principal purges, and it cannot be undone.
Ref
A catalog branch or tag: a named cut of a whole catalog.
Regulated
A flag on a catalog or namespace: a table beneath it with no classification of its own is closed to everything above describe.
Requirement
A condition in a commit that the current metadata must meet, such as a table branch still pointing at a given snapshot.
Restore
Bringing a dropped object back under its name or another, before its purge time. The API calls it undrop.
REST prefix
The part of every Iceberg REST path after /v1/ that names the catalog, or catalog@ref for a ref.
Retention class
A named set of minimum ages in the governance settings that a table can be classified with.
Row filter
A rule that limits which rows a group's members see, enforced by a trusted engine.
Separation of duties
The rule that one group cannot hold conflicting duties, such as managing grants and changing data.
Server
The running catalog server program, which answers engines, the console and the worker on port 8181.
Session policy
The policy the server attaches when it assumes a storage role, limiting the vended credentials to one table's prefix.
Sign in
To get a token from the identity provider and present it. The noun is sign-in.
Snapshot
The state of a table's data at one commit: the list of data and delete files it holds.
Storage profile
A named object store in the settings: its kind, endpoint, region, table root and allowed prefixes, and the role used to vend credentials.
Table
An Apache Iceberg table: a metadata file and the data and delete files its snapshots list.
Table branch
Iceberg's named line of snapshots inside one table's metadata file, such as its main. Not a catalog branch.
Table root
The path in a storage profile under which the server places new tables.
Table tag
Iceberg's named snapshot inside one table's metadata file. Not a catalog tag.
Tag
A read-only ref of a whole catalog that never expires.
Trusted engine
An engine in the server's registry that may name the end user it acts for, and that enforces row filters and column masks.
Update
A change in a commit, such as adding a snapshot or setting a property.
Vended credentials
Short-lived storage credentials, scoped to one table's prefix and unable to delete, that the server gives an engine with a table.
Verifier
The worker's job that checks the DR object store and moves each table's DR watermark.
View
An Apache Iceberg view: a metadata file holding a query and its versions.
Warehouse
The Iceberg client setting that names the catalog, or catalog@ref.
