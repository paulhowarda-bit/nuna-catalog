Engine compatibility

What each engine was tested doing against nuna: the version, and the result for each Iceberg feature, from the engine matrix that runs every night code changes.

Tested in the engine matrix

The engine matrix starts each engine in a container against a real nuna server and object store, and asserts each result below. Its seven tests (Spark, compaction, Kafka Connect, PyIceberg, the audit tables, branches and tags, SingleStore) all passed in the nightly run at commit 639b0da5, on 2026-11-25. An engine or version not listed here has not been tested by nuna; it may well work, since nuna serves the standard API (Other engines).

Limits the tests found

  • expire_snapshots commits, but leaves the expired files in place: vended credentials cannot delete objects. nuna's maintenance worker deletes them (Maintenance).
  • remove_orphan_files needs prefix_listing => true, since Spark's Hadoop file system has no s3 scheme, and refuses an older_than within the last 24 hours.
  • A table's compaction run by nuna's maintenance worker, as a Spark job, rewrote 32 files into 4.
  • A write to a catalog tag is refused twice over: Spark refuses an ALTER itself, since the tag does not advertise the endpoint, and a data write fails at the object store, since a tag's credentials are read-only.
