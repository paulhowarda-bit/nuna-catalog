Error responses

Every HTTP status and error type the server answers, when each comes, and what to do about it.

The error body

Both APIs answer every error with the Iceberg REST standard's error body. type names the error; Iceberg clients turn it into the exception of the same name. Messages are for people and may change; match on code and type.

{"error": {"message": "Table does not exist: equities.fills", "type": "NoSuchTableException", "code": 404}}

Exceptions: /v1/oauth/tokens answers the OAuth error form ({"error": "unsupported_grant_type", "error_description": "…"}); HEAD requests and 304 answers have no body; and a few 409 answers add fields beside error, listed below. Every answer carries X-Request-ID: quote it when you report a problem.

Two rules hold for every endpoint. A caller who holds nothing on an object gets 404, worded as for a missing object, so the answer does not say the object exists. A caller who holds something on it, but not what the endpoint needs, gets 403. Both are written to the audit trail.

400, 405 and 422: the request is wrong

TypeWhenWhat to do
BadRequestExceptionThe body or a parameter is not valid (Missing request body, Malformed request: …, Invalid namespace: …, Invalid page size: …, Invalid page token: …, Invalid snapshot mode: …, Invalid Idempotency-Key: must be 1 to 128 characters); a write through a branch or tag that happens on main only, or any write through a tag (… is refused on tag … of catalog …: a tag is read-only); a commit that breaks a catalog rule (Location is assigned by the catalog: …, a write path outside the table's location, a change to encryption.key-id, a snapshot stamped too far ahead of the catalog's clock); a location outside the storage profile; a register with overwrite; an idempotency key reused for another request; an unsupported format version. A wrong method on a route answers status 405 with this type and a message such as Method 'GET' is not supported.Correct the request. The message names what is wrong.
UnprocessableEntityException (422)A namespace properties update both sets and removes one key: Invalid namespace update, cannot simultaneously set and remove keys: …; or the request is well formed but its content cannot be applied.Send each key in one list only.

401: not signed in

TypeWhenWhat to do
NotAuthorizedExceptionNot authorized: the bearer token is missing or was not accepted. No token; a token that is expired, not yet valid, from an issuer the server does not trust, for another audience, or missing a claim the server needs; end-user headers that contradict each other. WWW-Authenticate says Bearer, Bearer error="invalid_token" or Bearer error="invalid_request".Get a new token (Get a token). If a fresh token is refused, a platform operator compares it with nuna.security.issuers; the audit record of the failure says why.

403: not allowed

TypeWhenWhat to do
ForbiddenExceptionYou hold something on the object but not the privilege the endpoint needs: you holds no privilege that gives privilege for operation. Also a governance refusal: a legal hold (… is under a legal hold and cannot be dropped), a freeze for DR reconcile, a regulated table with no classification, a table with a row/column policy loaded by an engine that is not trusted, a snapshot younger than the minimum snapshot age, a regulated write by an engine that named no end user; or Forbidden: client … is not a registered trusted engine, so it may not act for another user.Ask a grant admin for the privilege (Privileges), or a data steward about the hold, freeze or classification the message names.

404: not found

Each of these also answers when you hold nothing on the object.

TypeWhenWhat to do
NoSuchWarehouseExceptionThe catalog or prefix names nothing you can see: The given warehouse does not exist: …; the branch or tag does not exist or is past its expiry; Branch … is gone: merged, deleted or past its expiry.Check the catalog's name with GET /management/v1/catalogs, and the ref's with the refs listing.
NoSuchNamespaceExceptionNamespace does not exist: ….Check the name; create each level of a nested namespace in turn.
NoSuchTableExceptionTable does not exist: …; through a branch, also a table the branch does not hold.Check the name and the prefix.
NoSuchViewExceptionView does not exist: ….Check the name and the prefix.
NoSuchObjectExceptionA management route names a table or view, by id or name, that no longer exists.List the objects again.
NoSuchRefExceptionRef does not exist: ….List the refs again.
NoSuchBranchExceptionA grant names a branch that does not exist: Branch does not exist: …, The branch no longer exists: ….List the refs again.
NoSuchHoldExceptionNo hold … on this …: the hold was released or never existed.List the object's holds.
NoSuchAttributeExceptionUnknown governance attribute …; known attributes: …, or the attribute is not set on the object.Use one of the attributes the message lists.
NotFoundExceptionNo such route (No static resource …); a metadata file that is not in the object store; a securable that no longer exists.Check the path against the endpoint index.

409: conflict

TypeWhenWhat to do
AlreadyExistsExceptionThe name is taken: Namespace already exists: …, Table already exists: …, View with same name already exists: …, Ref already exists: …; or a registered file's UUID belongs to another table or view.Pick another name, or drop the one that holds it.
CommitFailedExceptionA commit's requirement failed because the table changed, or Commit lost to concurrent commits n times; the table changed too often to apply it. In a transaction, the message starts with the table's name.Load the table again and redo the change. Engines do this themselves.
NamespaceNotEmptyExceptionNamespace … is not empty, or a branch or tag still names a table or view in it.Drop what it holds first, or remove the object from the refs.
UndropWindowClosedExceptionThe undrop window of … closed at …; it is waiting to be purged.The object can no longer be restored.
RefLimitExceptionThe catalog holds as many branches or tags as nuna.refs.max-branches or nuna.refs.max-tags allow; or a merge would move more tables and views than nuna.refs.max-merge-tables.Delete refs you no longer need, or merge a smaller branch.
RefMergeConflictExceptionBranch … conflicts with main in …, so nothing moved: …. The body adds ref and conflicts, one entry per table or view in conflict.Settle the conflicts on the branch and merge again (Work on a branch).
RefsChangedExceptionThe refs naming an object kept changing while the request ran. The maintenance worker's form adds refs to the body.Send it again.
RefNotExpiredException, RefNotExpiringException, RefWarningInFlightExceptionThe maintenance worker tried to end a ref that has not expired, or warn about one not yet within nuna.refs.expiry-warning of its expiry, or another call is sending the warning.None: the worker tries again later.
MaintenanceNotAllowedExceptionA maintenance request the table's policy or legal hold does not allow: The maintenance policy of table … does not run …, Table … is under legal hold: nothing may be removed, so no … runs.Change the maintenance policy, or wait for the hold to be released.
NotDroppedException… is not a dropped table or view: restore or purge of an object that is not dropped.Check the object's state.
PurgeNotDueException, PurgeClaimedException, PurgeNotClaimedExceptionA purge before the object's purge time (… may not be purged before …), one another maintenance principal has claimed, or one not claimed first.None for people: these are the maintenance worker's.
NotDeletableExceptionFiles recorded for deletion for an object that is not active or dropped.None: the maintenance worker's.
NotFlaggedExceptionA row filter or column mask on a table that does not carry the row/column-policy flag.A data steward sets the flag first.
RowColumnRulesExistExceptionRemoving a table's row/column-policy flag while it has row filters or column masks.A grant admin removes the rules first.
TableReplacedExceptionA table health request names an id that the name now belongs to another table.Ask again with the current table.
ArchiveNotConfiguredExceptionA DR reconcile asked to accept archived commits, and nuna.audit.archive.bucket is not set.Configure the archive, or reconcile without it.
WatermarkAheadException, WatermarkBehindException, WatermarkMismatchException, UnknownVersionExceptionA DR watermark above the table's version, below one already kept, naming a different metadata file than the journal, or naming a version the journal does not hold.None for people: these are the maintenance worker's DR runs.

412: precondition failed

TypeWhenWhat to do
PreconditionFailedExceptionA row filter or column mask has moved past the version If-Match named, or was removed: … another change came first: list the rules again.List the rules, then repeat with the new version.

429: too many requests

TypeWhenWhat to do
TooManyRequestsExceptionMore audit reads in a minute than one caller is allowed (More than … audit reads in a minute by …; retry later), or more purges in a minute than the deployment allows. Retry-After: 60.Wait the Retry-After seconds.

500: server failure

TypeWhenWhat to do
CommitStateUnknownExceptionCommit … may or may not have been applied: …: the database did not answer whether the commit landed.Load the table to see, or repeat with the same Idempotency-Key, which answers the first outcome if it landed.
ServiceFailureExceptionInternal server error; a write whose outcome is unknown (… may or may not have been applied: …); Namespace … changed 5 times while its properties were updated; nothing was applied.Repeat with the same Idempotency-Key. If Internal server error repeats, report it with the X-Request-ID.
MetadataIntegrityExceptionA metadata file does not match the hash the catalog recorded for it.Report it to a platform operator: the file was changed outside the catalog.
ArchiveIntegrityExceptionThe audit archive does not verify, so it proves no tip: ….Report it to a platform operator.

503: try again

TypeWhenWhat to do
ServiceUnavailableExceptionNothing was applied, and the request can be sent again: Catalog store unavailable; nothing was applied: … (Retry-After: 2); Storage credentials cannot be issued now; retry later; Could not claim idempotency key …: catalog store unavailable; The token could not be checked: its issuer's signing keys could not be fetched; retry later (Retry-After: 2); another service the route needs is unreachable.Send the request again after Retry-After, with the same Idempotency-Key. If it lasts, see Troubleshooting.
