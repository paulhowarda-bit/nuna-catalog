Release notes

What version 0.1.0-SNAPSHOT holds, by the milestone that added it, oldest first.

nuna has not had a release. Every module builds as version 0.1.0-SNAPSHOT, with Apache Iceberg 1.12.0, Spring Boot 4.1.2 and Java 25.

M0: bootstrap

  • The module layout and pinned versions, and the server answering /v1/config on PostgreSQL with its list of endpoints.

M1 and M2: the storage interface and the databases

  • One storage interface and a shared suite that every database passes: PostgreSQL, CockroachDB, Oracle and MongoDB.
  • Commits decided by a pointer compare-and-swap under row locks, and an unknown outcome resolved only after a durability barrier.
  • The start-up self-check of each database's durability settings.

M3: the commit engine

  • Every Iceberg update and requirement type, format versions 1 to 3, with new tables at version 3.
  • The commit loop with bounded retries, the server's commit rules, and idempotency keys.

M4: the Iceberg REST routes

  • Namespaces, tables (including staged create, register, rename and soft drop), views, credentials and metrics.
  • Conditional loads with ETags, and the Iceberg error shapes.
  • The Iceberg REST Compatibility Kit run against the server.

M5: security

  • Tokens from several issuers, each with its own claim mapping; trusted engines that name an end user.
  • Grants to groups with inheritance down the tree, separation of duties, and no superuser.
  • Storage access to flagged tables only for trusted engines; unclassified tables under a regulated namespace closed.

M6: object storage and credential vending

  • Storage profiles, one per catalog, and table locations assigned by the server.
  • Metadata files checked by SHA-256, and STS credentials scoped to one table's prefix that cannot delete.

M7: governance and audit

  • The outbox and relay, the Kafka copy, the change stream and the hash-chained archive.
  • Maintenance policy with inheritance and guardrails, retention classes, legal holds, DR freezes, soft drop with a 30-day restore window, and rate-limited purges.

M8: hardening

  • Load, contention and resilience runs: up to 32 writers on one table, a table of over 10,000 snapshots, a primary killed mid-commit, a rolling upgrade, and a DR drill.
  • The engine matrix, now Spark, Kafka Connect, PyIceberg and SingleStore against the server deployed by its Helm chart.
  • Reconcile from storage for disaster recovery, and 503 with Retry-After when the database cannot be reached.

Since M8

  • The web console at /ui/.
  • Catalog branches and tags, with merges.
  • The maintenance worker: expiry, manifest rewrites, compaction on need, orphan scans, pending deletions, purges, maintenance on request and the DR verifier.
  • The audit log as the record of audit, Kafka made optional, and the audit tables writer with the queryable audit table and the archive.
  • Row filters and column masks for flagged tables, and unregister.
  • Helm charts for the three programs, and the local demo on a kind cluster.
