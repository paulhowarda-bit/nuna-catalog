Table properties

The Iceberg table properties nuna sets, refuses or reads, and the ones the console offers to change.

Iceberg table properties are set by engines and by the console. Most are read only by the engines that write the table; nuna stores them as given. This page lists the properties nuna itself sets, refuses or reads, and the ones the console offers to change.

Properties nuna sets

Properties nuna reads

Properties nuna reads
PropertyRead byWhat for
write.metadata.previous-versions-maxThe server, at a branch mergeHow many earlier metadata files the merged table's metadata log lists (Iceberg's default, 100, when unset). The commit journal keeps every commit whatever it says.
commit.manifest.target-size-bytesThe maintenance worker, rewriting manifestsThe size it writes manifests to (Iceberg's default when unset).

Compaction does not read write.target-file-size-bytes: it aims for the maintenance policy's compaction.target-file-size-bytes. Snapshot expiry follows the maintenance policy, not history.expire.*.

Properties the console offers

The console's Settings tab offers these, with the choices and ranges shown. The choices and ranges are set by the console; nuna adds no check of its own on these values when a commit sets them.

For a namespace the console offers comment, up to 1000 characters. It notes that a namespace's location changes nothing, since the catalog assigns every table's location itself, and that its owner property is not the owner the catalog enforces.

The console shows write.metadata.delete-after-commit.enabled as changing nothing: the catalog writes every metadata file, and the orphan scan removes those that fall off the log.
