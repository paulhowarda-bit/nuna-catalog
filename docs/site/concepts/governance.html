Governance

Governance is the set of attributes, holds and freezes that data stewards and platform operators put on catalogs, namespaces, tables and views, and that the server enforces on every request and every maintenance job.

What it is

Governance has three parts, each set on a catalog, namespace, table or view and each audited:

  • Attributes: a classification, an owner, a retention class, the regulated mark and the row-column-policy flag. Each carries its provenance, a sentence on where the value came from.
  • Legal holds, which stop data from being deleted.
  • DR freezes, which stop commits while disaster recovery reconciles.

Members of groups that hold manage-tags set attributes and place and release holds. Only platform operators set and lift freezes.

How it works

Attributes

The governance attributes
AttributeValuesWhat the server does with it
classificationany textSends it to engines as a label. In a regulated area, a table without its own classification is closed.
ownerany textSends it to engines as a label.
retention-classa class named in nuna.governance.retention-classesKeeps snapshots younger than the class's minimum age, against engines and the worker alike.
regulatedtrue or false; the console offers it on catalogs and namespacesMakes the area regulated: unclassified tables in it are refused everything but describe and manage-tags.
row-column-policytrue or false, on a table onlyWithholds the table's files from all but trusted engines and maintenance principals; see Row filters and column masks.

Attributes pass down: a table's effective classification, owner and retention class are the nearest level's, the table first. The row-column-policy flag is the exception: only a table's own flag counts.

Legal holds

A legal hold carries a reason and covers the object it is placed on and everything under it. While it stands:

  • Dropping a held table, view or namespace is refused, for example Table equities.fills is under a legal hold and cannot be dropped.
  • A commit that removes snapshots is refused: Table id is under legal hold: its snapshots cannot be removed. Commits that add data still succeed.
  • The maintenance policy turns snapshot expiry and orphan removal off, and maintenance on request for them is refused. Compaction still runs.
  • Purging a dropped table or view is refused, and so is unregistering a table or removing a held object from a catalog branch or tag.

A hold is released on the level it was placed on, by anyone whose group holds manage-tags there. See Place and lift a legal hold.

DR freezes

A DR freeze, set by a platform operator with a reason, refuses every commit under it: Writes to id are frozen for DR reconcile: reason. The maintenance policy also turns off snapshot expiry, orphan removal, compaction and manifest rewrites there. Lifting the freeze restores both.

Delete policies

Nothing the server vends can delete a file. To make the object store enforce the same rule, a platform operator reads the bucket policies at GET /management/v1/maintenance/delete-policies and applies them. They let only the maintenance worker's own storage identity, named as the profile's maintenance-principal, delete objects or change the bucket's lifecycle and policy, and deny it to everyone else, the server's own identity included. A profile without a maintenance-principal is listed as unprotected.

What it guarantees and what it does not

  • Every attribute change, hold and freeze is audited, with who made it and, for attributes, its provenance.
  • Each block is enforced in the server, against engines, the console and the maintenance worker alike, and each refusal is audited as a denial with its reason, such as legal_hold or dr_freeze.
  • A purge already claimed by the worker before a hold was placed still completes.
  • Without the delete policies applied, someone with other credentials to the bucket can still delete files. The server cannot see that.

Where you see it

In the console, the Governance page has the tabs Summary and Holds and freezes, and each object's Access tab has the panels Governance, Legal holds and Attributes. The endpoints are in the Governance API, and the settings in Governance and refs settings.

Limits

  • An attribute's value and provenance, and a hold's or freeze's reason, are at most 1,000 characters.
  • The row-column-policy flag cannot be removed while rules stand on the table.
  • A retention-class must name a configured class: Unknown retention class name; configured classes: […].
