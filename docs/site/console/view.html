The view page

A view's page answers what the view says (its SQL, schema and every version), what your groups may do with it, how it is governed and what has happened to it.

Who sees it

The page opens for anyone whose groups hold describe on the view or above. Overview and Versions load the view, which needs select. Access is open to all who see the view. Audit appears only to those who manage the catalog's grants. A grant admin, who holds manage-grants and no select, lands on Access.

The head

The head shows the view's path and view, with Copy link. The tabs are Overview, Versions, Access and Audit. A view has no settings, maintenance or export in the console.

Overview

Definition
The current SQL, with its version and dialects, and Copy the SQL.
Schema
Each column's Id, Column and Type.
Current state
View UUID, Current version, Written by, Default namespace, Location, Metadata file and Properties.

Versions

Every version of the view, newest first, each as Version N with its time, the engine that wrote it and its schema; the current one is marked Current.

Access

The same panels as the table page's Access tab, without retention class, the row and column flag, and row filters and column masks. For a view:

  • Its status says No DR freeze with "Its definition may be replaced." and, under a hold, "It cannot be dropped or purged."
  • What the catalog enforces lists Replacing the definition: Allowed · to groups holding modify.
  • Place a hold: "A legal hold stops this view being dropped or purged. Its definition can still be replaced. Only a steward can release it."
  • In Grant access, Read and write rows is not offered, and modify reads Change it (definition, properties).

Audit

The view's audit trail, with the same filters and completeness panel as the table page's Audit tab.
