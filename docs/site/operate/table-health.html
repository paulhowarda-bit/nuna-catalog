Table health

How the maintenance worker judges whether a table needs compaction, what its score means, what puts a table in tonight's queue, and how to ask for maintenance now.

For platform operators and data stewards

Each night, in the cleanup window, the maintenance worker reads every enabled table's current manifests and reports an assessment to the catalog: whether the table needs compaction, why, and how badly. Tables that need it join tonight's queue, and compaction Jobs start from its head.

Before you begin

  • The maintenance worker running, with a cleanup window (Maintenance nights).
  • select on a table to read its health; modify to change its policy or ask for maintenance.

Why a table needs compaction

Reasons in an assessment
ReasonWhen
small-filesOne partition holds at least compaction.min-input-files data files smaller than 75% of compaction.target-file-size-bytes.
deletesIts delete files (position deletes, deletion vectors and equality deletes) number more than compaction.delete-file-ratio of its data files.
equality-deletesIt has any equality-delete file, which every reader must join against.

The thresholds are maintenance policy keys, set on a catalog, namespace or table like the rest of the policy (Change a table's settings):

Compaction thresholds
Policy keyDefaultMeaning
compaction.target-file-size-bytes536870912The size a Job writes. A data file under 75% of it is small.
compaction.min-input-files5Small files one partition must hold before the table needs compaction for them.
compaction.delete-file-ratio0.3The share of its data files its delete files must pass. A decimal above 0.

The score and tonight's queue

The score says how far past its thresholds a table is: 1 at a threshold, 2 twice past it. It is the larger of small files over min-input-files and the delete files' share over delete-file-ratio.

Tonight's queue orders the tables that need compaction: tables with equality deletes first, then the highest score. Jobs start from its head while fewer than compaction.max-jobs run, so the head of the queue is what the night compacts first. Each table gets at most one Job a night. Tables still waiting when the window closes are counted as left over and assessed again the next night.

In the console, a table in the queue carries a mark beside its name and in the tree, and its page says where it stands: Tonight's queue, neediest first: this table is nth of m.

Read a table's health

Open the table and select its Maintenance tab. The Maintenance page lists tonight's queue for the whole catalog.

Call the table's health route (curl, reference):

curl -sS "$NUNA/management/v1/catalogs/trading/namespaces/equities/tables/fills/health" \
  -H "Authorization: Bearer $TOKEN"
{
  "id": "…",
  "catalog": "trading",
  "namespace": ["equities"],
  "name": "fills",
  "assessment": {
    "assessed-at": "…",
    "needs-compaction": true,
    "reasons": ["equality-deletes", "small-files"],
    "score": 2.0,
    "data-files": 40,
    "small-files": 10,
    "small-file-share": 0.25,
    "delete-files": 3,
    "position-delete-files": 1,
    "deletion-vectors": 1,
    "equality-delete-files": 1
  },
  "last-compaction": { "started-at": "…", "ended-at": "…", "outcome": "cut-off" },
  "requests": []
}
  • assessment is absent until the worker has assessed the table; last-compaction until a Job has run for it.
  • small-files counts only partitions holding at least min-input-files small files: what a Job would rewrite.
  • last-compaction.outcome is running, succeeded, failed or cut-off.

A caller with no grant on the table gets 404 NoSuchTableException, as for a table that does not exist. GET /management/v1/maintenance/tables lists the queue across every catalog, neediest first, showing only tables the caller may select.

Ask for maintenance now

With modify on a table you can ask for its compaction or orphan scan to run now, inside the window or outside it:

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/namespaces/equities/tables/fills/maintenance/requests" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"job": "compaction"}'
  • The answer is 202, with the request in state waiting. The worker takes it at its next scan, so it starts within one scan interval.
  • One request waits per table and job; asking again returns the one waiting.
  • A requested compaction runs whether or not the table needs one. Its Job stops nuna.maintenance.request-deadline (two hours) after it starts, in place of the window's end.
  • Each request is audited as a governance change of the table.

If it fails

Answer or symptomCause
403 on a requestNo modify on the table, or a DR freeze over it.
409 MaintenanceNotAllowedExceptionThe table's policy does not run that job: turned off at some level, or an orphan scan under a legal hold.
No assessmentThe worker has not run a cleanup window since the table was created, or the table's compaction is turned off.
Needy tables left over night after nightSee NunaCompactionFallingBehind.
