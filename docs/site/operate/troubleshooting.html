Troubleshooting

Symptoms, their causes and their fixes, grouped by the part that fails, with each message as nuna prints it.

For platform operators

Find the message you see, or the symptom, under the part that fails. Each error answer from the server is JSON with an error object holding message, type and code, and every answer carries X-Request-ID: search the logs and the audit records for it (The request id). When an alert fired, start from its runbook.

Server start-up

The server refuses an unsafe database

The log's last lines read The catalog's database is unsafe, so the server does not start, followed by the findings.

Cause: the start-up self-check found the database unsafe for a catalog. The message lists each finding as code: detail, and ends Make the database safe. Only a test or demo database may run so, by naming each code in nuna.database.allow-unsafe.

Fix: fix each finding in the database (the codes). Name a code in nuna.database.allow-unsafe only for a test or demo database; each allowed finding is then logged at WARN as The catalog's database is unsafe, allowed by nuna.database.allow-unsafe: ….

A ca-bundle setting stops the server or the worker

Cause: a CA bundle file is missing or not a PEM certificate. The message starts with the setting's name, such as nuna.storage.profiles.name.ca-bundle: , nuna.maintenance.storage.name.ca-bundle: , nuna.maintenance.dr.replicas.name.ca-bundle: or nuna.audit-tables.archive.ca-bundle: , followed by the reason.

Fix: check that the ConfigMap holding the bundle is mounted (storageCaConfigMap in the charts, at /etc/nuna/storage-ca) and that the setting names the file inside it.

Pods never become ready

Cause: the readiness probe reads GET /ui/config.json on port 8181. A server still migrating the database, or waiting for it, does not answer yet; the start-up probe allows about 10 minutes.

Fix: read the pod's log: kubectl -n "$NS" logs pod. If the pod restarted, add --previous to read the run that failed (Health checks).

A load balancer's check of /actuator/health fails

Cause: nuna has no Actuator endpoints. /actuator/health answers 404 No static resource actuator/health.

Fix: point the check at /ui/config.json, as the chart's probes do.

Database

Calls answer 503 Catalog store unavailable

Cause: the server cannot reach its database. The answer is 503 ServiceUnavailableException with Retry-After: 2 and the message Catalog store unavailable; nothing was applied: …; the server logs catalog store unavailable: … at WARN.

Fix: restore the database or the network path to it. Nothing was applied, so clients may retry. The servers recover by themselves once the database answers.

A commit answers CommitStateUnknownException

Cause: the database's answer to the commit was lost, so the server cannot tell whether it happened.

Fix: load the table and check its current snapshot before retrying. A client that sent an Idempotency-Key can send the same request with the same key: if the commit happened, it gets the first answer again.

Identity provider and tokens

Calls answer 401 Not authorized

Cause: the token is missing, expired, signed by an issuer the server does not trust, or for another audience. The answer says only Not authorized: the bearer token is missing or was not accepted; the reason stays in the audit record of the failure.

Fix: find the audit record for the request's id (AuthFailure) and read its reason. Then fix the token or the issuer settings (Connect an identity provider).

Calls answer 503 The token could not be checked

Cause: the server could not fetch the issuer's signing keys, so it does not know whether the token is good. The answer is The token could not be checked: its issuer's signing keys could not be fetched; retry later, with Retry-After: 2; the server logs the reason at WARN, such as Couldn't retrieve JWK set from URL: Read timed out.

Fix: check that the server reaches the issuer's JWKS URL, and that the identity provider answers quickly. Clients may send the same token again.

Calls answer 403 … holds no privilege that gives …

Cause: the caller is signed in but has no grant that gives the privilege the call needs. The message names the principal, the privilege and the operation, such as nuna-audit-tables holds no privilege that gives modify for updateTable.

Fix: grant the privilege to one of the caller's groups (Authorization).

Object store and credentials

A store's endpoint gives UnknownHostException

Cause: the endpoint names a host the pod cannot resolve, such as a Service name from another namespace written without its namespace.

Fix: write the endpoint as the pod resolves it, such as http://service.namespace.svc:port. The worker's store endpoints must be written exactly as the catalog's storage profiles write them.

TLS to the store fails with PKIX path building failed

Cause: a private CA signed the store's certificate and the client does not trust it.

Fix: give the profile or store a ca-bundle from the mounted CA ConfigMap. Compaction Jobs get a copy of their store's CA when the worker's store names one.

keytool says Input not an X.509 certificate

Cause: the file given is not a PEM or DER certificate: often a whole chain with text before it, or a private key.

Fix: give one certificate per file, starting at its BEGIN CERTIFICATE line.

Maintenance worker

The worker does not start, or the window is wrong

Cause: cleanup-window lacks start, end or zone, which have no default, or a time is unquoted: YAML 1.1 reads 22:30 as the number 1350.

Fix: quote the times: start: "22:30" (Set the cleanup window).

The console says no maintenance worker has reported

The console shows No maintenance worker has reported, so the catalog can't check this.

Cause: no worker has finished a scan since the catalog's records began, or the worker cannot reach the catalog.

Fix: see NunaWorkerNotScanning.

Deletions or purges fail

Cause: most often the worker's storage identity or the bucket's delete policy. See NunaDeletionsFailing.

Fix: give the worker's identity list and delete rights on the catalog's prefixes (Install the maintenance worker).

Compaction Jobs

A Job cannot reach the network

The Job's log reads Unable to execute HTTP request: Network is unreachable.

Cause: the Job's pod cannot reach the store or the catalog, often because a network policy in the Jobs' namespace blocks it.

Fix: allow egress from the Jobs' namespace to the store and to the catalog's address (compaction.catalog-uri). If the error is PKIX path building failed instead, it is the store's CA (above).

Jobs are cut off every night

Cause and fix: see NunaCompactionFallingBehind.

Audit

Reads or vends answer 503 Audit is unavailable

Cause: a record that must be audited before the answer was not acknowledged. The answer is Audit is unavailable, so nothing that must be audited first is handed out; retry later; the server logs refused a request whose audit record was not acknowledged.

Fix: restore the audit destination named in the log line (Run the audit pipeline).

The outbox relay stops on is not a catalog event

Cause: an outbox entry cannot be read as a catalog event. The log line reads outbox entry id of change id is not a catalog event: ….

Fix: the entry was written by another release of nuna or by hand. Raise it with the team that runs nuna, with the entry's id.

The audit tables writer stops at a record

Cause: a record it cannot map. From Kafka it logs … is not a catalog event this writer can map; the audit table stops here; from the log it writes the others and logs A log record of … is not a catalog event; it is not written to the audit table: ….

Fix: check that the writer reads the right topic or log, and that it runs the same release as the servers.

The writer may not commit to the audit tables

The writer logs nuna-audit-tables holds no privilege that gives modify for updateTable.

Cause: the writer's principal has no grant that gives modify on the audit tables.

Fix: grant modify on the audit tables, or the namespace that holds them, to the writer's group.

Telemetry

Nothing arrives at the collector

Cause: no endpoint is set, or the endpoint is gRPC on port 4317, which nuna does not support.

Fix: set telemetry.endpoint to the collector's OTLP/HTTP base URL, such as http://otel-collector.observability:4318 (Send telemetry).

Helm and rollouts

A changed Secret is not picked up

Cause: a Secret you manage yourself (existingSecret) is not part of the chart, so changing it does not roll the pods.

Fix: kubectl -n "$NS" rollout restart deployment/nuna-catalog (Helm and kubectl recipes). A Secret the chart makes rolls the pods on helm upgrade.

A few requests fail during a rollout

Cause: without the chart's preStop wait, a pod stops before the Service stops sending it requests.

Fix: keep the chart's preStop sleep 5 and its 45-second grace period. Without them, a rolling restart failed 3 of 583 requests in a test.

Console

The Audit page shows nothing and its reads answer 503

Cause: the Audit page reads the audit tables, which the audit tables writer fills. Without the writer and its tables, its reads cannot be answered.

Fix: install the writer (Install the audit tables writer).

Not documented yet: the exact message the Audit page's reads give when the audit tables are not configured.

The nights route answers 500

Cause: jobs in /management/v1/maintenance/nights was not a number. That is answered 500 where 400 belongs.

Fix: send whole numbers for days and jobs.

Engines

PyIceberg says Cannot write manifest for table version: 3

Cause: PyIceberg 0.12 cannot write format version 3 tables.

Fix: write version 3 tables with an engine that supports it, or create the table as version 2.

Writes answer 403 … is frozen for DR reconcile

Cause: a platform operator froze the table, its namespace or its catalog for disaster recovery.

Fix: wait for the freeze to be lifted (Freeze and unfreeze for disaster recovery).
