Metrics

Every metric the nuna server and the maintenance worker export: its name, type, unit, labels and meaning.

For platform operators

Both programs record metrics with Micrometer and push them over OTLP/HTTP every minute, cumulative, once an endpoint is set (Send telemetry). Neither has a scrape endpoint. Names below are Micrometer's, with dots. Over OTLP every timer is sent in milliseconds. Prometheus' default translation of OTLP names turns dots into underscores in names and labels, adds the unit, and ends counters in _total: nuna.catalog.requests arrives as nuna_catalog_requests_milliseconds_count, _sum and _bucket, and the label operation.id as operation_id. Micrometer also sends a _max gauge for each timer.

Each server holds only its own meters, so a deployment's figure is the sum over its servers, except the ref gauges, which every server reads from the database: take one server's value or the maximum. No label holds a namespace, table, principal or filter value, with one exception: nuna.maintenance.table.compaction.need.

Server labels

LabelValues
catalogThe name of a catalog that exists, or none for a call that named none, named one that does not exist, or was refused before its catalog was looked up.
operation.idThe Iceberg REST specification's operationId of the route, such as loadTable, updateTable, commitTransaction, loadCredentials, reportMetrics or getConfig.
outcomeSet per meter, below.
error.typeThe Iceberg error type the answer named, such as CommitFailedException or NotAuthorizedException; for the token route the OAuth error, such as invalid_client. none when there was no error or the body named no type.
requirement.typeFor a commit refused because a requirement failed, its type, such as assert-ref-snapshot-id. Otherwise none.
ref.kindOn commits, main or branch, where the commit landed. On the ref gauges, branch or tag.
report.typescan-report or commit-report.
operationA commit report's snapshot operation: append, replace, overwrite or delete; any other is other, and a scan report has none.
engine.nameThe engine-name in a report's metadata, such as spark. A server keeps the first 20 names it sees; later names, and names that are not 1 to 32 letters, digits, spaces, dots, hyphens or underscores starting with a letter or digit, count as other. none when the report gives none.

Commit outcomes

outcomeMeaning
committedThe change was committed.
unchangedThe request changed nothing, so nothing was written.
replayedAn Idempotency-Key repeated a commit already made, and its first answer was given again.
requirement-failedA requirement did not hold: 409 CommitFailedException. Contention with another writer, or a stale engine.
refusedAny other 4xx: a missing table, a bad update, a governance rule. error.type says which.
unknownThe commit may or may not have happened: CommitStateUnknownException.
failedAny other 5xx, including the database being unreachable (ServiceUnavailableException, nothing applied).

Vend outcomes

outcomeMeaning
issuedNew credentials were minted, audited and handed out.
cachedCredentials came from the credential cache: no STS call and no new audit record of an issue.
noneThe caller declined credentials (X-Iceberg-Access-Delegation: none), as the console always does.
failedNone could be issued. error.type names why, such as ServiceUnavailableException or ForbiddenException.

Engine reports

Each result in a client's scan or commit report becomes a meter named nuna.catalog.report. and the result's name with its hyphens made dots: total-duration becomes nuna.catalog.report.total.duration. A timer result is one timing; a counter result is a distribution summary with one sample per report, in bytes for the bytes results. Results the specification does not name are skipped.

  • Scan reports: total.planning.duration (timer); result.data.files, result.delete.files, total.data.manifests, total.delete.manifests, scanned.data.manifests, skipped.data.manifests, scanned.delete.manifests, skipped.delete.manifests, skipped.data.files, skipped.delete.files, indexed.delete.files, equality.delete.files, positional.delete.files, dvs (counts); total.file.size.in.bytes, total.delete.file.size.in.bytes (bytes).
  • Commit reports: total.duration (timer); attempts, added.data.files, removed.data.files, total.data.files, added.delete.files, added.equality.delete.files, added.positional.delete.files, added.dvs, removed.delete.files, removed.equality.delete.files, removed.positional.delete.files, removed.dvs, total.delete.files, added.records, removed.records, total.records, added.positional.deletes, removed.positional.deletes, total.positional.deletes, added.equality.deletes, removed.equality.deletes, total.equality.deletes, manifests.created, manifests.replaced, manifests.kept, manifest.entries.processed (counts); added.files.size.bytes, removed.files.size.bytes, total.files.size.bytes (bytes).

Worker meters

The maintenance worker registers each meter as it starts, so dashboards and alerts see zeros before the first scan. A scan succeeds when it read the whole work list; a job that fails inside it is counted under nuna.maintenance.failures and the scan still succeeds. The counters below have no labels unless the table says so.
