Create your first table

Create a namespace and a table in the demo's catalog lakehouse, write three rows from an engine, read them back and find the table's history in the console. It takes about 20 minutes.

Demo only For engine users

What you need

  • The demo running, with its certificate authority trusted, as Run nuna on your laptop leaves it.
  • Git Bash, for the commands on this page.
  • One engine. The demo runs Trino for you, with CloudBeaver as its web page, so the Trino tabs need nothing else. The Spark tabs need Spark 4.1 with Iceberg 1.12.0, and the PyIceberg tabs need PyIceberg 0.12.0, the versions nuna tests.

Get a token

  1. Set the server's address and the token of the demo user ana.

    export NUNA=https://localhost:8181
export TOKEN=$(tr -d '\r\n' < ~/.nuna-demo/tokens/ana.jwt)

    The demo minted a token for each of its users when it started and keeps them in ~/.nuna-demo/tokens/. Each lasts 7 days; demo/demo.sh token prints them again and mints new ones when they are about to expire. ana belongs to group demo-analysts, which holds create and modify on catalog lakehouse: she may create namespaces and tables and write to them.

  2. Ask the server for the catalog's configuration.

    curl -sS --cacert ~/.nuna-demo/tls/ca.crt --ssl-revoke-best-effort \
  -H "Authorization: Bearer $TOKEN" \
  "$NUNA/v1/config?warehouse=lakehouse"

    --cacert trusts the demo's certificate authority. Git Bash's curl checks certificates with Windows, which refuses the demo's authority because it names no revocation list, unless you add --ssl-revoke-best-effort. The answer lists 26 endpoints; here they are cut to two:

    {
  "defaults": {},
  "overrides": {
    "prefix": "lakehouse"
  },
  "endpoints": [
    "GET /v1/{prefix}/namespaces",
    "POST /v1/{prefix}/namespaces"
  ],
  "idempotency-key-lifetime": "PT24H"
}

The server answers with prefix lakehouse

The overrides name the prefix every other call on the catalog uses: /v1/lakehouse/…. An answer of 401 with Not authorized: the bearer token is missing or was not accepted means TOKEN is empty or expired: run demo/demo.sh token and set it again.

Point an engine at the demo

An engine needs the server's address, the warehouse, which is the catalog's name, and a token. It asks for vended credentials, so the server hands it short-lived keys for the table's files and the engine holds none of its own.

curl needs nothing more than NUNA and TOKEN. It creates namespaces and tables and reads them, but cannot write rows: writing rows means writing data files, which only an engine does.

Start spark-sql with a catalog named lakehouse. These are the settings nuna's engine tests use, with the demo's address:

spark-sql \
  --packages org.apache.iceberg:iceberg-spark-runtime-4.1_2.13:1.12.0,org.apache.iceberg:iceberg-aws-bundle:1.12.0 \
  --conf spark.sql.extensions=org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions \
  --conf spark.sql.catalog.lakehouse=org.apache.iceberg.spark.SparkCatalog \
  --conf spark.sql.catalog.lakehouse.type=rest \
  --conf spark.sql.catalog.lakehouse.uri=https://localhost:8181/ \
  --conf spark.sql.catalog.lakehouse.warehouse=lakehouse \
  --conf "spark.sql.catalog.lakehouse.token=$TOKEN" \
  --conf spark.sql.catalog.lakehouse.header.X-Iceberg-Access-Delegation=vended-credentials \
  --conf spark.sql.catalog.lakehouse.io-impl=org.apache.iceberg.aws.s3.S3FileIO \
  --conf spark.sql.catalog.lakehouse.rest-catalog-purge=true

rest-catalog-purge=true makes DROP TABLE … PURGE leave the files to the server instead of deleting them itself, which vended credentials could not do anyway.

The demo's Trino already has a catalog lakehouse pointed at the server, and sends each query with the token of the person who runs it.

  1. Open CloudBeaver at https://localhost:8185.
  2. Sign in through Keycloak as ana, with her password from ~/.nuna-demo/people.
  3. Open the connection nuna (Trino, as ana) and open an SQL editor on it.

The first query after Trino starts takes about 10 seconds; later ones about 2.

Load the catalog in Python. These are the settings nuna's engine tests use, with the demo's address:

import os
from pyiceberg.catalog import load_catalog

catalog = load_catalog("lakehouse", **{
    "type": "rest",
    "uri": "https://localhost:8181",
    "warehouse": "lakehouse",
    "token": os.environ["TOKEN"],
    "header.X-Iceberg-Access-Delegation": "vended-credentials",
})

Not documented yet: how Spark and PyIceberg on your laptop reach the demo's table files. The server vends s3.endpoint http://s3:9000, an address that resolves only inside the demo's cluster, and nuna's engine tests run Spark and PyIceberg inside it. Making these engines trust the demo's certificate and reach its object store on port 8187 has not been tested.

Create a namespace and a table

  1. Create the namespace quickstart.

    curl -sS --cacert ~/.nuna-demo/tls/ca.crt --ssl-revoke-best-effort \
  -X POST "$NUNA/v1/lakehouse/namespaces" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"namespace": ["quickstart"]}'
    {
  "namespace": ["quickstart"],
  "properties": {}
}
    CREATE NAMESPACE lakehouse.quickstart;
    CREATE SCHEMA lakehouse.quickstart;
    catalog.create_namespace("quickstart")

    If the namespace exists already, the server answers 409 with Namespace already exists: quickstart.

  2. Create the table quickstart.trades with four columns.

    curl -sS --cacert ~/.nuna-demo/tls/ca.crt --ssl-revoke-best-effort \
  -X POST "$NUNA/v1/lakehouse/namespaces/quickstart/tables" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "trades",
    "schema": {
      "type": "struct",
      "fields": [
        {"id": 1, "name": "trade_id", "type": "long", "required": false},
        {"id": 2, "name": "symbol", "type": "string", "required": false},
        {"id": 3, "name": "qty", "type": "long", "required": false},
        {"id": 4, "name": "price", "type": "double", "required": false}
      ]
    }
  }'

    The answer is the table's metadata, then config and storage-credentials with the vended keys. Here it is cut to the fields this step is about, with the keys left out:

    {
  "metadata-location": "s3://warehouse/tables/7f48984b-7fe8-4032-bbad-d4afa694fe8e/metadata/00001-72ff9cae-05a9-4735-aab3-e1526bd7d574.metadata.json",
  "metadata": {
    "format-version": 3,
    "location": "s3://warehouse/tables/7f48984b-7fe8-4032-bbad-d4afa694fe8e",
    "current-schema-id": 0,
    "current-snapshot-id": null,
    "properties": {
      "write.parquet.compression-codec": "zstd"
    }
  },
  "config": {
    "s3.endpoint": "http://s3:9000",
    "client.region": "us-east-1",
    "s3.path-style-access": "true"
  }
}
    CREATE TABLE lakehouse.quickstart.trades (
  trade_id bigint,
  symbol string,
  qty bigint,
  price double
) USING iceberg;
    CREATE TABLE lakehouse.quickstart.trades (
  trade_id bigint,
  symbol varchar,
  qty bigint,
  price double
);
    from pyiceberg.schema import Schema
from pyiceberg.types import DoubleType, LongType, NestedField, StringType

table = catalog.create_table("quickstart.trades", Schema(
    NestedField(1, "trade_id", LongType(), required=False),
    NestedField(2, "symbol", StringType(), required=False),
    NestedField(3, "qty", LongType(), required=False),
    NestedField(4, "price", DoubleType(), required=False),
))

    The server chose the table's location itself, a folder named by the table's id under the catalog's table root, so a renamed table keeps its files where they are (Catalogs, namespaces, tables and views).

The namespace lists the new table

curl -sS --cacert ~/.nuna-demo/tls/ca.crt --ssl-revoke-best-effort \
  -H "Authorization: Bearer $TOKEN" \
  "$NUNA/v1/lakehouse/namespaces/quickstart/tables"

The answer is {"identifiers":[{"namespace":["quickstart"],"name":"trades"}],"next-page-token":null}. The table has no snapshot yet: current-snapshot-id is null until the first write.

Write rows

curl has no tab here: an engine writes the data files to the object store with the vended keys, then commits them through the server.

  1. Insert three rows.

    INSERT INTO lakehouse.quickstart.trades VALUES
  (1, 'SAP', 100, 183.40),
  (2, 'DTE', 1500, 23.24),
  (3, 'SIE', 50, 211.10);
    INSERT INTO lakehouse.quickstart.trades VALUES
  (1, 'SAP', 100, 183.40),
  (2, 'DTE', 1500, 23.24),
  (3, 'SIE', 50, 211.10);
    import pyarrow as pa

rows = pa.schema([("trade_id", pa.int64()), ("symbol", pa.string()),
                  ("qty", pa.int64()), ("price", pa.float64())])
table.append(pa.Table.from_pylist([
    {"trade_id": 1, "symbol": "SAP", "qty": 100, "price": 183.40},
    {"trade_id": 2, "symbol": "DTE", "qty": 1500, "price": 23.24},
    {"trade_id": 3, "symbol": "SIE", "qty": 50, "price": 211.10},
], schema=rows))

    The engine's one commit adds one snapshot to the table. If the server refuses the commit, the engine shows its error: a 403 names the privilege the caller lacks, as in gary holds no privilege that gives select for loadTable.

The insert reports three rows

Trino reports 3 rows inserted. The table now has a current snapshot, which the next stage reads.

Read the rows back

  1. Select the rows.

    curl cannot read rows, but it reads the table's metadata, whose newest snapshot counts them:

    curl -sS --cacert ~/.nuna-demo/tls/ca.crt --ssl-revoke-best-effort \
  -H "Authorization: Bearer $TOKEN" \
  "$NUNA/v1/lakehouse/namespaces/quickstart/tables/trades"

    In the answer, metadata.current-snapshot-id names the snapshot the insert made, and that snapshot's summary holds "added-records": "3".

    SELECT * FROM lakehouse.quickstart.trades ORDER BY trade_id;
    SELECT * FROM lakehouse.quickstart.trades ORDER BY trade_id;
    table = catalog.load_table("quickstart.trades")
print(table.scan().to_arrow().to_pylist())

You get the three rows you wrote

Trade ids 1, 2 and 3, for SAP, DTE and SIE.

Find the table in the console

  1. Sign in to the console at https://localhost:8181/ui/ as ana.

    Select Sign in with the demo's Keycloak and sign in to Keycloak with her password. If you are signed in as someone else, select Sign out first.

  2. Press /, enter quickstart.trades and press Enter.

  3. Select the History tab.

    Each row is one version of the table, newest first: when it was committed, what it changed, the snapshot it added, the rows it added or removed and who committed it. Select Show on a row for the commit's updates.

The History tab shows two versions

Version 1 is the table's creation and version 2 the insert, which added 3 rows. Through Trino, the insert's row names Trino's principal acting for ana; from Spark or PyIceberg it names ana.

Remove what you made

  1. Drop the table.

    curl -sS --cacert ~/.nuna-demo/tls/ca.crt --ssl-revoke-best-effort \
  -X DELETE "$NUNA/v1/lakehouse/namespaces/quickstart/tables/trades?purgeRequested=true" \
  -H "Authorization: Bearer $TOKEN"

    The server answers 204 with no body. It ignores purgeRequested: every drop keeps the files, and the table can be restored for a time.

    DROP TABLE lakehouse.quickstart.trades PURGE;
    catalog.purge_table("quickstart.trades")

    Not documented yet: Trino's DROP TABLE against the demo. nuna has not checked it, so this step has no Trino tab.

  2. Drop the namespace.

    curl -sS --cacert ~/.nuna-demo/tls/ca.crt --ssl-revoke-best-effort \
  -X DELETE "$NUNA/v1/lakehouse/namespaces/quickstart" \
  -H "Authorization: Bearer $TOKEN"
    DROP NAMESPACE lakehouse.quickstart;
    DROP SCHEMA lakehouse.quickstart;
    catalog.drop_namespace("quickstart")

The namespace is gone

A GET of $NUNA/v1/lakehouse/namespaces/quickstart now answers 404. Every drop in nuna is soft: the server keeps the dropped table's files until its window ends, then the maintenance worker purges them. Dropping, restoring and purging explains the window.

What you did

You read a token the demo minted and asked the server for the catalog's configuration. You created a namespace and a table through the Iceberg REST API, wrote rows from an engine that received vended credentials rather than keys of its own, and read them back. You found the table in the console and read its versions on the History tab, then dropped it. Next, work on a catalog branch.
