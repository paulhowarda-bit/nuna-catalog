PyIceberg

Connect PyIceberg to a nuna catalog with load_catalog, read tables any engine wrote, and write to format version 2 tables.

For engine users Tested in the engine matrix

Before you begin

  • PyIceberg with pyarrow: pip install "pyiceberg[pyarrow]==0.12.0". The engine matrix tests 0.12.0 on Python 3.12.
  • An access token in NUNA_TOKEN (Get a token), and grants for one of its groups: select to read, write to change data, create to create namespaces and tables (Privileges).

Load the catalog

  1. Load the catalog with the server's address, the nuna catalog and the token.

    import os
from pyiceberg.catalog import load_catalog

catalog = load_catalog("trading", **{
    "type": "rest",
    "uri": "https://nuna.example",
    "warehouse": "trading",
    "token": os.environ["NUNA_TOKEN"],
    "header.X-Iceberg-Access-Delegation": "vended-credentials",
})

    warehouse names the nuna catalog, or catalog@ref for a branch or tag. PyIceberg takes the object store's address and short-lived credentials from each table's load answer, so it needs no keys of its own.

  2. List the namespaces.

    print(catalog.list_namespaces())

PyIceberg prints the namespaces you may see

For example [('equities',), ('reference',)]. NoSuchWarehouseException means the catalog name is wrong or you hold nothing in it.

Read a table

fills = catalog.load_table(("equities", "fills"))
rows = fills.scan(row_filter="symbol = 'ACME'").to_arrow()

PyIceberg reads tables Spark wrote, of format versions 2 and 3: row-level deletes, deletion vectors, evolved schemas and partitions, and time travel with snapshot_by_name and snapshot_as_of_timestamp. It cannot load a table with a variant column (Unsupported field type: 'variant') or a geometry column.

Write to a table

Create each level of a nested namespace in turn: the catalog refuses a namespace whose parent does not exist.

import pyarrow as pa

catalog.create_namespace(("equities",))
catalog.create_namespace(("equities", "daily"))

schema = pa.schema([pa.field("id", pa.int64(), nullable=False), pa.field("symbol", pa.string())])
positions = catalog.create_table(("equities", "daily", "positions"), schema=schema,
                                 properties={"format-version": "2"})

positions.append(pa.Table.from_pylist([{"id": 1, "symbol": "ACME"}, {"id": 2, "symbol": "INITECH"}], schema=schema))
positions.delete("id = 2")
positions.overwrite(pa.Table.from_pylist([{"id": 1, "symbol": "ACME2"}], schema=schema), overwrite_filter="id = 1")
  • Set format-version to 2 for a table PyIceberg writes. nuna creates format version 3 tables by default, and PyIceberg 0.12.0 refuses to append to them: ValueError: Cannot write manifest for table version: 3.
  • append, delete, overwrite and upsert work, all copy-on-write.
  • purge_table sends a purge request, which nuna ignores: the drop is soft, and the table is purged after the retention period.

What was tested

The engine matrix runs PyIceberg against nuna every night code changes: a v2 table's lifecycle; a v3 table's create, read, schema change and drop; reading Spark's tables of every kind in Engine compatibility; its own append, delete, overwrite and upsert; the audit tables; and reading and writing through a catalog branch and tag.

If it fails

What you seeWhyWhat to do
ValueError: Cannot write manifest for table version: 3PyIceberg 0.12.0 does not write format version 3.Write to a v2 table, or with another engine.
Namespace does not exist: … from create_namespaceThe parent namespace does not exist.Create the parent first.
Unsupported field type: 'variant'The table has a v3 type PyIceberg cannot read.Read it with Spark.
Not authorized: the bearer token is missing or was not acceptedThe token is missing, expired or not trusted.Get a new token.
