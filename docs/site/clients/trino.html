Trino

Connect Trino's Iceberg connector to a nuna catalog so each query reaches nuna as the person who runs it, with row filters and column masks applied through Trino's OPA access control.

For platform operators and engine users Not tested by nuna

No nuna test runs Trino

Trino is not part of the engine matrix. The settings below are the ones the local demo runs with Trino 484, and the demo shows them working, but no test checks them on each change.

Before you begin

  • Trino with its Iceberg connector. The demo runs trinodb/trino:484.
  • A token for Trino itself, from your identity provider, and Trino's client registered in nuna as a trusted engine by a platform operator (Engines). Trino's token needs no grants: it reads each catalog's configuration and vouches for each query's user.
  • Each person who queries brings their own token (Get a token).

How a query reaches nuna

The person's client sends their token to Trino as the extra credential token. With iceberg.rest-catalog.session=USER, Trino sends that token to nuna in Authorization, and its own token in X-Nuna-Engine-Authorization. nuna then sees Trino acting for the person, checks the person's grants, and records both in the audit trail. Because Trino is a trusted engine, nuna gives it the files of tables that carry row filters or column masks, and Trino applies them.

Configure the catalog

  1. Give Trino its token in an environment variable, NUNA_TOKEN, from your secret store.

  2. Write a catalog properties file, here etc/catalog/trading.properties.

    connector.name=iceberg
iceberg.catalog.type=rest
iceberg.rest-catalog.uri=https://nuna.example
iceberg.rest-catalog.warehouse=trading
iceberg.rest-catalog.security=OAUTH2
iceberg.rest-catalog.oauth2.token=${ENV:NUNA_TOKEN}
iceberg.rest-catalog.session=USER
iceberg.rest-catalog.http-headers=X-Nuna-Engine-Authorization: Bearer ${ENV:NUNA_TOKEN}
iceberg.rest-catalog.vended-credentials-enabled=true
iceberg.rest-catalog.nested-namespace-enabled=true
iceberg.rest-catalog.server-assigned-table-location-enabled=true
fs.native-s3.enabled=true
s3.endpoint=https://s3.example
s3.region=us-east-1
s3.path-style-access=true
    The properties that matter for nuna
    PropertyWhy
    iceberg.rest-catalog.warehouseThe nuna catalog, or catalog@ref for a branch or tag: trading@dev reads branch dev and commits to it.
    iceberg.rest-catalog.oauth2.tokenTrino's own token, which it uses to read the catalog's configuration.
    iceberg.rest-catalog.session=USERSends each query's user token to nuna instead of Trino's.
    iceberg.rest-catalog.http-headersAdds Trino's token in X-Nuna-Engine-Authorization to every request, so nuna knows a trusted engine is acting for the user.
    iceberg.rest-catalog.vended-credentials-enabledUses the credentials nuna vends with each table; Trino needs no object store keys.
    iceberg.rest-catalog.nested-namespace-enabledLists namespaces at every level.
    iceberg.rest-catalog.server-assigned-table-location-enabledLets nuna choose new tables' locations, as it does for every table.

  3. Turn on OPA access control, in etc/access-control.properties, so Trino asks nuna for row filters and column masks.

    access-control.name=opa
opa.policy.uri=https://nuna.example/opa/v1/allow
opa.policy.row-filters-uri=https://nuna.example/opa/v1/row-filters
opa.policy.batch-column-masking-uri=https://nuna.example/opa/v1/column-masks
opa.identity.extra-credentials-keys=token

  4. Map each Trino catalog to the warehouse it reads, in the server's setting nuna.opa.catalogs.

    nuna:
  opa:
    catalogs:
      trading: trading
      trading_dev: trading@dev

    A Trino catalog not named here gets no row filters or column masks from nuna. See Trino and OPA.

A query runs as you

Run trino --user you --extra-credential "token=$TOKEN" --execute 'SHOW SCHEMAS FROM trading'. The namespaces you may see are listed, and the catalog's audit trail shows you as the end user and Trino's client as the engine. The first query after Trino starts takes about ten seconds.

What works

In the demo, people query tables through Trino, including through a branch catalog, and read flagged tables with their row filters and column masks applied. A client that reads a flagged table without Trino, Spark with the person's own token, say, gets 403 for its data.

Not documented yet: which Iceberg features Trino 484 handles against nuna. No test has run Trino's writes, row-level changes, schema evolution or views against nuna.

If it fails

What you seeWhyWhat to do
Every query fails, and trino --debug shows nuna's answer that it does not issue tokensThe query carried no token extra credential, so Trino asked nuna to exchange one, and nuna issues none.Send your token as the extra credential token.
Forbidden: client … is not a registered trusted engine, so it may not act for another userTrino's client is not registered as a trusted engine.A platform operator registers it (Engines).
The given warehouse does not exist: trading@dev (…)The branch the catalog names is merged, deleted or expired.Make a new branch with that name, or point the catalog elsewhere. Trino reads a new branch of the same name at once.
A table with rules returns rows without its row filter or column masksThe Trino catalog is missing from nuna.opa.catalogs.Add it, mapped to its warehouse.

The reason for a refusal is in the error's cause, which trino --debug prints.
