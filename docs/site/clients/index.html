Command line and clients

There is no nuna command-line program. You call the APIs with curl, query and write data with Iceberg engines, run local stacks with two scripts, and run clusters with Helm and kubectl.

Every client needs an access token from your identity provider first. Start with the token, then pick the tool for the job.

  • Get a token An access token from your identity provider, a token an engine renews itself, and how long tokens last.
  • Use the APIs with curl The set-up every curl example on this site assumes, request ids, paging, safe retries and reading errors.
  • Spark Catalog settings, vended credentials, branches and tags, and maintenance procedures. Tested in the engine matrix.
  • Trino Queries that reach nuna as the person who runs them, with row filters and column masks. Not tested by nuna.
  • PyIceberg Loading the catalog from Python, reading any table, and writing format version 2 tables. Tested in the engine matrix.
  • Kafka Connect The Apache Iceberg sink writing topics into nuna tables. Tested in the engine matrix.
  • SingleStore Loading nuna tables into SingleStore with Iceberg pipelines. Tested in the engine matrix.
  • Other engines DuckDB, StarRocks, Flink and others, with the standard REST settings. Not tested by nuna.
  • demo.sh reference The script that runs the local demo: every subcommand and what it prints.
  • Run nuna on a local kind cluster The scripts that make a local Kubernetes cluster and run nuna on it.
  • Install the catalog server with Helm The Helm charts that install nuna on a cluster.
  • Helm and kubectl recipes Status, logs, restarts and rollbacks for a running deployment.
