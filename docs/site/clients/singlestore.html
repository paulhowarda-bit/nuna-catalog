SingleStore

Load nuna tables into SingleStore with Iceberg pipelines, which read through the catalog with vended credentials, and copy a SingleStore table's changes into a nuna table with nuna's change feed connector.

For engine users Tested in the engine matrix

Before you begin

  • SingleStore with Iceberg pipelines turned on. The engine matrix tests SingleStore 10.9.0.
  • An access token for SingleStore's pipelines (Get a token), whose groups hold select on the tables loaded.
  • Network access from SingleStore to the server and to the object store.

Load a nuna table into SingleStore

  1. Turn on Iceberg pipelines, which are off by default.

    SET GLOBAL enable_iceberg_ingest = 1;

  2. Create the table to load into.

    CREATE TABLE fills (fill_id BIGINT, symbol TEXT, quantity BIGINT);

  3. Create a pipeline that reads the nuna table through the catalog.

    CREATE PIPELINE fills_pipe AS LOAD DATA S3 ''
CONFIG '{"catalog_type": "REST", "catalog.uri": "https://nuna.example", "catalog.warehouse": "trading",
         "table_id": "equities.fills", "catalog.token": "${NUNA_TOKEN}",
         "catalog.header.X-Iceberg-Access-Delegation": "vended-credentials", "iceberg_vended_credentials": true,
         "endpoint_url": "https://s3.example", "region": "us-east-1", "ingest_mode": "one_time"}'
CREDENTIALS '{}'
INTO TABLE fills (fill_id <- fill_id, symbol <- symbol, quantity <- quantity)
FORMAT ICEBERG;

    ${NUNA_TOKEN} stands for the token: put its value in the statement when you run it. table_id is the table's namespace and name joined by dots, every level included. CREDENTIALS stays empty: with iceberg_vended_credentials, SingleStore reads the files with the credentials nuna vends.

  4. Run the pipeline.

    START PIPELINE fills_pipe FOREGROUND;

The rows are in SingleStore

SELECT COUNT(*) FROM fills; gives the nuna table's row count.

The pipelines only read: SingleStore does not write to nuna tables this way.

What was tested

The engine matrix runs SingleStore's pipelines against nuna every night code changes, with "ingest_mode": "one_time". SingleStore 10.9.0 read Spark's tables of format versions 2 and 3, a v3 table with a deletion vector, tables changed by row-level delete, update and merge both copy-on-write and merge-on-read, a table whose schema evolved (read by its current column names), a table whose partitioning evolved, a compacted table, a table upgraded from v2 to v3, and PyIceberg's own v2 table. SingleStore's own documentation names format versions 1 and 2 only.

Copy SingleStore changes into nuna

nuna's change feed connector runs inside a SingleStore pipeline and copies one table's changes, or several tables', into Iceberg tables through the catalog: CREATE PIPELINE … AS LOAD DATA CONNECTOR 'ChangeFeedConnector' CONFIG '{…}' … INTO TABLE receipts. Where the copy resumes is kept in the Iceberg table, so after a failure it starts again from the offsets of the table's current snapshot.

The change feed connector's settings
SettingMeaning
singlestore.url, singlestore.user, singlestore.passwordWhere the change feed is read. The connector runs on a leaf, so the URL names an aggregator. SingleStore merges CONFIG and CREDENTIALS, so the password can go in CREDENTIALS.
singlestore.database, singlestore.tableThe table whose changes are sent. singlestore.tables, a list, copies each table into an Iceberg table of the same name.
iceberg.catalog.*Iceberg's catalog properties, prefixed: uri, warehouse, token, header.X-Iceberg-Access-Delegation.
iceberg.namespace, iceberg.tableThe table written; namespace levels separated by dots.
iceberg.format-version, iceberg.partition-byUsed only when the connector creates the table. Default format version 2, no partitioning.
commit.interval.msHow long changes collect before a commit. Default 5000.
singlestore.append-onlytrue for a table only ever inserted into; the first update or delete then stops the feed. Default false.

The connector's own tests run it against a real SingleStore 10.9.0 in the heavy build, writing to an in-memory Iceberg catalog rather than to nuna; the engine matrix does not run it.

Not documented yet: how to build the change feed connector and install it into a SingleStore cluster, and the receipts table's columns. The local demo builds it into its SingleStore image.

What you seeWhyWhat to do
