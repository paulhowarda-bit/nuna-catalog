Spark

Connect Spark to a nuna catalog with Iceberg's REST catalog and vended credentials, read and write a branch or tag, and run Iceberg's maintenance procedures within nuna's limits.

For engine users Tested in the engine matrix

Before you begin

  • Spark 4.1 with Iceberg's Spark runtime and AWS bundle on the class path. The engine matrix tests Spark 4.1.4 with iceberg-spark-runtime-4.1_2.13 1.12.0 and iceberg-aws-bundle 1.12.0.
  • An access token in NUNA_TOKEN (Get a token), and grants on the catalog for one of its groups: select to read, write to change data, create and modify to create and change tables (Privileges).
  • Network access from the driver and the executors to the server and to the object store.

Configure the catalog

These are the settings the engine matrix runs, for a Spark catalog named trading on the nuna catalog trading. The Spark catalog's name is yours to choose; warehouse names the nuna catalog.

spark-sql \
  --packages org.apache.iceberg:iceberg-spark-runtime-4.1_2.13:1.12.0,org.apache.iceberg:iceberg-aws-bundle:1.12.0 \
  --conf spark.sql.extensions=org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions \
  --conf spark.sql.catalog.trading=org.apache.iceberg.spark.SparkCatalog \
  --conf spark.sql.catalog.trading.type=rest \
  --conf spark.sql.catalog.trading.uri=https://nuna.example/ \
  --conf spark.sql.catalog.trading.warehouse=trading \
  --conf "spark.sql.catalog.trading.token=${NUNA_TOKEN}" \
  --conf spark.sql.catalog.trading.header.X-Iceberg-Access-Delegation=vended-credentials \
  --conf spark.sql.catalog.trading.io-impl=org.apache.iceberg.aws.s3.S3FileIO \
  --conf spark.sql.catalog.trading.rest-catalog-purge=true
What each setting does
Setting, after spark.sql.catalog.tradingWhy
type=rest, uriIceberg's REST catalog client, at the server's address. The client adds /v1/… itself.
warehouseThe nuna catalog, or catalog@ref for a branch or tag.
tokenThe bearer token sent with every request. For a token that renews itself, set credential and oauth2-server-uri instead (Let an engine renew its own token).
header.X-Iceberg-Access-DelegationAsks for vended credentials, so Spark needs no object store keys of its own. nuna vends them without the header too.
io-implIceberg's S3 file IO, which takes the vended credentials and the object store's address from the table's load answer, and refreshes the credentials before they expire.
rest-catalog-purge=trueSends DROP TABLE … PURGE to the catalog instead of deleting files from Spark. nuna drops the table softly and purges it after the retention period.

Spark lists the catalog's namespaces

Run SHOW NAMESPACES IN trading;. The namespaces you may see are listed; an error that names NotAuthorizedException means the token was refused.

Read and write

Tables are named spark catalog.namespace.table, with every level of a nested namespace: trading.equities.daily.positions. Create a nested namespace one level at a time.

CREATE NAMESPACE IF NOT EXISTS trading.equities;
CREATE TABLE trading.equities.fills (fill_id BIGINT, symbol STRING, quantity BIGINT, filled_at TIMESTAMP)
  USING iceberg PARTITIONED BY (days(filled_at));
INSERT INTO trading.equities.fills VALUES (1, 'ACME', 100, TIMESTAMP '2026-11-25 14:30:00');
SELECT symbol, sum(quantity) FROM trading.equities.fills GROUP BY symbol;

New tables are format version 3. Set TBLPROPERTIES ('format-version'='2') for a v2 table. The catalog chooses each table's location: a LOCATION clause is ignored.

Branches and tags

A nuna branch or tag covers the whole catalog. Spark reaches it as another Spark catalog whose warehouse is catalog@ref, with the other settings the same:

  --conf spark.sql.catalog.trading_dev=org.apache.iceberg.spark.SparkCatalog \
  --conf spark.sql.catalog.trading_dev.warehouse=trading@dev \
  …
  • Through a branch, Spark reads the branch's tables and writes to them; the writes stay on the branch until it is merged with the management API (Work on a branch). Creating, dropping and renaming tables happen on main only.
  • Through a tag, Spark only reads. Iceberg's client refuses a table change itself, since the tag's configuration does not list the commit endpoint, and a data write fails at the object store, since a tag's credentials are read-only.

These are nuna's catalog-wide refs. Iceberg's own table branches and tags (ALTER TABLE … CREATE BRANCH, VERSION AS OF) also work, inside one table.

Maintenance procedures

Iceberg's procedures run through CALL trading.system.procedure(…). The engine matrix ran each of these:

ProcedureAgainst nuna
rewrite_data_files, rewrite_position_delete_files, rewrite_manifestsWork. They need write on the table.
expire_snapshotsCommits, but no file is deleted: vended credentials cannot delete objects. nuna's maintenance worker deletes expired files. Snapshots younger than the deployment's minimum snapshot age, or on a table under a legal hold, cannot be expired.
remove_orphan_filesNeeds prefix_listing => true, since Spark's Hadoop file system has no s3 scheme. An older_than within the last 24 hours is refused. No file is deleted, for the same reason as above.
compute_table_statsWorks; the statistics are committed to the table.

nuna's maintenance worker can also run compaction for you on a schedule (Maintenance).

What was tested

The engine matrix runs Spark against nuna every night code changes: create, read, evolve and drop tables of format versions 2 and 3 in a three-level namespace; row-level delete, update and merge, copy-on-write and merge-on-read; schema and partition evolution; time travel; table branches, tags and write-audit-publish; views; the procedures above; upgrading v2 to v3; v3 row lineage, variant and geometry types; and the catalog's branches and tags. Engine compatibility gives each result.

Spark itself refuses two things: column default values (Cannot add column d since setting default values in Spark is currently unsupported), and ALTER VIEW … AS (ALTER VIEW ... AS is not supported. Use CREATE OR REPLACE VIEW instead). Geometry and geography types need spark.sql.geospatial.enabled=true.

BadRequestException: createTable is refused on branch dev of catalog trading: …Tables are created, dropped and renamed on main only.Do it through the main catalog, then work on the branch.
