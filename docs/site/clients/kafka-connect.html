Kafka Connect

Write Kafka topics into nuna tables with the Apache Iceberg sink connector, which creates the tables, evolves their schemas and writes with vended credentials. It only appends: upsert is not supported.

For engine users Tested in the engine matrix

Before you begin

  • Kafka Connect with the Apache Iceberg sink connector on its plugin path. The engine matrix tests Kafka 4.2.2 with the sink 1.12.0: iceberg-kafka-connect, iceberg-parquet, iceberg-orc, iceberg-aws and iceberg-aws-bundle, with Hadoop's client libraries.
  • Put iceberg-orc on the plugin path even though the sink writes Parquet. Iceberg 1.12's writers register Parquet, Avro and ORC together; without ORC, none registers and nothing is written.
  • An access token in NUNA_TOKEN (Get a token), whose groups hold create on the namespace the sink creates tables in, and write and modify on its tables: a schema change needs modify (Privileges).

Configure the sink

  1. Set the worker to flush offsets every second.

    value.converter=org.apache.kafka.connect.json.JsonConverter
value.converter.schemas.enable=false
offset.flush.interval.ms=1000

    Connect polls an idle sink task about once per offset flush, 60 seconds by default, and the Iceberg sink reads its control topic only then. At that pace its control consumer misses the group join and every commit times out.

  2. Configure the connector with the nuna catalog.

    name=fills-sink
connector.class=org.apache.iceberg.connect.IcebergSinkConnector
tasks.max=1
topics=fills
iceberg.tables=equities.fills
iceberg.tables.auto-create-enabled=true
iceberg.tables.evolve-schema-enabled=true
iceberg.control.topic=fills-control
iceberg.control.commit.interval-ms=2000
iceberg.catalog.type=rest
iceberg.catalog.uri=https://nuna.example
iceberg.catalog.warehouse=trading
iceberg.catalog.token=${NUNA_TOKEN}
iceberg.catalog.header.X-Iceberg-Access-Delegation=vended-credentials
iceberg.catalog.io-impl=org.apache.iceberg.aws.s3.S3FileIO

    iceberg.catalog.* are Iceberg's REST catalog properties with a prefix: warehouse names the nuna catalog, and a renewing token uses iceberg.catalog.credential and iceberg.catalog.oauth2-server-uri in place of token (Let an engine renew its own token). How ${NUNA_TOKEN} is filled in depends on how you run Connect: a config provider, or the shell that writes the file.

The table appears and fills

Produce a few records, wait for the commit interval, then load the table: curl -sS "$NUNA/v1/trading/namespaces/equities/tables/fills" -H "Authorization: Bearer $TOKEN" -H "X-Iceberg-Access-Delegation: none". The newest snapshot's total-records counts the records.

What was tested

The engine matrix runs the sink against nuna every night code changes. It produces three JSON records; the sink creates the namespace (three levels deep) and a format version 3 table, and commits the three records. A fourth record with a new field makes the sink add a column. The test then reads the table through the API and drops it.

Upsert is not supported

The Apache Iceberg 1.12.0 sink has no upsert or change-data mode: it writes only appends. iceberg.tables.default-id-columns sets identifier fields on the tables it creates and nothing more. To apply updates and deletes from a topic, land it with the sink, then merge it into the target table with Spark.
