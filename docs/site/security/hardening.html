Hardening checklist

Every setting and deployment choice that tightens a nuna install, what to set it to, and how to check it is in place.

Grouped by the layer it protects, in the order a request meets them. Each setting links to its entry in the settings reference. The curl checks assume NUNA and TOKEN as Use the APIs with curl sets them, with a token for the role the check names.

Identity

Setting or choiceWhat to setHow to check
nuna.security.issuersOnly your organization's identity provider. For each issuer, the narrowest audiences (the catalog's own application) and only the algorithms it signs with.Read the rendered application.yaml in the release's ConfigMap. A request without a token answers 401: curl -sS -o /dev/null -w '%{http_code}' "$NUNA/v1/config".
Token lifetime at the identity providerShort. The server does not check revocation, so a token works until it expires.Decode the exp and iat claims of a token the provider issues.
The catalog's application at the identity providerEmits only the groups assigned to it. The server refuses tokens whose groups were moved elsewhere because there were too many.A member of many groups can sign in to the console.
nuna.security.clock-skewThe default, 60 s, or less where clocks are synchronized.Read the ConfigMap.
nuna.ui.dev-token-loginfalse, the default.The console's sign-in page offers no box to paste a token.

Roles

Setting or choiceWhat to setHow to check
nuna.security.grant-admin-groupsOne small group, or none, granting manage-grants per catalog instead.GET /management/v1/catalogs/catalog/grants/groups lists the grant-admin groups.
nuna.security.platform-operator-groupsOne small group, separate from the grant admins. The server refuses to start if a group is in both.The same answer lists the platform-operator groups.
nuna.security.maintenance-principalsOnly the maintenance worker's principal id.Read the ConfigMap. Each principal listed may call the worker's endpoints, purges included.
nuna.security.own-group-principalsEmpty. Anyone listed may grant to their own groups.Read the ConfigMap.
Grants on each catalogGroups, not broad catch-all groups; the lowest privilege on the highest object that covers the work.GET /management/v1/catalogs/catalog/grants/export as a grant admin, or Export every grant on the Grants page.

Engines and data

Setting or choiceWhat to setHow to check
Trusted enginesRegister only engines that apply row filters and column masks and pass on their users' identity. A trusted engine reads flagged tables' files.GET /management/v1/engines as a platform operator.
nuna.security.refuse-identity-less-commitstrue where regulated areas exist, so a trusted engine cannot write there without naming its user.Read the ConfigMap.
nuna.opa.catalogsEvery Trino catalog that reaches nuna, including each catalog@ref one. An unmapped Trino catalog gets no rules.Compare the map with Trino's catalog files.
Regulated areasMark the catalogs and namespaces that hold regulated data with regulated, so unclassified tables there are closed.The Regulated areas panel on the Governance page.
Flagged tablesFlag each table that needs row filters or column masks, and give every reading group a rule.The Flagged tables panel on the Governance page.

Storage

Setting or choiceWhat to setHow to check
nuna.storage.require-tlstrue, the default: a profile whose endpoint is plain http stops the server from starting.Read the ConfigMap.
nuna.storage.credential-lifetimeThe shortest your engines' longest query tolerates, from 15 to 60 minutes; 30 by default.A table load's s3.session-token-expires-at-ms.
nuna.storage.profiles.name.maintenance-principalThe worker's own storage identity on every profile.GET /management/v1/maintenance/delete-policies as a platform operator lists no profile as unprotected.
Delete policies on each bucketApply the policies that answer gives, so only the worker can delete objects or change the bucket's lifecycle and policy.Read the bucket policy from the store and compare.
nuna.storage.profiles.name.kms-keyOn AWS S3, the KMS key every write must use.A vended credential's writes without that key are refused by the store.
The STS role's own policyOnly the profile's allowed prefixes; the session policy narrows each credential further, never widens it.Read the role's policy in the store.
Store credentialsIn the release's Secret (secrets.existingSecret), never in config.The ConfigMap holds no secret-access-key.

Audit

Setting or choiceWhat to setHow to check
logging.level.nuna.auditINFO or finer. The server refuses to start otherwise.The server starts.
nuna.audit.archive.bucketA bucket with Object Lock, which the server checks every hour; it refuses to start if the bucket has none.GET /management/v1/audit/archive as an audit reader shows the last check.
nuna.audit.tables.readersA narrow group: audit readers see every object and every person in the trail.The grants on the audit catalog, recorded as granted by nuna-configuration.
Where the nuna.audit log goesTo a store you keep, through the telemetry logs endpoint or your log collector.Find a recent record of your own request by its request id.
nuna.governance.audit-reads-per-minuteThe default, 60 per caller, or lower.A script reading faster gets 429.

Database

Setting or choiceWhat to setHow to check
nuna.database.allow-unsafeEmpty, so the server refuses to start while the database's self-check reports an unsafe setting.The server's start-up log names no allowed finding.
TLS to the databaseA client certificate in databaseTls.secretName, named by the JDBC URL's TLS parameters.The database reports the connection as TLS.

Deployment

Setting or choiceWhat to setHow to check
podSecurityContext and securityContextThe chart's defaults: non-root user 10001, the RuntimeDefault seccomp profile, no privilege escalation, a read-only root file system, every capability dropped.kubectl get pod pod -o jsonpath='{.spec.securityContext}'.
ingress.tlsA certificate for the server's host, so engines and browsers reach it over HTTPS.curl -sSI "$NUNA/ui/" succeeds over https.
The console's headersNothing to set: every console response carries a strict Content-Security-Policy, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy: no-referrer and Cross-Origin-Opener-Policy: same-origin.curl -sSI "$NUNA/ui/" shows them.
telemetry.logsTokenSecretWhen logs go to the audit tables writer, a token in a Secret, sent as X-Nuna-Audit-Token.Read the release's values; the writer's own settings name the token it expects.

Not documented yet: a network policy for the server's pods. The chart makes none; which paths to allow is in Requirements.
