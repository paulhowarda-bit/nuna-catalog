Security

How the server protects every catalog, layer by layer, in the order a request meets them: its token, the grants of its groups, the rules on what it reads, the storage credentials it receives, and the audit record it leaves.

Read the pages in order to follow one request through the server. The server issues no tokens, holds no one's password and has no superuser: it trusts the identity providers you name, decides every request from grants to groups, and records what it allowed and what it refused. The last page lists every setting and deployment choice that tightens an install, each with a way to check it.

  • Authentication How the server checks a bearer token, which issuers it trusts, and how an engine acts for the person using it.
  • Authorization How privileges, grants to groups and the roles set in the server's settings decide each request, and what the server refuses.
  • Use OPA The decision endpoints the server answers for an engine's OPA access control, and how to wire Trino to them.
  • Row-level security and column masking How row filters and column masks reach the engine that applies them, and what the server withholds from every other engine.
  • Credential vending The short-lived storage credentials the server hands an engine for one table, what they allow, and what is recorded.
  • Encryption and keys Encryption in transit and at rest, and how a storage profile's KMS key is enforced on every write.
  • What is audited Every action and refusal that leaves an audit record, by record type, and what leaves none.
  • Hardening checklist Every setting and deployment choice that tightens an install, each with how to check it.
