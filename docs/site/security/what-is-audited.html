What is audited

Every action and refusal that leaves an audit record, by record type, how each record is written, and what leaves no record.

Every record goes to the server's log nuna.audit at INFO; the server refuses to start if that log is set coarser than INFO. With Kafka configured, records also go to the audit topic, best effort. The fields of each record are in Audit record format; how records are chained, carried and kept is in The audit trail.

Changes

A change is recorded in the same database transaction as the change itself, through an outbox, so a change that happened always has its record and a record never describes a change that did not happen. In the order the code defines the types; each type's name is nuna.catalog. followed by the name in the first column.

Record types written with a change
TypeRecorded when
commitA table or view's metadata pointer moves: a commit, a create, a register. A multi-table commit writes one per table, with one commit id.
grantA privilege is granted or revoked (GRANTED, REVOKED), including the audit catalog's grants the server makes at start-up, recorded as granted by nuna-configuration.
dropA table or view is dropped, with the time after which it can be purged.
namespaceA namespace is created, its properties change, or it is dropped (CREATED, PROPERTIES_CHANGED, DROPPED).
renameA table or view is renamed or moved to another namespace.
engineA trusted engine is registered or removed (REGISTERED, REMOVED).
storage-setupA storage profile is set or a catalog is created from the settings at start-up (PROFILE_SET, CATALOG_CREATED). Store credentials are never recorded.
governanceAn attribute is set or removed (SET, REMOVED): classification, owner, retention class, regulated, row-column-policy, the maintenance policy, a DR freeze, or a request for maintenance now. Includes the flags the server removes at start-up from catalogs, namespaces and views.
holdA legal hold is placed or released (PLACED, RELEASED), with its reason.
undropA dropped table or view is restored.
purgeA dropped table or view is marked purged once the worker has deleted its files.
unregisterA table is unregistered: the catalog stops tracking it and deletes nothing.
labelA classification, owner or retention class sent to engines changes, beside its governance record.
purge-claimThe worker claims a dropped object for purge, before deleting its files. From then on it cannot be restored.
file-deletionThe worker records files it no longer needs as pending deletions, and later reports them deleted (RECORDED, DELETED).
refA catalog branch or tag is made, renewed, deleted, merged, warned of before it expires, or ends at its expiry, or an object is taken out of one (CREATED, RENEWED, DELETED, MERGED, EXPIRING, EXPIRED, OBJECT_REMOVED). The expiry warning changes nothing and is written at once, not through the outbox.
row-column-ruleA group's row filter and column masks on a table are set or removed (SET, REMOVED).

Reads, refusals and credentials

These are written as they happen, before the answer is sent.

Record types written at once
TypeRecorded whenIf it cannot be written
readA table or view is loaded, including a load answered 304; the console reads a table's schema; an object is exported.The read is still answered.
denialThe server refuses a request on authorization or governance: a missing privilege, an unclassified table in a regulated area, a flagged table, an identity-less write, a legal hold, a DR freeze, the minimum snapshot age, separation of duties, the self-grant rule, a column a rule names, a role-only operation. Refusals answered as a missing name are recorded too.The refusal still stands.
auth-failureA request's token is missing or refused, or an unregistered client names an end user. The token is never recorded.The refusal still stands.
credential-issueStorage credentials are vended. The credentials are never recorded.The credentials are discarded and the request answers 503.
audit-readSomeone reads an object's audit trail, the catalog's audit feed or summary, a record's place in the chain, or the drop record of a dropped object.See the note below the table.
maintenance-exemptionA maintenance principal is given storage access to a flagged table.The access is refused with 503.
run-endA server stops in order: the last record of its run.

Not documented yet: what happens to the request when an audit-read record cannot be written. The code was not traced that far.

The type break-glass exists in the record format, but no part of the server writes it: there is no break-glass access.

What leaves no record

  • Listings and existence checks: listing namespaces, tables, views, catalogs and grants.
  • The grant preview and the batch privilege check, which ask a question and change nothing.
  • Reading governance, holds, the maintenance policy, rules, health and metadata logs.
  • A table load with X-Iceberg-Access-Delegation: none vends nothing and leaves no credential-issue, though the load itself leaves a read.
  • The OPA decision endpoints' answers.
  • Exporting a catalog's grants (GET …/grants/export) and its row filters and column masks (GET …/row-column-rules/export). The console's export dialog says The export is audited., but the server writes no record for either.

Not documented yet: whether each listing in the first item is free of a denial record when refused. Refusals go through the same code, so they are expected to be audited, but each route was not checked.
