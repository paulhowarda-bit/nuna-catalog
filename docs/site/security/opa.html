Use OPA

Point Trino's OPA access control at the server's decision endpoints, so that each query applies the row filter and column masks the grant admin set for its user's groups.

For platform operators Needs a platform operator

The server answers three endpoints in the form Trino's OPA access control expects, so no OPA server runs between them. They are outside the server's token check: each verifies the end user's own token, passed by Trino as an extra credential, and ignores the user and groups Trino names.

The decision endpoints
EndpointAnswers
POST /opa/v1/allowAlways {"result":true}: the server has already decided access on the catalog's own requests.
POST /opa/v1/row-filters{"result":[{"expression":"…"}]}: the user's combined filter on the table.
POST /opa/v1/column-masks{"result":[{"index":0,"viewExpression":{"expression":"…"}}]}: one entry per masked column Trino asked about.

Before you begin

  • Trino reaches the server's Iceberg REST API with vended credentials, as Trino describes.
  • Trino has a token of its own, from a client registered at the identity provider, in the environment variable NUNA_TOKEN.
  • You are a platform operator, to register Trino as a trusted engine, and you can change the server's settings.

Wire Trino to the server

  1. Register Trino's client as a trusted engine.

    curl -sS -X PUT "$NUNA/management/v1/engines" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"issuer": "https://idp.example/realms/data", "client-id": "trino"}'

    The issuer must be one of the server's trusted issuers. The registration is audited as a nuna.catalog.engine record.

  2. Make each Iceberg catalog in Trino send its users' tokens.

    With session=USER, Trino passes each user's own token, and the extra header names Trino itself, so the server decides each query for its user.

    connector.name=iceberg
iceberg.catalog.type=rest
iceberg.rest-catalog.uri=https://nuna.example
iceberg.rest-catalog.warehouse=trading
iceberg.rest-catalog.security=OAUTH2
iceberg.rest-catalog.oauth2.token=${ENV:NUNA_TOKEN}
iceberg.rest-catalog.session=USER
iceberg.rest-catalog.http-headers=X-Nuna-Engine-Authorization: Bearer ${ENV:NUNA_TOKEN}
iceberg.rest-catalog.vended-credentials-enabled=true
iceberg.rest-catalog.nested-namespace-enabled=true

  3. Point Trino's access control at the decision endpoints.

    access-control.name=opa
opa.policy.uri=https://nuna.example/opa/v1/allow
opa.policy.row-filters-uri=https://nuna.example/opa/v1/row-filters
opa.policy.batch-column-masking-uri=https://nuna.example/opa/v1/column-masks
opa.identity.extra-credentials-keys=token

  4. Map each Trino catalog to the nuna catalog it reads.

    Set nuna.opa.catalogs in the server's settings: each key is a Trino catalog's name, each value a nuna catalog, or catalog@ref for one read through a branch or tag. A Trino catalog that is not mapped gets no filters and no masks.

    config:
  nuna:
    opa:
      catalogs:
        trading: trading
        trading_dev: trading@dev

  5. Have each user send their token as the extra credential token.

    A query without one is refused by the catalog, since the server issues no tokens to exchange.

A reader sees only their rows

A member of a group with a row filter on a flagged table queries it through Trino and gets only the matching rows, with masked columns replaced. The same person's answer at GET /management/v1/catalogs/trading/namespaces/equities%1Fdaily/tables/positions/row-column-rules/mine says "rows": "filtered" and lists the masked columns.

If it fails

The decision endpoints fail closed: an answer they cannot give shows less, never more.

What you see, why, and what to do
What you seeWhyWhat to do
Every row is shown, unmasked, on a table with rules.The Trino catalog is not in nuna.opa.catalogs.Map it.
No rows, and every column NULL.The user's token is missing or was refused, the table was not found, or the user holds nothing on it. Or the user is in no group with a rule.Check the extra credential, the mapping, and the table's rules.
Every masked column in a query reads NULL.Trino asked about only some of the table's masked columns in one call.See the note below the table.
503 The user's token could not be checked; retry laterThe identity provider's signing keys could not be fetched.Retry; check the server can reach the issuer's JWKS URI.
403 Forbidden: client trino is not a registered trusted engine, so it may not act for another userTrino's client is not registered.Register it as in the first step.
403 only platform operators run the trusted-engine registryYou are not a platform operator.Ask one to register Trino.
400 Not a trusted issuer: …The registration names an issuer the server does not trust.Use an issuer from nuna.security.issuers.

Not documented yet: when Trino asks about only some of a table's masked columns in one call. No test or document says.
