Maintenance worker settings

Point the maintenance worker at the catalog and its stores, set its nightly window, and turn on compaction and the disaster recovery verifier.

For platform operators

The maintenance worker is its own program, nuna-maintenance, installed by its own chart. It signs in to the catalog as a maintenance principal (the catalog's nuna.security.maintenance-principals), reads the catalog's maintenance work list, and reaches storage with its own identity, the only one a profile's delete policy lets delete. Every setting here is read once, at start-up.

The token

The worker gets its bearer token one of two ways: from a file, read again whenever it changes, or by the OAuth 2 client-credentials grant against the identity provider's token endpoint. Set exactly one of file and endpoint: nuna.maintenance.token: set exactly one of file and endpoint. Without any token setting the worker stops with nuna.maintenance.token: set file, or endpoint, client-id and client-secret.

Storage

The worker's own identity on each store, keyed by a name of the deployment's choosing. Where on each store it lists and deletes, the catalog's storage profiles say at each scan: the worker serves a profile with the store whose kind and endpoint are the profile's. Everything else about the store comes from here alone. With no store the worker stops with nuna.maintenance.storage names no store: the worker lists and deletes table files with its own storage identity.

Compaction

In the cleanup window the worker runs one Kubernetes Job per table that needs compacting, each running Spark's rewrite_data_files signed in as the worker and stopped at the window's end. Compaction is off unless image is set.

Disaster recovery verifier

The verifier checks each table's and view's newer versions in the DR store, a read-only replica of a store: the same buckets and paths on another endpoint, as site replication keeps them. It is off unless a replica is named, and the worker then logs No DR replica named (nuna.maintenance.dr.replicas): the DR verifier is off.

Example

config:
  nuna:
    maintenance:
      catalog-uri: http://nuna-catalog.nuna.svc:8181/
      cleanup-window:
        start: "01:00"
        end: "05:00"
        zone: Europe/London
      token:
        endpoint: https://idp.example/realms/data/protocol/openid-connect/token
        client-id: nuna-maintenance
        scope: catalog
      storage:
        onprem:
          kind: ceph
          endpoint: https://s3.example
          ca-bundle: /etc/nuna/storage-ca/ca.crt
      compaction:
        image: registry.example/nuna-spark:3.5
        namespace: nuna-compaction
secrets:
  existingSecret: nuna-maintenance-secrets
storageCaConfigMap:
  name: storage-ca

The Secret holds the client secret and the store keys under their setting names, such as nuna.maintenance.token.client-secret and nuna.maintenance.storage.onprem.secret-access-key.
