Governance and refs settings

Bound purges and audit reads, name retention classes, declare the recovery window, set default maintenance and limit branches and tags.

For platform operators

These settings bound how fast purges and audit reads run on each server, name the retention classes, declare the database's point-in-time recovery window, set the maintenance policy every catalog starts from, and limit each catalog's branches and tags.

nuna.governance

nuna.governance.purges-per-minute

Purges this server accepts per minute, from all maintenance principals together. One more is refused with 429, Retry-After: 60 and More than N purges in a minute; retry later. At least 1: nuna.governance.purges-per-minute must be at least 1.

60
Environment variable
NUNA_GOVERNANCE_AUDITREADSPERMINUTE
Helm
config.nuna.governance.audit-reads-per-minute
Read by
the server
Restart
Needed

Reads of an object's audit records this server accepts per minute from one caller: the principal its token names, or the end user a trusted engine acts for. One more is refused with 429, Retry-After: 60 and More than N audit reads in a minute by caller; retry later.

The console reads once each time an object's Audit tab opens, its count changes or Refresh is pressed, so the default, one a second, never holds a person back. At least 1.

nuna.governance.pitr-window

Type
duration
Default
7d
Environment variable
NUNA_GOVERNANCE_PITRWINDOW
Helm
config.nuna.governance.pitr-window
Read by
the server
Restart
Needed

The database's point-in-time recovery window, as the deployment declares it: the server cannot read it from the database. Orphan removal touches only files older than it, so a database restored within it never names a removed file. Keep the database's own backups at least this long.

nuna.rest.drop-retention must be longer, or the server stops with nuna.rest.drop-retention (value) must be longer than nuna.governance.pitr-window (value), so a database restored within its PITR window never holds a live table whose files were purged.

nuna.governance.maintenance-defaults

Type
map of policy key to value
Default
empty: the built-in values below
Environment variable
set in YAML: the keys hold dots and hyphens
Helm
config.nuna.governance.maintenance-defaults
Read by
the server
Restart
Needed

The maintenance policy every catalog starts from, over the built-in values. Catalogs, namespaces and tables may set their own over it. The server checks the defaults at start-up as it checks a policy pushed through the API, and refuses to start on an unknown key (Unknown maintenance policy key key; known keys: …), on a snapshot-expiry.max-snapshot-age below minimum-snapshot-age, and on an orphan-removal.older-than not longer than pitr-window.

No test binds these dotted keys from YAML. Spring Boot drops the dots of a map key unless it is written in brackets, so write each key as "[snapshot-expiry.enabled]", as in the example below; the plain form has not been checked.

Maintenance policy keys
KeyBuilt-in valueWhat it sets
snapshot-expiry.enabledfalseWhether old snapshots expire.
snapshot-expiry.max-snapshot-ageP5DSnapshots older than this expire.
snapshot-expiry.min-snapshots-to-keep1Snapshots kept whatever their age.
orphan-removal.enabledfalseWhether files no snapshot reaches are removed.
orphan-removal.older-thanP14DOnly files older than this are removed.
compaction.enabledfalseWhether small data files are compacted.
compaction.target-file-size-bytes536870912The size compaction writes to.
compaction.min-input-files5A table needs at least this many small files to be compacted.
compaction.delete-file-ratio0.3Or this share of delete files.
manifest-rewrite.enabledfalseWhether manifests are rewritten.
manifest-rewrite.min-manifests100A table needs at least this many manifests.

A freeze turns off all four kinds of maintenance on what it covers; a hold turns off snapshot expiry and orphan removal.

nuna.refs

Limits and expiry for each catalog's branches and tags. A branch's creation, each commit on it and each renewal set its expiry branch-idle-expiry ahead, never past branch-max-life from its creation. Tags never expire.

Type
integer

100

Helm

The most tables and views one branch may change, so that a merge moves them in one transaction. A commit that would take a branch past it is refused with 400, and a merge of more with 409. At least 1.

Example

config:
  nuna:
    governance:
      pitr-window: 14d
      retention-classes:
        regulatory:
          minimum-snapshot-age: 30d
      maintenance-defaults:
        "[snapshot-expiry.enabled]": "true"
        "[orphan-removal.enabled]": "true"
        "[orphan-removal.older-than]": P21D
    rest:
      drop-retention: 30d
    refs:
      max-branches: 20
