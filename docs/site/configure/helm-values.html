Helm chart values

Every value of the three charts, nuna-catalog, nuna-maintenance and nuna-audit-tables, with its default and what it does.

For platform operators

nuna installs as three Helm charts, each one release per deployment: nuna-catalog (the servers), nuna-maintenance (the maintenance worker) and nuna-audit-tables (the audit tables writer). Each chart is version 0.1.0 with appVersion 0.1.0-SNAPSHOT. Each takes its program's settings under config and its secrets under secrets, and refuses to render without the settings its program cannot start without.

A change to config or secrets.values restarts the pods, since the chart stamps a checksum of each on the pod. A change inside a Secret named by secrets.existingSecret does not: run kubectl rollout restart on the deployment.

nuna-catalog

A Deployment of replicaCount servers, updated one at a time (maxSurge: 1, maxUnavailable: 0), a Service, a headless Service the servers find each other through, a PodDisruptionBudget and optionally an Ingress. The container listens on port 8181, and its start-up, readiness and liveness probes read /ui/config.json. Before it stops, each pod pauses 5 seconds so the Service stops sending it requests. The chart sets nuna.health.peers itself, to the headless Service, as the environment variable NUNA_HEALTH_PEERS.

nuna-maintenance

A Deployment of one worker, replaced rather than rolled (Recreate), so two workers never run together. With compaction on, the chart also makes, in the Jobs' namespace, a Role letting the worker's service account get and create Jobs and create Secrets (and ConfigMaps, when a store names a ca-bundle), its RoleBinding, and the Jobs' service account; and only then mounts the worker's service account token.

Refusals

  • config.nuna.maintenance.catalog-uri is required: the catalog the worker maintains
  • config.nuna.maintenance.storage needs at least one store: the worker's own storage identity on it
  • config.nuna.maintenance.storage.name.prefixes: the worker reads its prefixes from the catalog's storage profiles at each scan; name the store's kind and endpoint instead
  • config.nuna.maintenance.storage.name.kind is required, and the same for endpoint
  • config.nuna.maintenance.cleanup-window.start is required, and the same for end and zone
  • config.nuna.maintenance.compaction.namespace is required when compaction runs: a namespace for the Jobs alone, created beforehand
  • config.nuna.maintenance.compaction.namespace must not be the release's namespace
  • config.nuna.maintenance.compaction.job-service-account is required when compaction runs

nuna-audit-tables

A Deployment of one writer, replaced rather than rolled (Recreate): a second writer would only fail the first's commits. With the source otlp, the chart also makes a Service in front of the receiver (port name otlp-http), and the pod is ready once the port takes connections. The chart has no telemetry values.

Refusals

  • config.nuna.audit-tables.catalog-uri is required: the catalog the writer writes to
  • config.nuna.audit-tables.principal is required: the writer's own principal id, whose records it leaves out
  • config.nuna.audit-tables.token.endpoint is required: the identity provider's token endpoint
  • config.nuna.audit-tables.token.client-id is required: the writer's client id there
  • config.nuna.audit-tables.kafka.bootstrap-servers is required for the source kafka: the Kafka cluster holding the audit topic
