Database settings

Name the catalog's database and how the server reaches it, and read what the start-up self-check refuses.

For platform operators

One deployment uses one database, named by nuna.database.backend when it is installed. PostgreSQL, CockroachDB and Oracle are reached through Spring Boot's spring.datasource.* keys; MongoDB through nuna.database.mongodb.uri, with no JDBC database at all. Before it takes a request, and before it changes anything in the database, every server runs the database's self-check and refuses to start while it reports a finding.

Which database holds the catalog:

  • postgresql: PostgreSQL or CockroachDB, through spring.datasource.*. The server tells the two apart by what version() answers, and runs the self-check of the one it finds.
  • oracle: Oracle single instance, RAC or Exadata, through spring.datasource.*.
  • mongodb: a MongoDB replica set, through nuna.database.mongodb.uri. The server then leaves out Spring Boot's DataSource, so it needs no spring.datasource.url.

Choose it once, when the deployment is installed: nuna has no way to move a catalog from one database to another. The first server of a release migrates the database's schema after the self-check passes.

The self-check findings the server starts despite, each by its code, such as [pg.no-sync-standby]. Each finding allowed is logged as a warning at start-up, The catalog's database is unsafe, allowed by nuna.database.allow-unsafe: code: detail, and shown in the Store panel of the console's health page. Any finding not named still stops the server.

Only a test or demo database on a single node needs it. Leave it empty in production. The codes are in Self-check findings.

The MongoDB replica set's connection string. It must name the catalog's database and set socketTimeoutMS, which bounds every wait on the database. It carries the password, so it belongs in the deployment's Secret, never in config.

The server refuses to start without it when the backend is mongodb, with nuna.database.mongodb.uri is required when nuna.database.backend is mongodb; without a database name, with nuna.database.mongodb.uri must name the catalog's database, as in mongodb://h1,h2,h3/catalog?replicaSet=rs0&socketTimeoutMS=30000; and without a positive socketTimeoutMS, with nuna.database.mongodb.uri must set socketTimeoutMS, which bounds every wait on the database. The messages never quote the string, since it holds a password.

The catalog's MongoDB role needs clusterMonitor besides readWrite on the database, so that the self-check can read the replica set's configuration.

Spring datasource keys

These are Spring Boot's own keys. nuna reads them on PostgreSQL, CockroachDB and Oracle, and ignores them on MongoDB. Spring Boot's other spring.datasource.hikari.* keys, such as the pool size, keep Spring Boot's defaults: nuna sets none of them.

Where the catalog's database is:

  • PostgreSQL and CockroachDB: jdbc:postgresql://host:port/database, with any TLS parameters after a ?.
  • Oracle: jdbc:oracle:thin:@//host:port/service. The service is the catalog's own, with COMMIT_OUTCOME = TRUE (Transaction Guard) and no FAILOVER_TYPE, so the driver never replays a transaction. The self-check refuses any other.

The URL must reach the primary. The catalog chart refuses to render without it unless the backend is mongodb: config.spring.datasource.url is required: the catalog's database.

Self-check findings

Each server checks the database's safety settings before it migrates or serves. A finding stops the server with The catalog's database is unsafe, so the server does not start, followed by each finding's code and detail, and the advice to make the database safe or, for a test or demo database only, to name each code in nuna.database.allow-unsafe. A self-check that cannot run, because the role lacks a right it needs, stops the server too, and the server has changed nothing in the database. The codes, as the code reports them:

Self-check finding codes
CodeDatabaseReported when
pg.sync-commit-offPostgreSQLsynchronous_commit is neither on nor remote_apply.
pg.no-sync-standbyPostgreSQLsynchronous_standby_names is empty, or no standby streams in sync or quorum state. The role needs pg_monitor to see the standbys.
pg.fsync-offPostgreSQLfsync or full_page_writes is off.
pg.commit-cancel-timeoutPostgreSQLstatement_timeout or idle_in_transaction_session_timeout is not 0: a timeout can cancel a COMMIT's wait for the standby.
crdb.replicasCockroachDBA zone holding the catalog's database or one of its tables has fewer than 3 voting replicas.
crdb.fsync-offCockroachDBkv.raft_log.synchronization.unsafe.disabled is not false, or the role cannot read it (it needs VIEWCLUSTERSETTING).
crdb.read-committed-offCockroachDBA READ COMMITTED transaction runs at another isolation: set sql.txn.read_committed_isolation.enabled to true.
ora.no-data-guardOracleNo Data Guard standby is synchronized in MAXIMUM AVAILABILITY or MAXIMUM PROTECTION.
ora.no-transaction-guardOracleThe catalog's service has no COMMIT_OUTCOME = TRUE.
ora.commit-replayOracleThe service has a FAILOVER_TYPE that replays transactions (Application Continuity).
ora.commit-nowaitOracleCOMMIT does not wait for its redo to be written (COMMIT_WAIT is set to something other than WAIT).
ora.linguistic-sortOracleNLS_SORT is not BINARY. The driver sets the session's language from the JVM's locale and NLS_SORT follows it; an English locale gives BINARY.
ora.journal-job-downOracleThe scheduler job JOURNAL_PARTITIONS_AHEAD cannot run, or its last runs failed, so a month's first commit would create its own journal partition.
mongo.not-replica-setMongoDBThe server is not a replica set member.
mongo.too-few-votersMongoDBThe replica set has fewer than 3 voting data-bearing members.
mongo.weak-write-concernMongoDBThe default write concern is not majority, or majority writes are not journaled (writeConcernMajorityJournalDefault).

Examples

PostgreSQL with a password

config:
  spring:
    datasource:
      url: jdbc:postgresql://db.example:5432/nuna
      username: nuna_catalog
  nuna:
    database:
      backend: postgresql
secrets:
  existingSecret: nuna-catalog-secrets

The Secret holds the password under the key spring.datasource.password:

kubectl -n nuna create secret generic nuna-catalog-secrets \
  --from-literal=spring.datasource.password="$DB_PASSWORD"

PostgreSQL with a client certificate

The role has no password. The chart mounts the Secret named in databaseTls.secretName at /etc/nuna/db-tls, apart from the config tree, and the URL names its three files. The key is PKCS #8 DER, and the driver refuses a key file others can read, which is why the chart mounts the files with mode 0440.

config:
  spring:
    datasource:
      url: jdbc:postgresql://db.example:5432/nuna?sslmode=verify-full&sslrootcert=/etc/nuna/db-tls/ca.crt&sslcert=/etc/nuna/db-tls/client.crt&sslkey=/etc/nuna/db-tls/client.pk8
      username: nuna_catalog
databaseTls:
  secretName: nuna-catalog-db-tls

Oracle

config:
  spring:
    datasource:
      url: jdbc:oracle:thin:@//db.example:1521/nuna_catalog
      username: nuna_catalog
      hikari:
        data-source-properties:
          oracle.jdbc.ReadTimeout: 60000
  nuna:
    database:
      backend: oracle

MongoDB

Leave spring.datasource empty and put the connection string in the Secret:

config:
  nuna:
    database:
      backend: mongodb
secrets:
  existingSecret: nuna-catalog-secrets
kubectl -n nuna create secret generic nuna-catalog-secrets \
  --from-literal=nuna.database.mongodb.uri="mongodb://$MONGO_USER:$MONGO_PASSWORD@db1.example,db2.example,db3.example/nuna?replicaSet=rs0&socketTimeoutMS=60000"
