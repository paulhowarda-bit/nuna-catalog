SingleStore in the demo

Watch SingleStore's change feed copy the brokerage world's orders into an Iceberg table through nuna, and load an Iceberg table from nuna back into SingleStore.

Demo only For developers

Before you begin

  • The demo is running (Start, stop and reset the demo).
  • SingleStore is on: demo/demo.sh ss. It needs 1,536 MiB free on the cluster; turn metrics off first if the script refuses.
  • For the change feed to have something to copy, the brokerage world is on too: demo/demo.sh gen (The brokerage world).

What SingleStore holds

DatabaseWhat is in it
lakeTables loaded from Iceberg: xetra_trades and countries once, fx_rates continuously, and the view xetra_daily.
brokerageThe brokerage world's orders, order_events, routes and executions; the feeds' receipts in lake_commits; and, while Kafka is off, a table for each of the world's other feeds.
nuna_m8Copies of Spark's tables from catalog engines, once demo/demo.sh engines has run.

In SingleStore Studio, gary, oscar and presenter administer SingleStore, ana reads, writes, creates, alters and drops in every database, and stella reads every database.

Watch the change feed into Iceberg

The pipeline brokerage.brokerage_orders_to_lake reads the changes to brokerage.orders and commits them to the Iceberg table brokerage.trading.orders in lakehouse every 15 seconds while there are changes: new rows as data files, and equality deletes on the primary key for updated and deleted rows. The pipeline brokerage.brokerage_oms_to_lake copies order_events, routes and executions the same way, append-only. Both write through nuna as user singlestore, with credentials nuna vends.

  1. Open SingleStore Studio.

    Go to https://localhost:8183, type a person's username, such as ana, and select Sign in with SAML.

  2. Read the feed's receipts.

    Each commit to Iceberg leaves a receipt in brokerage.lake_commits:

    SELECT source_table, kind, rows_written, keys_deleted, committed_at
FROM brokerage.lake_commits
ORDER BY committed_at DESC LIMIT 10;

  3. Find the commits in the console.

    Open the console at https://localhost:8181/ui/, go to brokerage.trading.orders in catalog lakehouse and select History. Each receipt is a snapshot there.

Each commit stores SingleStore's offsets in the Iceberg snapshot, so a feed that stops resumes from Iceberg with nothing copied twice or skipped.

Load from Iceberg into SingleStore

The pipeline lake.fx_rates_feed loads each append to the Iceberg table markets.fx.rates into lake.fx_rates. To add a rate:

demo/demo.sh rate

The lake writer job appends a EURUSD rate through nuna. Kafka Connect and the generator stop while the job runs and start again after.

The rate reaches SingleStore within a few seconds

Run SELECT * FROM lake.fx_rates ORDER BY as_of DESC LIMIT 5; in Studio: the new rate is the first row. In the console, markets.fx.rates has a new snapshot.

Rules of the change feed

  • No pipeline may load a feed's copy, such as brokerage.trading.orders, back into SingleStore: its rows would come back. The feed checks every minute and stops with an error naming the pipeline if one does.
  • ALTER and DROP on brokerage.orders wait while the feed runs. Stop the pipeline first; a column added at the end is added to the Iceberg copy when the feed starts again.
  • If SingleStore no longer holds its log from where the copy ended, the feed takes a new snapshot of the table and replaces the copy. That commit's kind is resnapshot, and gap_after holds the offsets it could not continue from.
  • An append-only feed stops at the first UPDATE or DELETE, before that transaction reaches Iceberg.

If it fails

What you seeWhyWhat to do
ss refuses: … MiB of the cluster's memory, and only … MiB is free: demo/demo.sh metrics stop firstThe cluster has less than 1,536 MiB free.Turn metrics off, then run demo/demo.sh ss again.
The pipeline is in state Error.The feed met a table change it cannot follow, or found a pipeline loading its copy.Fix the cause, then START PIPELINE brokerage.brokerage_orders_to_lake. It resumes from the offsets in Iceberg.
Writes in SingleStore stop.Pipeline extractors reserve SingleStore's memory: each change feed 384 MB (pipelines_cdc_java_heap_size), each Iceberg data worker 128 MB.Stop a pipeline you do not need.
lake_commits has no new rows.The world is quiet outside New York's trading hours, or gen is off.Check demo/demo.sh brokerage logs for quiet until.
Studio refuses root.Studio takes no passwords.Sign in as a person, or use demo/demo.sh sql.
