Demo users and sign-in

The demo has five people who sign in through Keycloak, and accounts with tokens only, for the services that run the demo. This page lists each, its groups and privileges, and how each page of the demo signs them in.

Demo only For developers

People

Each person signs in to Keycloak, realm nuna on port 8180, with a password demo/demo.sh up made on this machine. The passwords are in ~/.nuna-demo/people; the same password signs each person in to the CDC leg's databases.

Privileges include the weaker ones

Modify includes write, and write includes select. The demo grants each group on the catalog, so a privilege covers every namespace and table in it.

Groups and their grants

up writes the catalog grants into the server's database on every start. The roles grant admin and platform operator come from the server's settings (grant-admin-groups, platform-operator-groups), and the server grants the audit table's readers and writers itself at startup. demo-quants' grants are made by gary through the management API, on a new lake.

Signing in to each page

A person signs in once, through Keycloak, and the console, kafbat, CloudBeaver, SingleStore Studio and Grafana ask no password after that. To change user, select Sign out in the console or Logout in CloudBeaver, which end Keycloak's session too, or use a private window.

PageAddressHow it signs in
The consolehttps://localhost:8181/ui/Select Sign in with the demo's Keycloak and sign in to Keycloak. In the demo the sign-in page also takes a token: select Developer sign-in, paste one under Paste a bearer token. and select Use this token.
CloudBeaverhttps://localhost:8185Keycloak. Each person's connections sign in as them: to nuna through Trino with their own token, and to the CDC leg's databases.
kafbathttps://localhost:8182Keycloak. oscar administers it and reads its audit log; ana, gary and stella administer topics but only read the catalog's (nuna.*), Kafka Connect's, the brokerage world's and those starting with _.
SingleStore Studiohttps://localhost:8183Type the username only, then select Sign in with SAML. Studio takes no passwords, so root cannot sign in there.
Grafanahttps://localhost:8188Keycloak. oscar and presenter administer it; everyone else views. Its local admin signs in at /login?disableAutoLogin=true.
Silo's consolehttps://localhost:8184Select Keycloak. ana browses and downloads the warehouse bucket's files, read-only; oscar sees the server's health, metrics, logs and traces, no data; presenter is Silo's administrator.
Keycloakhttps://localhost:8180/admin/nuna/console/oscar reads realm nuna's users, groups, sessions and events. /admin changes the realm, as user admin.

Keycloak keeps users and sessions in memory and imports realm nuna from demo/k8s/keycloak-realm.json each time its pod starts, so a change made in its admin console lasts only until the pod restarts. Its access tokens last 3,600 seconds and a sign-in session at most 36,000 seconds.

Tokens

up and demo/demo.sh token mint a token for each person and each service account, signed with the demo's own key, issuer https://idp.demo/nuna, valid for 7 days. They mint again when the tokens expire within an hour. The tokens are in ~/.nuna-demo/tokens/user.jwt, and the time they expire in ~/.nuna-demo/tokens/expires.txt.

export TOKEN=$(cat ~/.nuna-demo/tokens/ana.jwt)
curl -s --cacert ~/.nuna-demo/tls/ca.crt --ssl-revoke-best-effort \
  -H "Authorization: Bearer $TOKEN" "https://localhost:8181/v1/config?warehouse=lakehouse"

These tokens work only in the demo

The server trusts the demo's signing key because the demo configures it to. A token minted this way means nothing to a server set up with your own identity provider.
