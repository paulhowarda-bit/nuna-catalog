demo.sh reference

demo/demo.sh starts, stops and inspects the local demo. Run it from Git Bash in the root folder of a checkout.

Demo only For developers

Synopsis

demo/demo.sh up | down | wipe | status | token | engines | rate | sql
demo/demo.sh gen | ss | kafka | metrics [stop]
demo/demo.sh cdc [stop | reset]
demo/demo.sh brokerage logs
demo/demo.sh psql | sqlplus | cockroach [user]

Any other subcommand, or a second word a subcommand does not take, prints the usage and exits with status 2.

Run in the repository's main checkout, up, engines, gen, ss, kafka, cdc, metrics, token and rate run from ~/.nuna-demo/checkout, a second checkout held at the commit the main checkout's HEAD named when they started (The commit the demo runs). Only one of them runs at a time; another prints another demo.sh (pid n) is running from …/checkout: wait for it to end and stops.

gen, ss, kafka and cdc start images that up builds. Before the first up they print demo/demo.sh up first: it builds the images the switches start.

Subcommands

demo.sh up

Builds the jars and images from the checkout, starts the core, writes the sample data on a new lake with the catalog's branch dev and tag sample, turns gen, ss, kafka and metrics back on if they were on, and prints how to sign in with the tokens. It prints building commit commit subject as it starts. Start the demo lists its steps.

demo.sh down

Stops and deletes everything but the data. The volumes of PostgreSQL, Silo, Kafka, SingleStore, CloudBeaver, the CDC leg and the metrics stack stay, and the next up carries on from them. A running CDC leg pauses, as cdc stop pauses it.

demo.sh wipe

Runs down, then deletes namespace nuna-demo with its volumes: all the demo's data. It keeps the signing key, tokens, Keycloak's keys, the passwords and the certificates in ~/.nuna-demo. The next up writes fresh sample data.

demo.sh status

Shows the deployments, pods and services in nuna-demo, the switches, and the state of each of Kafka Connect's connectors and its tasks. It changes nothing.

Switches: gen off, ss off, kafka on, metrics off, cdc off

Kafka Connect's connectors (the connector's state, then its tasks'):
  Kafka Connect is off (it runs while gen or cdc is on)

demo.sh token

Prints the addresses, how to sign in and the tokens again. When the tokens expire within an hour, the token-minting code changed, or Trino's token is missing, it mints them again, then replaces SingleStore's running pipelines and restarts Trino, CloudBeaver, Kafka Connect and the brokerage world's generator so they use the new tokens. Its output starts with The demo runs commit commit subject.

demo.sh gen, demo.sh gen stop

gen turns on the brokerage world: its tables and its live generator, which writes through Kafka with Kafka Connect, or SingleStore, or both, as the switches kafka and ss say. It turns kafka on if neither is. gen stop turns the generator off, and Kafka with it unless the CDC leg runs. See The brokerage world.

demo.sh ss, demo.sh ss stop

ss turns on SingleStore, with its sample databases and change feeds; the generator's orders go to it again. It asks for 1,536 MiB and is refused when the cluster has less free, with demo/demo.sh metrics stop first as the hint. ss stop turns it off; its databases stay on its volume, and the generator carries on through Kafka, turning kafka on if it is off. See SingleStore in the demo.

demo.sh kafka, demo.sh kafka stop

kafka lets the generator use Kafka: every feed but the orders goes through Kafka and its sink. kafka stop stops Kafka; the generator carries on through SingleStore, with a change feed per table into brokerage.singlestore, or stops if ss is off. While the CDC leg runs, kafka stop is refused: the CDC leg needs Kafka: demo/demo.sh cdc stop first.

demo.sh metrics, demo.sh metrics stop

metrics starts an OpenTelemetry collector, Prometheus, Tempo and Grafana on port 8188 with nuna's dashboards, and has the server and the maintenance worker send their metrics and traces to it. It needs 1,472 MiB free: 704 MiB for its pods and 768 MiB for the server's new pod, which starts before the old one stops. Otherwise it is refused with metrics asks for … MiB of the cluster's memory, and only … MiB is free: turn a switch off first (demo/demo.sh ss stop frees 1.5 GB). With the demo down it only sets the switch, so the next up starts it. metrics stop turns it off; its series, traces and Grafana's database stay on their volumes. See Kafka, metrics and traces in the demo.

demo.sh cdc, cdc stop, cdc reset

cdc starts the CDC leg: PostgreSQL, Oracle and CockroachDB, captured by Debezium through Kafka Connect into Iceberg history tables. It starts Kafka and stops Trino, the maintenance worker and the generator while it runs, and the audit table writer too when SingleStore is on. The first run pulls Oracle's image, about 5 GB. A leg run before carries on from its kept databases.

cdc stop pauses the leg, keeping its databases, offsets, topics and history tables, and starts Trino and the writer again, and the generator if gen is on; Kafka stops unless gen is on. cdc reset deletes the leg with its databases' volumes, so the next cdc starts it anew. See Change data capture in the demo.

demo.sh engines

Runs the engine matrix (Spark, Kafka Connect, PyIceberg and SingleStore) against the demo's catalog engines, with Gradle. It stops Trino, CloudBeaver, Kafka Connect, the generator and the maintenance worker while it runs, and starts them again. The results are in catalog-tests-engines/build/engines-run/results.txt.

demo.sh rate

Appends an FX rate to the Iceberg table markets.fx.rates, with the lake writer Job; SingleStore loads it into lake.fx_rates. Kafka Connect and the generator stop while the Job runs and start again after. While the CDC leg runs it is refused: the CDC leg is running, and the lake writer does not fit beside it: demo/demo.sh cdc stop first.

demo.sh sql

Opens a SingleStore prompt as root. When SingleStore is off it prints SingleStore is off: demo/demo.sh ss first and exits with status 1.

The prompt opens database brokerage; USE lake moves to the other.

demo.sh brokerage logs

Follows the generator's log, starting from its last 100 lines.

demo.sh psql, sqlplus, cockroach [user]

Open a prompt on one of the CDC leg's databases, inside its pod. Each takes a user name; a person signs in with their Keycloak password, and sqlplus and cockroach print user's password is in …/people first.
