Start, stop and reset the demo

Start the demo with up, stop it with down keeping its data, or delete its data with wipe. This page also covers the demo's certificate, the commit it runs and the memory it needs.

Demo only For developers

Before you begin

You need the programs Run nuna on your laptop lists, and Git Bash open in the root folder of your checkout. The script has no separate stop or reset command: down stops the demo, wipe resets it, and each switch has its own stop (demo.sh reference).

Start the demo

demo/demo.sh up

up does these things, in order, and prints a line starting with == for each:

  1. It starts the Podman machine and the kind cluster nuna, creating the cluster from deploy/kind/cluster.yaml the first time. Creating it fails if another program holds one of the ports 8180 to 8188.
  2. It builds the server, maintenance worker, audit tables writer, change-feed connector and brokerage world from the checkout with Gradle, without running tests, and builds the demo's images with Podman. When nothing changed, Gradle and Podman do nothing. It puts each image on the cluster's node unless the node has it; the cluster never pulls an image itself.
  3. It mints the demo users' tokens if they expire within an hour, and makes once per machine the passwords, keys and certificates it keeps in ~/.nuna-demo.
  4. It starts PostgreSQL, Keycloak and Silo, installs the server with the Helm chart deploy/helm/nuna-catalog, and checks that the server signs in to its database only by client certificate over TLS.
  5. It grants the demo groups their privileges, registers Trino as a trusted engine and starts the audit tables writer.
  6. On a new lake only, it writes the sample tables, sets their governance, and makes the catalog's branch dev and tag sample. It turns maintenance on in catalog lakehouse's policy and sets the row filters and column masks of markets.desks.positions on every start.
  7. It turns the switches ss, kafka, gen and metrics back on if they were on, starts Trino and CloudBeaver, then the maintenance worker last, and prints how to sign in.

A step that sets data up (the branch and tag, the maintenance policy, the row and column rules) never stops up when it fails: up says so and the next up tries again.

Stop the demo

demo/demo.sh down

down uninstalls the Helm releases and deletes everything in namespace nuna-demo except the data: its volume claims, the configmaps demo-seeded and cdc-begun, and the namespace itself. It deletes the compaction Jobs' namespace nuna-demo-compaction. A running CDC leg is paused, as demo/demo.sh cdc stop pauses it. The next up carries on from the data: the lake, its branch and tag, the governance, the audit table, SingleStore's databases and the brokerage world as they were.

Reset the demo

wipe deletes all the demo's data

It deletes the namespace nuna-demo with its volumes: every table, grant, audit record and metric the demo held. It cannot be undone.

demo/demo.sh wipe

wipe runs down, then deletes the namespace with its volumes. The next up writes fresh sample data. Deleting the cluster with kind delete cluster --name nuna deletes the data too.

HTTPS and the certificate

Every port is HTTPS. The front door, an nginx pod, ends TLS with one certificate and passes each request on inside the cluster. The certificate is in ~/.nuna-demo/tls:

FileWhat it is
tls.crtThe server certificate, then any intermediate certificates (PEM).
tls.keyIts private key (PEM, not encrypted).
ca.crtThe certificates of the authority that issued it (PEM), which the script's own calls trust.
ca.keyThe demo authority's key, when the script made the authority.

When the folder is empty, up makes a certificate authority of the demo's own, which can vouch only for localhost and 127.0.0.0/8, and a certificate from it for localhost, valid for 397 days and made again a month before it ends. Trust the authority once in your Windows user's trust store:

certutil -user -addstore Root ~/.nuna-demo/tls/ca.crt

To serve the demo under another name, put that name's certificate, key and issuing authority in the folder and set NUNA_DEMO_HOST to the name; every address the demo prints then uses it. With curl in Git Bash, add --ssl-revoke-best-effort beside --cacert ~/.nuna-demo/tls/ca.crt: Git Bash's curl checks certificates with Windows, which refuses an authority that names no revocation list.

The commit the demo runs

Run in the repository's main checkout, up builds one commit: the checkout's HEAD when it starts. It runs from ~/.nuna-demo/checkout, a second checkout of the repository that it keeps at that commit and locks, so commits made in the main checkout during the run change nothing in it. engines, gen, ss, kafka, cdc, metrics, token and rate do the same. One of them at a time holds that checkout; another is refused until it ends. Run from any other checkout, the script runs from that checkout's files as they are.

up prints building commit commit subject as it starts, and its last lines, like demo/demo.sh token's, start with The demo runs commit commit subject.

Resources

The demo is sized for a Podman machine with 8 GB of memory, whose kind node offers about 7.6 GB to pods. With the core running and no switch on, the pods asked for 4,210 MiB. The switches add their own: SingleStore asks for 1,536 MiB, the metrics stack 704 MiB, and Kafka, kafbat, Kafka Connect and the brokerage world's generator 1,792 MiB together. The script refuses metrics and ss when the node lacks the room, and stops services for the commands that need theirs: up, rate and engines stop Kafka Connect and the generator while they run, and cdc stops Trino, the maintenance worker and the generator.

demo.sh status shows what runs

demo/demo.sh status lists the deployments, pods and services in nuna-demo, a Switches: line such as gen off, ss off, kafka on, metrics off, cdc off, and the state of Kafka Connect's connectors.
