Iceberg REST: tables

List, create, load, commit to, drop, rename, register and unregister tables, get their storage credentials and report metrics, under /v1/{prefix}/namespaces/{namespace}/tables.

These are the standard's table endpoints. This page gives what nuna adds or does differently: who may call each, the storage credentials it vends, its ETags, the rules it puts on commits, and its refusals. Engines call these routes for you; read this page to understand what an engine sees. The examples use curl with NUNA and TOKEN set as Use the APIs with curl describes.

  • Tables and views share one set of names in a namespace, matched without regard to case.
  • The catalog assigns every table's location, under the catalog's storage profile. A location in a request is ignored.
  • Every write takes an Idempotency-Key (Idempotency keys) and is audited.
  • Through a branch, commits change only the branch; creates, drops, renames and registrations happen on main only. Through a tag, only reads are served (The prefix).

Read tables

GET /v1/{prefix}/namespaces/{namespace}/tables

Lists the tables in a namespace, sorted by name. Through a branch or tag, it lists the tables that ref holds. Paging works as Paging describes.

Needs describe on the namespace

Parameters

NameInTypeRequiredDescription
pageTokenquerystringNoEmpty for the first page; then the last answer's next-page-token.
pageSizequeryintegerNoTables per page, with pageToken only. Default 100, at most 1000.

Responses

StatusWhen
200{"identifiers": [{"namespace": […], "name": "…"}, …], "next-page-token": token or null}.
404Namespace does not exist: namespace (NoSuchNamespaceException), also when you hold nothing on it.

Example

curl -sS "$NUNA/v1/trading/namespaces/equities/tables" -H "Authorization: Bearer $TOKEN"
{
  "identifiers": [
    {"namespace": ["equities"], "name": "fills"},
    {"namespace": ["equities"], "name": "orders"}
  ],
  "next-page-token": null
}

GET /v1/{prefix}/namespaces/{namespace}/tables/{table}

Loads a table's metadata and, unless asked not to, short-lived storage credentials for its files. Through a branch or tag, the metadata is that ref's version of the table. Each load is recorded as a read.

The credentials reach only the table's own location. A caller who may write to the table gets credentials that read and write; anyone else gets read-only ones. No credentials the catalog vends can delete objects: deletion is the maintenance worker's. A caller writing through a branch gets credentials and write paths for the branch's own folder, table location/branches/ref id/data and …/metadata. See Credential vending.

Needs select on the table Audited

Parameters

NameInTypeRequiredDescription
snapshotsquerystringNoall (the default) or refs, for only the snapshots a branch or tag of the table names. Anything else answers 400, Invalid snapshot mode: value.
referenced-byquerystringNoThe view the table is read through. It changes only the ETag.
X-Iceberg-Access-DelegationheaderstringNovended-credentials asks for credentials. none alone asks for none: the answer then has no config credentials and no storage-credentials. Without the header, credentials are vended.
If-None-MatchheaderstringNoAn ETag from an earlier load, a list of them, or *.

Responses

StatusWhen
200The load table result, with an ETag header.
304If-None-Match names the current ETag: nothing changed. No body; the ETag header is repeated.
400Invalid snapshot mode: value.
403You hold something on the table but not select; or the table is regulated and has no classification yet (table table is in a regulated area and has no classification; it is closed until it is classified); or it carries a row/column policy and you are not a trusted engine (table table has a row/column policy; only a trusted engine that enforces it gets storage access); or its location is outside the storage profile.
404Table does not exist: namespace.table (NoSuchTableException), also when you hold nothing on it.
503Storage credentials cannot be issued now; retry later (ServiceUnavailableException): the object store's token service failed.

Create and change tables

POST /v1/{prefix}/namespaces/{namespace}/tables

Creates a table. The catalog assigns its location, table root/uuid under the catalog's storage profile, whatever the request says. The format version defaults to 3, the highest supported. With "stage-create": true, the answer is the new table's metadata and credentials, and the table exists only once a commit to it creates it.

Needs create on the namespace Audited

Body

The standard's create-table request: name and schema are required; partition-spec, write-order, stage-create and properties are optional, and location is ignored. The property format-version picks the format version.

Responses

StatusWhen
200The load table result of the new table.
400The request is not valid; the prefix names a branch or tag; or Table format version n is not supported; the highest is 3.
403You hold something on the namespace but not create.
404Namespace does not exist: namespace.
409Table already exists: namespace.table, or View with same name already exists: … when a view has the name (AlreadyExistsException).

Example

curl -sS -X POST "$NUNA/v1/trading/namespaces/equities/tables" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: create-fills-1" \
  -d '{
    "name": "fills",
    "schema": {"type": "struct", "schema-id": 0, "fields": [
      {"id": 1, "name": "fill_id", "type": "long", "required": true},
      {"id": 2, "name": "symbol", "type": "string", "required": true},
      {"id": 3, "name": "quantity", "type": "long", "required": true},
      {"id": 4, "name": "filled_at", "type": "timestamptz", "required": true}
    ]}
  }'

POST /v1/{prefix}/namespaces/{namespace}/tables/{table}

Commits a change to a table: the standard's requirements, which must all hold, and updates, which are applied in one step. A commit to a table that does not exist on main creates it, which is how a staged create finishes. Through a branch, it changes the branch's version of a table the branch holds.

The privilege needed depends on the updates. A commit made only of add-snapshot, remove-snapshots, set-snapshot-ref, remove-snapshot-ref, set-statistics, remove-statistics, set-partition-statistics and remove-partition-statistics needs write: that is a data change. Anything else, such as a schema, partition spec or property change, needs modify.

If another commit lands first and the requirements still hold, the server applies the change again on top, up to four attempts within two seconds. See Commits.

Needs write or modify on the table Audited

Body

The standard's commit-table request: requirements and updates. nuna refuses these updates:

  • A set-location to anywhere but the assigned location: Location is assigned by the catalog: assigned, not asked.
  • Setting write.data.path, write.metadata.path, write.object-storage.path or write.folder-storage.path outside the table's location: Property name must lie within the table location ….
  • Changing encryption.key-id: Property encryption.key-id is fixed when the table is created.
  • A snapshot stamped further ahead of the catalog's clock than the allowed skew: Snapshot id is stamped time, more than skew ahead of the catalog clock.
  • Removing snapshots of a table under a legal hold, or snapshots younger than the deployment's minimum snapshot age (nuna.governance.minimum-snapshot-age, or the table's retention class).

Responses

StatusWhen
200Committed: the load table result after the commit.
400The request is not valid, the prefix names a tag, or one of the refused updates above.
403You lack the privilege the updates need; Table table is under legal hold: its snapshots cannot be removed; Snapshot id of table is younger than age, the deployment's minimum snapshot age: it cannot be removed yet; Writes to table are frozen for DR reconcile: reason; or engine client named no end user, and writes to regulated areas must name one.
404Table does not exist: …; through a branch, also for a table the branch does not hold.
409A requirement failed (CommitFailedException), or Commit lost to concurrent commits n times; the table changed too often to apply it. Load the table again and redo the change.
500Commit … may or may not have been applied: … (CommitStateUnknownException). Load the table to see, or repeat with the same Idempotency-Key.
503Catalog store unavailable; nothing was applied: …, with Retry-After: 2.

DELETE /v1/{prefix}/namespaces/{namespace}/tables/{table}

Drops a table. Every drop is soft: purgeRequested is ignored, the files stay, and the table can be restored until it is purged, nuna.rest.drop-retention (default 30 days) after the drop. See Drop, restore and purge.

Needs modify on the table Audited

Parameters

Responses

StatusWhen
204Dropped.
400The prefix names a branch or tag.
403You lack modify; Table table is under a legal hold and cannot be dropped; or the table is frozen for DR reconcile.
404Table does not exist: ….

Renames a table, or moves it to another namespace of the same catalog. Its files do not move.

Needs modify on the table and create on the target namespace Audited

Body

destinationbodyobjectYesThe same form, the table after.

Responses

StatusWhen
204Renamed.

404The table or the target namespace does not exist.

Example

curl -sS -X POST "$NUNA/v1/trading/tables/rename" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \

Register and unregister

POST /v1/{prefix}/namespaces/{namespace}/register

Registers a table whose metadata file already exists, inside the catalog's storage profile. Registering the file a dropped or unregistered table left behind brings that table back, in the namespace it left. See Register an existing table.

Needs create on the namespace Audited

Body

NameInTypeRequiredDescription
namebodystringYesThe table's name.
metadata-locationbodystringYesThe metadata file.
overwritebodybooleanNoMust not be true when the name is taken: overwrite is refused.

Responses

StatusWhen
200The load table result.
400The file is outside the storage profile, or was written by a branch; or Registering over an existing table (overwrite) is not supported: …. Commit to the table, or drop or unregister it first; a register would skip the commit rules and the table's journal.
404The namespace or the metadata file does not exist.
409The name is taken, or another table or view holds the file's table UUID (AlreadyExistsException); or the dropped table's restore window has closed (UndropWindowClosedException).

POST /v1/{prefix}/namespaces/{namespace}/tables/{table}/unregister

Removes a table from the catalog and leaves its files where they are. The answer gives the last metadata file, so the table can be registered again.

Needs modify on the table Audited

Responses

StatusWhen
200{"metadata-location": "…", "metadata": {…}}.
400The prefix names a branch or tag.
403You lack modify; table table is in a regulated area and cannot be unregistered; a steward removes the regulated flag first; or table table has a row/column policy and cannot be unregistered; a steward removes the flag first.
404Table does not exist: ….

FieldTypeDescription

ETags

A load's ETag changes when the metadata file, the snapshot mode, referenced-by, the credentials, the labels or the ref change. When the credentials it would carry expire within nuna.rest.credential-refresh-margin (default 5 minutes), the answer has no ETag, so the next load gets fresh ones. Credentials last nuna.storage.credential-lifetime, 30 minutes by default.
