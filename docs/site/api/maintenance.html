Maintenance

Ask for a table's compaction or orphan scan, read the maintenance nights, the estate, the neediest tables and the worker's scans, check readiness and storage setup, and set the maintenance policy, under /management/v1/maintenance and each catalog's paths.

The maintenance worker does the work; these routes let you ask for it, see what it did and decide what it may do (see Maintenance). The routes only the worker calls, to claim work and report jobs, scans and assessments, are on Worker endpoints. Table health is on Health. The examples use curl with $NUNA and $TOKEN set as curl shows.

Requests and figures

POST /management/v1/catalogs/{catalog}/namespaces/{namespace}/tables/{table}/maintenance/requests

Asks the worker to compact a table, or to scan it for orphan files, in its next window. Asking again while a request waits returns the waiting request.

Needs modify on the table Audited

Parameters

NameInTypeRequiredDescription
namespacepathstringYesThe namespace levels joined by %1F.
jobbodystringYescompaction or orphan-scan.

Responses

StatusWhen
202{"job", "requested-by", "requested-at", "state", "started-at"}; state is waiting or started. The request is audited as a governance record with the attribute maintenance-request.
400Field job is compaction or orphan-scan.
403You hold no modify on the table, or it is frozen: Table equities.fills is frozen for DR reconcile: reason.
404The table is not there, or you hold nothing on it.
409Table equities.fills is under legal hold: nothing may be removed, so no compaction runs, or The maintenance policy of table equities.fills does not run compaction: compaction.enabled is false, set by built-in (MaintenanceNotAllowedException).

Example

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/namespaces/equities/tables/fills/maintenance/requests" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"job": "compaction"}'

GET /management/v1/maintenance/nights

Reads the figures of recent maintenance nights, newest first. The catalog keeps 32 nights. A job's table is named only when you may select it.

Needs a signed-in caller

Parameters

NameInTypeRequiredDescription

Responses

StatusWhen

Setup

GET /management/v1/catalogs/{catalog}/maintenance/readiness

Says whether the worker can maintain the catalog, in four steps, each done, missing, refused or unknown:

  • grant: a group the worker's token last carried holds write on the catalog.
  • storage: the worker's own storage identity covers every allowed prefix of the catalog's storage profile.
  • store: the store let the worker list beneath every prefix and refused none of its deletes.
  • policy: the catalog's maintenance policy turns at least one job on.

The first three come from the newest scan the worker reported. Before any scan, or while the newest reported no storage, they are unknown. Names (groups, profile, prefixes) go only to callers who may modify the catalog or manage its grants, and to platform operators; names says whether you got them. A read writes no audit record.

Needs describe on the catalog, or a platform operator

Responses

StatusWhen
200{"catalog", "names", "scanned-at", "reported-at", "grant", "storage", "store", "policy"}.
403You hold something in the catalog but not describe.
404You hold nothing in the catalog, or it does not exist.

Example

curl -sS "$NUNA/management/v1/catalogs/trading/maintenance/readiness" -H "Authorization: Bearer $TOKEN"
{
  "catalog": "trading",
  "names": true,
  "scanned-at": "2026-11-26T02:00:04.871Z",
  "reported-at": "2026-11-26T02:00:04.871Z",
  "grant": {"state": "done", "groups": [{"group": "platform-maintenance", "write": true}]},
  "storage": {
    "state": "done",
    "profile": "onprem",
    "endpoint": "https://s3.example",
    "prefixes": [
      {"prefix": "s3://trading-lake/tables", "covered-by": {"kind": "ceph", "endpoint": "https://s3.example", "prefix": "s3://trading-lake/tables"}}
    ]
  },
  "store": {
    "state": "done",
    "deletes-since": "2026-11-26T02:00:01.204Z",
    "prefixes": [

}

GET /management/v1/maintenance/storage-setup

Says what a platform operator sets up outside the catalog so the worker can maintain each storage profile's catalogs: the profile's catalogs and prefixes, what the worker last reported reaching there, the worker's settings for the store when it reported no identity there, and the delete policies with the commands that apply them. The catalog applies none of it and never holds or gives a key of the worker's: the settings mark where the key goes. Catalogs are named, never a namespace, table or view. A read writes no audit record.

Needs a platform operator

Responses

StatusWhen
200{"scanned-at", "reported-at", "profiles": [{"name", "catalogs", "kind", "endpoint", "prefixes", "maintenance-principal", "worker", "store"}]}. worker.state is reported with the prefixes reached, or gives the worker's settings for the store (store, yaml, secret). store.state is generated, with policies each holding apply-as, the policy and its commands, or unprotected, with the setting to add: nuna.storage.profiles.name.maintenance-principal.
403You are not a platform operator.

Example

curl -sS "$NUNA/management/v1/maintenance/storage-setup" -H "Authorization: Bearer $TOKEN"

Not documented yet: every field of the worker settings block (store, yaml, secret, note) and when each appears. The demo's worker reached its store, so the block was not shown.

GET /management/v1/maintenance/delete-policies

Gives the object store policies that leave deleting to the worker alone, for a platform operator to apply once per store. The catalog never applies them itself: its own credentials would then need the right to undo them. On AWS S3 and Ceph, one bucket policy per bucket holds every profile's prefixes there. On MinIO, which enforces no bucket policy on signed requests, each profile gets two user policies: one for every user but the worker (except), the catalog's own included, and one for the worker (to). A profile with no maintenance-principal is listed in unprotected.

Needs a platform operator

Responses

StatusWhen
200{"policies": [{"apply-as": "bucket-policy" | "user-policy", "endpoint", "bucket", "profiles", "except" | "to", "policy"}], "unprotected": [profile, …]}. policy is the policy document, as a JSON string.
403You are not a platform operator.

Example

curl -sS "$NUNA/management/v1/maintenance/delete-policies" -H "Authorization: Bearer $TOKEN"

GET /management/v1/maintenance/storage-prefixes

Gives the worker, at each scan, the prefixes of every storage profile that names a maintenance-principal: each profile's name, kind, endpoint and allowed prefixes, never a credential. The worker matches a profile to one of its own store identities by kind and endpoint.

Internal Needs a maintenance principal

Responses

StatusWhen
200{"profiles": [{"name", "kind", "endpoint", "prefixes"}]}, with kind in lower case.
403only a maintenance principal may call listMaintenanceStoragePrefixes, audited.

Example

curl -sS "$NUNA/management/v1/maintenance/storage-prefixes" -H "Authorization: Bearer $TOKEN"
{"profiles": [{"name": "onprem", "kind": "ceph", "endpoint": "https://s3.example", "prefixes": ["s3://trading-lake/tables"]}]}

Maintenance policy

A maintenance policy turns the worker's jobs on and sets their limits. It may be set on a catalog, namespace, table or view; the nearest level that sets a key wins, then nuna.governance.maintenance-defaults, then the built-in value. Guardrails override all of them: a legal hold turns snapshot expiry and orphan removal off, a DR freeze turns every job off, and snapshot ages are raised to the minimum snapshot age. The policy routes are served on all four paths; object stands for any of them.

Maintenance policy keys, in the code's order
KeyBuilt-in valueValue
snapshot-expiry.enabledfalsetrue or false
snapshot-expiry.max-snapshot-ageP5DISO-8601 duration, at least the minimum snapshot age
snapshot-expiry.min-snapshots-to-keep1whole number, at least 1
orphan-removal.enabledfalsetrue or false
orphan-removal.older-thanP14DISO-8601 duration, longer than the database PITR window (nuna.governance.pitr-window, default 7 days)
compaction.enabledfalsetrue or false
compaction.target-file-size-bytes536870912whole number, at least 1
compaction.min-input-files5whole number, at least 1
compaction.delete-file-ratio0.3decimal number above 0
manifest-rewrite.enabledfalsetrue or false
manifest-rewrite.min-manifests100whole number, at least 1

GET /management/v1/catalogs/{catalog}/maintenance-policy

Also served on the namespace, table and view paths. Reads the keys the object sets itself, the value that applies for every key with where it came from, and the configured retention classes.

Needs describe on the object

Responses

StatusWhen
200{"target", "policy": {own keys}, "resolved": {key: {"value", "source", "reason"}}, "retention-classes": [{"name", "minimum-snapshot-age"}]}. source is built-in, default, kind:id of the level that sets it, or guardrail, which gives a reason such as under legal hold: nothing may be removed or frozen for DR reconcile.
404The object is not there, or you hold nothing on it.

Example

curl -sS "$NUNA/management/v1/catalogs/trading/namespaces/equities/maintenance-policy" \
  -H "Authorization: Bearer $TOKEN"

PUT /management/v1/catalogs/{catalog}/maintenance-policy

Also served on the namespace, table and view paths. Replaces the object's own policy with the keys in the body: keys it leaves out are inherited. Values the guardrails forbid outright are refused.

Needs modify on the object Audited

Request body

{"compaction.enabled": true, "snapshot-expiry.enabled": true, "snapshot-expiry.max-snapshot-age": "P7D"}

Responses

StatusWhen
200The policy is set; the answer is the attribute, with provenance management-api.
400
  • A maintenance policy sets at least one key; DELETE removes the policy
  • Unknown maintenance policy key x; known keys: […], Maintenance policy key x needs a plain value
  • key is true or false, not y, key is an ISO-8601 duration such as P7D or PT12H, not y, key is a whole number, not y, key is a decimal number such as 0.3, not y, and the bounds (must be positive, must be at least 1, must be above 0)
  • snapshot-expiry.max-snapshot-age must be at least d, the minimum snapshot age
  • orphan-removal.older-than must be longer than the database PITR window w, so a restore never needs a removed file
403You hold something on the object but not modify.
404The object is not there, or you hold nothing on it.

Example

curl -sS -X PUT "$NUNA/management/v1/catalogs/trading/namespaces/equities/maintenance-policy" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"compaction.enabled": true}'
