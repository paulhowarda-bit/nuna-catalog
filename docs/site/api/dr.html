Disaster recovery

Read how far each table is behind its DR watermark, and reconcile a catalog from storage after a recovery, under /management/v1.

For platform operators

A table's DR watermark is the newest version of its main pointer whose every file the verifier found in the DR store (see Disaster recovery). Both routes here need a platform operator. Freezing and lifting a freeze are on Governance; the verifier's own routes are on Worker endpoints. The examples use curl with $NUNA and $TOKEN set as curl shows.

Endpoints

GET /management/v1/dr/watermarks

Lists, by id, every table and view behind its DR watermark, in every catalog: its pointer's version, its watermark (null when the verifier has passed none of its versions), how many versions behind it is, and its lag, the time since its oldest unverified commit.

Needs a platform operator

Parameters

pageSizequeryintegerNoDefault 50, at most 200.

400Invalid page token: x.

POST /management/v1/catalogs/{catalog}/dr-reconcile

The reconcile-from-storage step of recovery. It walks every active table of the catalog forward along its metadata-log chain, taking each step only when storage holds every file it adds, data included, and stopping at the first that lacks one. Without apply it only reports. With apply, tables under a DR freeze move through their proven files and any tip named in accept. With accept-archived, the audit archive is read whole first, and a tip whose swap it records is taken too; an accept entry the archive contradicts stops its table and is reported.

With rewind, the step goes the other way: each table and view whose pointer is above its DR watermark, or that has none, is reported with the commits a rewind gives up, and with apply, each one under a DR freeze moves back to its watermark in one commit. Branches and tags are never walked or rewound: the answer only reports those whose files storage lacks.

Needs a platform operator

Parameters

NameInTypeRequiredDescription
applybodybooleanNotrue to move frozen tables; default false, a report only.
acceptbodyarray of stringsNoMetadata locations to accept as a table's tip.
accept-archivedbodybooleanNoAlso accept tips whose swap the audit archive records.
rewindbodybooleanNoMove back to the watermarks instead. Takes neither accept nor accept-archived.

Request body

{"apply": false, "accept": [], "accept-archived": false}

Responses

StatusWhen
200Forward: {"tables", "refs", "unknown-locations", "unused-accepts", "contradicted-accepts"}; unknown-locations lists table locations in storage that no table or view of any catalog holds, to register by name. Rewind: {"tables", "views"}, each with the commits it gives up.
400rewind takes neither accept nor accept-archived: it moves each table back to its DR watermark, never forward.
403You are not a platform operator.
409accept-archived without an audit archive (ArchiveNotConfiguredException).
500The archive failed its integrity check (ArchiveIntegrityException). Nothing was applied.
503The archive cannot be read now (ServiceUnavailableException). Nothing was applied.

Example

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/dr-reconcile" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"apply": false}'
