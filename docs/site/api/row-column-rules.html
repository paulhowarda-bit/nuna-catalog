Row and column rules

Set, remove and list each group's row filter and column masks on a table, export every rule, and read what your own rules do to you, under /management/v1/catalogs/{catalog}/row-column-rules.

A rule belongs to one group on one table. The server hands the rules to trusted engines, which apply them (see Row filters and column masks and OPA decisions). A rule needs the table's row-column-policy flag, which a data steward sets through the governance attributes, so writing the rules and flagging the table take two people. The examples use curl with $NUNA and $TOKEN set as curl shows.

No filter or mask expression reaches a caller without manage-grants. Every refusal is audited, and a refusal on a table you hold nothing on is answered as if the table did not exist.

POST /management/v1/catalogs/{catalog}/row-column-rules

Sets a group's rule on a table: a row filter, column masks or both. It replaces the rule the group had. Each expression must parse as Trino SQL, checked with Trino's own parser; a subquery, and so another table, is allowed. A rule names only columns the table's current schema has. Afterwards, a schema change that renames or drops a column a rule names is refused until the rule changes, since a mask is served by its column's name and a rename would unmask it.

To act only on the rule as you read it, send its version back in If-Match. When the group's rule is at another version, or has been removed, the answer is 412 and nothing is written. Without If-Match, the set replaces whatever rule there is.

Needs manage-grants on the table or above it Audited

Parameters

NameInTypeRequiredDescription
catalogpathstringYesThe catalog's name.
If-MatchheaderstringNoThe rule's version from the list, in double quotes: "1795706330054677". A weak tag, a list or * is refused.
tablebodyobjectYes{"type": "table", "namespace": [levels], "name": name}. Only a table: views take no rules.
groupbodystringYesThe group the rule is for.
row-filterbodystringNoAn SQL predicate: the group sees the rows it admits. At most 4000 characters, with no NUL. To give the group every row, set it to true.
column-masksbodyobjectNoColumn name to SQL expression: the group sees the expression's value instead of the column's. At most 500 columns, each expression at most 4000 characters.

Request body

{
  "table": {"type": "table", "namespace": ["equities", "daily"], "name": "positions"},
  "group": "trading-analysts",
  "row-filter": "desk = 'EQ'",
  "column-masks": {"trader": "'***'"}
}

Responses

StatusWhen
204The group has the rule, whether this request set it or it was set already.
400

The body is wrong. The messages include:

  • A rule filters rows (row-filter), masks columns (column-masks), or both; to give a group every row, set row-filter to true
  • A rule names its table: {"table": {"type": "table", "namespace": [...], "name": ...}}
  • Row filters and column masks go on tables only
  • A rule names the group it is for; rules never go to individuals …
  • row-filter is an SQL expression, as text, and row-filter is at most 4000 characters, with no NUL
  • column-masks is an object from column name to SQL expression, column-masks names each column it masks, A rule masks at most 500 columns
  • The mask of trader is not a Trino SQL expression: at line 1, column 5, …, with Trino's own message
  • column-masks names traderx, which the table's current schema does not have; a mask names a column of the table as it is now …, and the same for row-filter
  • If-Match names the rule's version as the list gives it, as "<version>"
403You hold no manage-grants on the table or above it; or you belong to the group: no one sets row filters or column masks for a group they belong to: group, audited with the reason separation-of-duties.
404The catalog or table is not there, or you hold nothing on it.
409The table is not flagged: The table does not carry the row/column-policy flag; a steward sets it first, so that only trusted engines read its files … (NotFlaggedException).
412The rule is not the one If-Match named: The rule for group is at version n, not the one named in If-Match; another change came first: list the rules again, or The rule for group named in If-Match has been removed; list the rules again (PreconditionFailedException).
500The catalog may or may not have finished setting the rule; repeat it: …. Repeating a set is safe.

Example

curl -sS -i -X POST "$NUNA/management/v1/catalogs/trading/row-column-rules" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H 'If-Match: "1795706330054677"' \
  -d '{"table": {"type": "table", "namespace": ["equities", "daily"], "name": "positions"},
       "group": "trading-analysts", "row-filter": "desk = '"'"'EQ'"'"'",
       "column-masks": {"trader": "'"'"'***'"'"'"}}'
HTTP/1.1 204
X-Request-ID: 8c2e4a6b0d1f4e3a9b5c7d9e1f2a3b4c

POST /management/v1/catalogs/{catalog}/row-column-rules/remove

Removes a group's rule from a table. If-Match works as for a set.

Needs manage-grants on the table or above it Audited

Parameters

NameInTypeRequiredDescription
catalogpathstringYesThe catalog's name.
If-MatchheaderstringNoThe rule's version, in double quotes.
tablebodyobjectYesThe table, as for a set.
groupbodystringYesThe group whose rule to remove.

Responses

StatusWhen
204The rule is gone.
400The body is wrong, as for a set.
403You hold no manage-grants on the table or above it, or you belong to the group.
404The group has no rule on the table: No row filter or column masks for group on the table (NotFoundException). Or the catalog or table is not there.
412The rule is not at the version If-Match named.
500The database did not say whether the removal happened. Repeating it answers 404 if it did.

Example

curl -sS -i -X POST "$NUNA/management/v1/catalogs/trading/row-column-rules/remove" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"table": {"type": "table", "namespace": ["equities", "daily"], "name": "positions"},
       "group": "data-stewards"}'

GET /management/v1/catalogs/{catalog}/row-column-rules

Lists every group's rule on one table, with the expressions and each rule's version.

Needs manage-grants on the table or above it

Parameters

NameInTypeRequiredDescription
catalogpathstringYesThe catalog's name.
namespacequerystringYesOne namespace level. Repeat it for each level, in order.
namequerystringYesThe table's name.

Responses

StatusWhen
200{"table": securable, "rules": [rule, …]}. The table is named as on the Grants page.
400The table is not named fully.
403You hold no manage-grants on the table or above it.
404The catalog or table is not there, or you hold nothing on it.

    },

GET /management/v1/catalogs/{catalog}/row-column-rules/export

Exports every rule in the catalog, for access reviews: tables in the catalog's walk order, each table's rules by group. A caller with manage-grants on the catalog gets the expressions. An audit reader, who holds select on the audit tables' catalog, gets each rule without them, for any catalog. Anyone else is refused.

Needs manage-grants on the catalog, or select on the audit catalog

Parameters

NameInTypeRequiredDescription
catalogpathstringYesThe catalog's name.

Responses

StatusWhen
200{"catalog", "expressions", "rules": [exported rule, …]}. expressions says whether the rules carry their expressions.
403You hold no manage-grants on the catalog and are not an audit reader.
404The catalog does not exist, or you hold nothing in it and are not an audit reader.

Example

The response below is cut to one rule.

curl -sS "$NUNA/management/v1/catalogs/trading/row-column-rules/export" \
  -H "Authorization: Bearer $TOKEN"
{
  "catalog": "trading",
  "expressions": true,
  "rules": [
    {
      "table": {
        "kind": "table",
        "id": "5f6a7b8c-9d0e-4f1a-8b2c-3d4e5f6a7b8c",
        "path": ["equities", "daily", "positions"]
      },
      "group": "trading-analysts",
      "rows": "filtered",
      "masked-columns": ["trader"],
      "row-filter": "desk = 'EQ'",
      "column-masks": {"trader": "'***'"},
      "set-by": "sam",
      "set-at": "2026-11-25T15:18:50.054677Z"
    }
  ]
}

GET /management/v1/catalogs/{catalog}/namespaces/{namespace}/tables/{table}/row-column-rules/mine

Says what your own groups' rules do to you on a table, combined as Trino receives them, without the expressions. You see the rows any of your groups' filters admit, and a rule of yours with no filter admits every row. A column is masked only when every one of your rules masks it. When the table has rules and none is for your groups, you get no rows.

Needs select on the table

Parameters

NameInTypeRequiredDescription
catalogpathstringYesThe catalog's name.
namespacepathstringYesThe namespace levels joined by the unit separator, %1F in a URL: equities%1Fdaily.
tablepathstringYesThe table's name.

Responses

StatusWhen
200{"target": {"kind", "id"}, "flagged", "rows", "masked-columns"}: whether the table carries the flag, all, filtered or none, and the columns masked for you.
403You hold something on the table but not select.
404The table is not there, or you hold nothing on it.

Example

curl -sS "$NUNA/management/v1/catalogs/trading/namespaces/equities%1Fdaily/tables/positions/row-column-rules/mine" \
  -H "Authorization: Bearer $TOKEN"
{
  "target": {"kind": "table", "id": "5f6a7b8c-9d0e-4f1a-8b2c-3d4e5f6a7b8c"},
  "flagged": true,
  "rows": "filtered",
  "masked-columns": ["trader"]
}

GET /management/v1/catalogs/{catalog}/namespaces/{namespace}/tables/{table}/schema

Reads a table's current schema and properties, flagged or not, so a mask editor can pick its columns. It gives no location, snapshot or file and no storage credentials, so it is not storage access. The server reads the metadata file itself and checks it against the hash it recorded.

Needs describe on the table Audited

Parameters

catalog, namespace and table, as for your own rules.

Responses

StatusWhen
200{"target": {"kind", "id"}, "format-version", "schema", "properties"}. schema is the Iceberg schema that current-schema-id names. The read is audited as a read record.
403You hold something on the table but not describe.
404The table is not there, or you hold nothing on it.
500The metadata file of the table does not match its recorded hash (MetadataIntegrityException).

Example

The schema below is cut to two fields.

curl -sS "$NUNA/management/v1/catalogs/trading/namespaces/equities%1Fdaily/tables/positions/schema" \
  -H "Authorization: Bearer $TOKEN"
{
  "target": {"kind": "table", "id": "5f6a7b8c-9d0e-4f1a-8b2c-3d4e5f6a7b8c"},
  "format-version": 2,
  "schema": {
    "type": "struct",
    "schema-id": 0,
    "fields": [
      {"id": 1, "name": "desk", "required": false, "type": "string"},
      {"id": 2, "name": "trader", "required": false, "type": "string"}
    ]
  },
  "properties": {"write.parquet.compression-codec": "zstd"}
}

Objects

Rule

FieldTypeDescription
groupstringThe group the rule is for.
row-filterstringThe SQL predicate. Absent when the rule masks columns only.
column-masksobjectColumn name to SQL expression, keyed by the column as the table's current schema spells it. Empty when the rule filters only.
set-bystringThe subject who set it.
set-atstringWhen, as an ISO-8601 instant.
versionintegerThe rule's version, for If-Match.

Exported rule

FieldTypeDescription
tableobject{"kind", "id", "path"}: path is the namespace levels and the table's name.
groupstringThe group the rule is for.
rowsstringfiltered when the rule has a row filter, otherwise all.
masked-columnsarray of stringsThe columns the rule masks.
row-filter, column-masksOnly when expressions is true; row-filter only when the rule has one.
set-by, set-atstringWho set the rule, and when.
