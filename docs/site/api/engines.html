Engines

Register, list and remove trusted engines: the shared engines whose clients may act for the people who run queries through them, under /management/v1/engines.

For platform operators

The registry names an engine by the issuer of its tokens and its client id. A registered engine is a trusted engine, and the server lets it do three things an ordinary client cannot:

  • It may name the person it acts for in the X-Nuna-End-User and X-Nuna-End-User-Groups headers, beside its own token.
  • It may vouch for a person's own token with its own in X-Nuna-Engine-Authorization, as Trino does when it forwards each user's token.
  • Acting as itself, it sees every catalog, so it can read a catalog's configuration with its own token.

A client that is not registered and names an end user is refused with 403. See Authentication for how the server checks each header. The examples use curl with $NUNA and $TOKEN set as curl shows.

Only a platform operator may call these endpoints: a member of a group in nuna.security.platform-operator-groups. Any other caller gets 403 ForbiddenException with the message only platform operators run the trusted-engine registry, and the refusal is audited as a denial with the reason no_privilege.

Endpoints

Engine registry endpoints
MethodPathWhat it does
GET/management/v1/enginesLists every registered engine.

GET /management/v1/engines

Lists every registered engine, sorted by issuer and then by client id. A read writes no audit record.

Needs a platform operator

Responses

StatusWhen
200{"engines": [engine, …]}, each as in Engine.
403You are not a platform operator.

Example

curl -sS "$NUNA/management/v1/engines" -H "Authorization: Bearer $TOKEN"
{
  "engines": [
    {
      "issuer": "https://idp.example/realms/data",
      "client-id": "trino-prod",
      "end-user-claim": "sub",
      "flags": []
    }
  ]
}

PUT /management/v1/engines

Registers an engine. Sending the same issuer and client id again replaces the registration's end-user-claim and flags; sending it unchanged also answers 204. The issuer must be one the server trusts, listed in nuna.security.issuers. The client id is matched against the claim that issuer's client-id-claim setting names in the engine's token.

Needs a platform operator Audited

Parameters

NameInTypeRequiredDescription
issuerbodystringYesThe exact iss value of the engine's tokens.
client-idbodystringYesThe engine's client id at that issuer. Not blank.
end-user-claimbodystringNoThe token claim the engine names its end users by. Default sub.
flagsbodyarray of stringsNoSingle words, each without a comma or white space. Default none.

The server stores end-user-claim and flags, lists them and puts them in the audit record. In this version no authorization decision reads either of them: the end user comes from the X-Nuna-End-User header or from the token in Authorization, as Authentication describes.

Request body

{
  "issuer": "https://idp.example/realms/data",
  "client-id": "trino-prod",
  "end-user-claim": "sub",
  "flags": []
}

Responses

StatusWhen
204The engine is registered.
400
  • An engine is named by its issuer and client-id: issuer is missing, or client-id is missing or blank.
  • Not a trusted issuer: issuer.
  • a flag is one word, got 'flag'.
  • A JSON body is needed, or Invalid JSON body: ….
403You are not a platform operator.
500The change may or may not have been applied; repeat it: … (ServiceFailureException): the database's answer was lost. Send the same request again.

A registration is audited as a nuna.catalog.engine record with the action REGISTERED.

Example

curl -sS -X PUT "$NUNA/management/v1/engines" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"issuer": "https://idp.example/realms/data", "client-id": "trino-prod"}'

DELETE /management/v1/engines

Removes an engine. From then on its clients may no longer name an end user, and a request that tries is refused with 403.

Needs a platform operator Audited

Parameters

NameInTypeRequiredDescription
issuerquerystringYesThe engine's issuer, URL-encoded.
client-idquerystringYesThe engine's client id.

Responses

StatusWhen
204The engine is removed.
400A parameter is missing: Required parameter 'issuer' is not present.
403You are not a platform operator.
404No such engine: client-id of issuer (NotFoundException).
500The change may or may not have been applied; repeat it: … (ServiceFailureException).

A removal is audited as a nuna.catalog.engine record with the action REMOVED.

Example

curl -sS -X DELETE \
  "$NUNA/management/v1/engines?issuer=https%3A%2F%2Fidp.example%2Frealms%2Fdata&client-id=trino-prod" \
  -H "Authorization: Bearer $TOKEN"
