Iceberg REST: configuration and tokens

GET /v1/config tells a client which catalog its warehouse names, the prefix to use and the endpoints the server serves there; /v1/oauth/tokens refuses, since nuna issues no tokens.

An Iceberg client calls /v1/config once, when it starts, with the warehouse it was given. It then sends every catalog request under /v1/{prefix} and uses only the endpoints the answer lists. The examples use curl with NUNA and TOKEN set as Use the APIs with curl describes.

GET /v1/config

Answers the configuration for one catalog, or for one branch or tag of it. The warehouse is a catalog's name, or catalog@ref for a branch or tag. The answer's overrides.prefix is the prefix the client sends from then on, and endpoints lists every route the server serves through that prefix.

Needs any grant in the catalog

Parameters

NameInTypeRequiredDescription
warehousequerystringNoA catalog's name, or catalog@ref. When it is missing or blank, the server uses nuna.rest.default-warehouse; with that unset too, the request is refused.

Responses

StatusWhen
200The configuration follows.
400No warehouse was named and none is set: Missing query parameter warehouse, and this server has no default warehouse (BadRequestException).
401The token is missing or was not accepted.
404The catalog does not exist, or you hold nothing in it: The given warehouse does not exist: warehouse (NoSuchWarehouseException). The same type, with (catalog catalog has no branch or tag ref) added, when the ref does not exist or the branch is past its expiry.

Example

curl -sS "$NUNA/v1/config?warehouse=trading@dev" -H "Authorization: Bearer $TOKEN"
{
  "defaults": {},
  "overrides": {"prefix": "trading@dev"},
  "endpoints": [
    "GET /v1/{prefix}/namespaces",
    "GET /v1/{prefix}/namespaces/{namespace}",
    "HEAD /v1/{prefix}/namespaces/{namespace}",
    "GET /v1/{prefix}/namespaces/{namespace}/tables",
    "GET /v1/{prefix}/namespaces/{namespace}/tables/{table}",
    "HEAD /v1/{prefix}/namespaces/{namespace}/tables/{table}",
    "POST /v1/{prefix}/namespaces/{namespace}/tables/{table}/metrics",
    "GET /v1/{prefix}/namespaces/{namespace}/tables/{table}/credentials",
    "GET /v1/{prefix}/namespaces/{namespace}/views",
    "GET /v1/{prefix}/namespaces/{namespace}/views/{view}",
    "HEAD /v1/{prefix}/namespaces/{namespace}/views/{view}",
    "POST /v1/{prefix}/namespaces/{namespace}/tables/{table}",
    "POST /v1/{prefix}/namespaces/{namespace}/views/{view}",
    "POST /v1/{prefix}/transactions/commit"
  ],
  "idempotency-key-lifetime": "PT24H"
}

POST /v1/oauth/tokens

The standard's token endpoint. nuna answers every call to it, with any method and without a token, with the same OAuth error, so that a client configured to ask the catalog for a token learns where to get one. /v1/config does not list it. See Get a token.

Responses

StatusWhen
400Always: {"error": "unsupported_grant_type", "error_description": "This catalog does not issue tokens. Get an access token from the organisation's identity provider and send it as a bearer token."}. The words the organisation's identity provider come from nuna.rest.identity-provider. This body is the OAuth error form, not the catalog's error body.

Example

curl -sS -X POST "$NUNA/v1/oauth/tokens" -d "grant_type=client_credentials"
{
  "error": "unsupported_grant_type",
  "error_description": "This catalog does not issue tokens. Get an access token from the organisation's identity provider and send it as a bearer token."
}

The prefix

The prefix names a catalog and, after an @, a branch or tag of it: trading is the catalog's main line, as trading@main is, and trading@dev is branch dev. Catalog names and ref names never hold an @, so a prefix reads one way. Names match without regard to case; the prefix answered is the catalog's name, and the ref's, in their stored lower-case form. See Branches and tags.

What the prefix allows:

  • On main, every endpoint below.
  • On a branch, the reads, plus committing to a table, replacing a view and committing a transaction. A branch's commits change only the branch. Creates, drops, renames, registrations and namespace changes happen on main only.
  • On a tag, the reads only: a tag is read-only.

Iceberg clients read the endpoint list and refuse an unlisted write themselves, before it reaches the server. A client that sends one anyway gets 400, for example createTable is refused on tag eod-2026-11-25 of catalog trading: a tag is read-only.
