Audit

Read an object's audit records, search a catalog's audit feed, count recent records, and check the archive and one record's place in its hash chain, under /management/v1.

Every route here reads the audit trail; none changes it. The records themselves are described in Audit record format, and what the trail is in The audit trail. The examples use curl with $NUNA and $TOKEN set as curl shows.

Two kinds of caller read audit. A caller with manage-grants on an object reads that object's records. An audit reader, who holds select on the catalog that holds the audit tables (nuna.audit.tables.catalog), reads the feed, the summary, the archive and the chain for any catalog.

Each caller may make at most nuna.governance.audit-reads-per-minute (default 60) object, feed, chain and uncached summary reads a minute on each server. Beyond that the answer is 429 TooManyRequestsException, More than 60 audit reads in a minute by caller; retry later, with Retry-After: 60; that answer is not audited.

GET /management/v1/catalogs/{catalog}/audit

Also served on the namespace, table and view paths. Reads the newest records about one object, as the trail holds them. The server reads the audit tables when nuna.audit.tables.catalog is set; otherwise it reads the audit topic in Kafka, scanning back at most 20,000 messages.

Needs manage-grants on the object or above it Audited

Parameters

NameInTypeRequiredDescription
limitqueryintegerNoMost records. Default 50, from 1 to 200.

Responses

200From the tables: {"target", "source": "table", "records", "complete", "table": {"name", "snapshot-id", "committed-at"}}; complete is true when no older record exists. From the topic: {"target", "source": "topic", "records", "window": {"topic", "partition", "earliest-offset", "from-offset", "to-offset", "complete", "scan-limit": 20000}}. Each record is the CloudEvent as the trail holds it. The read leaves an audit-read record.
400limit must be a whole number from 1 to 200, not x.
403You hold something on the object but not manage-grants.
404The object is not there, or you hold nothing on it.
429Too many audit reads in a minute.
503Neither the audit tables (nuna.audit.tables.catalog) nor the audit topic (nuna.audit.kafka-bootstrap-servers) is configured on this server, or The audit topic cannot be read now; retry later, or the audit table cannot be read.

GET /management/v1/catalogs/{catalog}/audit/feed

Searches one catalog's records in the audit tables, newest first by time, then by partition and offset. Each filter only narrows the catalog's records; none reaches another catalog's. A page reads at most about 500,000 rows: when it stops short, searched-to says how far back it got, and next-page-token carries on from there. Each record carries the chain status the archive check last found for it.

Needs select on the audit catalog Audited

Parameters

NameInTypeRequiredDescription
catalogpathstringYesThe catalog whose records to read.
typequerystringNoRecord types, separated by commas: nuna.catalog.grant,nuna.catalog.denial.
principalquerystringNoThe principal who acted.
pathquerystringNoNamespace levels, and a table or view name, separated by %1F: equities%1Ffills.
branchquerystringNoA branch's or tag's name, or main, without its @.
subjectquerystringNoAn id the record is about, a UUID.
from, toquerystringNoInstants such as 2026-11-22T00:00:00Z. from must be before to.
limitqueryintegerNoMost records in a page. Default 50, from 1 to 200.
pageTokenquerystringNoThe next-page-token of the page before.

Responses

StatusWhen
200{"catalog", "records": [feed record, …], "next-page-token", "searched-to", "table"}. The read leaves an audit-read record on the catalog.
400

  • from must be an instant such as 2026-11-22T00:00:00Z, not x (and the same for to)
  • type must be audit record types such as nuna.catalog.read, separated by commas, not x
  • path must be namespace levels, and a table or view name, separated by 0x1F, none of them empty
  • branch must be a branch's or tag's name, or main, without its @, not x
  • subject must be a UUID, not x
  • pageToken is not one this feed gave: x
  • limit must be a whole number from 1 to 200, not x
403You hold no select on the audit catalog.
404The catalog does not exist.
429Too many audit reads in a minute.
503The audit tables are not configured on this server (nuna.audit.tables.catalog), or The audit table cannot be read: …, or The audit table cannot be read now; retry later.

GET /management/v1/catalogs/{catalog}/audit/summary

Counts the last day's records in the catalog by type, the same for the whole deployment, and names the 10 busiest objects. The counts are kept for 1 minute, so two calls a few seconds apart give the same answer.

Needs select on the audit catalog

Responses

StatusWhen
200{"catalog", "from", "to", "by-type", "busiest": [{"kind", "id", "path", "records", "reads", "writer"}], "deployment-by-type", "table"}.
403You hold no select on the audit catalog.
404The catalog does not exist.
429Too many audit reads in a minute.
503The audit tables are not configured, or cannot be read.

Example

curl -sS "$NUNA/management/v1/catalogs/trading/audit/summary" -H "Authorization: Bearer $TOKEN"
{
  "catalog": "trading",
  "from": "2026-11-25T04:34:21.494744751Z",
  "to": "2026-11-26T04:34:21.494744751Z",
  "by-type": {},
  "busiest": [],
  "deployment-by-type": {},
  "table": {"name": "nuna_audit.audit.events", "snapshot-id": null, "committed-at": null}
}

Not documented yet: the exact meaning of reads and writer in a busiest entry. This page was written from the route, not from the code that counts them.

GET /management/v1/audit/archive

Says whether the audit archive is configured and, when it is, where it is and how the last archive check went.

Needs select on the audit catalog

Responses

StatusWhen
200{"configured": false}, or {"configured": true, "bucket", "prefix", "check"}. check is null before the first check; otherwise it holds started-at, ended-at, intact, complete, checkpoints (latest, at, interval, late, problems), runs, runs-done, records-verified and chains.
403You hold no select on the audit catalog.

Example

curl -sS "$NUNA/management/v1/audit/archive" -H "Authorization: Bearer $TOKEN"
{"configured": false}

Not documented yet: every field of a chains entry in the archive check, beyond chain, run, records-verified, sequence and hash. The demo has no archive to show one.

GET /management/v1/audit/chains/{run}/records/{number}

Shows where one record sits in its hash chain: the log run that wrote it, its number in that run and, once it is archived, its hash, its neighbours' hashes and whether the links hold.

Needs select on the audit catalog

Parameters

NameInTypeRequiredDescription
runpathstringYesThe record's log run, a UUID (nunarun, or log-run in the feed).
numberpathintegerYesThe record's number in its run, from 1 (nunaseq, or log-seq).
event-idquerystringNoThe record's id, a UUID, to check the chain holds that record at that place.

Responses

StatusWhen
200{"chain", "log-run", "log-seq", "event-id", "archived"}, and once archived also position, hash, previous-hash, next-hash, link-holds, verified, checked-at and segment (key, first-position, last-position).
400run must be a UUID, not x, number must be the record's number in its run, a whole number from 1, not x, or event-id must be a UUID, not x.
403You hold no select on the audit catalog.
429Too many audit reads in a minute.
503The audit archive is not configured on this server (nuna.audit.archive.bucket), or The audit archive cannot be read now; retry later.

Example

curl -sS "$NUNA/management/v1/audit/chains/e1f2a3b4-c5d6-4e7f-8a9b-0c1d2e3f4a5b/records/912" \
  -H "Authorization: Bearer $TOKEN"
