Health

Read one server's figures, the whole deployment's catalog health, and one table's health, under /management/v1.

Server and catalog health are for platform operators: anyone else is refused with 403, audited, before anything is gathered. Table health is for anyone who may read the table. For liveness and readiness probes, see Health checks. The examples use curl with $NUNA and $TOKEN set as curl shows.

Endpoints

Health endpoints
MethodPathWhat it does
GET/management/v1/health/serverReads this server's figures over the last day, and optionally its view of the database.
GET/management/v1/health/catalogAdds up every server's figures, with the SLOs and alerts.
GET/management/v1/catalogs/{catalog}/namespaces/{namespace}/tables/{table}/healthReads one table's health score, last compaction and waiting requests.

GET /management/v1/health/server

Reads the figures of the server that answers, over the last day or since it started, whichever is shorter. With store=true, it also reads the catalog's database as this server finds it; that part is asked for separately so the servers gathering figures never wait on a database that does not answer.

Needs a platform operator

Parameters

NameInTypeRequiredDescription
storequerybooleanNotrue to add the database's facts. Default false.

Responses

StatusWhen
200{"server": {"id", "name", "started-at"}, "from", "to", "figures": {name: number}, "store"}. figures holds counts such as commit, load, not-modified and their latency buckets (commit.le.300: commits within 300 ms), vends.issued, vends.cached, vends.none and the alerts.* counts.
403You are not a platform operator: only platform operators may call readServerHealth.

GET /management/v1/health/catalog

Adds this server's figures to those of every other server that answers, and shapes them into SLOs, credential vends, audit delivery and alerts. Each server is listed once, with whether it answered; a server that did not answer says why.

Needs a platform operator

Responses

StatusWhen
200{"alerts", "audit", "credential-vends", "slos", "to", "answered", "silent", "servers"}. Each SLO has objective-ms, count, within, met and p99. Each server has id, name, address (for other servers), answered, started-at and from; this-server marks the one that answered you. A silent server has address, answered: false and why.
403You are not a platform operator.

Example

curl -sS "$NUNA/management/v1/health/catalog" -H "Authorization: Bearer $TOKEN"
{
  "alerts": {"metadata-integrity": 0, "regulated-schema-change": 0, "large-metadata": 0},
  "audit": {"acknowledged": 0, "failed": 0},
  "credential-vends": {"issued": 509, "cached": 5140, "none": 2, "failed": 0, "failures": {}},
  "slos": {
    "load": {"objective-ms": 50, "count": 3941, "within": 3787, "met": false, "p99": {"at-most-ms": 300}},
    "not-modified": {"objective-ms": 10, "count": 1704, "within": 973, "met": false, "p99": {"at-most-ms": 300}},
    "commit": {"objective-ms": 300, "count": 3, "within": 2, "met": false, "p99": {"over-ms": 300}}
  },
  "to": "2026-11-26T04:40:26.118Z",
  "answered": 1,
  "silent": 0,
  "servers": [
    {"id": "bb06eee7-159b-493c-a12b-918371ef3622", "name": "nuna-catalog-6c65d6c9dd-lw69w", "answered": true, "started-at": "2026-11-25T23:42:24.801Z", "from": "2026-11-25T23:42:24.801Z", "this-server": true}
  ]
}

Not documented yet: the target share each SLO's met is judged against. It is set in Figures.java, which this page was not checked against.

GET /management/v1/catalogs/{catalog}/namespaces/{namespace}/tables/{table}/health

Reads a table's health: the worker's last assessment of its files, with the health score and the reasons it needs compaction, its last compaction, and the maintenance requests waiting on it. A table the worker has not assessed has no assessment.

Needs select on the table

Parameters

NameInTypeRequiredDescription
namespacepathstringYesThe namespace levels joined by %1F: equities%1Fdaily.
tablepathstringYesThe table's name.

Responses

StatusWhen
200The table health follows.
403You hold something on the table but not select.
404The table is not there, or you hold nothing on it.

Example

curl -sS "$NUNA/management/v1/catalogs/trading/namespaces/equities%1Fdaily/tables/positions/health" \
  -H "Authorization: Bearer $TOKEN"
{
  "id": "5f6a7b8c-9d0e-4f1a-8b2c-3d4e5f6a7b8c",
  "catalog": "trading",
  "namespace": ["equities", "daily"],
  "name": "positions",
  "assessment": {
    "assessed-at": "2026-11-26T02:00:03.117Z",
    "needs-compaction": false,
    "reasons": [],
    "score": 0.0,
    "data-files": 1,
    "small-files": 0,
    "small-file-share": 0.0,
    "delete-files": 0,
    "position-delete-files": 0,
    "deletion-vectors": 0,
    "equality-delete-files": 0
  },
  "requests": []
}

Objects

FieldTypeDescription
id, catalog, namespace, nameThe table.

assessment.data-files, small-files, small-file-sharenumberIts data files, how many are small, and their share.
assessment.delete-files, position-delete-files, deletion-vectors, equality-delete-filesintegerIts delete files, in all and by kind.
last-compactionobject{"started-at", "ended-at", "outcome"}, when it has been compacted.
requestsarrayWaiting or started maintenance requests, as a request answers them.
