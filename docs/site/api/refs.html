Branches and tags

Make, list, renew, merge and delete catalog branches and tags, and take a table or view out of the refs that keep it, under /management/v1/catalogs/{catalog}/refs.

A ref covers the whole catalog: a catalog branch takes commits of its own and merges back into main, and a tag is fixed. Engines reach a ref through the Iceberg REST prefix trading@dev. See Catalog branches and tags. The examples use curl with $NUNA and $TOKEN set as curl shows.

Creating, renewing, deleting and merging a ref, and taking an object out of refs, accept an Idempotency-Key header of 1 to 128 characters. The server keeps the first answer for that key, your identity, the route and the body: a repeat gets the same answer, and a repeat sent while the first still runs waits for it. A key used with a different request is answered 400 Idempotency key key was used for a different request. A 5xx answer frees the key for a retry.

The two endpoints the maintenance worker calls to warn of and end an expired branch are on Worker endpoints.

Refs

GET /management/v1/catalogs/{catalog}/refs

Lists the catalog's refs, with the deployment's limits and whether you may make one.

Needs any grant in the catalog

Parameters

NameInTypeRequiredDescription
catalogpathstringYesThe catalog's name.
expiredquerybooleanNotrue to list branches past their expiry too: such a branch holds its name until the worker ends it. Default false.
pageTokenquerystringNoThe next-page-token of the page before.
pageSizequeryintegerNoDefault 100, held between 1 and 1000.

Responses

StatusWhen
200{"refs": [ref, …], "next-page-token", "limits", "may": {"create"}}. Each branch also has changed-count, the tables and views it changed.
404You hold nothing in the catalog, or it does not exist.

GET /management/v1/catalogs/{catalog}/refs/{ref}

Reads one ref. A branch also lists what it changed: each table and view, the version it was cut at and the version it holds now.

Needs any grant in the catalog

Responses

StatusWhen
200The ref, with changed ([{"namespace", "name", "kind", "cut-version", "version"}]) for a branch, and may.
404Ref does not exist: name (NoSuchRefException), or the catalog is not there.

Example

curl -sS "$NUNA/management/v1/catalogs/trading/refs/dev" -H "Authorization: Bearer $TOKEN"

POST /management/v1/catalogs/{catalog}/refs

Makes a branch or a tag, cut from main or from another ref. A branch expires nuna.refs.branch-idle-expiry (default 30 days) after it is made, unless renewed, and never lives longer than nuna.refs.branch-max-life (default 180 days). A tag never expires.

Needs create on the catalog Audited

Parameters

NameInTypeRequiredDescription
Idempotency-KeyheaderstringNo1 to 128 characters.
namebodystringYesThe ref's name, with no @ and no /, and not main.
kindbodystringYesbranch or tag.
frombodystringNomain (the default) or another ref's name.
descriptionbodystringNoOne line of plain text, at most 200 characters.

Request body

{"name": "dev", "kind": "branch", "from": "main", "description": "Rework of the fills schema"}

Responses

StatusWhen
201The new ref.
400
  • Invalid ref name: a ref's name holds no @ and no /: x, or Invalid ref name: main is the catalog's main line, not a ref's name
  • Field kind must be branch or tag
  • Field description must be a string, Field description is longer than 200 characters (n), or Field description must be one line of plain text: character n is U+xxxx, a control, line-breaking or bidirectional formatting character
  • Invalid Idempotency-Key: must be 1 to 128 characters
403You hold something in the catalog but not create on it.
404The from ref does not exist: Ref does not exist: name.
409Ref already exists: name (AlreadyExistsException); a branch past its expiry keeps its name until the worker ends it, and the message says so. Or the catalog is at its limit: Catalog trading holds 50 open branches, as many as nuna.refs.max-branches allows, or the same for tags and nuna.refs.max-tags (RefLimitException).

Example

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/refs" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: make-dev-1" \
  -d '{"name": "dev", "kind": "branch"}'

POST /management/v1/catalogs/{catalog}/refs/{ref}/renew

Moves a branch's expiry to nuna.refs.branch-idle-expiry from now, never past branch-max-life from its creation and never earlier than it was.

Needs create on the catalog Audited

Responses

StatusWhen
200The branch, with its new expires-at.
400Ref name is a tag, which never expires.
403You hold no create on the catalog.
404The ref does not exist.

Example

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/refs/dev/renew" -H "Authorization: Bearer $TOKEN"

Responses

POST /management/v1/catalogs/{catalog}/refs/{ref}/merge

Moves every table and view the branch changed onto main, all or nothing, and ends the branch. A table whose main moved since the cut is rebased when the changes do not conflict; when any table conflicts, nothing moves. With dry-run=true, the server works out the same answer and writes nothing.

Needs create on the catalog, and write or modify on each table on main Audited

Parameters

NameInTypeRequiredDescription
refpathstringYesThe branch's name.
dry-runquerybooleanNotrue to try the merge without moving anything. A dry run needs only a grant in the catalog.
Idempotency-KeyheaderstringNo1 to 128 characters.

Responses

StatusWhen
200Merged: {"ref", "tables": [merged table, …]}. A dry run: {"dry-run": true, "ref", "changed", "max-tables", "answer": {"code", "type", "message"}, "tables", "hidden", "may-merge"}, where answer is what the real merge would answer.
400Ref name is a tag; only a branch merges.
403You lack a privilege the merge needs. A table with a row and column policy can be merged only by a trusted engine that enforces it.
404The ref does not exist.
409A conflict: Branch dev conflicts with main in 1 of the 2 tables and views it changed, so nothing moved: … (RefMergeConflictException); the body adds ref and conflicts. Or too many tables: Branch dev changed n tables and views, and one merge moves at most 100 (nuna.refs.max-merge-tables) (RefLimitException).

Example

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/refs/dev/merge?dry-run=true" \
  -H "Authorization: Bearer $TOKEN"

Not documented yet: a captured merge or dry-run response. Neither was run, because the demo is shared and only read requests were allowed; the field lists above come from the code.

Objects kept by refs

A table or view dropped on main stays readable through every ref that still names it, and its files stay until no ref does. These routes show which refs keep it and take it out of them.

GET /management/v1/catalogs/{catalog}/namespaces/{namespace}/objects/{name}/refs

Lists every table or view of that name in the namespace, live or dropped, with the refs that keep each. The walk looks at 10,000 objects at most; cut-short says when it stopped. Who dropped an object is looked up for the 5 newest dropped objects only.

Needs describe on the object

Responses

StatusWhen
200{"objects": [kept object, …], "cut-short"}.
404The namespace is not there, or you hold nothing on it.

Example

curl -sS "$NUNA/management/v1/catalogs/trading/namespaces/equities/objects/orders/refs" \
  -H "Authorization: Bearer $TOKEN"

GET /management/v1/catalogs/{catalog}/objects/{id}/refs

The same, for one table or view by its id.

Needs describe on the object

Responses

StatusWhen
200{"objects": [kept object], "cut-short"}.
400Not an object id: x.
404No table or view id in trading (NoSuchObjectException).

Example

curl -sS "$NUNA/management/v1/catalogs/trading/objects/3d4e5f60-7a8b-4c9d-8e0f-1a2b3c4d5e6f/refs" \
  -H "Authorization: Bearer $TOKEN"

POST /management/v1/catalogs/{catalog}/objects/{id}/refs/remove

Takes a table or view out of the named refs, or out of every ref that names it.

Needs manage-tags on the object Audited

Parameters

NameInTypeRequiredDescription
idpathstringYesThe table's or view's id.
Idempotency-KeyheaderstringNo1 to 128 characters.
refsbodyarray of stringsNo1 to 1000 ref names, each at most 1000 characters.
all-refsbodybooleanNotrue for every ref that names the object. Send this or refs.

Responses

StatusWhen
200{"object": {"id", "namespace", "name", "kind", "state"}, "refs": [ref, …]}.
400Not an object id: x, Field all-refs must be true or absent, Name the refs to take the table or view out of, {"refs": [name, ...]}, or ask for every ref that names it, {"all-refs": true}, Field refs must be an array of 1 to 1000 ref names, or Field refs must hold ref names, each a non-empty string of at most 1000 characters.
403You hold no manage-tags on the object; or it is under a legal hold (what is under a legal hold, so its refs keep it) or a DR freeze.
404No table or view id in trading, or No table or view id on ref r of trading (NoSuchObjectException).
409The refs naming x kept changing while it was being taken out of them; ask again (RefsChangedException).

Example

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/objects/3d4e5f60-7a8b-4c9d-8e0f-1a2b3c4d5e6f/refs/remove" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"refs": ["dev"]}'
