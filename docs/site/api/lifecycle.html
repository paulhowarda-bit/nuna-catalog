Lifecycle

List dropped tables and views, restore one inside its window, purge it after, and read any table's or view's export and metadata log, under /management/v1/catalogs/{catalog}.

An engine drops a table or view through the Iceberg REST API (drop a table). The drop removes the name but keeps the object, its id, its grants and its history until its purge-after time, which the server fixes at the drop: the drop time plus nuna.rest.drop-retention. Until then a caller with create on its namespace can restore it; the API calls this undrop. After it, the maintenance worker purges it: it claims the purge, deletes the object's files with its own storage identity, and completes the purge. See Dropping, restoring and purging for the whole cycle.

The routes on one object name it by its id, {id}, because a dropped object has no name in its namespace. The {namespace} segment joins its levels with the unit separator, %1F in a URL: equities%1Fdaily. A caller who holds nothing in the catalog gets 404 NoSuchWarehouseException (The given warehouse does not exist: trading), and the refusal is audited. The examples use curl with $NUNA and $TOKEN set as curl shows.

Dropped objects and restore

GET /management/v1/catalogs/{catalog}/namespaces/{namespace}/dropped

Lists every dropped table and view directly in the namespace, tables first, each with the time until which it can be restored. The list is not paged. A read writes no audit record.

Needs describe on the namespace

Responses

StatusWhen
200{"dropped": [object, …]}, each as in Lifecycle object.
400The namespace segment has an empty level: Invalid namespace: ….
403You hold something on the namespace but not describe.
404Namespace does not exist: equities.daily (NoSuchNamespaceException): the namespace is not there, or you hold nothing on it.

Example

curl -sS "$NUNA/management/v1/catalogs/trading/namespaces/equities/dropped" -H "Authorization: Bearer $TOKEN"

POST /management/v1/catalogs/{catalog}/objects/{id}/undrop

Restores a dropped table or view before its purge-after time. It comes back with the same id, grants and history. If its old name has been taken in its namespace since, give it another one in the body.

Needs create on the object's namespace Audited

Parameters

NameInTypeRequiredDescription
idpathstringYesThe object's id.
namebodystringNoA new name, at most 1000 characters. Without it, the object takes its old name. The body may be left out.

Request body

{"name": "orders_restored"}

Responses

StatusWhen
200The object is active again; the answer is its lifecycle object, with state active.
400Not an object id: x, Missing field name: a non-empty string, Field name is longer than 1000 characters, The request body must be a JSON object, or The request body is not JSON: ….
403You lack create on the namespace. Or a DR freeze covers the object: The namespace of id is frozen for DR reconcile: reason, audited with the reason dr_freeze.
404No table or view id in catalog (NoSuchObjectException), or The namespace of id no longer exists (NoSuchNamespaceException).
409
  • id is not a dropped table or view (NotDroppedException).
  • The undrop window of id closed at time; it is waiting to be purged (UndropWindowClosedException).
  • The name name is taken in its namespace; undrop it under another name (AlreadyExistsException).
500Undropping id may or may not have been applied: … (ServiceFailureException).

A restore is audited as a nuna.catalog.undrop record.

Example

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/objects/3e4f5a6b-7c8d-4e9f-a0b1-c2d3e4f5a6b7/undrop" \
  -H "Authorization: Bearer $TOKEN"

Purge

Only a maintenance principal may call these three endpoints: a principal in nuna.security.maintenance-principals, acting as itself. Any other caller gets 403 ForbiddenException with the message only a maintenance principal may call operation, audited with the reason not_maintenance. The maintenance worker calls them; people do not.

GET /management/v1/maintenance/purge-eligible

The worker's purge queue, across every catalog, by purge-after and then id. It lists the dropped objects whose purge-after time has passed and that no legal hold, DR freeze or catalog branch or tag covers, and every object already claimed for purge, whatever covers it now, so its claimant can finish.

Needs a maintenance principal Internal

Parameters

NameInTypeRequiredDescription
pageTokenquerystringNoThe next-page-token of the page before.
pageSizequeryintegerNoObjects in one page. Default 200; a value outside 1 to 1000 is taken as the nearer bound.

Responses

StatusWhen
200{"objects": [object, …], "next-page-token"}, each as in Lifecycle object. next-page-token is there while more may follow.
400Invalid page token: ….
403You are not a maintenance principal.

Example

curl -sS "$NUNA/management/v1/maintenance/purge-eligible?pageSize=50" -H "Authorization: Bearer $TOKEN"

POST /management/v1/catalogs/{catalog}/objects/{id}/purge-claim

Claims a dropped object's purge for the calling maintenance principal, once its purge-after time has passed. From the claim on, the object can no longer be restored, and a hold placed after the claim does not stop the purge. The same principal asking again gets the same answer, so a worker that stopped part way can resume. Each server accepts at most nuna.governance.purges-per-minute claims a minute from all maintenance principals together; each replica counts its own.

Needs a maintenance principal Audited Internal

Responses

StatusWhen
200The object is claimed; the answer is its lifecycle object, with state purging and purge-claimant.
400Not an object id: x.
403
  • You are not a maintenance principal.
  • id is under a legal hold and cannot be purged, audited with the reason legal_hold.
  • The namespace of id is frozen for DR reconcile, followed by the freeze's reason when the server finds the freeze before it writes, audited with the reason dr_freeze.
404No table or view id in catalog (NoSuchObjectException).
409
  • id may not be purged before time (PurgeNotDueException).
  • id is claimed for purge by another maintenance principal (PurgeClaimedException).
  • id is not a dropped table or view (NotDroppedException).
429More than n purges in a minute; retry later (TooManyRequestsException), with Retry-After: 60.

A claim is audited as a nuna.catalog.purge-claim record.

Example

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/objects/3e4f5a6b-7c8d-4e9f-a0b1-c2d3e4f5a6b7/purge-claim" \
  -H "Authorization: Bearer $TOKEN"

POST /management/v1/catalogs/{catalog}/objects/{id}/purge

Completes a purge the caller claimed, after it has deleted the object's files. The server marks the object purged, deletes its grants and its pending deletions, and keeps its record as history. Only the maintenance principal that holds the claim may complete it.

Needs a maintenance principal Audited Internal

Responses

StatusWhen
204The object is purged.
400Not an object id: x.
403You are not a maintenance principal.
404No table or view id in catalog (NoSuchObjectException).
409
  • id is not claimed for purge; claim it first, then delete its files (PurgeNotClaimedException).
  • id is claimed for purge by another maintenance principal (PurgeClaimedException).
  • id is not a dropped table or view (NotDroppedException), for an object already purged or never dropped.
500Purging id may or may not have been applied: … (ServiceFailureException).

A completed purge is audited as a nuna.catalog.purge record.

Example

curl -sS -X POST "$NUNA/management/v1/catalogs/trading/objects/3e4f5a6b-7c8d-4e9f-a0b1-c2d3e4f5a6b7/purge" \
  -H "Authorization: Bearer $TOKEN"

Export and metadata log

Both work for an active or a dropped table or view, and both take ref to read the object as a catalog branch or tag reads it. Through a ref, 404 NoSuchRefException (Ref does not exist: ref) means no live ref has the name, and 404 NoSuchObjectException (No table or view id on ref ref of catalog) means the ref's cut does not hold the object. See Catalog branches and tags.

GET /management/v1/catalogs/{catalog}/objects/{id}/export

Exports the object: its lifecycle object, its pointer, the metadata file the pointer names, and its whole commit journal, oldest first. The server checks the metadata file against the SHA-256 it recorded and refuses one that does not match. Through ref, the pointer is the ref's: a branch's own where it has one, else the one its cut took; the journal is the metadata log as the ref reads it, oldest first, each entry naming its line in branch.

Needs select on the object Audited

Parameters

NameInTypeRequiredDescription
idpathstringYesThe object's id.
refquerystringNoA catalog branch or tag to read the object through.

Responses

StatusWhen
200{"object", "pointer", "metadata", "ref", "journal"}. pointer and metadata are left out for an object with no pointer; ref is there only through a ref.
400Not an object id: x.
403You lack select on the object.
404No table or view id in catalog (NoSuchObjectException), or a ref that does not serve the object.
500The metadata file of id does not match its recorded hash (MetadataIntegrityException).

An export that returns metadata is audited as a nuna.catalog.read record, as a table load is.

GET /management/v1/catalogs/{catalog}/objects/{id}/metadata-log

Reads the object's metadata log, newest first, a page at a time: its commit journal entries in the export's form, each the metadata file one commit wrote, and the pointer the newest leads to. A page's token names the version it stopped before, so commits made meanwhile never shift the pages after the first. A page holds fewer entries only where versions are missing; keep reading while next-page-token is there. A read writes no audit record.

Through ref, the log first holds the versions a branch committed of its own, numbered from 1 whatever the cut's version, then the log of what the ref was made from, at and below the cut. Each entry names its line in branch: the ref's name, or main. The answer's ref gives the ref's name, kind and the cut's version, and log-stops-at-cut is true when the versions below the cut came from a ref that has ended.

pageSizequeryintegerNoEntries in one page. Default 25; a value outside 1 to 100 is taken as the nearer bound.

400Not an object id: x, or Invalid page token: ….

Objects

Lifecycle object

FieldTypeDescription
idstringThe object's id.
catalogstringIts catalog's name.
kindstringtable or view.
namestringIts name; for a dropped object, the name it had.
namespace-idstringThe id of its namespace.
statestringactive, dropped, purging (claimed for purge), purged or unregistered.
dropped-atstringWhen it was dropped. Left out for an active object.
purge-afterstringThe end of its undrop window, fixed at the drop. Left out for an active object.
purge-claimantstringThe maintenance principal that claimed its purge. Left out until a claim.
locationstringThe root of its files in the object store.

Journal entry

FieldTypeDescription
commit-idstringThe commit's id.
committed-atstringWhen the server applied it.
principalstringThe principal that committed it.
end-userstringThe end user a trusted engine acted for. Left out when there was none.
enginestringThe engine's client id. Left out when there was none.
old-locationstringThe metadata file before the commit. Left out for the first version.
new-locationstringThe metadata file the commit wrote.
new-versionintegerThe pointer's version after the commit.
requirements, updatesarrayThe commit's Iceberg requirements and updates, as the engine sent them.
branchstringThrough a ref only: the line the entry is on, the ref's name or main.
