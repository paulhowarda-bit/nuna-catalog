Build nuna from source

Build every module and run the tests that need only Java, then build the three container images.

Before you begin

  • Install a JDK 25. The build uses a Java 25 toolchain and does not download one.
  • Use the Gradle wrapper in the repository, ./gradlew; it runs Gradle 9.9.1.
  • Make Maven Central reachable, or point settings.gradle.kts at a Maven-format mirror of it: every library and plugin comes from that one repository.
  • For the container images, have Docker or Podman.

Build and test

  1. Run the fast build from the repository root.

    ./gradlew build

    It compiles every module and runs every test that needs only Java, about 1,580 tests, with no containers. Its checks also fail on version conflicts between dependencies and on credential-shaped text in any tracked file.

  2. Run one module's tests while you change it.

    ./gradlew :catalog-core:test

    Add --tests Class for one class.

A green build ends with BUILD SUCCESSFUL

The server's runnable jar is then in catalog-server/build/libs/, named *-exec.jar.

Build the images

Each program has a Dockerfile in deploy/image/, based on eclipse-temurin:25.0.5_8-jre-noble. The server's image is built from its jar folder:

docker build -f deploy/image/Dockerfile \
  -t <registry>/nuna-catalog:<version> catalog-server/build/libs

The worker's and the audit tables writer's images use deploy/image/maintenance.Dockerfile and deploy/image/audit-tables.Dockerfile; Container images gives their build contexts.

If it fails

What you seeWhyWhat to do
Gradle cannot find a Java 25 toolchain.No JDK 25 is installed, and the build does not download one.Install a JDK 25.
The secretShapes task fails.A tracked file holds text shaped like a credential.Replace the value with a placeholder.
The dependencyConvergence task fails.Two dependencies ask for different versions of one library.Pin the version in the root build script.
