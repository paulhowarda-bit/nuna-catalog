Install the audit tables writer

Install the audit tables writer with the nuna-audit-tables chart, so every audit record lands in the audit catalog's events table, read from the Kafka audit topic or from the server's log over OTLP.

For platform operators

The writer is optional. It writes each audit record as a row of an Iceberg table, nuna_audit.audit.events by default, about a minute behind, so auditors can query the audit trail with any engine, and the console's Audit page reads it back. Its source is kafka, the server's audit topic, or otlp, the server's nuna.audit log sent to it over OTLP, which needs no Kafka.

Before you begin

  • The catalog server and the maintenance worker are installed, and the nuna-audit-tables image is in your registry (Container images).
  • For the source kafka, the server sends to Kafka (nuna.audit.kafka-bootstrap-servers).
  • You can create a client at the identity provider and change the catalog server's release.

Prepare the audit catalog

  1. Declare the audit catalog on the catalog server.

    Add nuna_audit under config.nuna.storage.catalogs with a profile, a KMS key set and a legal entity, as for any catalog (Create a catalog).

  2. Give the writer a client and a group of its own at the identity provider.

    A confidential client with the client-credentials grant, whose service account is in a group that holds nothing anywhere else. The token's user id is the writer's principal.

  3. Name the audit catalog and its groups on the catalog server.

    config:
  nuna:
    audit:
      tables:
        catalog: nuna_audit
        readers: auditors
        writers: audit-writers

    At start-up the server grants the readers' group (one group) select on the audit catalog, and the writers' group create and write, each recorded as granted by nuna-configuration. It refuses to start if the catalog is not declared or a grant would break the separation of duties. Readers see every record of the deployment, so keep their group narrow.

  4. Grant the maintenance worker's group write on nuna_audit.

    Its expiry and compaction then keep the table tidy.

Install the release

  1. Create the writer's Secret.

    kubectl -n nuna create secret generic nuna-audit-tables-secrets \
  --from-literal=nuna.audit-tables.token.client-secret=… \
  --from-literal=nuna.audit-tables.otlp.token="$(openssl rand -hex 32)"

    Leave out otlp.token for the source kafka. For the source otlp it must be at least 32 characters, and the catalog server sends the same token: put it in a second Secret the catalog release reads, as below.

  2. Write the values file.

    image:
  repository: registry.example/nuna-audit-tables
  tag: "0.1.0"
config:
  nuna:
    audit-tables:
      catalog-uri: http://nuna-catalog.nuna.svc:8181/
      principal: service-account-nuna-audit-tables
      token:
        endpoint: https://idp.example/realms/data/protocol/openid-connect/token
        client-id: nuna-audit-tables
        scope: openid
      source: otlp
secrets:
  existingSecret: nuna-audit-tables-secrets

    For the source kafka, set source: kafka and kafka.bootstrap-servers; the topic defaults to nuna.catalog.audit and the consumer group to nuna-audit-tables. Set token.scope to a scope the identity provider knows: Iceberg's client asks for catalog when none is set.

  3. Install the release.

    helm install nuna-audit-tables deploy/helm/nuna-audit-tables -n nuna -f audit-tables-values.yaml

  4. For the source otlp, send the catalog server's log to the writer.

    kubectl -n nuna create secret generic nuna-audit-token --from-literal=token=…
    telemetry:
  logsEndpoint: http://nuna-audit-tables.nuna.svc:4318/v1/logs
  logsTokenSecret: {name: nuna-audit-token, key: token}

    The token value is the writer's otlp.token. The server's logs then go to the writer, while metrics and traces go to telemetry.endpoint or nowhere. The writer keeps only the nuna.audit records.

Rows appear in the events table

About a minute after any audited action, a member of the readers' group can query nuna_audit.audit.events from an engine, and the console's Audit page shows the record.

What the chart creates

  • A Deployment of one replica, Recreate, with a grace period of 70 s; a ConfigMap; a ServiceAccount; and a Secret when secrets.values is set and secrets.existingSecret is not.
  • For the source otlp only: a container port and a Service port, both named otlp-http, on 4318, with a TCP readiness probe on it.

The archive, an Object Lock bucket the writer can fill from the log, is set under config.nuna.audit-tables.archive; see Audit tables writer settings and Run the audit pipeline.

What the chart refuses

The chart's refusals
Error
config.nuna.audit-tables.catalog-uri is required: the catalog the writer writes to
config.nuna.audit-tables.principal is required: the writer's own principal id, whose records it leaves out
config.nuna.audit-tables.token.endpoint is required: the identity provider's token endpoint
config.nuna.audit-tables.token.client-id is required: the writer's client id there
config.nuna.audit-tables.kafka.bootstrap-servers is required for the source kafka: the Kafka cluster holding the audit topic

If it fails

What you seeWhyWhat to do
A chart error from the table above.A required value is missing.Set it.
The catalog server refuses to start after you set nuna.audit.tables.The audit catalog is not declared, or a grant would break the separation of duties.Declare nuna_audit, and keep the readers' and writers' groups apart from every other role.
The writer refuses to start for the source otlp.No nuna.audit-tables.otlp.token, or one shorter than 32 characters.Put a token of at least 32 characters in its Secret.
The token request fails with an unknown scope.No token.scope, so Iceberg's client asked for catalog.Set a scope the identity provider knows.
The console's Audit page answers 503.nuna.audit.tables.catalog is not set on the catalog server.Set it.
