Install the catalog server with Helm

Install the catalog server on Kubernetes with the nuna-catalog chart: put settings in config, passwords and keys in a Secret, and read what the chart and the server refuse.

For platform operators

Before you begin

  • The nuna-catalog image is in a registry your cluster pulls from (Container images).
  • The database exists, with a role for the server, and its safety settings pass the self-check: Use PostgreSQL, Use CockroachDB, Use Oracle or Use MongoDB.
  • Each bucket exists, with the server's own identity on the store (Set up object storage).
  • You know each trusted issuer's settings and the groups for platform operators and grant admins (Connect an identity provider).
  • You can create a namespace, a Secret and a Helm release in the cluster.

How settings reach the server

The chart takes the server's settings in two parts.

  • config holds Spring Boot properties in YAML form. The chart renders them into application.yaml in a ConfigMap, mounted at /etc/nuna/config, which the server reads beside its built-in settings (SPRING_CONFIG_ADDITIONAL_LOCATION). Every nuna.* key is on its page under Configuration.
  • secrets names a Secret that Spring Boot reads as a config tree, mounted at /etc/nuna/secrets (SPRING_CONFIG_IMPORT=optional:configtree:/etc/nuna/secrets/). Each key of the Secret is a property name, and its value is that property's value. Passwords and secret keys go here, never in config.

You make the Secret yourself and set secrets.existingSecret, or pass the keys in secrets.values and the chart makes it. When both are set, existingSecret wins and the chart makes no Secret. Keep a values file that holds secrets.values out of version control.

Install the release

  1. Create the namespace.

    kubectl create namespace nuna

  2. Create the Secret with the database password and any store keys.

    kubectl -n nuna create secret generic nuna-catalog-secrets \
  --from-literal=spring.datasource.password=… \
  --from-literal=nuna.storage.profiles.onprem.secret-access-key=…

    Leave out the password if the server signs in to PostgreSQL by a client certificate (Use PostgreSQL). On MongoDB the connection string goes here, as nuna.database.mongodb.uri.

  3. Write the values file.

    This one is for PostgreSQL and a Ceph store. The two keys the chart insists on are config.spring.datasource.url (unless the database is MongoDB) and at least one entry in config.nuna.security.issuers.

    image:
  repository: registry.example/nuna-catalog
  tag: "0.1.0"
config:
  spring:
    datasource:
      url: jdbc:postgresql://db.example:5432/catalog?sslmode=verify-full
      username: nuna_catalog
  nuna:
    storage:
      profiles:
        onprem:
          kind: CEPH
          endpoint: https://s3.example
          region: us-east-1
          table-root: s3://trading/tables
          allowed-prefixes: [s3://trading/tables]
          sts-role: arn:aws:iam:::role/nuna-vend
          access-key-id: nuna-catalog
          maintenance-principal: arn:aws:iam:::user/nuna-maintenance
      catalogs:
        trading:
          profile: onprem
          kms-key-set: trading-keys
          legal-entity: Example Markets Ltd
    security:
      issuers:
        - issuer: https://idp.example/realms/data
          jwks-uri: https://idp.example/realms/data/protocol/openid-connect/certs
          audiences: [nuna-catalog]
          algorithms: [RS256]
          user-id-claim: preferred_username
          groups-claim: groups
          client-id-claim: azp
      grant-admin-groups: [grant-admins]
      platform-operator-groups: [platform-operators]
      maintenance-principals: [service-account-nuna-maintenance]
    governance:
      pitr-window: 7d
    rest:
      drop-retention: 30d
    ui:
      oidc:
        issuer: https://idp.example/realms/data
        client-id: nuna-console
secrets:
  existingSecret: nuna-catalog-secrets
ingress:
  enabled: true
  className: nginx
  host: nuna.example
  tls:
    - hosts: [nuna.example]
      secretName: nuna-example-tls

    nuna.rest.drop-retention must be longer than nuna.governance.pitr-window, the database's real point-in-time-recovery window, or the server refuses to start. Leave nuna.database.allow-unsafe empty, nuna.storage.require-tls at its default (true) and nuna.ui.dev-token-login off.

  4. Render the chart to check the values.

    helm template nuna-catalog deploy/helm/nuna-catalog -n nuna -f values.yaml > /dev/null

    It prints nothing when the values pass the chart's checks, and an error naming the missing value when they do not (What the chart refuses).

  5. Install the release.

    helm install nuna-catalog deploy/helm/nuna-catalog -n nuna -f values.yaml

  6. Wait for the servers to be ready.

    kubectl -n nuna rollout status deployment/nuna-catalog --timeout=15m

    The first server of a release migrates the schema before it answers, and the start-up probe allows it 10 minutes.

Three servers are ready and answer without a token

kubectl -n nuna get pods -l app.kubernetes.io/instance=nuna-catalog shows three pods Running and 1/1 ready. Through the Ingress, curl -sS https://nuna.example/ui/config.json answers with the console's sign-in settings. Check the install goes further.

What the chart creates

The objects take the release's name if it holds the chart's name (as nuna-catalog does), and release-nuna-catalog otherwise.

The chart's objects
KindNameWhat it is
DeploymentnameThe servers: replicaCount replicas (3), rolled one new server at a time (maxSurge: 1, maxUnavailable: 0).
ServicenameClusterIP on port 8181, named http, with sessionAffinity: None.
Servicename-peersA headless Service with an address for each ready server. The chart sets NUNA_HEALTH_PEERS to it, and the health page asks each server for its figures there.
ConfigMapnameapplication.yaml, rendered from config.
SecretnameOnly when secrets.values is set and secrets.existingSecret is not.
ServiceAccountnameIts token is not mounted: the server never calls the Kubernetes API. Annotate it for IRSA on EKS (Set up object storage).
PodDisruptionBudgetnamemaxUnavailable: 1.
IngressnameOnly with ingress.enabled: one rule for ingress.host, path /, to the Service's http port, with ingress.tls as you give it.

Each pod:

  • Mounts the ConfigMap at /etc/nuna/config, the Secret at /etc/nuna/secrets, databaseTls.secretName at /etc/nuna/db-tls with mode 0440, and storageCaConfigMap.name at /etc/nuna/storage-ca, each only when set.
  • Carries the annotations checksum/config and checksum/secret, so a change to config or secrets.values rolls the servers.
  • Runs its readiness, liveness and start-up probes on GET /ui/config.json, which needs no token and reads nothing from the database.
  • Pauses 5 s before shutdown (preStop), so the Service stops routing to it before Spring's graceful shutdown starts, within terminationGracePeriodSeconds (45).
  • Runs with JAVA_TOOL_OPTIONS from javaToolOptions, by default -XX:MaxRAMPercentage=75 -XX:+ExitOnOutOfMemoryError, and any extra variables in env.

Every value, with its default, is on Helm chart values.

What the chart refuses

helm template, helm install and helm upgrade stop with one of these errors, before anything reaches the cluster:

The chart's refusals
ErrorWhat to set
config.spring.datasource.url is required: the catalog's databaseThe JDBC URL. Not asked for when config.nuna.database.backend is mongodb.
config.nuna.security.issuers needs at least one trusted token issuerAt least one entry in config.nuna.security.issuers.

Change settings later

Edit the values file and run helm upgrade nuna-catalog deploy/helm/nuna-catalog -n nuna -f values.yaml. A change to config or secrets.values rolls the servers. A change to a Secret you made yourself does not, so restart them after it:

kubectl -n nuna rollout restart deployment/nuna-catalog

If it fails

A server that refuses to start logs why and exits, so its pod restarts and shows CrashLoopBackOff. Read the log with kubectl -n nuna logs deployment/nuna-catalog.

What you seeWhyWhat to do
A chart error from the table above.A required value is missing.Set it and run the command again.
The catalog's database is unsafe, so the server does not start, followed by codes such as pg.no-sync-standbyThe database's safety settings failed the self-check.Fix each finding the message names; the database page lists them. Never list them in nuna.database.allow-unsafe in production.
nuna.security.issuers names no trusted token issuer; the catalog accepts no request without oneThe issuers list is empty in the rendered settings.Check the indentation of config.nuna.security.issuers.
nuna.rest.drop-retention (…) must be longer than nuna.governance.pitr-window (…)A dropped table's files could be purged while a database restore could still bring the table back.Make drop-retention longer than the PITR window.
nuna.storage.profiles.name.endpoint must use https, got …An http endpoint while nuna.storage.require-tls is on.Use the store's HTTPS endpoint.
nuna.storage.catalogs.name needs profile, kms-key-set and legal-entityA catalog is declared without all three.Set them; see Create a catalog.
schema migration failedThe role cannot create the schema's objects, or a migration failed on the database.Read the cause logged below it and check the role's privileges on the database page.
Pods stay not ready and the start-up probe fails after 10 minutes.The server is still waiting, often on the database or on another server's migration lock.Read the log. The migration lock is waited on for up to 5 minutes.
