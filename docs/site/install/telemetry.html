Send telemetry

Point the catalog server and the maintenance worker at an OpenTelemetry collector, so their metrics, traces and logs reach your monitoring.

For platform operators

Both programs send metrics, traces and logs over OTLP/HTTP once an endpoint is set, and export nothing until then. Their log lines go to stdout as JSON either way, so the cluster's own log collection works without a collector.

Before you begin

  • An OpenTelemetry collector, or another receiver, that takes OTLP over HTTP with protobuf, usually on port 4318. OTLP over gRPC (port 4317) is not supported.
  • The catalog and maintenance worker charts installed, or about to be (Install the catalog server with Helm, Install the maintenance worker).

Set the endpoint

  1. Add a telemetry block to each chart's values.

    telemetry:
  endpoint: http://otel-collector.observability:4318
  headersSecret: {name: otlp-headers, key: headers}
  caConfigMap: {name: otlp-ca, key: ca.crt}
  sampling: "0.1"
  resourceAttributes: {deployment.environment.name: prod}

    Only endpoint is needed. /v1/metrics, /v1/traces and /v1/logs are added to it.

  2. Put any credential headers in a Secret.

    Headers are name=value pairs separated by commas. Make the Secret in the release's namespace:

    kubectl -n "$NS" create secret generic otlp-headers \
  --from-literal=headers='authorization=Bearer <key>'

    When nothing in them is secret, use headers: "x-tenant=lake" instead. headersSecret wins when both are set.

  3. Trust an internal CA, if the collector uses one.

    For an https endpoint signed by an internal CA, put the CA's PEM certificate in a ConfigMap and name it in caConfigMap. The chart mounts it at /etc/nuna/otlp-ca.

  4. Upgrade the releases.

    helm upgrade nuna-catalog deploy/helm/nuna-catalog -n "$NS" -f catalog-values.yaml
helm upgrade nuna-maintenance deploy/helm/nuna-maintenance -n "$NS" -f maintenance-values.yaml

Check it worked

Within a minute or two your metrics store holds nuna_catalog_alerts_metadata_integrity_total, which every server sends each minute from its start, with job set to namespace/nuna-catalog.

What the chart sets

The charts turn the values into the standard OpenTelemetry variables, which Spring Boot reads:

Environment variables the charts set
VariableFrom
OTEL_EXPORTER_OTLP_ENDPOINTtelemetry.endpoint
OTEL_EXPORTER_OTLP_HEADERStelemetry.headersSecret, or telemetry.headers
OTEL_EXPORTER_OTLP_CERTIFICATEThe file from telemetry.caConfigMap
OTEL_TRACES_SAMPLER, OTEL_TRACES_SAMPLER_ARGparentbased_traceidratio and telemetry.sampling
OTEL_SERVICE_NAMEAlways the chart's name: nuna-catalog or nuna-maintenance
OTEL_RESOURCE_ATTRIBUTESAlways service.namespace, service.version (the image tag), service.instance.id (the pod), k8s.namespace.name, k8s.pod.name and k8s.node.name, plus telemetry.resourceAttributes

If your platform injects the OTEL_* variables itself, with an operator or a sidecar, leave telemetry.endpoint empty. The endpoint and headers it injects take effect, beside the service name, resource attributes and sampler the chart sets.

Send the logs elsewhere

The catalog chart can send its logs alone to another OTLP/HTTP endpoint: telemetry.logsEndpoint, the full URL ending /v1/logs. It takes precedence over endpoint for logs; metrics and traces still go to endpoint, or nowhere. The usual use is the audit tables writer's receiver, so the console's Audit page needs no Kafka:

telemetry:
  logsEndpoint: http://nuna-audit-tables:4318/v1/logs
  logsTokenSecret: {name: audit-receiver-token, key: token}

The token in logsTokenSecret is sent with every log export as the X-Nuna-Audit-Token header (Run the audit pipeline).

Outside Kubernetes

Set the same variables yourself:

OpenTelemetry variables nuna reads
VariableMeaning
OTEL_EXPORTER_OTLP_ENDPOINTThe collector's OTLP/HTTP base URL. Switches on all three signals.
OTEL_EXPORTER_OTLP_METRICS_ENDPOINT, OTEL_EXPORTER_OTLP_TRACES_ENDPOINT, OTEL_EXPORTER_OTLP_LOGS_ENDPOINTOne signal's full URL instead.
OTEL_EXPORTER_OTLP_HEADERSHeaders sent with every export.
OTEL_EXPORTER_OTLP_LOGS_HEADERSHeaders for log exports only.
OTEL_EXPORTER_OTLP_CERTIFICATEA PEM file with the CA that signed an https collector's certificate.
OTEL_SERVICE_NAME, OTEL_RESOURCE_ATTRIBUTESThe resource the signals come from.
OTEL_TRACES_SAMPLER, OTEL_TRACES_SAMPLER_ARGWhich traces are kept. Without them, 10% of new traces.

Metrics stay off until a metrics endpoint is set, even though Spring Boot alone would push to localhost:4318.

If it fails

  • Nothing arrives. Check the endpoint is OTLP over HTTP, not gRPC, and that the pods reach it. Each failed export logs a warning.
  • Requests slow when the collector is down. They do not: exports run on background threads with queues of 2,048, and records that do not fit are dropped. A stopping pod waits up to 10 s for its last exports.
  • Series arrive under unexpected names. See If your Prometheus names differ.
