Use CockroachDB

Prepare a CockroachDB database and user for the catalog server, connect to it, and pass the safety self-check the server runs before it starts.

For platform operators and database administrators Tested nightly

The server reaches CockroachDB with the PostgreSQL driver, so nuna.database.backend stays postgresql; the server sees CockroachDB from the version it reports and uses its own schema for it. nuna's tests run on CockroachDB v25.4.20.

Before you begin

  • You can create users and databases and change cluster settings and zone configurations, or you work with someone who can.
  • The cluster keeps 3 voting replicas of the catalog's data.

Prepare the cluster

  1. Allow READ COMMITTED transactions.

    SET CLUSTER SETTING sql.txn.read_committed_isolation.enabled = true;

    Without it CockroachDB runs a READ COMMITTED transaction as SERIALIZABLE, and the store's locking is verified only under READ COMMITTED.

  2. Create the database and the server's user.

    CREATE DATABASE catalog;
CREATE USER nuna_catalog;
ALTER DATABASE catalog OWNER TO nuna_catalog;
GRANT SYSTEM VIEWCLUSTERSETTING TO nuna_catalog;

    The first server of a release creates the schema's tables in the user's current schema. VIEWCLUSTERSETTING lets the self-check read whether the Raft log is synced.

  3. Keep 3 voting replicas for the database and its tables.

    The self-check reads SHOW ZONE CONFIGURATION for the database and every table in the user's schema and counts num_voters, or num_replicas where no voters are set.

Connect the server

config:
  spring:
    datasource:
      url: jdbc:postgresql://crdb.example:26257/catalog?sslmode=verify-full
      username: nuna_catalog
  nuna:
    database:
      backend: postgresql

The password goes in the server's Secret as spring.datasource.password (Install the catalog server with Helm).

Not documented yet: signing in to CockroachDB by a client certificate with the chart's databaseTls. The chart mounts the files for any JDBC URL, but only PostgreSQL's client-certificate sign-in is described or exercised.

The safety self-check

Before it migrates the schema, each server checks these. Any finding stops it with The catalog's database is unsafe, so the server does not start, followed by each code: detail.

CockroachDB findings
CodeDetail the server logsWhat to do
crdb.replicasevery zone holding catalog data needs 3 voting replicas; target has n, …Raise num_voters (or num_replicas) to 3 for each target named.
crdb.fsync-offkv.raft_log.synchronization.unsafe.disabled is value; it must be false, or cannot read kv.raft_log.synchronization.unsafe.disabled (the catalog role needs VIEWCLUSTERSETTING): …Set the setting to false, or grant VIEWCLUSTERSETTING.
crdb.read-committed-offa READ COMMITTED transaction runs as isolation; set sql.txn.read_committed_isolation.enabled to true, the isolation the store's locking is verified underSet the cluster setting, as above.

nuna.database.allow-unsafe names findings the server starts despite, logging each as a warning. Leave it empty in production (Database settings).

The server reports CockroachDB

As a platform operator, GET /management/v1/health/server?store=true shows "configured": "postgresql", a backend naming CockroachDB, and an empty allowed list (Check the install).
