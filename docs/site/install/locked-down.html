Install on a locked-down network

Build and install nuna where machines have no outbound access: mirror the Gradle distribution, the Maven repositories and the container images, and trust an internal certificate authority.

For platform operators

A normal build reaches three places on the internet: services.gradle.org for Gradle, Maven Central for every library and plugin, and Docker Hub for the base images. The Spark image also downloads jars from Maven Central while it builds. On a network without outbound access, point each at an internal mirror before you start.

Before you begin

  • An internal Maven-format repository that mirrors Maven Central, or holds every artifact the build needs.
  • An internal container registry, and a Java 25 runtime image approved for it.
  • JDK 25 installed on the build machine: the build never downloads one.
  • The PEM certificates of the internal certificate authority that signs your database, object store and collector certificates.

Mirror the build tools

  1. Point the Gradle wrapper at an internal copy of Gradle 9.9.1.

    In gradle/wrapper/gradle-wrapper.properties, change distributionUrl to the internal copy of gradle-9.9.1-bin.zip, and keep distributionSha256Sum, so the wrapper still checks the file it downloads.

    distributionUrl=https\://repo.example/gradle/gradle-9.9.1-bin.zip
distributionSha256Sum=d8a18a7a841dd5df825d35a685fad6f2d7f12ac0c280e57b67c27b4a520ba228

  2. Replace both mavenCentral() lines in settings.gradle.kts with the internal repository.

    One resolves plugins and the other libraries. Replace each with:

    maven { url = uri("https://repo.example/maven") }

    Every library and plugin then resolves from it. A missing artifact fails the build and names itself; add it to the mirror and build again.

  3. Build the jars.

    ./gradlew :catalog-server:bootJar :catalog-maintenance:bootJar :catalog-audit-tables:bootJar

Mirror the images

  1. Build each Java image from your approved base image.

    docker build -f deploy/image/Dockerfile \
  --build-arg BASE_IMAGE=registry.example/java-runtime:25 \
  -t registry.example/nuna-catalog:0.1.0 catalog-server/build/libs

    Do the same for maintenance.Dockerfile and audit-tables.Dockerfile (Container images). The base image needs java and sleep on the path.

  2. Mirror the Spark image's sources, if you want compaction.

    catalog-tests-engines/images/spark/Dockerfile starts from apache/spark:4.1.4-scala2.13-java21-python3-ubuntu and downloads iceberg-spark-runtime-4.1_2.13-1.12.0.jar and iceberg-aws-bundle-1.12.0.jar from Maven Central. Mirror the base image, and change the two ADD URLs to your Maven mirror in your copy of the Dockerfile.

  3. Push the images to the internal registry and name it in each chart's image.repository.

    Set imagePullSecrets if the registry needs credentials.

Trust an internal certificate authority

The JVM's trust store is left alone. Each connection that can meet an internal CA takes the CA's certificates where it is set:

Where each program takes an internal CA
ConnectionWhere the CA goes
Server to PostgreSQLA Secret named in databaseTls.secretName, and sslrootcert in the JDBC URL (Use PostgreSQL).
Server and worker to an object storeA ConfigMap named in storageCaConfigMap.name, and the profile's or store's ca-bundle (Set up object storage). The worker hands it to its compaction Jobs.
Audit tables writer to the archive bucketA ConfigMap named in archiveCaConfigMap, mounted at /etc/nuna/archive-ca.
Server and worker to the OpenTelemetry collectorA ConfigMap named in telemetry.caConfigMap (Send telemetry).
Engines to the object storeEach engine's own setup: vended credentials carry the endpoint, not the CA.

Not documented yet: trusting an internal CA for the identity provider's JWKS URL and the worker's token endpoint. Neither chart has a setting for it, and those clients use the JVM's trust store.

Proxies

Not documented yet: running the server or the worker behind an outbound HTTP proxy. No setting names one and no test runs behind one. Keep the database, the object store, the identity provider and the collector reachable without a proxy.

Nothing reaches the internet

The build finishes with the wrapper and repositories pointed at your mirrors, the images build from your registry, and the pods start with images pulled only from it.

If it fails

What you seeWhyWhat to do
Gradle cannot resolve an artifact and names it.The mirror lacks it.Add it and build again.
The wrapper refuses the Gradle zip.The mirror's copy is not the same file: the SHA-256 sum differs.Mirror the exact gradle-9.9.1-bin.zip.
Gradle cannot find a Java 25 toolchain.The build never downloads one.Install JDK 25.
A test fails to pull an image.The image is not mirrored, or its name is not overridden.Mirror it and set the property, or the Testcontainers prefix.
A server or worker logs PKIX path building failed.A connection meets a certificate its trust does not cover.Give that connection the CA as the table above says.
