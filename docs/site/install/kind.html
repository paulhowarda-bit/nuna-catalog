Run nuna on a local kind cluster

Try the catalog server and maintenance worker charts on your own machine, on a one-node kind cluster in Podman, with throwaway PostgreSQL, Kafka, Silo and Keycloak.

For platform operators and developers

Two scripts do it. deploy/kind/kind.sh makes or starts the kind cluster nuna (context kind-nuna) and puts images on its node. deploy/local/run.sh builds the catalog image, starts the backing services, installs the charts with deploy/local/values.yaml and deploy/local/worker-values.yaml, and checks the result. Everything it makes is for a laptop: plain HTTP, a test token issuer, keys kept in your home folder, and a database the self-check would refuse. For a look around with data, use the demo instead (The local demo), which runs on the same cluster.

Before you begin

  • You have bash (Git Bash on Windows), Podman, kind, kubectl, helm, curl and JDK 25, and a checkout of the nuna repository.
  • The Podman machine has room for 3 GiB of memory limits for up, and 3 GiB more for worker. The demo shares the cluster; beside it there might not be room.
  • For worker, the Spark image is built: podman build -t nuna-engines/spark:4.1.4-iceberg-1.12.0 catalog-tests-engines/images/spark.

Try the charts

  1. Install the catalog server and its backing services.

    deploy/local/run.sh up

    It takes about 2 minutes. It starts the cluster if needed, builds nuna-catalog:local, and installs two servers in namespace nuna-local.

  2. Check it through each server.

    deploy/local/run.sh smoke

    It ends with smoke passed on pod and pod.

  3. Install the maintenance worker beside it.

    deploy/local/run.sh worker

  4. Open the console.

    kubectl --context kind-nuna -n nuna-local port-forward svc/nuna-catalog 8181:8181

    Then open http://localhost:8181/ui/ and paste a token from ~/.nuna-k8s/tokens/.

  5. Remove it when you are done.

    deploy/local/run.sh down

The smoke check passes on two servers

smoke prints ok for each call and ends with smoke passed on and the two pods' names. A FAIL line names the step that failed.

The cluster script, deploy/kind/kind.sh

The cluster is one node, the Podman container nuna-control-plane, made from deploy/kind/cluster.yaml. It publishes ports 8180 to 8188 on localhost, and its API server takes node ports from 8180 up. Pods reach your machine as host.docker.internal.

kind.sh up

Starts the Podman machine if it is stopped, creates the cluster if there is none or starts its node if it is stopped, waits for the node to be ready, lifts the task limits on the node and its containers, and adds host.docker.internal to the cluster's DNS.

kind.sh load image…

Copies each image from Podman's store onto the node, unless the node has it already. A name without a registry, such as nuna-catalog:local, becomes docker.io/library/nuna-catalog:local on the node. The local values use pullPolicy: Never, so a pod runs only an image loaded this way.

Any other argument prints the script's usage and exits with status 2.

The install script, deploy/local/run.sh

run.sh up

Builds the server's jar and the image nuna-catalog:local, starts or creates the cluster and loads the image, makes test tokens with a test issuer, creates the namespace, starts PostgreSQL 18.7, Kafka and Silo, creates Silo users for the server and the worker, installs the chart with two servers, applies the delete policies to Silo as a platform operator, and grants the test groups.

run.sh smoke

Through two different servers: 401 without a token, the configuration, a namespace, a table, a load with vended credentials, then a write beneath the table that succeeds, deletes refused for the vended credentials and the server's own Silo user (403) and allowed for the worker's (204), and finally drops the table and the namespace.

run.sh worker

After up: builds nuna-maintenance:local, starts Keycloak 26.8.2 with a client for the worker, grants the worker's group write, and installs the worker's chart in nuna-local-maintenance with its compaction Jobs in nuna-local-compaction. The worker's cleanup window is open all day, and it scans every minute.

run.sh down

Uninstalls both releases and deletes the three namespaces. The tokens and keys in ~/.nuna-k8s stay.

Any other argument prints the usage and exits with status 2.

Environment variables

VariableDefaultMeaning
NUNA_K8S_CONTEXTkind-nunaThe kubectl and helm context. The script never uses the current context.
NUNA_K8S_NAMESPACEnuna-localThe catalog's namespace; the worker's and the Jobs' add -maintenance and -compaction.
NUNA_K8S_HOME~/.nuna-k8sWhere the test tokens, the issuer's key and every generated password and key are kept.
JAVA_HOMEnoneThe JDK 25 to run with, if java on the path is another.

If it fails

What you seeWhyWhat to do
need two running servers, found nsmoke found fewer than two running server pods.Wait for up to finish, or read the pods' logs.
FAIL: no vended credentials in the loadThe server could not vend from Silo.Read the server's log.
no image nuna-engines/spark:4.1.4-iceberg-1.12.0 for the compaction JobsThe Spark image is not built.Build it as the message says.
Pods stay Pending, or waits run out.The Podman machine is out of memory, often with the demo running beside it.Free memory, or run one at a time.
