# Decision ledger

Branches from `reports/Enterprise Iceberg REST catalog plan.md` (D1–D34). Each branch is OPEN, RESOLVED or BLOCKED-ON. Resolved in the grilling session of 2026-11-06; all 41 branches RESOLVED.

**This ledger supersedes the report where they differ.** Paul's decisions that depart from the report's recommendations:
- D7: four backends (PostgreSQL, CockroachDB, Oracle incl. Exadata/RAC, MongoDB), all in v1. The report's "never: pluggable multi-backend persistence" is overridden. YugabyteDB was a fifth until Paul dropped it on 2026-11-11 (D7's amendment).
- D12: new tables default to v3 (report: v2).
- D28: unlimited namespace depth (report: capped).
- D33: catalog-wide Nessie-style branches, tags and merges, designed in v1 and shipped in v1.x. The report's "never: long-lived branches and merges" is overridden.
- New since the report: D35 (SingleStore as a client), D36/D36a (one deployment, on-prem or AWS, managing tables on both), D37 (zero loss in-region, async DR).

(5) and (8) Nothing the worker finds is deleted at once: expiry, manifest rewrite and the orphan scan hand every unreferenced file to the pending-deletion list, and the worker deletes the due ones with its own storage identity. It reads the metadata again after the listing, and queues only unreachable files older than the policy's orphan age. (6) A purge is a claim, the deletion of everything beneath the object's location, and the completion. Another worker's claim is skipped; a worker that dies part-way leaves its claim, and the next scan by the same principal finishes it. (7) The worker's storage identity must list as well as delete. Reruns are safe: the catalog now keeps a file pending once per object (a unique index), and recording one again answers 200 and keeps its first not-before. Where the build departs from the plan, awaiting Paul's OK: compaction is not in the engine matrix, since that would mean deploying the worker there, and the heavy `KubernetesCompactionTest` covers it in Docker Desktop's cluster instead. The time of a table's last orphan scan and compaction is kept in memory, so a restarted worker scans every table again at once; a Job still kept stops a second compaction. Iceberg's expiry leaves a file that a snapshot it keeps had deleted; the orphan scan queues it once it is older than the orphan age, so it waits that age plus the PITR window. The overnight memory test (`LargeOrphanScanTest`) has not run, so where memory runs out is not yet known. | |
