# 21. A CA bundle per storage profile

Status: done

Effort: M, a trust store per profile, and a test store with a private CA

`build-plan.md`, M6, Open: the JVM trust store serves every storage profile today. An on-prem store with its own CA
needs it added to the JVM's.

Done when a profile can name its own CA bundle, and a test against a store with a private CA passes.

Done: a profile's `ca-bundle` names a PEM file, in the server (`nuna.storage.profiles.<name>.ca-bundle`) and the
worker (`nuna.maintenance.storage.<name>.ca-bundle`, which needs the profile's `endpoint`). Every S3 and STS client
built for that profile then trusts the bundle's certificates beside the JVM's CAs: the server's `MetadataFiles` and
`CredentialVendor` (`CaBundle.applyTo` in catalog-objectstore), and the worker's own `S3FileIO`s and those it reads
tables with on vended credentials (`TrustedS3Clients`, an Iceberg S3 client factory matched on the endpoint). A file
that cannot be read, holds no certificate or holds one that does not parse stops startup with the setting's name and
the path. Without the setting nothing changes; vended credentials are unchanged, and the docs say engines trust the
store through their own setup. Helm: `storageCaConfigMap` in both charts, mounted at `/etc/nuna/storage-ca`. Docs:
`docs/install-at-work.md` sections 5 and 6, `catalog-maintenance/README.md`.
- Tests (Java only): `CaBundleTest` (PEM parsing), `CaBundleHandshakeTest`, `CaBundleProfileTest` and
  `TrustedS3ClientsTest`, which shake hands with an in-process JDK `HttpsServer` whose certificate a keytool-made
  private CA signed (`PrivateCa`, catalog-tests-s3): refused without the bundle, answered with it, through the
  clients the profiles use. 19 tests, all passing in the fast build.
- Bites in `bites/M6/`, recorded and checked with `git apply --check`, not run; `M6/startup-overlap-unchecked` and
  `OBS-41/objectstore-not-observed` recorded again against the moved `CatalogStorage`.
- Not run: no test against a real store behind TLS with a private CA (Ceph or MinIO); the in-process server stands
  in for it.
