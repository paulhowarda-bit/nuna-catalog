# 54. KubernetesCompactionTest: kubectl's jsonpath filter loses its quotes on Windows

Status: done
Done: 2026-11-16 on k8s-test-quoting
Added: 2026-11-16 by overnight run 2026-11-16

Touches: catalog-maintenance/src/test/java/keel/maintenance/KubernetesCompactionTest.java

`KubernetesCompactionTest#compactionRunsAsAJobPerTable` checks the reason a cut-off Job failed with
`kubectl get job ... -o jsonpath={.status.conditions[?(@.type=="Failed")].reason}` (item 46). Java on Windows passes
the inner double quotes unescaped, so the process sees `@.type==Failed` and kubectl refuses the template ("unrecognized
identifier Failed"). Everything the test checks before that line passed on the cluster.

The heavy build stops at the first module that fails, so the Oracle, MongoDB and CockroachDB suites, the conformance,
engine and rolling-upgrade tests and every bite did not run that night.

Evidence: the heavy build and the Ceph leg of the overnight run of 2026-11-16, both
`java.lang.AssertionError: kubectl --context docker-desktop get job keel-compact-... exited 1: error: error executing
jsonpath "{.status.conditions[?(@.type==Failed)].reason}": Error executing template: unrecognized identifier Failed`
(C:\Users\paulh\code\keel-overnight\runs\2026-11-16\heavy.log, ceph.log).

Done when the filter quotes its value in a way that reaches kubectl intact, and the test passes in the overnight run.

The filter quotes `Failed` with single quotes. Run through `ProcessBuilder` against the docker-desktop cluster, the
double-quoted form fails with the overnight run's error and the single-quoted one answers; the fast build is green.
The test is heavy: the next overnight run runs it (status/2026-11-16-k8s-test-quoting.md).
