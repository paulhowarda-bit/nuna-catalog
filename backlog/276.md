**What is missing.** Item 262 stamped every line the server logs with its run and number (`nunarun`, `nunaseq`) and
kept the stamp off the audit topic. Item 272 put the stamp in the audit table (`log_run`, `log_seq`), so a feed row can
be placed in its run's archive chain, but a row the table writer took from the topic has neither: the console says it
cannot be checked. `AuditTrail` publishes `EventCodec.encode(event)` to Kafka and logs
`EventCodec.encode(event, stamp)`; `TableWriter` builds its rows with `AuditRows.of(event, partition, offset)`.

Paul, asked on 2026-11-25 whether the Kafka copy should carry the stamp too, answered "Keep it unstamped", then "stamp
it to sorry changed my mind".

**What done looks like.**

- Each record's copy on the audit topic, and on the change stream, is the log's line byte for byte: the same
  `nunarun` and `nunaseq`, for the synchronous records and the relayed batches alike.
- The table writer with the source `kafka` fills `log_run` and `log_seq` from the stamp, so a row from the topic is
  placed as one from the log is; a record from a server older than the stamp still has neither.
- Tests: the trail's Kafka copy equals its log line; the topic writer's rows keep the stamp. A bite for each.
- docs/observability/audit-log.md and catalog-audit-tables/README.md no longer say the topic carries no stamp.

**Done 2026-11-25.**

- `StampedEvent` (`catalog-audit`) is a record with the stamp it was logged with; `encode()` gives the log's line.
  `AuditTrail` logs each record and hands Kafka that `StampedEvent`: `EventPublisher.publish(StampedEvent)` for the
  synchronous records, a new `StampedTarget` for a relayed batch, and `ChangeStream.fanOut` takes and gives
  `StampedTarget`s. The relay still hands the trail plain `CatalogEvent`s (`RelayTarget`): the number is given where
  the record is logged. A Kafka copy without the stamp cannot be built by mistake: the types carry it.
- `KafkaEventPublisher` sends `StampedEvent.encode()`, the log's line byte for byte, keyed by subject as before.
- `TableWriter` (`source: kafka`) fills `log_run` and `log_seq` from the copy's stamp
  (`EventCodec.envelope(...).stamp()`); a copy from an older server still has neither.
- The console needs no change: the feed places a row by `log_run`, whatever its source, so a stamped row from Kafka
  gets the pill, the Hash chain line and "Check this record" as a logged one does. Its Read from line still names the
  partition and offset, not the run.
- Tests: `KafkaRecordTest` (new, no broker), `AuditTrailTest` (the copies on the topic and the stream equal the log's
  lines), `TableWriterTest#keepsTheRunAndNumberEachRecordWasLoggedWith` (new), `ChangeStreamTest` (stamps kept),
  `KafkaPublishingTest` and `BrokerOutageTest` (heavy, compiled, not run: the overnight run runs them).
- Bites: four new in `bites/OBS-276/`, six re-recorded against the moved code; nine run, all BITES, tree restored.
  `D23/scan-fails-when-kafka-down` (`KafkaDownTest`, heavy) is left to the overnight run.
- Docs: `docs/observability/audit-log.md`, `catalog-audit-tables/README.md`, the `AuditTrail`, `AuditRow` and
  `AuditRows` javadoc.
