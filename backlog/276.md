**What is missing.** Item 262 stamped every line the server logs with its run and number (`nunarun`, `nunaseq`) and
kept the stamp off the audit topic. Item 272 put the stamp in the audit table (`log_run`, `log_seq`), so a feed row can
be placed in its run's archive chain, but a row the table writer took from the topic has neither: the console says it
cannot be checked. `AuditTrail` publishes `EventCodec.encode(event)` to Kafka and logs
`EventCodec.encode(event, stamp)`; `TableWriter` builds its rows with `AuditRows.of(event, partition, offset)`.

Paul, asked on 2026-11-25 whether the Kafka copy should carry the stamp too, answered "Keep it unstamped", then "stamp
it to sorry changed my mind".

**What done looks like.**

- Each record's copy on the audit topic, and on the change stream, is the log's line byte for byte: the same
  `nunarun` and `nunaseq`, for the synchronous records and the relayed batches alike.
- The table writer with the source `kafka` fills `log_run` and `log_seq` from the stamp, so a row from the topic is
  placed as one from the log is; a record from a server older than the stamp still has neither.
- Tests: the trail's Kafka copy equals its log line; the topic writer's rows keep the stamp. A bite for each.
- docs/observability/audit-log.md and catalog-audit-tables/README.md no longer say the topic carries no stamp.
