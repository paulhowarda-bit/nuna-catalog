# 136. A nightly or heavy run by hand does not hold other sessions' builds

Status: done
Done: 2026-11-22 on worktree-agent-a53125bd431c6231a
Added: 2026-11-22 by nightly by hand 2026-11-22
Touches: nightly.sh heavy.sh CLAUDE.md
Effort: S, two scripts take and drop one lock file, and one CLAUDE.md line

CLAUDE.md tells every agent to start no build while `.overnight/running` exists in the main checkout, and
`overnight.sh` writes that file for its whole run. A nightly or heavy pass run by hand (`./nightly.sh`, `./heavy.sh`
in a worktree, at Paul's word) writes nothing, so other sessions' agents keep building beside it.

Evidence: the first nightly by hand on 2026-11-22 failed 13 tests on waits that ran out while five agent worktrees ran
fast builds (test results written from 15:20 to 16:10, four at once at 16:10) and Windows paged in a median 22,700
pages a second. The second, with those agents asked by message to hold their builds, passed all 233
(`status/2026-11-22-nightly-2026-11-22.md`). The session running it could not write `.overnight/running` itself: its
worktree guard refuses writes to the main checkout.

Done looks like: `nightly.sh` and `heavy.sh` write `.overnight/running` in the main checkout (found with
`git rev-parse --git-common-dir`) with their pid when it is absent, remove it on exit (a trap) only if it is still
theirs, and leave a run that already holds it alone; `overnight.sh` keeps working as now (it finds its own lock, or a
dead pid's, and takes it over); CLAUDE.md says a run by hand holds the lock too. Checked by running `./nightly.sh
--test-dry-run` and seeing the file appear and go.

Done: `nightly.sh` and `heavy.sh` carry the same lock block, run right after their `cd`. It finds the main checkout
from `git rev-parse --git-common-dir` (the lock is `$NUNA_OVERNIGHT_HOME/running` when that is set, as in
`overnight.sh`), writes its pid there in `overnight.sh`'s format (`pid:`, `started:`, `by: <script> in <folder>`) when
no live pid holds the lock, and removes it from an `EXIT` trap only if the pid in it is still its own (`INT` and `TERM`
exit 130 so the trap runs). A live pid's lock it leaves alone, says so and runs anyway. `overnight.sh` runs
`nightly.sh` in `.overnight/clone`, which is a clone, not a worktree, so there `--git-common-dir` names the clone: a
checkout named `clone` with `runs/` beside it is taken for the overnight run's, and its lock is the one beside it.
`overnight.sh` is unchanged. CLAUDE.md (Builds) says a run by hand holds the lock, and that an overnight run starting
while one does stops at once and tests nothing that night.

Checked in this worktree against the main checkout's lock, with a watcher logging each change to it:
`./nightly.sh --test-dry-run` wrote it with its pid at the start and it was gone after (exit 0); a second dry run
started while a first held it said "pid 136633 holds ... leaving it to that run", and the lock was unchanged when it
ended and gone only when the first ended. With stub builds in scratch layouts: under `overnight.sh`'s layout a live
pid's lock was left unchanged and nothing written in the clone, a dead pid's lock was taken over and removed; for
`heavy.sh` in a git worktree, the lock went to the repository's main checkout and was removed after a pass, a failed
build (exit 1) and a `TERM` (exit 130); and `overnight.sh --dry`, given `heavy.sh`'s live lock, stopped with "another
overnight run is going" and left it in place. `status/2026-11-22-agent-a53125bd431c6231a.md` has the detail.
