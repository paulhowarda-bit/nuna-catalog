The catalog measures nothing about its own work. The build plan's SLOs (load p99 < 50 ms, 304 p99 < 10 ms, commit p99
< 300 ms, at least 500 commits/s; R7, M8) are measured only by the load tests' clients, so at work nothing can alert
on them. Alerts (`ServerAlerts`: metadata integrity, regulated schema change, large metadata) are log lines only,
which Prometheus cannot see. Client metrics reports (D13) are logged whole and never counted.

Done when the catalog records, with Micrometer:
- Every Iceberg REST call: a timer named by the spec's operationId (`loadTable`, `updateTable`, `commitTransaction`,
  `loadCredentials`, `reportMetrics`, and so on) with its outcome (status class and, for an error, the Iceberg error
  type such as `CommitFailedException`), with histogram buckets at the SLO bounds 10, 50 and 300 ms, set in code.
- Commits: committed; refused because a requirement failed (409), by requirement type (`assert-ref-snapshot-id`,
  `assert-table-uuid`, and so on); and ended in an unknown state.
- Loads answered 200 and 304 (D14), and metadata cache hits and misses.
- Credential vends (D21): count, time, failures and cache hits.
- Each alert kind as a counter, besides its log line.
- Client reports, aggregated: the commit and scan report results (`total-duration`, `attempts`, `added-data-files`,
  `result-data-files`, `skipped-data-manifests`, and so on) as timers and distributions labelled by catalog, report
  type, operation and the client's `engine-name` from the report's `metadata`. Units are converted by the unit each
  result states (`unit`, `time-unit`), never assumed. A result name the server does not know is skipped, not
  invented. Per-table detail stays in the log line item 37 leaves.
- Labels hold only the catalog name, operationId, outcome, error type, requirement type, report type, operation and
  engine name. Never a table, namespace, principal or filter value: Prometheus series must stay bounded, and names
  may be sensitive.
- Tests drive the routes and read the meters. The metrics that guard something (the commit outcome split, the SLO
  buckets, the label rule) are recorded as bites in `bites/OBS-39/`.
- `docs/observability/catalog-metrics.md` lists every meter, its labels and the question it answers, for the
  dashboards at work (item 44).
