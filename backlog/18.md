Done when an automated browser test covers the screens checked by hand then (tree, table and view tabs, governance,

What was done: `ConsoleBrowserTest` (`catalog-server`, `keel.catalog.server.governance`, 7 tests, untagged) drives
Chrome 147 in a container, through Testcontainers' Selenium module and Selenium 4.43.0, against the console the M7
tests' server serves, signed in by a token put in the tab's storage. It covers the tree down to tables and views,
with the filter and deep links; a v2 table's overview, three schemas with added fields marked, partition specs, sort
orders, snapshots with a tag and a branch, and the metadata log, and a v3 table's overview; a view's two versions
with their SQL; governance (a DR freeze, an inherited hold and owner, the table's own classification); grant and
revoke, grants by group, and a separation-of-duties refusal; three more refusals (D27's unclassified table in a
regulated namespace, the audit trail without manage-grants, a grant admin loading data); and the audit trail with
commits, a read, its credential issue, a denial and the raw record. Every refusal is compared word for word with
the catalog's own answer to the same request. The console is unchanged and still has no third-party code.

Four bites in `bites/UI/` each fail on their assertion: `console-refusal-reworded`, `console-audit-hides-denials`,
`console-tree-drops-views` and `console-schema-added-against-first`. The fast build passed on 2026-11-15 with these
tests in it: 1,229 tests, no failures, `ConsoleBrowserTest` 60 s for the class. `build-plan.md`'s Status ("Console
browser tests 2026-11-15") has the run times and the tooling choice.
