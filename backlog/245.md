# 245. Console: Grants as a rail item for those who manage grants; a table or view opens on Access for someone who may manage its grants but not read it

Effort: S, a rail entry and a landing tab chosen from what the caller may do, both already known to the console (access.js)

## What is wrong

Paul asked on 2026-11-24 how to add grants from the console. It already can, in two places, and he had not found
either (Atelier's answer, 2026-11-24):

- Governance, then its Grants tab: "Grant a privilege" (`governance.js`, `grantsPage`).
- A namespace's, table's or view's Access tab: "Grant on this <kind>" (`panels.js:579`, `grantsTab`).

No rail item names either. Governance opens on Summary. On Access the form is the third block. A table opens on
Overview, which refuses a grant admin such as `gary`, who holds no data access, so he reaches the tab that would let
him grant only by knowing it is there. Branches were missed the same way on 2026-11-23.

## Done when

- Those who may manage grants in the catalog (`may(catalog, 'manage-grants')`) see a "Grants" rail item after
  Governance, opening the Grants page; Governance keeps Summary and Holds and freezes. Everyone else does not see it.
- A table or view opens on Access for a caller who may manage its grants but may not read it.
- Console tests show both, as `gary` and as `ana`.

## What was done

- The rail has "Grants" after Governance (key icon), drawn only where `may(catalog, 'manage-grants')`; it opens
  `p=grants`, the page that was Governance's Grants tab (`grantsPage`, now exported). Governance keeps Summary and
  Holds and freezes. A link to the old tab, `p=governance&tab=grants` (with `g=`), opens the new page (`route.js`); a
  link to `p=grants` from someone who manages no grants says so in plain words, as Audit and Service do.
- A table or view whose link names no tab opens on Access when the caller manages the catalog's grants but holds no
  `select` there (`openingTab` in `access.js`). Its Overview link then names `tab=overview`, which every table and
  view link now accepts, so Overview stays a tab away.
- `ConsoleBrowserTest#grantsHaveARailItemAndAGrantAdminOpensATableOrViewOnAccess` signs in as `gary` (a grant admin)
  and as `ana` (create and modify, no grants). The rail assertions for the grant admin and the caller with every duty
  gain Grants; the grant admin's table refusal is read on `tab=overview`.
- Bites: `console-rail-no-grants`, `console-grant-admin-opens-on-overview`, `console-old-grants-link-lost`;
  `console-rail-no-refs` recorded again against `app.js`.
- Left: the decision is catalog-wide, from the catalog list. A caller who manages grants and reads only some of the
  catalog still opens a table they cannot read on Overview. The table page also loads the table on every tab, so a
  grant admin on Access still draws one refused load (as before this change).
