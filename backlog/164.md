What still lets one test stop the run:

- `overnight.sh` runs the bites only when the heavy build passed. Every heavy build from 2026-11-16 to 2026-11-23
  failed (one to nine tests a night, among 2,000), so no bite has run since 2026-11-15, while the runs ended between
  01:43 and 02:22 and left four hours before the 06:30 deadline unused (`.overnight/runs/*/summary.md`: "Bites | not
  run: the heavy build did not pass").
- No test task has a timeout. One test that hangs holds its leg until the deadline, and with it every module after
  it in that leg and every leg after it.

Already done: since item 122 (landed 2026-11-22), the heavy build and the Ceph leg run with `--continue`, and
`nightly.sh` has run both its steps with it. On 2026-11-23 the heavy build ran all 18 test tasks while four of them
failed (`catalog-server` 520 tests, 6 failed; `catalog-store-sql`, `catalog-store-sql-raft` and
`catalog-tests-conformance` one each). Before it, the heavy build of 2026-11-21 stopped after its first failing module,
having tested three modules in 4 minutes. Within a test task JUnit runs every test whatever the others did; nothing in
the build sets fail-fast, and no task depends on a test task.

Done looks like:

- The bites run whatever the heavy build's tests did. A bite whose own test class failed tonight, in any leg, is not
  run: applying it could only make an already failing test fail, so its verdict would mean nothing. The summary lists
  those bites. The bites are left out only when the heavy build failed with no failing test (it did not compile, or a
  check such as `:bitesApply` failed), as every bite would then come out SETUP.
- With `-Pheavy` or `-Pnightly`, a test task that runs past its timeout fails, and `--continue` goes on with the
  other modules.

The bites now run whatever the legs' tests did. Each leg adds the classes with a failing test to a list (module and
class, from the result files written since the leg started), and a module whose test task was stopped at its timeout
counts as failing in every class: which test hung is not known, and its bites would hang too. A bite whose `Module:`
and `Test:` class are on that list is not run (a failure in a nested class counts for its outer class), and the
summary lists it under "Bites not run: their tests failed or hung tonight". The bites are left out only when the heavy
build failed with no failing test and no hung task.

Each test task has a timeout with `-Pheavy` (60 min), `-Pnightly` and `-Pbites` (120 min), in `build.gradle.kts`.
Gradle stops a task past it and fails it, and `--continue` goes on. The summary names such a task under the failed
tests ("stopped at its timeout, a test hung"). The longest modules seen were 16 min (heavy, `catalog-server`) and 66
min (nightly, `catalog-maintenance` on 2026-11-21, with Windows paging the Docker VM out).
