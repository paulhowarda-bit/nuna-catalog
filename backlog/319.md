# 319. Console: a link to Grafana's charts on the Service page, when a Grafana URL is configured

Effort: S, one optional setting carried to the console, one link on one page, and the demo setting it with `metrics`

The console never mentions Grafana. An operator who sees a missed latency objective on the Service page has nowhere to
go from it, though Grafana holds the same figures over time and the traces behind them (demo/README.md, "metrics").
Paul asked for a link (2026-11-27); Atelier agreed and placed it:

- On the Service page head, not the global header: the header is full (three overflow fixes this week), and the
  Service page is shown only to platform operators, Grafana's audience.
- "Charts over time in Grafana", with the external-link icon, in a new tab; "Grafana" alone on a phone.
- A server setting `nuna.ui.grafana-url`, carried in `/ui/config.json` beside `docs-url`. Absent (the default, and at
  work until Grafana is wired on site): no link at all. The demo sets it to `https://<host>:8188` only while `metrics`
  is on.
- Deep links (a catalog's dashboard by uid, a request's trace in Tempo) later: the dashboards' uids at work are not
  known yet. The observability expert found the console already holds the trace id (`X-Request-ID` is the trace id
  when the client sends none, `RequestIds`), but sampling keeps few refusals' traces, so a trace link is for later and
  for 5xx answers first; catalog-security should weigh Grafana viewers seeing every trace before one ships.

Done when the Service page shows the link when the setting is set and nothing when it is not, the setting refuses
anything but an http(s) URL, and the demo's catalog gets it while `metrics` runs.
