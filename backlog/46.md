Paul decided on 2026-11-15 (item 42, the D30 amendment of that date, which this item builds; read it first) that
compaction runs on need, in a nightly cleanup window. Today the worker does the opposite:
- A table's first compaction starts whenever the worker first sees it, and each Job's `ttlSecondsAfterFinished`
  (`KubernetesJobs`, set to `compaction-interval`) holds the next one about a day later at the same hour, so
  compactions drift around the clock and run in the day (`Worker.maintain`, `due(compactions, …)`).
- Orphan scans keep their clock in memory (`Worker.orphanScans`), so a worker restart rescans every table at once,
  whatever the hour.
- A Job is launched whether or not the table needs one.

Done when:
- The worker takes a cleanup window (start, end, named time zone) as a setting, and starts compaction Jobs and
  orphan scans only inside it. A worker restarted in the day starts neither. Tests drive a `Clock` across the window's
  edges, across midnight and across a daylight-saving change.
- At the window's end nothing new starts. Each compaction Job carries a Kubernetes deadline at the window's end and
  runs `rewrite_data_files` with partial progress. An orphan scan cut short is not recorded, and its table is scanned
  again the next night.
- In the window the worker reads each enabled table's current manifests and launches a Job only for a table with:
  enough data files under 75% of its target size; delete files (position, equality, deletion vectors) above a share
  of its data files; or any equality-delete file. The thresholds are new maintenance policy keys resolved like
  `compaction.target-file-size-bytes`, defaulting to `rewrite_data_files`' own defaults; `catalog-maintenance/README.md`
  lists them.
- `compaction-interval` is gone (settings, README, chart). The Job's TTL no longer does scheduling.
- Needy tables are compacted in order of how far past their thresholds they are, tables with equality deletes first.
- Meters, beside item 40's: tables assessed, tables needing compaction by reason, Jobs started, Jobs cut off at the
  window's end, tables left over when it closed (all without a table label), and for every needy table a series
  labelled with catalog, namespace and table name, uncapped (Paul accepted names reaching Grafana viewers).
  `docs/observability/worker-metrics.md` lists them.
- The Helm chart takes the window; `deploy/helm/keel-maintenance` and the README say how.
- Each guarded rule (outside the window nothing heavy starts; the deadline; the need conditions; the order) is
  recorded as a bite in `bites/D30/`.
