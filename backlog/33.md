Paul (2026-11-15) opened <http://localhost:8180/realms/nuna/account>, which `demo/README.md` and the sign-in text
`demo.sh` prints give for signing out of Keycloak to change user, and got "Something went wrong / Sorry, an unexpected
error has occurred".

The page signs in, but Keycloak's account API answers its token with 401 (`/realms/nuna/account/supportedLocales`
and `/realms/nuna/account/?userProfileMetadata=true`, seen in the browser's network log). Users imported from
`demo/k8s/keycloak-realm.json` get no roles: `kcadm.sh get-roles -r nuna --uusername ana --effective` lists none,
neither `default-roles-nuna` nor the `account` client's `view-profile` and `manage-account`, which a user made in the
admin console gets by default. Without them the account console's token is not addressed to the account API.

Done when each demo user in the realm file holds `default-roles-nuna`, the account page loads for them, the
console's and kafbat's tokens are unchanged, and the README and `demo.sh` send people to Keycloak's logout page
(`/realms/nuna/protocol/openid-connect/logout`), which signs out in one click.

What was done: each user in the realm file holds `default-roles-nuna`; the README and `demo.sh` send people to the
logout page to change user. Checked on the running demo's Keycloak without restarting it: the branch's file imported
as a throwaway realm gave ana the account roles and her account page loaded; the console's and kafbat's access and ID
tokens were unchanged. The live realm's users were given the role too, and ana's account page in `nuna` loads.
status/2026-11-15-keycloak-account-roles.md has the detail.
