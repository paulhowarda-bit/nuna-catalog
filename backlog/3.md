# 3. bites/run.sh counts a setup failure as a bite

Status: done
Done: 2026-11-14 on worktree-agent-aff0da0daee64ec31
Added: 2026-11-14 by Change Manager, from build-plan.md at Paul's request

`build-plan.md`, REST spec fixes of 2026-11-14: a first run had five of six bites "bite" only because the Spring
context failed to start (Ryuk, with Docker crowded by the nuna-demo stack). `judge()` in `bites/run.sh` adds
`failures` and `errors` from the result files, so a test that errors in setup counts as a bite.

Done when a bite whose tests fail only in setup (context start, container start) is reported as SETUP, not BITES,
and a test of `run.sh` or a deliberate run shows both verdicts.

What was done: `run.sh`'s new `tally` reads each testcase of the result files. A failure is setup's when the
testcase is Gradle's `initializationError` or `executionError` (a failed `@BeforeAll` or `@AfterAll`), when Spring's
test context did not load ("Failed to load ApplicationContext", "ApplicationContext failure threshold"), or when
Testcontainers is on its stack. A bite whose failures are all setup's is `SETUP: <k> of <n> failed in setup` and fails
the run; one test failing on its own (an assertion, or the code under test throwing) still makes it BITES. The last
line now reads `<n> bites, <f> not biting or not restored (<s> of them SETUP); logs in build/bites/`.

Both verdicts shown on 2026-11-14 with the nuna-demo stack up: `D13/default-warehouse-ignored` BITES (1 of 2 failed),
and with Testcontainers' Ryuk image unreachable `SETUP: 2 of 2 failed in setup`; `M8/reconcile-takes-unproven-file`
with Ryuk unreachable `SETUP: 2 of 2 failed in setup`; `M4/default-check-never-applies` BITES. `bites/test-run.sh`
checks the verdicts against those runs' result files without Gradle or Docker (15 cases). `build-plan.md`'s Status
has the details.

Left over: two bites fail only by stopping the server's start and are now SETUP (item 30).
