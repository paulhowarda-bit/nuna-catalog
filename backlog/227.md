What was done, 2026-11-25:

- Why it never bit: MongoDB's cut reads each table's main pointer in the snapshot and leaves out a table with none
  there. `everyTableInACutHasItsNamespace`'s writer makes a namespace and a table in it; a table made after the
  snapshot has no pointer in it, so the cut leaves it out whether the tables are read in the snapshot or outside it.
  The race cannot show the break, however often it lands.
- New test, `MongoStoreSuiteTest#aCutReadsNamespacesAndTablesInOneSnapshot`: a client of its own
  (`MongoReplicaSet.linkClientWatchedBy`) has a command listener, which the driver runs on the sending thread before
  a command goes out. When the cut sends its find on `catalog_object`, after the namespaces' read, the listener makes
  a namespace and moves an existing table into it. In the snapshot the cut holds the table where it was; read outside
  it, the table comes under the new namespace, which the cut does not hold. It lands there every time.
- The bite's `Test:` line names it: `bites/run.sh` says BITES (1 of 1 failed), on "in the namespace made after the
  cut read the namespaces: expecting empty but was [the table]". The test passes on the code as it is (0.6 s).
- Run with the demo taken down (D49): beside it the replica set could not elect a primary, with Windows at 634 MB
  free and paging.
