The redesign's namespace **Contents** (D45; `docs/design/console/prototype.html`, the namespace page;
`docs/design/console/wireframes.html`, browse note 5) gives each table row its format, its snapshot count and its last
commit. The console's Contents (`catalog-server/src/main/resources/nuna/ui/browse.js`, `contentsTable`) has Name,
Kind, Tonight's queue and Governance, and no snapshot or commit column: item 124 left it out, since no route gives
them for a listing (`browse.js`, header comment).

Evidence:
- The wireframe's note says the columns come from each table's metadata through the Iceberg REST load, with
  `X-Iceberg-Access-Delegation: none`. That is one `loadTable` per row, and every load is audited
  (`table.js`, "every load is audited"): a namespace of 300 tables would write 300 audit records each time someone
  opens it, and read 300 metadata files from the object store.
- The routes Contents uses (`GET /v1/{prefix}/namespaces/{ns}/tables`, the governance marks, the queue) give names and
  marks only. `GET /management/v1/maintenance/estate` (item 127) gives each table's assessment, data files among
  them, but not its snapshots or last commit.

What done looks like:
- A read that lists, for the tables of one namespace the caller may describe, each table's format version, its
  snapshot count and the time and committer of its last commit, from what the catalog keeps (its pointer and commit
  journal), paged, with no object-store read and no per-table audit record. Tables the caller may not describe are
  left out, as Contents leaves them out today.
- Contents shows Format, Snapshots and Last commit for each table row, as the prototype draws them.
- A fast route test (store double) for what is listed and what is left out; a browser test (`heavy`) for the columns;
  bites for a table listed to a caller who may not describe it and for a page without a bound.
- docs/observability/ (or the route's own doc) describes the read.

What was done:

- **The read.** `GET /management/v1/catalogs/{catalog}/namespaces/{namespace}/tables`, in `NamespaceTablesRoutes`
  (catalog-server), documented in `docs/observability/namespace-tables.md`. One row per active table of the namespace,
  by name: its id, name, `format-version` and `snapshots` from the projection the commit engine stores beside the main
  pointer (D5), and `last-commit` (version, `committed-at`, principal, end user and engine) from the journal entry of
  the pointer's version. No metadata file is read and no table loaded, so no audit record is written per table.
- **No store change.** The pointer and journal reads are the existing `readPointer` and `readJournal`, two reads a
  row. A store read joining them to the listing would take one query a page instead, but would add a method to all
  four stores.
- **Who sees what.** A table is listed only to a caller the authorizer allows `describe` on it, decided for the
  whole page at once; any other is skipped, and skipping it audits nothing. The namespace is answered to a caller who
  holds something on it, above it or in it; any other is refused (audited as `listNamespaceTables`) and answered 404
  `NoSuchNamespaceException`, as for a namespace that does not exist. So a caller who holds `select` on one table of
  a namespace sees that table alone. Iceberg's `listTables`, which Contents still uses for the names, asks `describe`
  on the namespace and names every table in it.
- **Paging** as the estate read pages: `pageSize` 100 by default, 1 to 200, at most 1,000 tables looked at a page; a
  page may hold fewer rows, even none, with a token; the token is the store's own.
- **Contents** (`browse.js`) has the prototype's columns in its order: Name, Kind, Format, Tonight's queue,
  Governance, Snapshots, Last commit. Format is a `v2`/`v3` badge, Snapshots a count, Last commit the local time (its
  full date and time on hover) and who committed (`ana via trino` when an engine acted for someone). Namespace and
  view rows show a dash in all three. The style sheet's phone and mid-width rules already hid the prototype's 3rd,
  6th and last columns, so it is unchanged. The page reads the new route through `api.all` and `api.managed`, with
  no change to `api.js`.
- **Tests.** `NamespaceTablesRoutesTest`, 7 tests, Java only, passing. `ConsoleBrowserTest` gained
  `contentsShowEachTablesFormatSnapshotsAndLastCommit` (heavy), written and not run here; the overnight run runs it.
- **Bites** in `bites/D45/`, each run against the route test here and biting, then restored and checked with
  `git apply --check`: `namespace-tables-lists-undescribable` (bites `aTableTheCallerMayNotDescribeIsLeftOut` and
  `aPageLooksAtAThousandTablesAtMost`) and `namespace-tables-page-unbounded` (bites
  `aPageHoldsAtMostTwoHundredRows`).
