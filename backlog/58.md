The demo serves every page over plain HTTP on localhost:8180 to 8186: it ran without TLS by choice, because
self-signed certificates do not work well at work (Paul, 2026-11-15). Paul now has real certificates at work
and wants the demo ready to take them: "I now have real certificates at work that I just want to plug into
this, So we should plan on having certs here so I can just plug in my work certs" (2026-11-17), and approved
the plan, including rebuilding the demo to test it ("Yes, go ahead", 2026-11-17).

The plan: the certificate lives in one folder, `~/.nuna-demo/tls/` (`tls.crt` with its intermediates,
`tls.key`, `ca.crt`); at home `up` makes a demo CA and a server certificate for localhost there, at work Paul
replaces the three files and sets `NUNA_DEMO_HOST` to the certificate's name. One nginx pod takes ports 8180 to
8186, ends TLS with that certificate and forwards over plain HTTP inside the cluster, which keeps its in-cluster
names. Every address the browser uses becomes `https://<host>:<port>`. No client certificates.

Done when a fresh `up` serves every UI over HTTPS with the folder's certificate (Keycloak and its admin
console, the console, kafbat, Studio, Silo's console, CloudBeaver, and Kafka Connect's REST API while the CDC
leg runs), each person signs in as before, `demo.sh`'s own calls trust `ca.crt`, `up` refuses a certificate
that does not name the host or does not match its key, and the README and the work guide say how to plug in
work's files.

What was done: nginx (`ports.yaml`, Deployment `front`) takes 8180 to 8186 and ends TLS with the certificate in
`~/.nuna-demo/tls`, published as Secret `demo-tls` by `publish_tls`, which makes a name-constrained demo CA and a
localhost certificate at home and checks any files it finds (host, expiry, key, chain). `NUNA_DEMO_HOST` names
the host in every address; Keycloak, kafbat, oauth2-proxy, the realm and the catalog's issuer use https. Studio
serves HTTPS itself behind the front door, as its SAML address comes from the request. `demo.sh`'s calls trust
`ca.crt` and retry a connection that never sent its request; the front door's pod keeps serving 10 s as it
stops. The README and `docs/install-at-work.md` section 10 say how to plug in work's files, a `.pfx`
included. Checked with the demo rebuilt, on localhost and on `nuna.localhost` with stand-in work files, and the
CDC leg: `status/2026-11-17-demo-tls.md`. Left: no real browser has loaded the pages yet, as the demo CA is not
trusted on this machine; name resolution and the LAN address at work can only be seen there.
