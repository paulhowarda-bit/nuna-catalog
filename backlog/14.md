Done: the leak held on 2026-11-19, and not only on HEAD, loads and metrics: every Iceberg route that names a
namespace, table or view looked the name up (404) before asking the guard (403). The amendment names no status code,
so the hidden answer is the 404 a missing name gets, word for word (`NoSuchNamespaceException`, `NoSuchTableException`,
`NoSuchViewException`; a bare 404 on HEAD), which is what Iceberg clients expect.
- Who sees a name: a caller that holds any privilege on the object or above it (as the authorizer reads grants; a grant
  admin's `manage-grants` counts, a platform operator holds none), or, for a namespace, on anything inside it, as the
  catalog list counts a catalog (item 20). Such a caller is refused with 403 as before; any other is answered as if
  the name did not exist. A trusted engine is answered for the end user it acts for. `Guard` decides it
  (`catalog-server/src/main/java/nuna/catalog/server/rest/Guard.java`); the catalog itself stays 403 (item 68).
- Routes: HEAD, load and drop of namespaces, tables and views; the namespace properties route; listing namespaces under
  a parent, tables and views; create, register and register-view; commit (a commit to a name no table holds is judged
  as a create there would be), replace view, rename (the source is asked about before the destination is looked up,
  so a missing destination tells nothing), unregister, metrics, credentials and transactions. A create table asks the
  guard before checking the name's form, so a bad name answers 400 only to a caller that may see the namespace.
- The refusal is audited either way, with what was refused (operation, privilege, reason, path, actor). An idempotency
  key keeps a hidden answer as it keeps a missing one, so a reused key tells nothing; an unregister of a hidden or
  missing table still reaches the engine, which answers 404 and keeps it under the key.
- Tests: `HiddenNamesTest` (new, Java only, 23 cases: the real routes, guard and authorizer over a store double) and
  `SecurityGateTest` (heavy): six cases now expect the hidden 404 with the denial audited, and a new
  `namesAreHiddenFromACallerThatHoldsNothingOnThem` compares hidden and missing answers word for word on eight routes,
  besides a namespace HEAD, and shows a caller with `describe` on one table refused with 403.
- Bites: five new in `bites/D18/` (`names-shown-to-outsiders`, the existence check before access again;
  `hidden-refusal-unaudited`; `namespace-blind-to-grants-inside`; `rename-destination-first`;
  `create-name-checked-first`), and twelve recorded again with the same break against the routes' new code (D13 metrics
  and register and unregister, D15 transactions, D30, M5, M6, M7). Recorded and checked with `git apply --check`, not
  run.
