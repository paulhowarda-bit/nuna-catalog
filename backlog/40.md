Starts once 38 is on main: it adds the worker's telemetry dependency and configuration.

The worker reports each scan in one log line (`WorkerApplication.java:69`, `ScanReport.toString()`) and each failure
as a warning. Nothing can alert when it stops scanning, falls behind, or fails every purge.

Done when the worker records, with Micrometer:
- Per scan, the counts `ScanReport` already keeps (tables, snapshots expired, manifests rewritten, orphan scans and
  orphans found, compactions started, files recorded and outside, purged and skipped, files deleted), and failures
  by kind.
- Each scan's duration, and the time the last scan succeeded as a gauge, so an alert can fire when no scan has
  succeeded for, say, three intervals.
- Labels hold only bounded things (kind of work, outcome), never a table, namespace or file path.
- Tests run a scan and read the meters. The last-success gauge is recorded as a bite in `bites/OBS-40/`.
- `docs/observability/worker-metrics.md` lists every meter and the alert each supports, and
  `catalog-maintenance/README.md` points to it.
