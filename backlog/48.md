# 48. Health dashboard in the console: catalog health and table health (D38; after 39, 40 and 47)

Status: done
Done: 2026-11-15 on worktree-agent-aab5cf81e7a767284

What was done: the console has a **Health** page (`health.js`, `#p=health`) and each table's page a **Health** tab.
The page's top half is catalog health over the last day for the whole deployment: alerts fired by kind, the audit's
Kafka acknowledgements (count, mean, p99, failures), credential vends by outcome and failures by type, loads, 304s and
commits against their SLOs (count, share within the objective, p99 bucket, met or not), the worker's last successful
scan, scans, failed scans and failed jobs of the last day, the latest failure and the ten latest scans, and the
servers the figures came from. Beneath it, the neediest tables the viewer may select, 50 a page, each linking to its
table's Health tab, which shows the latest assessment, why it is needy and the last compaction. Gathering, with no
schema step and no new dependency (`keel.catalog.server.health`): a meter registry of its own (`HealthMeters`) that
Boot records every meter in, keeping every count and histogram bucket since start; a reading each minute, the last
day being now's reading less the newest a day old (`HealthWindow`); `GET /management/v1/health/server` answering one
server's figures and `GET /management/v1/health/catalog` adding every other server's, found by resolving
`keel.health.peers` (`host:port`) to all its addresses and asking each with the operator's own token, deduplicated by
each server's id, a silent server named with why. The Helm chart gained a headless Service,
`<release>-keel-catalog-peers` (ready pods only), and sets `KEEL_HEALTH_PEERS` to it. Both routes are for platform
operators only, refused and audited for anyone else; the table reads are item 47's, by select. Tests:
`HealthWindowTest` (5), `PeersTest` (2), `ConsoleHealthTest` (Selenium: an operator, a reader, someone with no grant,
against a fake second server and a silent third). Bites in `bites/D38/`: `catalog-health-for-anyone`,
`server-health-for-anyone`, `one-server-only`, `window-never-moves`, `histograms-roll-over`,
`table-health-for-anyone`, each biting. docs/observability/health-page.md describes it all.

What is left: no test runs two real servers; the second server is a stand-in answering the server route. The chart's
headless Service was checked with `helm lint` and `helm template` only, not in a cluster, and the demo was not
started. The figures of a server that restarted or went away within the day are lost with it, and the last day is
each server's own (a younger server counts from its start).
