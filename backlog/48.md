Done when the console (`catalog-server/src/main/resources/keel/ui`, plain JavaScript, no third-party code) has:
- A health page. At the top, catalog health for the whole deployment, not one server: alerts fired by kind over the
  last day (item 39's counters), the audit's Kafka acknowledgement time, credential vending failures, request
  latencies against the SLOs (load p99 < 50 ms, 304 p99 < 10 ms, commit p99 < 300 ms), and the worker's last
  successful scan and recent failures (item 47).
- Each server holds only its own meters, so the page's figures are gathered from every server. How is this item's to
  settle (for example a headless Service each server resolves by DNS: the servers mount no service account token, so
  no Kubernetes API call). If it needs a schema step or a new dependency, ask Paul first.
- Beneath it, the neediest tables (item 47's read route), only those the viewer may read, each linking to its
  table's page.
- On each table's page (`detail.js`), its health: the latest assessment, why it is needy, when it was last compacted.
- Catalog health is shown only to the platform operators' group (SEC-1); a table's health to anyone who may read the
  table.
- The console's end-to-end tests (Selenium, P8) cover the page for an operator, for a reader who sees only their own
  tables, and for someone who sees no catalog health. Bites in `bites/D38/`.
