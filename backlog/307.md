Paul, 2026-11-27, after Atelier's advice on where the console should link to the documentation site (backlog 301):
"Yes, build them".

What is missing: the documentation site (`docs/site/`) opens only from disk. The console has no link to it, and a
deployment has no copy of it to link to.

Atelier's plan: the server serves `docs/site` at `/docs/` from its own jar, so the documentation always matches the
build that runs and works on a network with no way out; one setting, `nuna.ui.docs-url` (unset: `/docs/`; a URL: a
copy elsewhere; `none`: every link hidden), points the console's links; the console links from its header (a Docs
button; in the drawer on a phone), from each page (the documentation of the page shown), from the keys dialog, from
the sign-in screen and from the states that hold nothing for the caller; and the console and the documentation share
one theme key.

What done looks like: `GET /docs/` answers the site's home with no token, under a Content-Security-Policy that allows
no connections; the site's tools and design notes are not in the jar; `/ui/config.json` carries `docs-url`; the
console draws its links from it. `DocsSiteTest` (fast) and `ConsoleTest`, `ConsoleConfiguredTest` (heavy) show it.
