Paul, 2026-11-27, after Atelier's advice on where the console should link to the documentation site (backlog 301):
"Yes, build them".

What is missing: the documentation site (`docs/site/`) opens only from disk. The console has no link to it, and a
deployment has no copy of it to link to.

Atelier's plan: the server serves `docs/site` at `/docs/` from its own jar, so the documentation always matches the
build that runs and works on a network with no way out; one setting, `nuna.ui.docs-url` (unset: `/docs/`; a URL: a
copy elsewhere; `none`: every link hidden), points the console's links; the console links from its header (a Docs
button; in the drawer on a phone), from each page (the documentation of the page shown), from the keys dialog, from
the sign-in screen and from the states that hold nothing for the caller; and the console and the documentation share
one theme key.

What done looks like: `GET /docs/` answers the site's home with no token, under a Content-Security-Policy that allows
no connections; the site's tools and design notes are not in the jar; `/ui/config.json` carries `docs-url`; the
console draws its links from it. `DocsSiteTest` (fast) and `ConsoleTest`, `ConsoleConfiguredTest` (heavy) show it.

What was done: the server serves `docs/site` under `/docs/` from its jar (`UiWiring`; `processResources` copies the
site without `tools/` and the Markdown notes), with no token (`Authentication`) and a Content-Security-Policy that
allows only the site's own files and no connections. `nuna.ui.docs-url` (`UiSettings`: `/docs/` by default, an
http(s) URL, or `none`; anything else stops the server) reaches the console as `docs-url` in `/ui/config.json`. The
console draws a Docs button in its header that opens the documentation page of the page shown, at the tab shown
(in the drawer on a phone, as "This page in the docs"), a line naming the documentation in the keys dialog, a link
on the sign-in screen, and "Who may use what, in the docs" on a page the caller's groups cannot use and on the page
for a caller who holds nothing. The documentation reads the console's theme key (`nuna.theme`), so one choice holds
on both. `configure/server.html` documents the setting.

Checked: `DocsSiteTest` (3 tests, fast), `ConsoleTest` and `ConsoleConfiguredTest` (8 tests, heavy, run by hand),
`ConsoleRulesTest`, `CatalogListTest`; five bites (three recorded again, two new) bite; the fast build is green;
`docs/site/tools/check.py`: 156 files, 0 errors.

Left: one change from Atelier's plan: the per-page link is the header's Docs button itself, which follows the page
shown, not a second link beside Copy path and Copy link on each page. Next-step links in the other empty and
refused states come as each state is touched. The console's new links were not seen in a browser: the demo runs an
older commit, and the console's browser tests do not cover them.
