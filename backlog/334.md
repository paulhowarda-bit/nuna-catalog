# 334. Maintenance skips tables closed until classified without loading them, and alerts when it has for a day

Effort: M, a flag on the work list, the worker's skip, a gauge, an alert rule with its promtool test, and three bites


Follow-up to item 327's open question, answered by catalog-security on 2026-11-28 (option (b)), read from the code
and not seen live.

What is wrong:
- A table in a regulated area with no classification is closed until classified (D27): `Authorizer.decide` answers
  403, reason `UNCLASSIFIED` (catalog-security/src/main/java/nuna/catalog/security/Authorizer.java, around line 287).
  The maintenance worker's load of it is refused like anyone's.
- Each scan, about 288 a day per closed table, that refusal publishes an audited denial, flooding the denial trail.
- It also counts in `nuna_maintenance_failures_total{kind="table-load"}`, so `NunaMaintenanceJobFailing` (`for: 3h`)
  probably fires as a misleading "jobs fail at every scan" (`Worker.java` around line 400, `WorkerMetrics`,
  `deploy/grafana/rules/nuna-maintenance.rules.yaml`).

The decision, catalog-security's option (b): the maintenance principal stays refused by the closure, with no
exemption; who the Authorizer lets through does not change.

Done when:
- Catalog: in `MaintenanceRoutes.work`, each `tables` and `requests` entry for a closed table carries `"closed": true`
  (closed: `authorizer.decide` for the calling maintenance principal, on the operation the worker's load uses, is
  `Denied` with `UNCLASSIFIED`, as `MaintenanceEstate` already detects it). The check refuses nothing and gives
  nothing, so it publishes no denial.
- Worker: skips a closed entry without loading it, still names it in the scan's `failed-jobs` with reason `closed`
  (item 327, so the console is unchanged), no longer counts it in `nuna_maintenance_failures_total`, and sets the gauge
  `nuna.maintenance.tables.closed` (`nuna_maintenance_tables_closed`): how many work-list entries the last finished
  scan found closed, with no table label.
- Alert `NunaMaintenanceSkipsClosedTables` (`max by (job) (nuna_maintenance_tables_closed) > 0`, `for: 1d`, warning),
  with a promtool test `deploy/grafana/tests/nuna-maintenance.test.yaml` (fires after a day at 1, silent at 0) run from
  `AlertRulesTest`; the gauge and the alert in docs/observability/worker-metrics.md.
- Tests: `AuthorizerTest` (the maintenance principal refused `select` and `write` on a closed table, `UNCLASSIFIED`),
  a catalog work-list test (closed flag on the closed table only, no denial published), a catalog-maintenance test
  beside `FailedJobsReportTest` (no load, counter unchanged, gauge 1, report names the table with reason `closed`).
  Bites: `bites/D27/` exempting maintenance from the closure, dropping the flag, loading closed entries anyway.
