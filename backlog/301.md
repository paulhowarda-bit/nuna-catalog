Paul, 2026-11-26: "we need to build the best technical documentation known to man for this catalog. It should include
everything you can do, UI and commandline. Installation and everything in a typical software package documentation.
It should be web pages." He asked that Atelier be consulted.

What is missing: nuna's documentation is internal Markdown written for agents and Paul (`deploy/README.md`,
`demo/README.md`, `docs/install-at-work.md`, the module READMEs, `docs/observability/`). There is no user-facing guide
to the console, no reference for the REST and management APIs or the `nuna.*` settings, and no install guide written
for someone who has not read the decision ledger.

What done looks like: `docs/site/index.html` opens from disk with no server and no network; every page the site map
in `docs/site/DESIGN.md` names exists, says only what the code does (each fact checked against the source), and every
link between pages resolves.

What was done: `docs/site/`, 156 static pages that open from disk with no server and no network, in the console's
Ice line look, light and dark, phone width and print. Atelier designed it (`docs/site/DESIGN.md`: the site map, ten
page types, the HTML contract, the voice rules) and built the chrome (`assets/`), local search (`tools/index.py`),
the contract checker (`tools/check.py`, with `tools/test_check.py` and a fixture), the home page, 33 screenshots of
the running demo's console in light and dark, and six diagrams. Eleven writers wrote the pages from the code: Get
started (four tutorials), Concepts, the demo, the console guide (every page and tab), 18 task guides, clients and
curl, install (Helm, the four databases, object storage, identity provider, locked-down networks), every `nuna.*`
setting and Helm value, operate (metrics, traces, dashboards, a runbook per alert rule, troubleshooting), security,
both APIs endpoint by endpoint, and reference (errors, privileges, audit records, limits, glossary, FAQ).
`python docs/site/tools/check.py`: 156 files, 0 errors, 0 warnings.

Left: three screenshots are pending because the demo cannot show them truthfully (its audit table is empty, no
archive is configured, and the first-table tutorial's table is not there), and about 40 visible gaps (`p.gap`, which
`check.py` lists) where the code does not settle a fact. Links to endpoints from outside `api/` go to each API page's
endpoint table, not to the endpoint's own block. After a change to a page, run `tools/index.py` and `tools/check.py`.
