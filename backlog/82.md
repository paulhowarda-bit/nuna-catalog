Item 68 hid a catalog from a caller that holds nothing on it on `GET /v1/config?warehouse=<name>` and on every route
under the prefix (D18, amended 2026-11-20). Paul's decision names the config call with a warehouse; it does not say
what a client that names no warehouse is told when the deployment sets a default (`nuna.rest.default-warehouse`,
item 56) and the caller holds nothing in that catalog. Item 68 left it as it was: `GET /v1/config` answers 200
with the default catalog's prefix to any signed-in caller (`ConfigRoute.defaultCatalog`), so such a caller still
learns the default catalog's name.

The choices:

- 404 NoSuchWarehouseException, as if the default named a catalog that does not exist: the name stays hidden, and an
  engine with no grant fails at its first call.
- 400, as if no default were set ("Missing query parameter warehouse"): hides even that a default exists.
- 200 as today: the default's name is part of the deployment, not of any catalog's contents.

Done when Paul has chosen, `ConfigRoute` answers so, and a test shows the answer to a caller that holds nothing in
the default catalog beside one that holds something there.

**Paul's answer, 2026-11-20 (D18):** "404, like missing": `/v1/config` with no warehouse, a default catalog set and a caller that holds nothing in it answers the 404 a missing catalog gets.

Done, under item 68's claim (`./backlog.sh claim 82 catalog-server/` was refused: item 68 holds `catalog-server/`):
`ConfigRoute` takes the default warehouse's name when the client names none and finds it through `Holdings.catalog`,
as it finds a named one. A caller that holds nothing in the default gets the 404 NoSuchWarehouseException a missing
warehouse gets, echoing the configured default's name as a default naming no catalog always has, and the refusal is
audited (`getConfig`). Platform operators, grant admins, a registered trusted engine acting as itself (item 84) and
any caller that holds something in the default get its config. With no default set the answer is still 400.
`ConfigRoute` no longer reads the store itself.
