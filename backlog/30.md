# 30. Two bites fail only by stopping the server's start, so run.sh calls them SETUP

Status: open
Added: 2026-11-14 by the agent closing item 3

Since item 3, `bites/run.sh` reports a bite as SETUP when every failure came from starting the tests' fixtures,
a Spring context that did not load among them. Two recorded bites break the server so that its context never
loads, so the test they name never reaches an assertion, and they now come out SETUP:

- `bites/M8/store-skips-postgresql-steps.patch` (`SchemaAtStartupTest`). Run on 2026-11-14:
  `SETUP: 1 of 1 failed in setup`. The context fails with `ERROR: function journal_extend(timestamp with time
  zone) does not exist`: without the PostgreSQL steps there is no `journal_extend`, and `migrate()` calls it.
- `bites/D7/oracle-backend-runs-sql-store.patch` (`OracleBackendTest`, heavy). Not run; read from the code: the SQL
  store's `migrate()` asks Oracle `SELECT version()`, which fails, so `StoreWiring` cannot make the store and the
  context does not load either.

A failure in startup shows only that the server did not start, which any server test shows, and a crowded Docker
shows the same way. `./heavy.sh` and the overnight run will fail on both until they are dealt with.

Done when each either bites on an assertion (a different break of the same check, or a test that checks it without
starting the whole server) or Paul has said what to do with it, and `bites/run.sh` on both reports BITES or his
decision is recorded here.
