`demo/demo.sh up` reads the checkout it is in for its whole run: Gradle builds the jars from it, `docker build`
reads its Dockerfiles, `apply` reads `demo/k8s`, and bash reads `demo.sh` itself a chunk at a time. Run from the
main checkout, as D49 says, it shares that checkout with every `land.sh`, which moves its files mid-run. On
2026-11-24 this bit three times: an `up` stopped midway when items 195/196 landed and changed `demo.sh`; an `up`
built images from 2a776fdf while 248 landed at af8b0353 during the build, so the demo may have run a mix of both;
and sessions kept telling one another "main moved since, not in it", unable to name what the demo ran.

Done looks like: `up`, and every other command that reads repo files (engines, gen, ss, kafka, cdc, token, rate),
started in the main checkout, pins its HEAD at the start and runs from a detached, locked worktree at that commit
in `$NUNA_DEMO_HOME/checkout`, as the overnight run does for its tests (backlog 166); `up` prints the commit it
builds and `print_access` the commit the demo runs; a scratch-repo test shows a landing during the run changes
neither the script nor the files it reads; CLAUDE.md's D49 says so. Run from any other worktree, demo.sh runs in
place as before.
