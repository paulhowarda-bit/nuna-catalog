# 148. The audit feed and summary answer 500 where audit tables are configured: the reader loads Iceberg's AWS client factory, which needs the KMS SDK the server leaves out

Status: open
Added: 2026-11-22 by Paul
Touches: catalog-audit-tables/src/main/java/nuna/audittables/EventsReader.java, catalog-server/build.gradle.kts, catalog-server/src/test/java/nuna/audittables/, bites/D23/feed-reader-builds-aws-factory.patch, backlog/125.md
Effort: S, one constructor call in the reader, a Java-only test on the server's classpath, a bite and a build-file comment

Paul's click-through of the nuna-demo on 2026-11-22, the first with the audit tables configured (item 144): the
console's Audit page calls `GET .../audit/feed` and `.../audit/summary` (item 125) and both answer 500. The catalog
server's log (`kubectl --context docker-desktop -n nuna-demo logs deployment/nuna-catalog`):

- the first call: `NoClassDefFoundError: software/amazon/awssdk/services/kms/model/EncryptionAlgorithmSpec`, at
  `AwsProperties.<clinit>`, from `AwsClientFactories.<clinit>`, `S3FileIOAwsClientFactories.initialize`,
  `PrefixedS3Client.<init>(PrefixedS3Client.java:67)`, `S3FileIO.newInputFile`, `TableMetadataParser.read`,
  `EventsReader.open(EventsReader.java:199)`;
- every later call: `NoClassDefFoundError: Could not initialize class org.apache.iceberg.aws.AwsClientFactories`.

`catalog-server/build.gradle.kts` links `:catalog-audit-tables` without `software.amazon.awssdk:kms`: the server never
calls KMS (D26, `NoKmsBoundaryTest`). `EventsReader.open` hands Iceberg's `S3FileIO` the server's S3 client but no
asynchronous one, and Iceberg 1.12's `PrefixedS3Client` builds the missing one's supplier from
`S3FileIOAwsClientFactories` as soon as the first file is opened, whether or not it is ever used. That factory's class
needs the KMS model classes. So the feed fails in every deployment with audit tables configured. No test caught it:
`AuditFeedRoutesTest` uses a double of the table, `EventsReaderTest` runs on catalog-audit-tables' own classpath,
which has the KMS SDK, and the heavy `ConsoleBrowserTest` runs with no audit tables.

What done looks like:
- The reader opens and pages the table on the server's runtime classpath, the KMS SDK still absent, without loading
  Iceberg's AWS client factories, so the server still neither needs nor calls KMS (`NoKmsBoundaryTest` holds).
- A test in the fast build reads a real table through `EventsReader.open` on the server's classpath, with no
  network; it fails today with the `NoClassDefFoundError` and passes after.
- Its bite, restoring the broken path, recorded under `bites/D23/`.
- The build file's comment says why the KMS SDK can stay out.
- Item 125 says its route tests do not use the real reader.
