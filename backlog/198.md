Done (2026-11-23, local_e487fb16): `GET /management/v1/names?q=&catalog=&pageToken=&pageSize=` (`NameSearchRoutes`).
- It lists every namespace, table and view whose name holds the fragment, with its catalog, path and kind, in every
  declared catalog the caller holds something in (`Holdings.inCatalog`), or in the one named. A named catalog is found
  as every route finds one (`Holdings.catalog`, item 68): one the caller holds nothing in answers 404 as an unknown one
  does, and the refusal is audited; an undeclared one answers the same 404, unaudited. Rows the caller may not
  describe are skipped and never counted, and searching writes no denial.
- A table or view is listed where the authorizer allows `describe`; a namespace where a grant reaches it or anything in
  it (`Holdings.onAboveOrIn`'s rule), read once per catalog from the caller's own grants there. A grant admin finds
  everything; a platform operator, and a trusted engine acting as itself with no grants, find no names; an engine
  acting for a user finds what that user may describe; a closed-until-classified table (D27) is found.
- From the `catalog-security` review of 2026-11-23: every object of a held catalog is decided, a fixed 200 at a time,
  before its name is looked at, and namespace visibility is known before the walk, so a hidden match costs what no
  match costs (D18); a caller who holds nothing is answered at once, with no token; the page token carries a skip
  count, not a store cursor of our making; `more-namespaces` also says when the walk stopped at its limit. Left as
  follow-ups, by the review: a forged token only moves the start point (the store cursor is an object id), and there is
  no way to page past `more-namespaces`.
- Paged: namespaces first, then tables, then views; at most 200 rows a page and 5,000 objects examined.
- Go to a path: what you opened lately first (kept per person in this browser), then what this catalog has listed,
  then the search's matches, each with its catalog when it is not the one open; with nothing typed, opened lately,
  then tonight's queue. "No namespace, table or view you may see has a name like that, in any catalog" when nothing
  matches; the old "listed so far" answer, with an example from this catalog, only when the search does not answer.
- Tests: `NameSearchRoutesTest` (Java only: each role, D27, an undeclared catalog, a named catalog, a hidden match's
  cost, paging) and `ConsoleBrowserTest#goToAPathOpensAFullDottedPathNotListedYet` (a name typed alone opens, then
  comes first as opened lately). Bites: `name-search-lists-undescribed`, `name-search-decides-matches-only`,
  `name-search-shows-every-namespace`, `name-search-named-catalog-unaudited` (each checked to bite),
  `console-goto-no-search`; `console-goto-example-fixed` retired, as the example it guarded now shows only when the
  search does not answer.
