# 50. backlog.sh done fails on a branch name with a slash

Status: done
Done: 2026-11-15 on worktree-agent-a5dc2e6403550e821
Added: 2026-11-15 by obs37 report-sanitize agent, while doing item 37
Touches: backlog.sh

`./backlog.sh done <n>` writes the `Done:` line with `sed -i "s/^Status: open\$/Status: done\nDone: $today on $branch/"`
(`backlog.sh`, `cmd_done`). The branch name goes into the expression unescaped, and the app now names worktree
branches `claude/<name>`, so the slash ends the replacement early. The command then prints that it marked the item
done although it changed nothing:

    $ ./backlog.sh done 37        # on claude/obs37-report-sanitize-83a9ec
    sed: -e expression #1, char 59: unknown option to `s'
    backlog/37.md marked done: say what was done beneath it, commit and land, then ./backlog.sh release 37

`backlog/37.md` still read `Status: open`; the agent wrote the two lines by hand.

Done when `done` writes `Status: done` and `Done: <date> on claude/<name>` for a branch with a slash (and any other
character sed treats specially, such as `&`), fails with a message when the edit does not happen, and a test or a
scripted run shows both.

What was done: `cmd_done` no longer builds a sed expression. It hands the `Done:` line to awk as data (through the
environment, `ENVIRON["DONE"]`, so not even awk's `-v` escapes apply), writes the edited copy to `<item>.md.new`, and
replaces the item only once that copy holds both `Status: done` and the exact `Done:` line; otherwise it removes the
copy, prints `could not mark backlog/<n>.md done; it is unchanged` and exits 1. Nothing else in `backlog.sh` changed,
and `backlog/README.md` needs no change (item 52's condition).

`./test-backlog.sh` shows both, in a scratch repository so this clone's claims are untouched: on branch
`claude/x&y$1.w#v%u` it claims an item and `done` writes exactly the two lines; with `awk` stubbed on the PATH to copy
the item unchanged, then to exit 1, `done` refuses with that message, exits non-zero and leaves the item byte for byte.
All three checks pass; against main's `backlog.sh` all three fail, the first with this item's
`sed: -e expression #1, char 59: unknown option to 's'` and the item still open. `done` also marked items 50 and 51 on
this branch.

Left over: nothing. A branch name cannot hold `\` (git refuses it) nor, on Windows, `|` (a ref is a file), so the test
uses the characters git and Windows let a branch hold.
