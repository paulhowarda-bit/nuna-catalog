# 50. backlog.sh done fails on a branch name with a slash

Status: open
Added: 2026-11-15 by obs37 report-sanitize agent, while doing item 37
Touches: backlog.sh

`./backlog.sh done <n>` writes the `Done:` line with `sed -i "s/^Status: open\$/Status: done\nDone: $today on $branch/"`
(`backlog.sh`, `cmd_done`). The branch name goes into the expression unescaped, and the app now names worktree
branches `claude/<name>`, so the slash ends the replacement early. The command then prints that it marked the item
done although it changed nothing:

    $ ./backlog.sh done 37        # on claude/obs37-report-sanitize-83a9ec
    sed: -e expression #1, char 59: unknown option to `s'
    backlog/37.md marked done: say what was done beneath it, commit and land, then ./backlog.sh release 37

`backlog/37.md` still read `Status: open`; the agent wrote the two lines by hand.

Done when `done` writes `Status: done` and `Done: <date> on claude/<name>` for a branch with a slash (and any other
character sed treats specially, such as `&`), fails with a message when the edit does not happen, and a test or a
scripted run shows both.
