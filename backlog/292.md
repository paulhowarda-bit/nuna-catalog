# 292. GitHub's push protection refuses the openssl pkcs8 command's argument order

Status: done
Done: 2026-11-26 on secret-scanning
Added: 2026-11-26 by Paul (work note 007, 2026-11-26)
Touches: demo/demo.sh deploy/README.md docs/install-at-work.md build.gradle.kts docs/from-work/
Effort: S, one command written in a new order in three places and one shape in the build's check

From `docs/from-work/007-github-push-protection-openssl-pkcs8.md`: work's GitHub refused the 2026-11-26 drop with
`HIGH_CONFIDENCE_ECS_CLIENT_SECRET_FORMAT_VALUE` on the command that turns the database client key into PKCS #8 DER,
in `demo/demo.sh` (`db_tls`), `deploy/README.md` and `docs/install-at-work.md`. With `-in client.key` before
`-outform DER` it is refused; with `-inform PEM -outform DER -nocrypt -in client.key -out client.pk8` work's push was
accepted. `secretShapes` did not catch it.

Done when the three places use the accepted order and `secretShapes` fails on the refused one.

What was done: the three places write the command in the order work's push accepted
(`-topk8 -inform PEM -outform DER -nocrypt -in client.key -out client.pk8`; `-inform PEM` is openssl's default, so
the conversion is the same). `secretShapes` fails on an `openssl pkcs8` line that gives its input before `-outform`;
a planted copy of the refused line in `deploy/README.md` failed it, and the clean tree passes. The work note
describes the refused command in words rather than quoting it.

Left: `demo.sh`'s `db_tls` was not run with the new order; work's push used the same order.
