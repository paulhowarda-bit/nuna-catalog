In the overnight run of 2026-11-28 (commit ce73c9d0) every container-backed test in the heavy build (373 failures,
10 min) and the Ceph leg (31 failures, 2 min) failed at its start with `java.lang.IllegalStateException: Could not
find a valid Docker environment` (then `Previous attempts to find a Docker environment failed. Will not retry`), or
with a Spring context that would not load because of it. Every module with such tests was hit: catalog-server 179,
catalog-core 130, catalog-maintenance 27, catalog-security 14, catalog-tests-conformance 8, and the rest. The nightly
leg started six seconds after the Ceph leg ended (01:50:45) and passed in 120 min, its store suites all on
containers, so Podman was reachable by then. A first pass the same night, from 00:07 on f5c61065, failed the same way
in its heavy build, Ceph leg and nightly (2.5 min), after "Podman still held test containers, or did not answer,
after 3 min". The heavy run by hand started at 06:26 reached Podman. The test reports' system-err is empty, so the
strategy's own reason (`nuna.catalog.tests.docker.FreshPipeStrategy`, with `TESTCONTAINERS_CLIENT_PING_TIMEOUT` 60 s
from overnight.sh) is not recorded. Because of it, 226 bites were not run that night.

Evidence: `C:\Users\paulh\code\nuna-catalog\.overnight\runs\2026-11-28\summary.md`, `overnight.log`, `heavy.log`,
`ceph.log`, `heavy-results\podman-info.txt`, and for example
`heavy-results\catalog-audit\build\test-results\test\TEST-nuna.catalog.audit.archive.LockedArchiveTest.xml`.

Done when the cause is named, the run waits for Podman (or records why the strategy gave up) before its heavy leg,
and the overnight run's heavy build and Ceph leg reach containers.
