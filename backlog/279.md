`{"refs":[...]}` or `{"all-refs":true}`, gated by `manage-tags` on the object, audited), so a dropped table's data can
leave the tags that keep it and cleanup can delete its files. The console has no control for it: `backlog/156.md`
says "The console has no control for the route yet (item 109's screens are where it would go)". An operator has to
call the API by hand.

`manage-tags` on it can take it out of chosen refs or all of them, through a dialog that says what this does (the
refs no longer keep its files, and a dropped table's data can then be deleted by cleanup), names what the answer
left, and shows a refusal as the catalog answered it; callers without the right see no control; a browser test
(heavy) and the fast console rules tests. Atelier decides the control's design and words; ask her through the

## Atelier's design, 2026-11-25

Relayed word for word by the Catalog UI Expert session (`atelier-2026-11-25-279-167-169-170.md`, section 279).

### What it stands on (check before building)

- **No read lists the refs that keep a table.** `RefRoutes` calls `store.listRefPointers(object.id())` only inside the removal. Item 170 needs the same fact. Build it once, in 170, which is starting now, and have 279 wait on it. If 279 starts first, it builds the read to this spec and 170 adds the drop's actor.
  - **The read:** by path (namespace and name; the route's shape is the builder's choice) and by id. For each table or view at that path that is not purged, live or dropped, newest first:
    - `id`, `kind`, `state`, `dropped-at`, `dropped-by`, `purge-after`;
    - `refs`: each ref whose cut keeps it, with `name`, `kind`, `created-at`, `expires-at`, `expired` (past expiry, name still held), and `own-version` (a branch's own pointer for it, if any);
    - `may: {remove}`: whether the caller holds `manage-tags` on it.
  - Objects the caller holds nothing on are left out. It is gated by `describe`, with a 404 for a caller holding nothing, as Holdings does.
- **Why not Overview:** Overview, Schema and History load through `loadTable`, which needs `select` (`Guard.LOAD_TABLE`). A tag steward (the TAGS duty, kept apart from DATA by D18) may not hold it. A dropped table also answers 404 on main by path, so the governance read that gives the console its object id fails too.

### Where the control sits

1. **The Access tab** of the table or view page, on main and read through a ref. Access is where labels and holds already live: what protects the data and what keeps it.
   - A panel, `id="kept-by-refs"`, placed after the governance panel. It draws from the read alone, never from `loadTable` or governance, so it works for a steward without `select` and for a dropped table read through a ref.
   - Through a ref it needs no "main's" note: the refs are the catalog's, the same through any ref.
2. **Item 170's "Dropped on main, read on main" state:** its list of refs carries the same button and the same panel words (see 170 below).
3. **Overview is unchanged.**

### The panel: every word

| Element | Words | When |
|---|---|---|
| Title | `Kept by branches and tags` with meta `{n}` | always; no meta when n is 0 |
| Lead (live) | `Each reads this {kind} as it was at its point, or as the branch has changed it, and keeps its files from cleanup.` | n ≥ 1, state active |
| Lead (dropped) | `Main dropped this {kind} on {d Mon}. These still read it and keep its files from cleanup; once none does, cleanup can purge it and delete its files.` then, if `purge-after` is known: ` Its purge time is {d Mon}.` | n ≥ 1, state dropped |
| Empty | `No branch or tag keeps this {kind}.` | n = 0 |
| Row | `@name` chip (`cref`), linked to this {kind} read through that ref; then `tag · made {d Mon}` or `branch · expires {d Mon}`; add ` · changed it: its version {own-version}` when present; add ` · you are reading it here` when it is the page's ref | each ref |
| Row, expired | chip, then `branch · past its expiry {d Mon}; the worker ends it at its next run` | `expired` |
| Button | `Take out of branches and tags` (`btn sm`, `data-act="take-out"`) | `may.remove`, n ≥ 1, no hold or freeze known |

| No right, dropped | `A tag steward, holding manage-tags on it, can take it out of them so cleanup can delete its files.` | no `may.remove`, state dropped |
| No right, live | nothing: the list only | no `may.remove`, state active |
| Read refused | `failure(error, {compact: true})`, as the catalog answered | the read fails |

- Hold and freeze come from governance when the page has it. A dropped table has no governance on main, so the button shows, and a hold refuses verbatim in the dialog.

### The dialog

- **Title:** `Take {name} out of branches and tags`
- **Paragraphs, in order:**
  1. **`Each branch and tag you choose stops keeping {path}.`** ` Reads of it through them answer 404, as if they had never held it, and they no longer keep its files from cleanup.`
  2. If dropped: `Main dropped it on {d Mon}. Once no branch or tag keeps it, cleanup can purge it and delete its files.` If live: `Main still has it. Files that only these reached are left to the orphan scan, which removes them once they are older than its minimum age.`
  3. Only when a listed ref is a branch with `own-version`: `A branch's own commits to it go too, so a merge can no longer bring them to main.`
  4. **`This cannot be undone:`** ` no branch or tag can take it back. Each ref's record in the audit names the change.`
- **Choice:** a fieldset with legend `Take it out of`. Nothing is chosen when it opens.
  - Radio: `Every branch and tag that keeps it ({n})`, with the fine line `Those that keep it when the catalog runs this, a branch past its expiry included.` This sends `{"all-refs": true}`.
  - Radio: `Only the ones I tick`, followed by one checkbox per ref, using the panel's row words. Ticking a box selects this radio. This sends `{"refs": [...]}`.
  - An expired branch's checkbox is disabled, with the fine line `Past its expiry: Every takes it out, or the worker ends it at its next run.` The route refuses an expired ref named by name.
- **Submit button** (class `danger`). Its label follows the choice:
  - nothing chosen: `Take it out`
  - one ticked: `Take it out of @{name}`
  - several ticked: `Take it out of {k} branches and tags`
  - Every: `Take it out of every one`
  - Submitting with nothing chosen writes `Choose which branches and tags to take it out of.` in the dialog's answer area, as the make dialog does with `Name the ref.`
- **Focus** starts on Cancel, as in `deleteDialog`, so one Enter never removes anything.
- **Phone, 390x844:** a long list scrolls inside the dialog, and the buttons stay in view. Check this; `.dlg` ran past the viewport before.
- **What the answer left** (`granted`). Afterwards the submit is hidden (item 109, choice 7):
  - Title: `Took {path} out of {@a, @b}` (chips, from the answer's `refs`).
  - More, by what a fresh read shows:
    - dropped, none left: `No branch or tag keeps it now. Cleanup can purge it and delete its files.`
    - some still keep it: `{@x, @y} still keep it.`
    - live, none left: `Main still has it; no branch or tag keeps it now.`
  - Every, with an empty `refs`: title `Nothing to take out`, more `No branch or tag kept {path} when the catalog looked; nothing changed.`
- **On close:** the panel reads again. If the page reads through a ref the table just left, go to the same {kind} on main (drop `r=`). A live table loads there; a dropped one shows 170's state.
- **A refusal:** `failure(error)` in the dialog's answer area, with the catalog's words verbatim. The dialog stays open with its button; nothing changed. Notes (`opts.note`):
  - `NoSuchRefException`, or a `NoSuchObjectException` whose message names a ref (`… on ref …`): `The branches and tags changed since this list was read. The list above is read again; choose again.` Then read the list again into the dialog.
  - `NoSuchObjectException` for the object itself: `It may have been purged since this page was read.`
  - Anything else (a 403 for the right, `legal_hold` or `dr_freeze`, or the 409 `RefsChangedException`, whose message already says "ask again"): no note. `failure` already adds `The refusal is recorded in the audit.` to a 403.
