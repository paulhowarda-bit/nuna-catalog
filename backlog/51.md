# 51. ConsoleBrowser.awaitText throws on a stale element instead of waiting

Status: open
Added: 2026-11-15 by obs37 report-sanitize agent, while doing item 37
Touches: catalog-server/src/test/java/keel/catalog/server/ConsoleBrowser.java

`ConsoleBrowser.await` (`catalog-server/src/test/java/keel/catalog/server/ConsoleBrowser.java:89`) waits with a plain
`WebDriverWait`, which ignores only `NotFoundException`. `awaitText` and `await(By)` call `isDisplayed()` and
`getText()` on elements they just found; when the console re-renders the element between the find and the call,
Selenium throws `StaleElementReferenceException` and the wait ends with it instead of looking again.

Evidence: on 2026-11-15 the fast build failed twice in a row, on branch `claude/obs37-report-sanitize-83a9ec`
(which changes only the metrics route) after the keel-demo stack was taken down, with one test:

    ConsoleBrowserTest > grantsAreMadeAndRevokedAndASeparationOfDutiesRefusalIsShownVerbatim() FAILED
    org.openqa.selenium.StaleElementReferenceException: stale element reference: stale element not found in the current frame
        at keel.catalog.server.ConsoleBrowser.awaitText(ConsoleBrowser.java:103)
        at ...ConsoleBrowserTest.grantsAreMadeAndRevokedAndASeparationOfDutiesRefusalIsShownVerbatim(ConsoleBrowserTest.java:313)

Line 313 waits for "Revoked select from …" in the status line, which the console redraws after the revoke. Run alone,
the class passed 7 of 7; it fails only beside another module's tests, when timing shifts.

Done when the waits ignore `StaleElementReferenceException` (`.ignoring(...)` on the `WebDriverWait`) and look again,
and `ConsoleBrowserTest` passes in several fast builds in a row.
