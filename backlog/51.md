`ConsoleBrowser.await` (`catalog-server/src/test/java/nuna/catalog/server/ConsoleBrowser.java:89`) waits with a plain
`WebDriverWait`, which ignores only `NotFoundException`. `awaitText` and `await(By)` call `isDisplayed()` and
`getText()` on elements they just found; when the console re-renders the element between the find and the call,
Selenium throws `StaleElementReferenceException` and the wait ends with it instead of looking again.

Evidence: on 2026-11-15 the fast build failed twice in a row, on branch `claude/obs37-report-sanitize-83a9ec`
(which changes only the metrics route) after the nuna-demo stack was taken down, with one test:

        at ...ConsoleBrowserTest.grantsAreMadeAndRevokedAndASeparationOfDutiesRefusalIsShownVerbatim(ConsoleBrowserTest.java:313)

Done when the waits ignore `StaleElementReferenceException` (`.ignoring(...)` on the `WebDriverWait`) and look again,

What was done: `ConsoleBrowser.await(String, Function)`, which `await(By)` and `awaitText` go through, adds
`.ignoring(StaleElementReferenceException.class)` to its `WebDriverWait`, so a stale element makes the wait look again
until `WAIT` runs out, as a missing one already did. Nothing else in the file changed (item 48 changes it next).
