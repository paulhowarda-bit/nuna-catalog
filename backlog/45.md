# 45. A sanitized scan filter's hash can be reversed for short values such as an SSN (Paul decides)

Item 37 sanitizes a scan report's filter with Iceberg's own `ExpressionUtil.sanitize` before the report reaches the
`nuna.telemetry.metrics` logger, as the stock Java client does before sending. A string literal becomes
`(hash-%08x)`, and that hash is Iceberg's `bucket[2147483647]` transform: an unkeyed 31-bit Murmur3, the same on
every machine (javap of iceberg-api 1.12.0, `ExpressionUtil.<clinit>`). A value from a small space can be recovered
from the log by trying every candidate.

Evidence (2026-11-15, a scratch program on iceberg-api 1.12.0, eight cores): `ExpressionUtil.sanitize` turns
`ssn == "123-45-6789"` into `ref(name="ssn") == "(hash-7f7bcfed)"`. Hashing all 10^9 strings of the form
`ddd-dd-dddd` took 8.2 s and found two that give `7f7bcfed`: `123-45-6789` and `909-09-7755`. Account numbers, dates
of birth and other short identifiers fall the same way. The server cannot fix this for the Java client by hashing its
placeholder again: both steps are the same public function, so anyone reading the logs hashes each candidate twice.

The question for Paul: what may a filter value become in the telemetry logs?
- **Iceberg's hash, as now.** Equal values still match across reports. The log store must then be treated as holding
  recoverable filter values, read only by people who may see the data.
- **A keyed hash.** Replace each `(hash-…)` with an HMAC under a key the server holds (from work's secret store).
  Equal values still match while the key lasts; without the key nothing can be enumerated. The key needs managing,
  and a new key breaks matching across the change.
- **No value at all.** Forward each predicate's column and operator with a fixed `(value)`. Nothing can be recovered
  and nothing needs a key, but reports can no longer show that two scans asked for the same value.

Done when Paul's choice is recorded in `decision-ledger.md` (D13) and, if it changes the code, a test sends
`123-45-6789` and finds in what is forwarded neither the value nor Iceberg's hash of it, with the check recorded as a
bite in `bites/D13/`.

What was done: Paul chose on 2026-11-15 to keep Iceberg's hash ("Keep icebergs hash"); the D13 amendment of that
date records it and its condition, that only people who may see the tables' data may read the log store holding
`nuna.telemetry.metrics`. The code is unchanged, so no test or bite was added.
