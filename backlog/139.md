The redesign's Health page (D45; `docs/design/console/prototype.html`, h2 "Store") has a Store panel: backend and
version, point-in-time recovery, last self-check. `docs/design/console/wireframes.html` asks for
`GET /management/v1/health/store`. Item 124 left it out: no route serves it. Paul approved building it on 2026-11-22.

What the server truly knows:
- Its backend, `nuna.database.backend` (PostgreSQL or CockroachDB through `postgresql`, Oracle, MongoDB), and the
  database's version, asked on the live connection: `SELECT version()` on PostgreSQL's wire (CockroachDB answers
  "CockroachDB CCL v…", as `Backend.of` in catalog-store-sql tells them apart), the JDBC driver's product version on
  Oracle, `buildInfo` on MongoDB.
- Its self-check: every server runs `CatalogStore.selfCheck()` at start (D8.2, `StoreWiring.ready`) and refuses to
  start on a finding, unless `nuna.database.allow-unsafe` names it. When it ran and which findings were let through
  is real, and today only the log says so.
- Point-in-time recovery: no source. It is the database's own backup setting (WAL archiving and a backup tool on
  PostgreSQL, backup schedules on CockroachDB, RMAN and Flashback on Oracle, the backup system on MongoDB), which the
  catalog's role cannot read on most of them and which nothing in the server records. Left out, and the panel says
  why, rather than show a window nobody measured.

What done looks like:
- `GET /management/v1/health/server?store=true` adds a `store` field: the backend found and its version (or what was
  configured and why it could not be read), and the self-check at start with the findings allowed. Who may read it
  is as the route already decides: platform operators; a refusal comes before the database is asked. Opt-in, so the
  other servers asked for their figures (`Peers`) never wait on a database that is down.
- The store API (`catalog-store-api`) is unchanged: the version is read through the server's own DataSource or
  MongoClient, the one read outside the store, and it reads nothing of the catalog.
- Health shows a Store panel to platform operators: backend and version, the self-check at start (passed, or the
  findings it started despite), and why point-in-time recovery is not shown.
- Fast tests: the route's field for each backend (PostgreSQL, CockroachDB, Oracle, MongoDB, unreachable), a refused
  caller never reaching the database, and the self-check's findings allowed. The heavy browser test of item 138 also
  checks the panel. Bites for each.
