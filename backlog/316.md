## Found, 2026-11-27

- `demo.sh sql` opens database `brokerage` now (landed with 313 to 315).
- The writer commits nothing because every commit is refused 403: "service-account-nuna-audit-tables holds no
  privilege that gives modify for updateTable". The demo's `nuna_audit.audit.events` predates the writer's added
  columns (`log_run`, `log_seq`, `branch`, `subject_ids`), and `EventsTable.open` adds them on open, a schema change
  that needs `modify`; `AuditCatalogGrants` gives the writers' group only `create` and `write` (D23, amended
  2026-11-20). At work every upgrade that adds a column meets the same wall.
- catalog-security recommends that the server add the absent columns itself at startup, recorded as
  `nuna-configuration`, and the writer keep `create` and `write` (least privilege: `modify` would let it drop or
  rename the table). That changes what D23 covers, so it waits on Paul. The other ways: grant the writers `modify`
  (amends D23 too), or grant it in the demo alone (no D row; work stays broken until an operator acts).

## What was done

- Paul chose "Server adds them" (D23, amended 2026-11-27). `AuditTableColumns` (catalog-server) runs once the server
  is ready: it finds `<nuna.audit.tables.catalog>.<nuna.audit.tables.namespace>.events`, and if the table lacks any
  of the writer's added columns it commits them through the commit engine as `nuna-configuration`, journaled and
  audited as any commit. No audit catalog, no table yet or nothing absent changes nothing; a failure is logged and the
  server serves on.
- `EventsColumns.update` (catalog-audit-tables) turns the table's metadata JSON into the Iceberg REST commit that adds
  the absent columns with their ids, guarded by the current schema id and last column id, so Iceberg stays out of the
  server's code. A table that gave an added column's id to another column is refused.
- The writer keeps `create` and `write`, and still adds anything absent itself on opening (a writer that holds
  `modify` elsewhere still works).
- Tests: `EventsColumnsTest` (fast, 6) applies the commit as a REST catalog would; `AuditTablesTest#theServerGives
  AnOlderTableTheColumnsTheWriterMayNotAdd` (heavy) has the writer refused on a real server, the server add the
  columns, and the writer open the table. Bite `bites/D23/server-adds-present-columns.patch` bites.
