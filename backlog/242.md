## What is missing

Atelier's design for the rules in the console (2026-11-24; the panel is backlog 243) needs answers the server does
not give:

1. **A flagged table's schema.** The console's table read is refused on a flagged table (backlog 241), so a mask
   editor has no columns to pick from. A describe-only answer, schema and properties with no files and no storage
   credentials, for anyone who may describe the table.
2. **A reader's own view.** Whether their rows are filtered and which columns are masked for them, without the
   expressions. Today the rules list needs manage-grants (`RuleRoutes.java:70`). The security expert says showing the
   column names leaks nothing: the reader already sees the schema and the masked values. The route is audited and
   decided per caller.
3. **Rule counts for stewards.** How many rules a table has and for which groups, in the table's governance answer,
   without the expressions.
4. **Flagged tables in the governance summary,** with their rule counts, and an export of every rule for access
   reviews (manage-grants or audit).

## Done when

Each answer exists, refuses callers who may not have it as the existing routes do, and has route tests and a bite
per refusal.

## What was done

Four answers, each decided for its caller; no filter or mask expression reaches a caller without `manage-grants`.
The routes and shapes are in build-plan.md, M7, "Who may call the management routes".

1. **A table's schema:** `GET .../namespaces/{namespace}/tables/{table}/schema`, describe on the table, flagged or
   not: `{"target", "format-version", "schema", "properties"}`, with no location, snapshot, file or credentials. The
   catalog reads the metadata file itself, checks its hash, and audits the read as an `ObjectRead`, as the export
   does (`RowColumnReadRoutes`).
2. **A reader's own view:** `GET .../tables/{table}/row-column-rules/mine`, select on the table:
   `{"target", "flagged", "rows": "all" | "filtered" | "none", "masked-columns": [...]}`, the caller's groups' rules
   combined as Trino gets them (`RowColumnPolicy`).
3. **Rule counts:** a table's `GET .../governance` carries `"row-column-rules": {"count", "groups"}` for a caller
   with manage-tags or manage-grants on it; anyone else gets the answer without it (`ManagementGuard.allows`).
4. **Flagged tables and the export:** the catalog's governance summary has `tables.flagged` and `flagged`, each table
   with `on` and `rules` (its rule count); `GET /management/v1/catalogs/{catalog}/row-column-rules/export` gives every
   rule in the catalog, with the expressions for manage-grants on the catalog, and without them for an audit reader
   (select on the audit catalog); anyone else is refused as on the grant routes.

Every refusal goes through `ManagementGuard` and is audited as a `Denial`; a caller that holds nothing on the table
or catalog gets the missing answer (D18). `RowColumnReadRoutesTest` (12 tests, Java only) covers each answer and
refusal; `SecurityGateTest#theConsoleReadsAFlaggedTablesSchemaRuleCountsAndEachCallersOwnView` (heavy) checks them on
the wire. Six bites in `bites/D20/` (`rule-view-schema-unguarded`, `rule-view-mine-without-select`,
`rule-view-mine-shows-the-filter`, `rule-counts-for-every-describer`, `rule-export-unguarded`,
`rule-export-expressions-to-auditors`); all six bite.

Left as it was: the audit records of rule changes (`RowColumnRuleChange`) carry the filter and masks, and audit
readers read them in the audit feed and tables without `manage-grants`.
