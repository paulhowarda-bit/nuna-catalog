Done (2026-11-23, branch `claude/console-wayfinding-d47d6a`): `auth.js` calls the IdP (discovery and token) through
one helper that gives up after 15 s and names the host: "keycloak:8080 is not answering: no reply in 15 s." Every
sign-in failure, and the refusal of an answer this tab did not start, now offers Start again, which forgets a
half-finished sign-in (`nuna.oidc.pending`) and opens the sign-in screen afresh. The sign-in keeps the IdP's ID token
in the tab (`nuna.id-token`, sessionStorage like the access token) only to send it as `id_token_hint` on sign-out, so
Keycloak ends its session without its "Do you want to log out?" page. The settings fetch gives up after 15 s and
offers Try again. The menu's "until" reads as every other time does (`at()`, "until 20:10"). The keyboard hint is
hidden where the pointer is coarse and nothing hovers. A namespace's header shows its dotted path only below the top
level. Contents drops a column with nothing on any row (format, queue, governance, snapshots or last commit), and on
a phone each value is labelled by its column (`data-label` on every cell `tbl()` draws). Checked live in the demo as
ana through the swap: `markets` shows its name once, its Contents has Name, Kind, Snapshots and Last commit only, the
menu reads "until 20:10". The sign-out and the slow IdP are checked by `ConsoleSignInTest` (heavy; not run live: the
demo's signed-in tab predates the ID token). Bites `console-ns-path-repeated`, `console-empty-column-kept`,
`console-signout-asks` and `console-idp-wait-unnamed`; `console-sign-in-ignores-state` recorded again.
