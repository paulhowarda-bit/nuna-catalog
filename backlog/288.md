# 288. Oracle reads every branch grant's ref as "?": V20's any_grant view lost its regex back-references

Status: done
Done: 2026-11-26 on worktree-agent-ace5262e199921c89
Added: 2026-11-26 by local_d6cc62d1-6c9d-46f4-88db-623c74725e78
Touches: catalog-store-oracle/src/main/resources/nuna/store/oracle/migration/
Effort: S: one new migration that replaces a view; the store suite's grant tests already cover it

Item 113's Oracle migration `V20__ref_grant.sql` builds `any_grant.ref_scope` for a grant that names a branch with
`REGEXP_REPLACE(RAWTOHEX(ref_id), '(.{8})(.{4})(.{4})(.{4})(.{12})', '\1-\2-\3-\4-\5')`, but the file holds the
control characters 0x01 to 0x05 where `\1` to `\5` should be (`od -c` of line 27 shows `001 - 002 - 003 - 004 -
005`): the backslash escapes were read as octal when the file was written. So every branch grant's ref reads back as
those characters, which reach Java as `"?"`, and `OracleGrants.grant` fails on `UUID.fromString("?")`.

Evidence: the by-hand heavy run on main at 4c5e0084 (Podman), `OracleStoreSuiteTest$Grants`, "Branch grants: a grant
may name a branch beside the same grant on every ref ...": `java.lang.NumberFormatException: Error at index 0 in:
"?"` at `OracleGrants.grant(OracleGrants.java:193)` from `GrantSuite.aGrantMayNameABranch(GrantSuite.java:76)`.
PostgreSQL and CockroachDB cast the uuid to text and MongoDB writes `UUID.toString()`, so only Oracle has the flaw.

Done: a new migration replaces the view with one that writes the id in lower-case hex with dashes without regex
back-references (V20 stays as it landed, so a database that applied it validates), and
`OracleStoreSuiteTest$Grants` passes.

## What was done (2026-11-26)

`V21__any_grant_ref_scope.sql` replaces `any_grant` with a view that cuts `RAWTOHEX(ref_id)` with `SUBSTR` and joins
the parts with dashes, lower-cased: no regex, so no escapes to lose. V20 is left as it landed, so an Oracle database
that applied it still validates and V21 mends its view. PostgreSQL (V19) and CockroachDB (V18) cast the uuid to text
and MongoDB writes `UUID.toString()`, the same lower-case dashed form, so the four stores agree and only Oracle
changed. No bite: the change adds no check, and no recorded bite touches the migration. `OracleStoreSuiteTest$Grants`
on Podman: 12 tests, 0 failures, 0 errors, 0 skipped; fast build green.
