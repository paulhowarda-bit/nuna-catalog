`AuditFeed.reader()` opens a new `EventsReader` whenever the audit table's pointer has moved (the writer commits about
once a minute) and drops the old one without closing it. `EventsReader.open` makes an Iceberg `S3FileIO`, and Iceberg
logs a WARN from the finalizer for every one collected unclosed. The nuna-demo's server log, 2026-11-22, three of them
in the minutes after Paul's click-through:

```
{"log":{"level":"WARN","logger":"org.apache.iceberg.aws.s3.S3FileIO"},"process":{"thread":{"name":"Finalizer"}},
 "message":"Unclosed S3FileIO instance created by:\n\torg.apache.iceberg.aws.s3.S3FileIO.<init>(S3FileIO.java:146)
 ...\n\tnuna.audittables.EventsReader.open(EventsReader.java:198)\n\tnuna.catalog.server.governance.AuditFeed.reader(
 AuditFeed.java:139) ...
```

`EventsReaderOnTheServerTest` (item 148) prints the same warning. With item 148 fixed the feed works, so a server
whose Audit page is open logs one such WARN for about each commit of the writer.

Closing the `S3FileIO` as it stands would close the S3 client it was handed (Iceberg 1.12's `PrefixedS3Client.close`
closes it), which is the server's client for the audit catalog (`AuditFeed.s3`), shared by every reader after it.

What done looks like: a replaced reader is closed without closing the shared S3 client (for example, the reader hands
`S3FileIO` a client whose `close` does nothing), and a test shows a replaced reader is closed and the next one still
reads.

What was done (2026-11-22, worktree-agent-aa7031d4244cedf1e):
- `EventsReader` is `AutoCloseable`: `close()` closes the table's `FileIO`, so its `S3FileIO`. `EventsReader.open`
  hands `S3FileIO` the caller's client wrapped in `Borrowed`, an SDK `DelegatingS3Client` whose `close` does nothing,
  so closing a reader leaves the server's client open. Read from iceberg-aws 1.12.0's bytecode: `S3FileIO.close`
  closes each `PrefixedS3Client`, which closes the client it was given, and `S3FileIO.finalize` calls `close()`
  before it logs the WARN. So before this, each unclosed reader the collector reached also closed the audit
  catalog's shared S3 client, and every reader after it read through a closed client: worse than the log line.
- `AuditFeed.reader()` closes the reader it replaces once the new one is open. A page another caller is still
  reading from the replaced reader finishes: a closed `S3FileIO` takes its client from its supplier again (the same
  bytecode), and that client's `close` does nothing.
- `AuditFeedReaderTest` (catalog-server, fast build, only Java): the real `AuditFeed` over a store double, the audit
  catalog's S3 client a double serving a real audit table (`AuditTableOverS3`: item 148's double, moved out of
  `EventsReaderOnTheServerTest` so both tests share it; once closed it refuses every call, as the SDK's client
  does). The pointer moves; the replaced reader is closed, the shared client is not, and the next reader pages both
  commits' rows. With today's code (both halves of the fix taken out) it fails: the replaced reader is not closed.
- Bites, both BITES: `bites/D23/feed-leaves-replaced-reader-open.patch` (the feed drops the replaced reader
  unclosed) and `bites/D23/feed-reader-closes-the-servers-client.patch` (`S3FileIO` gets the server's own client).
  Item 148's bite `bites/D23/feed-reader-builds-aws-factory.patch` is recorded again, with the same break, against
  the moved line; `EventsReaderOnTheServerTest` still passes, and fails under that bite with the same
  `NoClassDefFoundError`.
- Also on this branch: a view's Governance tab said "No DR freeze · Commits are allowed."; a view has no commits, so
  on a view it now says "Its definition may be replaced.", as the tab's "Replacing the definition" row does
  (`catalog-server/src/main/resources/nuna/ui/panels.js`).
