## What is missing

`GET /management/v1/maintenance/delete-policies` (`DeletePolicyRoutes.java`) is read by no console page, names no
commands, gives nothing for a profile with no `maintenance-principal` but "unprotected", and nothing produces the
worker's settings for a new bucket (Atelier, 2026-11-24). The operator dialog (item 254) needs all of it. D21 and D30
stand: the catalog writes these, never applies them.

## Done when

`GET /management/v1/maintenance/storage-setup`, for platform operators only, gives for each catalog storage profile:

- its catalogs and prefixes, and the worker's coverage and reach there (item 250);
- `worker-settings`: the prefix added to the worker's profile on the same store, or a new profile for a new store with
  the key's place marked, never a key. After item 256, a new store only;
- `store`: each delete policy with its commands for the store's kind (`mc admin policy create/attach` for MinIO,
  `aws s3api put-bucket-policy`, with `--endpoint-url` for Ceph), or `unprotected` with the catalog setting to add
  (`nuna.storage.profiles.<name>.maintenance-principal`).

Route tests cover MinIO, AWS S3 and Ceph, a bucket on a store the worker already reaches and one on a new store, and an
unprotected profile.

## Done (2026-11-24)

- `GET /management/v1/maintenance/storage-setup` (`StorageSetupRoutes`), platform operators only through
  `guard.requireOperator` as `/delete-policies` (`getMaintenanceStorageSetup`, refusals audited, reads not). Shape and
  example: docs/observability/table-health.md, "Storage setup"; a pointer in deploy/README.md, "Delete rights".
  `reported-at`, then per profile by name: `name`, `catalogs` (names from `nuna.storage.catalogs`), `kind`,
  `endpoint`, `prefixes`, `maintenance-principal` if named, `worker` (`reported` with each prefix's reach, or
  `not-reported`), `worker-settings` only while `not-reported` (`store`, `yaml` with
  `<the worker's access key on this store>` and a `ca-bundle` placeholder for a profile with a CA bundle, `secret`,
  and on AWS S3 `note` on IRSA/Pod Identity), and `store`: `generated` with `policies` (bucket policies with
  `aws s3api put-bucket-policy`, `--endpoint-url` on Ceph; MinIO's `except` and `to` with `mc admin policy
  create/attach`, `<alias>` and `<user>` marked) or `unprotected` with `setting`.
- The worker's identity on a profile's store is matched by kind and endpoint (scheme, host, port) as the worker
  matches them; reach comes from the newest scan with storage (listing) and the newest ended one (deletes), as
  readiness judges it. Shared, not written twice: `DeletePolicyRoutes.policies` (the same policy text as
  `/delete-policies`, whose output is unchanged) and `ReadinessRoutes.reach` (per-prefix reach).
- MinIO policies are named per profile (`nuna-no-delete-<profile>`, `nuna-worker-<profile>`): with one name per
  store, a second profile's `mc admin policy create` would replace the first's.
