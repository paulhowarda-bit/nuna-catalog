# 47. Table health and the worker's scans, kept by the catalog (D38; after 46)

Status: done
Done: 2026-11-15 on worktree-agent-acc3a000d93f274f0

What was done: the worker reports its own work through three PUT routes, `/management/v1/maintenance/scans/{id}`,
`.../tables/{id}/assessment` and `.../tables/{id}/compaction` (`HealthRoutes`): each scan as it starts and ends
(outcome as its meters judge it, failed jobs by kind, why a failed scan failed), each table's assessment as it makes it
(data files, small files, position deletes, deletion vectors, equality deletes, reasons, score), and each Job as it
starts, or is found after a restart, and ends (running, succeeded, failed, cut-off). Only a maintenance principal acting
as itself may report; a report names the table by id and name and is refused with 404 when it is gone and 409 when the
name is now another table's. Reports write no audit record; refusals are audited. A report the catalog does not take is
a new `report` failure kind in the worker and the work goes on. The store keeps the latest assessment and last
compaction per table (newest wins) and the last 50 scans plus the last success (`MaintenanceStore`: six new calls), on
PostgreSQL (V8), CockroachDB (V7), Oracle (V9) and MongoDB (step 7), each step only adding tables or collections and
indexes, so the rolling upgrade stays safe; a purge deletes the table's health. Reads: `GET
/management/v1/maintenance/tables` (the neediest tables the caller may select, in the worker's order, paged), `GET
.../tables/{table}/health` (select on it) and `GET /management/v1/maintenance/scans` (platform operators), all in
docs/observability/table-health.md for the console page (item 48). Tests: `HealthSuite` (6, in each store's suite),
`HealthRoutesTest` (5), `MutatingRoutesAuditTest` (the three report routes refused and audited), and
`NightlyCleanupTest` and `ScanMetricsTest` checking through real scans what the catalog keeps. Bites
`bites/D38/assessment-from-anyone` and `neediest-unfiltered`, both biting.
status/2026-11-15-agent-acc3a000d93f274f0.md has the detail.

What is left: the Oracle, MongoDB and CockroachDB suites (`HealthSuite` on each, and their schema steps) were written
but not run here; the overnight heavy build runs them. The worker does not read back what the catalog keeps: its night
state is still in memory, and a worker restarted after the window closed leaves that night's Jobs shown running until
the table's next Job.

Paul decided on 2026-11-15 (D38) that the console gets a health dashboard showing catalog health and table health.
Table health comes from the worker's nightly assessment (D30 as amended 2026-11-15, built by item 46), which would
otherwise exist only in the worker's meters and log. The console is served by the catalog, so the catalog must keep
it.

Done when:
- The worker reports, through a management route under `/management/v1/maintenance/`, each table's assessment as it
  makes it (small data files and their share, delete files by kind, equality deletes, the verdict and its reasons, when
  assessed, when last compacted and how that ended), and each scan's start, end and outcome.
- The catalog keeps the latest assessment per table and the last scans (enough to show the last successful one and
  recent failures) on all four stores (PostgreSQL, CockroachDB, Oracle, MongoDB), each with a schema step that keeps
  the rolling upgrade safe: older servers keep serving while the first new one migrates. This is maintenance state the
  catalog's own worker produces, like pending deletions; it is not the engines' metrics reports, which D13 keeps out of
  the database.
- Only the worker's identity may report, as with its other management calls. A report for a table that no longer
  exists, or is now another table by id, is refused.
- A management read route returns the neediest tables, only those the caller may read (select), and one table's
  assessment. The shared store suite covers the new store calls on all four backends (the fast build runs PostgreSQL).
- Bites in `bites/D38/` for the report refused from anyone but the worker, and the read filtered by grants.
