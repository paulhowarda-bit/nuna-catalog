## What is wrong

Row filters and column masks landed (backlog 115), but the console was not changed for them. Atelier, designing
their place in the console on 2026-11-24:

- On a flagged table (the demo's `markets.desks.positions`), the console's own table read is refused, since loading
  a table counts as storage access (`Guard.java`, `LOAD_TABLE`), even with delegation `none`. Overview, Schema and
  History show a bare 403 to everyone.
- A steward (manage-tags) has no button to set or remove the flag.
- The audit page has no kind or description for `row-column-rule`, so rule changes fall under "Other" with no words.

## Done when

- A flagged table's Overview, Schema and History say: "Its data is read through Trino, which applies each group's
  rules. The console shows no rows." No bare 403.
- On a table's Access tab, a steward sees "Flag for row and column rules" or "Remove the flag" (tables only:
  backlog 239). Removing it while rules stand is refused in words: "Rules stand: the grant admin removes them first."
- Rule changes on the audit page have their own kind and a sentence each: who set or removed which group's rule on
  which table.
- The console's browser tests cover each.

## What was done

Console only, in Atelier's words:

- **A flagged table's tabs.** When the console's load is refused (403) and the table's own row-column-policy flag is
  true (its governance answer; a flag on a level above does not close it), Overview, Schema and History show "Its data
  is read through Trino, which applies each group's rules. The console shows no rows." (`#read-through-trino`) instead
  of the refusal (`table.js`, `flaggedLoad`). Backlog 242's schema route is not used yet.
- **The steward's button.** On a table's Access tab, in the Governance panel's label buttons, a caller whose groups hold
  manage-tags sees "Flag for row and column rules" or "Remove the flag", tables only. Its dialog sets the flag `true`
  with provenance `console` through `PUT .../attributes/row-column-policy`, or removes it with `DELETE` (new
  `api.removeAttribute`). The catalog's 409 `RowColumnRulesExistException` shows as "Rules stand: the grant admin
  removes them first." (`panels.js`, `setFlag`).
- **Audit words.** `row-column-rule` is its own kind, "Row and column rules" with the badge "Rule", counted among the
  changes, and each record says "<who> set|removed the rule for group <group> on table <path>", on the Audit page and
  in an object's trail.
- **Tests.** `ConsoleFlaggedTableBrowserTest` (heavy, 3 tests): the steward flags a table, a reader's three tabs say
  the words with no refusal, removal is refused in words while a rule stands and succeeds once it is gone; a rule set
  and removed shows as two "Rule" rows with their sentences in the table's trail; the Audit page counts and filters the
  kind. Bites recorded: `bites/UI/console-flagged-table-shows-refusal`, `console-rules-stand-unworded`,
  `console-rule-change-no-kind`.
