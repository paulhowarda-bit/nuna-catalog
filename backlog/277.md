# 277. The console says no worker has reported when its newest scan reported no storage

## What is wrong

Since item 275, a scan that could not read its storage prefixes (the worker could not get a token just after a
restart, say) reports no storage, and readiness then answers grant, storage and store `unknown` with no
`reported-at`: the same answer as before any scan. The console can't tell the two apart, so Maintenance's readiness
panel (item 252) says "No maintenance worker has reported, so the catalog can't check this." on all three steps,
which is false: a worker did report, it only could not say what it reaches. Service's Worker storage panel (item 254)
says "No report yet" in the worker's identity column for the same case, though storage setup answers `unknown` there,
and the dialog "Set up the worker's storage" says "One change outside the catalog, in the store", when whether the
worker also needs settings is not known.

## Evidence

- `ReadinessRoutes.readiness` puts `reported-at` only from `Reported.last`, which is empty both with no scans and when
  the newest scan has no `storage`; nothing else in the answer differs (`ReadinessUnreadPrefixesTest` asserts the
  answer has no `reported-at` in the second case).
- `readiness.js`: `NOT_KNOWN` is drawn for every `unknown` grant and storage step, and for the store step when there is
  no `reported-at`.
- `storage.js` `identityOf`: no `reported-at` gives "No report yet", whatever `worker.state` says; `setupDialog` words
  its intro only by whether `worker-settings` is there.

## Done looks like

- Readiness and storage setup give `scanned-at`, the newest scan's time (its end, or its start while it runs), whenever
  the worker has reported a scan; it names nothing, so who reads each route is unchanged. A fast unit test asserts it
  in both cases, and a bite drops it.
- The readiness panel says the worker's last scan did not report its access when `scanned-at` is there and
  `reported-at` is not; the Service panel and the dialog say the same for a worker `unknown`. The words for no scan at
  all are unchanged.
- The browser tests that read these words (`ConsoleReadinessBrowserTest`, `ConsoleStorageSetupBrowserTest`) cover the
  new case; they are heavy, so the overnight run checks them.
