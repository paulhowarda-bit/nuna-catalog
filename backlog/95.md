# 95. Change feed: opt-in singlestore.append-only for insert-only tables

Status: done
Decided: 2026-11-20, D35
Done: 2026-11-20 on worktree-work-issues-002-003
Added: 2026-11-20 by Paul (from the install at work)
Touches: singlestore-change-feed/, decision-ledger.md, demo/README.md, bites/D35/
Effort: S, one pipeline setting, two checks and their tests

Reported from the Nuna install at work on 2026-11-20 (`for-paul/pending/003-change-feed-opt-in-singlestore-append-only-for-ins.md`
there, made on work's `main` in b6ed318, with D35 amended there). Work copies insert-only tables into Iceberg whose
primary key holds more columns than their shard key, which D35 rule (1) refuses. Rule (1) guards against an update
moving a row's key, which cannot happen on a table that is never updated.

At home, `SourceTable.read` refuses any table whose primary key is not exactly its shard key, and `ChangeBatch`
takes updates and deletes for every table.

What done looks like, as on work's `main`: a pipeline setting `singlestore.append-only` (`true`/`false`, default
false). With it on, the primary key need only contain the shard key (`SourceTable.checkKeys`), and the first UPDATE
or DELETE stops the feed in `ChangeBatch.accept`, before its transaction is applied, so no Iceberg commit or recorded
offset includes it and every restart stops at the same change. Off, nothing changes. `ChangeFeedTest` gets heavy
steps against a real SingleStore; D35 is amended; demo/README.md says how to recover (stop the pipeline, drop the
copy, `SNAPSHOT DATABASE`, start it). Work's heavy run found that dropping the copy alone replays the refused
change, because a start with no offsets reads the latest database snapshot and the log after it.

Done: `FeedConfig` reads `singlestore.append-only` (`true` or `false`, anything else refused); `SourceTable.checkKeys`
lets an append-only table's primary key contain its shard key, and tells others the setting exists;
`ChangeBatch.accept` stops at an append-only table's first UPDATE or DELETE, before its transaction, with a message
naming the table, partition, offset and the way back. D35 amended; demo/README.md has the recovery. The module's fast
tests pass, 28 of 28, and both bites in `bites/D35/` bite (ChangeBatchTest 1 of 5 failed, SourceTableTest 1 of 6).
`ChangeFeedTest` has three new heavy steps (append-only table copied; an update stops it at every start, copy and
offsets unchanged; dropping the copy alone stops again, and after `SNAPSHOT DATABASE` the copy is made afresh). They
were not run at home: the overnight heavy build runs them.
