Left over from 38, which made the worker export over OTLP but gave it nothing to trace:
- The worker makes no spans of its own. A scan, a purge or a compaction launch shows in a collector only as log lines
  and, once 40 lands, metrics. `nuna.maintenance.TelemetryTest` makes its one span by hand.
- Its calls to the catalog (`Worker.java`, `Management.java`, `TokenSource.java`) use a bare `java.net.http.HttpClient`,
  so they send no `traceparent`: the catalog's span for each call starts a trace of its own, and its request ID, which
  is that trace ID (38), joins nothing on the worker's side.

Done when:
- Each scan and each of its parts (the catalog reads, a purge, a compaction launch) is an Observation, so it is a span
  when tracing exports, named for what it does and labelled with no table, namespace or person beyond what 38's rule
  allows (docs/observability/README.md, "What labels and attributes never hold").
- The worker's HTTP calls to the catalog carry the current trace (W3C `traceparent`), so the catalog's spans join the
  worker's trace and the catalog's request ID for each call is the worker's trace ID. Micrometer's instrumentation of
  the JDK client (`micrometer-java11`) does this; it is a new artifact for work's mirror (docs/install-at-work.md).
- A test runs the worker against a catalog and an OTLP receiver (`OtlpReceiver`, catalog-server's test jar) and sees a
  scan's span and the catalog's span for one of its calls in one trace. Each guarded rule's bite is in `bites/OBS-49/`.

What was done: each scan is a trace. `ScanSpans` (catalog-maintenance) makes the scan an Observation,
`nuna.maintenance.scan.run` (span `maintenance scan`), and each part of it a child, `nuna.maintenance.part` (span
`maintenance <part>`): a work list page, a table's load, snapshot expiry, manifest rewrite, a compaction assessment, a
compaction launch, an orphan scan, a purge, an object's deletions, and each report to the catalog (item 47). Their
attributes are `part`, `outcome`, `exception` and, on the span alone, the work list's `section` and the report's kind;
a failure's span names the exception's class only. The worker's management calls and token requests go through
`micrometer-java11`'s client, so each is a client span carrying `traceparent`, its `uri` a route naming no catalog or
id; Iceberg's REST requests get the current span's `traceparent` from `BearerAuthManager`. `micrometer-java11` 1.17.2
is on install-at-work.md's list. `docs/observability/worker-spans.md` says what the spans are.

`WorkerTraceTest` runs the worker as a service against a catalog, both exporting to one `OtlpReceiver`, and sees the
scan's span, its parts, and the catalog's spans for the work list read and the table's load in one trace, with no
table, namespace, location, catalog or principal in the worker's attributes. `ScanSpansTest` checks nesting, outcomes
and failures without Docker. Seven bites in `bites/OBS-49/` all bite; three worker bites (D30 purge-without-claim,
D30 worker-maintains-another-table, OBS-40 purge-failure-counted-as-deletion) were recorded again against the moved
code and bite. The fast build passed: 1,319 tests, catalog-maintenance 50, all 282 bites apply.
