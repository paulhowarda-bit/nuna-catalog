**Implications**
- **(a) Enterprise running MinIO on-prem.** The community server got no releases after 2025-10-15, the repo is archived, and there are no official binaries or images. Any CVE found later stays unfixed upstream. A deployment older than `RELEASE.2025-10-15T17-29-55Z` is exposed to CVE-2025-62506, which lets a session-scoped credential escape its scope. That is exactly the catalog's threat model. The realistic paths are AIStor Enterprise or Enterprise Lite (paid), AIStor Free (single node only, licence file), or a fork such as Silo (one maintainer). The catalog must model MinIO's AssumeRole as "calling user's policies ∩ session policy". The vending identity should be a dedicated MinIO user whose own policy is the ceiling for the warehouse, not root: with root the ceiling is everything, and only the session policy limits it.
- **(b) MinIO as a test container.** `minio/minio` can no longer be pulled anonymously. Pin `pgsty/silo:RELEASE.2026-10-26T00-00-00Z`. Its STS session-policy code path is the same, by source inspection. Add a regression test for CVE-2025-62506: a vended credential calling the admin "add service account" API must be denied.

- moto provably ignores session policies.
- LocalStack's Hobby plan has no IAM enforcement at all, and Hobby is non-commercial anyway.

Prefer the Paid plan in that account: the Free plan auto-closes after 6 months.

## Recommended test setup

1. **Three oracles, one adversarial matrix.** Run the same parameterised suite on every target. For each vended credential scoped to `bucket/orders/`, assert:
   - Allowed: Get, Put and List (prefix `orders/`).
   - Denied: GetObject and PutObject on `orders2/x`; ListObjectsV2 with prefix `orders` (no slash), `orders2/` or `""`; DeleteObject outside the prefix; multipart upload outside the prefix; CopyObject from `orders2/` into `orders/`; any other bucket; a session policy over 2048 characters (must be rejected at vend time); calling AssumeRole again with the vended credential.
   - **Bite-test every deny:** first show that the unscoped parent credential *can* read `orders2/x`, so the denial is provably caused by the session policy.
2. **Laptop and CI (Testcontainers, every build):**
   - **MinIO semantics:** `pgsty/silo:RELEASE.2026-10-26T00-00-00Z`, pinned, via `MinIOContainer` 2.0.5 with `asCompatibleSubstituteFor("minio/minio")`. Create a dedicated MinIO user with a warehouse-bucket policy and vend from that user, never root. Add the CVE-2025-62506 regression check: the vended credential must not be able to create a service account.
   - **Ceph semantics:** `ghcr.io/clyso/ceph-test:v20.2.5` and `:v21.2.0` as a matrix, since Umbrella is 9 days old. Set `CEPH_EXTRA_CONF` with `rgw_s3_auth_use_sts = true` and `rgw_sts_key = <ceph-authtool --gen-print-key output>`. Wait with `ceph-test-health rgw`, then create the role and its policy with `execInContainer("radosgw-admin", …)`. Write a thin in-repo `GenericContainer` wrapper rather than depending on `jarlah` or `CleverCloud`: one is pinned to the stale `ceph/demo` images, and the other is not maintained against current releases (inference). The young clyso image is the main risk. Fallback: build the same image from its MIT Dockerfile in-repo.
3. **Real AWS (nightly or pre-release, not on every laptop run):** a dedicated sandbox account on the Paid plan, using its credits. One IAM role whose trust policy names the catalog's principal, one bucket, and the same matrix. This is the only oracle for AWS semantics.
4. **Do not use LocalStack or moto for the guardrail tests.** moto ignores session policies. LocalStack Hobby has no IAM enforcement, Hobby is non-commercial, and its paid enforcement does not document session policies or `s3:prefix`. A green run there would be the "exit 0 with plausible output" failure mode.
5. **Not verified by running:** every Docker image above on Windows Docker Desktop 27.1.1, the Java `StsClient` against Silo and RGW, and the signing region each expects. These are the first things to smoke-test.
